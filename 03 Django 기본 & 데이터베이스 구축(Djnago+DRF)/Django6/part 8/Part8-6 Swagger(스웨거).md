Swagger(스웨거)란 무엇인가?
	Swagger는 API 사용 설명서 + 테스트 도구입니다.

서버가 제공하는 API를 사람이 읽기 쉬운 문서로 보여주고,  
웹에서 직접 테스트까지 할 수 있게 해주는 도구입니다.

API가 뭐길래 Swagger가 필요한가요?

예를 들어,
- 서버 개발자:
	회원 목록을 가져오는 API 만들었어요.
    
- 프론트엔드 개발자:
	- 어떤 주소로 요청해요?  
	- GET이에요 POST에요?” 
	- 파라미터는 뭐 넣어요?  
	- 응답은 어떤 형태에요?
이런 질문이 계속 오가면 매우 비효율적이죠.
그래서 등장한 것이 Swagger입니다.

---
🧭 Swagger의 핵심 역할 (한 줄 요약)
	서버와 클라이언트가 API 약속을 한 눈에 보고, 직접 시험해볼 수 있게 해주는 도구

Swagger Editor란?

특징
- ✅ 설치 필요 없음 (웹사이트 접속만 하면 끝)
- ✅ 왼쪽에 **API 설명서(OpenAPI YAML)** 작성
- ✅ 오른쪽에 **실제 API 문서 화면**이 실시간으로 생성됨
    
📌 즉,  
설명서를 쓰는 즉시 → 문서 + 테스트 화면이 만들어짐

---
Swagger로 할 수 있는 일

|기능|쉽게 말하면|
|---|---|
|📄 API 문서화|API 설명서를 자동으로 만들어줌|
|🧩 입력값 안내|이 API를 쓰려면 무엇을 보내야 하는지 알려줌|
|🧪 즉시 테스트|버튼 클릭으로 실제 요청을 보내볼 수 있음|

🤔 Swagger는 언제 쓰나요?

✔ 이런 상황에서 사용합니다

- API가 제대로 동작하는지 빠르게 테스트하고 싶을 때

✅ Django에서 Swagger를 적용하려면?

1. Swagger 설치용 패키지 사용
Django에서는 **`drf-yasg`** 라는 패키지를 많이 사용합니다.
```
uv pip install drf-yasg
```

2. settings.py에 설정 추가
	`INSTALLED_APPS`에 `drf_yasg` 추가

3. `mysite/urls.py`에 Swagger URL 추가
```python
from drf_yasg.views import get_schema_view
from drf_yasg import openapi

schema_view = get_schema_view(
    openapi.Info(
        title="API 문서 제목",
        default_version='v1',
        description="API 설명",
    ),
    public=True,
)

urlpatterns = [
    ...
    path('swagger/', schema_view.with_ui('swagger', cache_timeout=0), name='schema-swagger-ui'),
]
```

`mysite/settings.py` 
```python
INSTALLED_APPS = [
    # ...
    "drf_yasg",          # ✅ 이 줄 필요
    # ...
] 
```

4. 이제 `/swagger/` 주소로 접속하면!
- 내가 만든 API들이 리스트로 쭉 나옵니다.
- 각 API를 클릭하면 어떤 값이 필요한지 확인 가능
- 실제 요청까지 해볼 수 있음!

✅ Swagger 사용의 장점

|장점|설명|
|---|---|
|✅ API 문서 자동 생성|코드만 잘 작성하면 문서를 따로 쓸 필요 없음|
|✅ 협업 편리|프론트/서버 개발자 간 소통 간편|
|✅ 테스트 가능|Postman 없이도 웹에서 바로 API 실행 가능|
|✅ 보기 쉬움|어떤 입력값이 필요한지, 어떤 응답이 오는지 명확하게 표시됨|

✅ Swagger는 꼭 써야 하나요?

- 반드시 써야 하는 건 아니지만, 팀 프로젝트나 협업 시 거의 필수 도구처럼 쓰입니다.
- Django, Spring, Node 등 거의 모든 백엔드 프레임워크에서 사용 가능
- Swagger 외에도 `Redoc`, `Postman`, `Rapidoc` 등의 도구도 존재

input과 output 필요한 이유
	서버와 대화를 하려면,  내가 뭘 말할지(input) 정해야 하고,  
	서버가 뭐라고 대답할지(output) 알아야 해요.

|역할|설명|예시|
|---|---|---|
|**input**|서버에게 보내는 데이터|예: {"name": "eunice", "password": "1234"}|
|**output**|서버가 나에게 돌려주는 결과|예: {"result": "success", "token": "abc123"}|
그런데 output에는 단순히 "화면에 보여줄 데이터" 외에도 다양한 정보가 들어갑니다.

| 항목               | 설명                           | 예시                                                |
| ---------------- | ---------------------------- | ------------------------------------------------- |
| 요청 결과 (성공/실패 여부) | 요청이 성공했는지 실패했는지 알려주는 코드나 메시지 | `"status": "success"`, `"code": "200"`            |
| 에러 메시지           | 실패한 경우, 왜 실패했는지 설명           | `"message": "비밀번호가 틀렸습니다."`                       |
| 응답 데이터           | 실제로 화면에 보여줄 유저 정보, 상품 목록 등   | `"username": "eunice"`, `"products": [...]`       |
| 토큰 or 인증 정보      | 로그인 후 인증용 토큰 발급              | `"token": "abc123.jwt.token"`                     |
| 페이징 정보           | 여러 페이지 중 몇 번째인지              | `"page": 1`, `"total_pages": 5`                   |
| 메타데이터            | 결과에 대한 부가 설명                 | `"count": 100`, `"timestamp": "2025-06-10T08:00"` |

---
우리가 input/output을 문서화하고 명시적으로 설계하는 이유는,  
“내가 아닌 다른 사람”도 이 API를 사용하게 될 것이기 때문입니다.  
즉, 협업을 위해서입니다.

왜 일일히 input/output을 정의해야 할까?

| 클라이언트 개발자(앱, 프론트엔드)가 이 API를 사용할 수 있도록 하기 위해  | 이들이 서버 코드를 열어볼 수 없기 때문입니다. API 스펙이 있어야 호출이 가능                |
| -------------------------------------------- | ------------------------------------------------------------ |
| 테스트와 디버깅을 쉽게 하기 위해                           | “이 API는 어떤 걸 줘야 하고, 어떤 걸 받을 수 있어요”라는 명세가 있어야 QA나 테스트가 가능합니다  |
| 유지보수와 확장을 위해                                 | 몇 달 뒤, 또는 다른 팀원이 왔을 때 "이 API는 왜 이렇게 만들었지?" 하고 코드를 뒤적이지 않게    |
| 자동화 도구와 연동하기 위해                              | Swagger, Postman, CI 테스트, API 게이트웨이 등 많은 도구들이 명세를 기준으로 작동합니다 |
| API 사용자(외부 개발자, 클라이언트)의 입장에서 완전히 독립적인 설명이 필요 | API는 하나의 제품이기 때문에 설명서 없이 쓸 수 없습니다                            |

Swagger는 JSON 코드(또는 코드 내부의 스펙)를 자동으로 분석해서  
"이 API는 이런 input을 받고 이런 output을 줍니다"라고 시각적인 문서로 정리해주는 도구입니다.

OpenAPI 문법이란 API 명세(specification)를 작성할 때 사용하는 표준 형식이고,
그것을 표현하는 문서 포맷 중 하나가 바로 YAML(.yml) 파일

입니다.
