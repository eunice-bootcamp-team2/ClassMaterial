🔹 GET (기본 요청)
- 설명: 서버에서 정보를 가져오기 위한 요청이에요. 데이터를 가져올 뿐, 서버의 내용은 바뀌지 않아요.
- 예시 주소: 제품 목록을 요청 (읽기 전용)
```python
https://example.com/?lecture=abc
```

🔹 POST
- 설명: 서버에 새로운 데이터를 보내서 등록할 때 사용해요.
- 예시 주소:
```python
https://example.com/lecture/order
```
→ 새로운 상품을 추가할 때 (예: 상품명, 가격 등 전송)

🔹 PUT
- 설명: 서버의 데이터를 완전히 수정할 때 사용해요. 기존 데이터를 통째로 바꿔요.
- 예시 주소:
```python
https://example.com/lecture/10
```
→ ID가 10번인 상품 정보를 전부 수정

🔹 DELETE
- 설명: 서버의 특정 데이터를 **삭제**할 때 사용해요.
- 예시 주소:
```python
https://example.com/lecture/10
```
→ ID가 10번인 상품을 삭제

📝 참고용 (보조 요청 메서드)
`5.` HEAD
- 설명: GET과 비슷하지만, 본문(body) 없이 헤더만 요청해요. 빠르게 서버 상태 확인할 때 사용.

`6.` CONNECT
- 설명: 클라이언트와 서버 간에 터널 연결을 설정해요. 주로 HTTPS 통신 때 사용.

`7.` OPTIONS
- 설명: 해당 URL에서 **어떤 HTTP 메서드들이 가능한지** 확인할 때 사용해요.
- 예시: 브라우저가 서버에 먼저 OPTIONS 요청을 보내서 CORS 허용 여부를 확인함.

`8.` TRACE
- 설명: 서버가 받은 요청을 그대로 되돌려주는 테스트. 네트워크 디버깅용으로 사용돼요.

`9.` PATCH
- 설명: PUT과 비슷하지만, 일부분만 수정할 때 사용해요.
- 예시 주소:
```python
https://example.com/lecture/10
```
→ ID 10번 상품의 가격만 수정할 때

🔹 GET 방식  
- 데이터를 가져올 때 사용 (조회)  
- 주소(URL)에 데이터가 포함됨 (예: ?id=123&name=kim)  
- 보안이 낮고, 주로 검색, 조회 등에 사용  
  
💬 예시:  
- 웹사이트에서 검색: https://example.com/search?q=apple  
- 블로그 글 보기: https://blog.com/post?id=123  

🔹POST 방식  
- 데이터를 서버에 보낼 때 사용 (저장, 전송)  
- 주소(URL)에 데이터가 보이지 않음  
- 보안이 필요할 때, 데이터 변경이 있을 때 사용  

💬 예시:  
- 회원가입: https://example.com/signup (아이디, 비밀번호 입력 후 서버로 전송)  
- 게시글 작성: https://blog.com/newpost (제목, 내용 입력 후 저장)  

💬 쉽게 기억하는 방법:
- GET → "가져오기" (조회)  
- POST → "보내기" (저장, 전송)  
 ---
🔹 GET을 쓰는 이유
- 빠름: 
	캐싱(저장)이 가능해서 같은 요청을 하면 서버가 빠르게 응답할 수 있어.  
- 편리함: 
	URL에 데이터가 포함되므로, 공유하거나 북마크(즐겨찾기)할 수 있음.  
	예시: https://example.com/search?q=apple → 다음에도 같은 검색 가능  
- 조회 전용: 
	데이터를 변경하지 않고 "읽기"만 할 때 적절함.  

---
🔹 GET의 보안 문제
- URL에 데이터 노출:  
	- 브라우저 히스토리, 로그, 즐겨찾기 등에 저장될 수 있음.  
	- 예시: https://bank.com/account?user=kim&balance=1000000 → 이런 정보가 노출되면 안 됨!  
- 데이터 길이 제한:  
	- URL 길이에 제한이 있어서 많은 데이터를 보낼 수 없음.  
---
🔹 보안이 필요할 때는?

⭕ 보안이 중요한 경우에는 POST를 사용!
- 로그인, 개인정보 조회 등 민감한 데이터는 POST를 써야 함.  
	- ❌ 잘못된 예: https://example.com/login?user=kim&password=1234 (GET 방식, 비번 노출!)  
	- ⭕ 올바른 예: POST https://example.com/login (비번 숨김)  

 ✅ GET을 사용할 때 보안 강화 방법
- 민감한 정보는 URL에 포함하지 않기  
- HTTPS 사용: GET이라도 암호화됨 (중간에서 가로채는 걸 방지)  
- 토큰 인증 사용: URL 대신 인증 토큰을 활용해서 접근 제어  
  
---
정리하면:
- GET: 조회용, 민감한 정보 X (예: 검색, 게시글 보기)  
- POST: 보안이 필요한 데이터 전송 (예: 로그인, 회원가입, 결제)  
- 보안이 필요한 GET 요청? → HTTPS + 토큰 방식 활용!
