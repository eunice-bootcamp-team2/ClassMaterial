# 3. 기능 정의 (학생용 요구사항 명세)
## 3-1. 도메인 정의: 거래(지출/수입)
	데이터가 무엇인가? / 어떤 구조로 다루나?

도메인 정의란?
	이 프로젝트에서 다루는 핵심 개념(데이터)이 무엇인지 정리하는 것

- 가계부라는 시스템에서,
- 기본 단위 데이터는 무엇이며,
- 어떤 정보들이 포함되어야 하는가?
---
🔹 한 건의 거래
	가계부에서 우리가 기록할 기본 단위는 "거래 한 건" 입니다.  
	거래 한 건은 아래 다섯 가지 정보를 반드시 포함합니다:

| 항목              | 의미               | 예시         |
| --------------- | ---------------- | ---------- |
| 날짜(date)        | 돈이 오간 날짜         | 2025-01-01 |
| 구분(type)        | 지출인지, 수입인지       | 지출 / 수입    |
| 카테고리(category)  | 어디에 썼는지, 어떤 종류인지 | 식비, 교통, 급여 |
| 내용(description) | 간단한 메모           | 점심 식사      |
| 금액(amount)      | 얼마인지 (원 단위)      | 8000       |
이 다섯 가지를 하나로 묶어서 관리하는 것이 목표입니다.

`[요구사항]`
➤ “거래 한 건을 표현할 수 있는 구조를 만들어라.”

`두가지 방법을 선택할수 있습니다.`
✔ 딕셔너리로 만들기  
✔ 클래스로 만들기

둘 다 OK — 형태만 맞으면 됩니다.

예시 (클래스 버전):
```python
class Transaction:
    def __init__(self, date, ttype, category, description, amount):
        self.date = date          # "2025-01-01"
        self.ttype = ttype        # "지출" 또는 "수입"
        self.category = category
        self.description = description
        self.amount = amount      # int
```
이 클래스는 거래 한 건을 저장하는 틀(템플릿)입니다.  
앞으로 우리가 입력하는 모든 지출/수입 데이터는 이 틀을 사용해 하나의 객체로 만들어 관리할 수 있습니다.

예를 들어:
```python
t1 = Transaction("2025-01-01", "지출", "식비", "점심", 8000)
```
이렇게 하면 `t1` 안에 거래 정보가 하나로 묶여 저장됩니다.


예시 (딕셔너리 버전):
```python
transaction = {
    "date": "2025-01-01",
    "type": "지출",
    "category": "식비",
    "description": "점심 식사",
    "amount": 8000
}
```
→ 키(문자열)로 값을 저장하는 아주 단순한 구조죠.

🔹 여러 건을 저장하고 싶다면?
	리스트 + 딕셔너리 조합을 사용합니다.
```python
transactions = [
    {
        "date": "2025-01-01",
        "type": "지출",
        "category": "식비",
        "description": "점심",
        "amount": 8000
    },
    {
        "date": "2025-01-02",
        "type": "수입",
        "category": "급여",
        "description": "아르바이트",
        "amount": 300000
    }
]
```
이렇게 하면:
- 리스트 = “거래 목록”
- 딕셔너리 = “거래 한 건” 이 됩니다.

여기는 데이터를 어떻게 “형태로 표현할지” 정의하는 부분입니다.
즉, “거래 데이터를 어떻게 저장할까?” (딕셔너리로? 클래스 객체로?)를 정하는 단계입니다.

## 3-2. 기능 요구사항 (MVP)
	이 데이터를 가지고, 프로그램이 무엇을 할 수 있어야 하는가?

- F1 — 등록
- F2 — 목록 조회
- F3 — 요약 통계
- F4 — 저장/불러오기
- F5 — 카테고리 통계
위와 같이 작업단위를 쪼개서 하나씩 완성하면 됩니다.

---
예시: 
“가계부 기능을 만든다” 라고 하면 학생이 막연하지만,

이렇게 적으면
> “버튼 클릭 시 거래 저장”  
> “화면에 표로 표시”  
> “CSV에 저장” 처럼 구현 목표가 눈에 보이므로 이런식으로 생각해 보기

---
### ✅ F1. 거래 등록 (입력 기능)

**요구사항**
1. 사용자는 다음 항목을 입력할 수 있어야 한다:
    - 날짜
    - 구분(지출/수입)
    - 카테고리
    - 내용
    - 금액(정수)
2. “등록” 버튼을 누르면:
    - 입력값으로 **거래 한 건 객체(또는 딕셔너리)** 를 만든다.
    - 거래 목록 리스트에 추가한다.
3. 금액은 숫자가 아니면 추가되지 않도록 한다(최소한 기본 검증).

**Streamlit 기준**
- 입력 폼 구성:
    - `st.date_input()`
    - `st.selectbox()`
    - `st.text_input()`
    - `st.number_input()`
- `st.button("등록")` 클릭 시 처리 실행.
---
### ✅ F2. 거래 목록 조회 (표 보기)

**요구사항**
1. 현재 저장된 거래 목록을 표로 보여준다.
2. 표에는 최소한 다음 컬럼이 있어야 한다:
```
날짜 | 구분 | 카테고리 | 내용 | 금액
```
    
3. 목록이 비어 있으면 **“등록된 거래가 없습니다.”** 같은 안내 메시지를 보여준다.
    
**Streamlit 기준**
- 거래 리스트 → `pandas.DataFrame` 변환
- `st.dataframe()` 또는 `st.table()` 로 출력
---
### ✅ F3. 요약 통계 (총합 계산)

**요구사항**
1. 전체 거래를 기준으로:
    - 총 수입 합계
    - 총 지출 합계
    - 현재 잔액(수입−지출)을 계산한다.
    
2. 계산 로직은 별도 함수로 분리한다:
```python
calc_summary(transactions) -> (income, expense, balance)
```
    
2. 화면 상에서 한눈에 보기 쉽게 표시한다.
    
**Streamlit 기준**
- `st.metric()` / `st.write()` 등을 사용해 표시.
---
### ✅ F4. 파일 저장 / 불러오기 (CSV)

**요구사항**
1. 프로그램은 거래 데이터를 **CSV 파일**로 저장한다.
2. 앱 실행 시:
    - CSV가 존재하면 → 파일에서 데이터를 읽어 목록에 넣는다.
    - CSV가 없으면 → 빈 리스트로 시작한다.
3. 사용자가 거래를 등록하면:
    - 리스트에 추가
    - **CSV에 덮어쓰기 저장**
4. CSV 형식 예시는 다음과 동일해야 한다:

```
date,type,category,description,amount
2025-01-01,지출,식비,점심,8000
...
```

**Repository 설계**
- `load_transactions()`
- `save_transactions()` 처럼 함수로 분리.
---
### ✅ F5. 카테고리별 지출 통계 (그래프)

**요구사항**
1. 거래 중 **type == "지출"** 인 데이터만 대상으로 한다.
2. 카테고리별 합계를 계산한다.
    
예:
```
식비: 22000
교통: 4500
기타: 12000
```
    
3. 계산된 결과를 그래프로 시각화한다.

**Streamlit 기준**
- DataFrame 그룹화 후
- `st.bar_chart()` 로 막대 차트 표시.
---

## 3-3. 선택(도전) 기능
	필수는 아니지만, 하면 실력 + 점수 + 자신감이 올라가는 미션입니다.

#### D1. 기간 필터 (날짜로 보기)

**목표**
> 시작일 ~ 종료일을 선택하면 그 기간에 해당하는 거래만 목록/통계에 반영된다.

**요구사항**
1. 화면에 날짜 범위 선택 UI 추가:
```python
start, end = st.date_input("기간 선택", value=[기본_시작, 기본_종료])
```

2. 거래 목록에서:
```
start<= 거래.date<=end
```

조건에 맞는 데이터만 필터링한다.

3. 필터된 결과를:
	- 목록 표
	- 요약 통계
	- 그래프 모두에 적용한다.

---
#### D2. 메모 검색 (키워드 필터)

**목표**
> 내용(description)에 특정 단어가 포함된 거래만 보여준다.

**요구사항**
1. 검색 입력창 추가:
```python
keyword = st.text_input("검색어 입력 (내용 포함)")
```

2. keyword가 비어있지 않으면:
```
keyword.lower() in transaction["description"].lower()
```

조건을 만족하는 거래만 보여준다.
3. 검색은 목록 + 통계 모두에 연동되도록 한다.

---

#### D3. 간단한 테스트 코드 (TDD 맛보기)

**목표**
> 눈으로만 확인 하는 대신 assert 로 자동 체크하는 경험을 해본다.

**요구사항**
1. `tests/` 폴더에 테스트 파일 생성:
```
tests/test_services.py
```

2.  아래 항목을 테스트한다:
- `calc_summary()`
- (선택) 카테고리별 합계 함수

2. 예시 코드:
```python
import unittest
from ledger.services import calc_summary   # 실제 함수 불러오기

class TestServices(unittest.TestCase):

    def test_calc_summary(self):
        transactions = [
            {"type": "수입", "amount": 10000},
            {"type": "지출", "amount": 3000},
        ]

        income, expense, balance = calc_summary(transactions)

        self.assertEqual(income, 10000)
        self.assertEqual(expense, 3000)
        self.assertEqual(balance, 7000)


# python test_services.py 로 직접 실행해도 동작
if __name__ == "__main__":
    unittest.main()
```

