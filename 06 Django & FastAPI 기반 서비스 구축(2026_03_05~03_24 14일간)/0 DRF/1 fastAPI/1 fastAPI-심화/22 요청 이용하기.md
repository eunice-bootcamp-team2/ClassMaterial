`Request`란?
`Request`는 클라이언트(브라우저, React 앱 등)가 FastAPI 서버에 요청을 보낼 때 전달되는 모든 정보를 담고 있는 객체입니다.

쉽게 말해:
	"누가 언제 어떤 내용으로 요청했는지 다 담겨있는 내용입니다."

왜 필요한가?
FastAPI는 기본적으로 `GET`, `POST` 등의 요청을 받아서 응답을 해줘요. 하지만, 어떤 요청인지, 누구한테서 왔는지, 어떤 값을 보냈는지 세부 정보가 필요할 때가 많습니다.

예를 들어:
- 로그인한 사용자의 IP가 궁금할 때
- 요청 헤더나 쿠키로 인증 정보를 받고 싶을 때
- 요청 본문(body)에 파일이나 JSON 데이터가 있는지 확인할 때
- URL에 쿼리스트링이 붙었는지 확인할 때

###### Request에서 어떤 정보들을 꺼낼 수 있나?
| 항목                     | 예시                                | 설명                                                                          |
| ---------------------- | --------------------------------- | --------------------------------------------------------------------------- |
| `request.method`       | `"GET"`, `"POST"` 등               | 클라이언트가 사용한 HTTP 요청 방식 (GET, POST, PUT, DELETE 등)                            |
| `request.url`          | `http://127.0.0.1/items/3`        | 요청의 전체 URL 주소                                                               |
| `request.headers`      | `User-Agent`, `Authorization` 등   | 요청에 포함된 HTTP 헤더 정보 (브라우저 정보, 인증 토큰 등)                                       |
| `request.cookies`      | 로그인 쿠키 등                          | 요청에 포함된 쿠키 정보 (예: 세션 ID, 로그인 상태 등)                                          |
| `request.query_params` | `?name=abc&age=3`                 | URL에 붙는 쿼리 파라미터들을 key-value 형태로 가져옴                                         |
| `request.path_params`  | `items/{item_id}` 중 `{item_id}` 값 | URL 경로에 포함된 변수 값 (예: `/items/3` → `item_id=3`)                              |
| `request.body()`       | JSON 등 POST로 보내는 본문 데이터           | 요청의 본문(body) 데이터를 비동기적으로 읽어올 때 사용. 일반적으로 JSON 데이터 처리에 사용됨                   |
| `request.form()`       | 폼 데이터를 받을 때                       | `application/x-www-form-urlencoded` 또는 `multipart/form-data` 형식의 폼 데이터를 파싱함 |
| `request.client`       | 요청한 사람의 IP 주소 등                   | 클라이언트의 IP 주소 및 포트 정보 (`(ip, port)` 튜플)                                      |
| `request.app`          | 현재 실행 중인 FastAPI 앱                | 현재 실행 중인 FastAPI 애플리케이션 인스턴스에 접근 가능                                         |

언제 사용하는가?
- API 디버깅할 때 (요청을 모두 기록하는 로그용)
- 사용자 인증 정보 확인
- 웹 클라이언트가 어떤 기기인지 판단할 때 (`User-Agent`)
- 쿠키 기반 로그인 처리
- 성능 측정용 (미들웨어로 요청 처리 시간 측정)

요청의 전체 목적 요약:
아래 요청은 브라우저(Chrome)가 FastAPI 서버의 `/request-info` 경로에 대해 `GET` 요청을 보낸 상황입니다. 서버는 이 요청에 대해 다음을 응답했습니다:
요청에 대한 전체 메타정보(메서드, 헤더, 쿠키 등) 를 JSON 형태로 반환
```python
# request_info.py
from fastapi import FastAPI, Request

app = FastAPI()

@app.get("/request-info")
async def get_request_info(request: Request):
    return {
        "method": request.method, # 요청 방식: GET, POST 등
        "url": str(request.url),  # 전체 요청 URL
        "client_host": request.client.host,# 클라이언트 IP 주소
        "headers": dict(request.headers),# 전체 요청 헤더
        "query_params": dict(request.query_params),  
        # 쿼리 파라미터 (?key=value)
        
        "cookies": request.cookies,  # 쿠키 정보
        "path_params": request.path_params, # 경로매개변수(/{id} 등)
        "app_name": str(request.app.title),# 현재 FastAPI 앱 이름
    }
```

실행:
```
uvicorn request_info:app --reload
```

요청 결과:
```json
{
  "method": "GET",
  "url": "http://localhost:8000/request-info?name=banana&price=3000",
  "client_host": "127.0.0.1",
  "headers": {
    "host": "localhost:8000",
    "user-agent": "Mozilla/5.0 ...",
    "accept": "*/*",
    ...
  },
  "query_params": {
    "name": "banana",
    "price": "3000"
  },
  "cookies": {},
  "path_params": {},
  "app_name": "FastAPI"
}
```

- `request.method`: 어떤 방식으로 요청했는지 (GET, POST 등)
- `request.url`: 전체 URL을 문자열로 출력
- `request.client.host`: 요청한 사람의 IP 주소
- `request.headers`: 요청할 때 같이 보낸 헤더들
- `request.query_params`: URL에 `?key=value`로 붙은 정보
- `request.cookies`: 쿠키를 사용하는 경우
- `request.path_params`: URL에 포함된 변수들 (`/items/{id}` 같은 경우)
- `request.app.title`: FastAPI 앱의 이름 (`FastAPI()` 기본값은 `"FastAPI"`)

기본 요청 정보
```json
{
  "method": "GET",
  "url": "http://127.0.0.1:8000/request-info",
  "client_host": "127.0.0.1"
}
```
- `method`: `GET` → 클라이언트가 서버에서 데이터를 조회하고자 요청함.
- `url`: `http://127.0.0.1:8000/request-info` → 로컬 서버 주소. FastAPI 앱이 이 주소에서 동작 중.
- `client_host`: `127.0.0.1` → 요청을 보낸 클라이언트의 IP. 로컬(자기 자신)에서 요청함.

헤더 정보
```json
"headers": {
  "host": "127.0.0.1:8000",
  ...
  "user-agent": "Mozilla/5.0 ... Chrome/138.0.0.0 Safari/537.36",
  ...
  "accept-language": "ko-KR,ko;q=0.9,en-US;q=0.8,en;q=0.7"
}
```
요청 헤더는 브라우저 또는 클라이언트가 서버에게 요청을 보낼 때 첨부되는 추가 정보입니다.
- `"host"`: 요청 대상 서버의 주소 (`127.0.0.1:8000`)
- `"user-agent"`: 요청을 보낸 브라우저 정보 (Chrome 138 on Windows)
- `"accept"`: 클라이언트가 받고자 하는 응답 타입들 (`text/html`, `application/json` 등)
- `"accept-language"`: 브라우저 언어 설정 (`ko-KR` 우선)
- `"cookie"`: 클라이언트의 세션 및 사용자 관련 식별 정보 포함

쿠키 정보
```json
"cookies": {
  "username-127-0-0-1-8888": "...",
  "_xsrf": "...",
  "csrftoken": "...",
  "sessionid": "..."
}
```
###### 요청 시 포함된 **쿠키 값**들입니다:
|쿠키 이름|의미|
|---|---|
|`username-127-0-0-1-8888`|사용자 이름 정보 (base64 인코딩된 JSON)|
|`_xsrf`|CSRF 보호 토큰 (보안용)|
|`csrftoken`|Django 기반에서 자주 쓰이는 CSRF 토큰|
|`sessionid`|세션 인증에 사용되는 고유한 식별자|
이 쿠키들은 대부분 인증 또는 사용자 상태를 유지하기 위한 용도입니다.

쿼리 파라미터 / path 파라미터
```json
"query_params": {},
"path_params": {}
```
- 둘 다 비어 있음 → `/request-info`는 단순 조회용 URL이며, `?id=1` 같은 추가 파라미터 없이 호출됨.

어떤 앱에서 이 요청을 처리했는가
```json
"app_name": "FastAPI"
```
- 이 요청을 처리한 서버는 `FastAPI`로 구축된 웹 애플리케이션입니다.
- 아마 다음과 같은 라우터 함수가 FastAPI에 정의되어 있을 것으로 예상됩니다:

✅ 이 요청으로 할 수 있는 것들:

`1.` 누가 요청했는지 확인할 수 있어요 (클라이언트 디버깅)
요청을 보낸 사용자의 정보를 확인할 수 있습니다.
- 어떤 브라우저인지 알 수 있어요 → `User-Agent`
- 어디서 접속했는지(IP) 확인할 수 있어요 → `client.host`
- 쿠키에 어떤 값이 들어있는지 볼 수 있어요 → `request.cookies`
- 요청에 포함된 모든 헤더를 확인할 수 있어요 → `request.headers`
- 사용자의 언어 설정이 뭔지도 볼 수 있어요 → `accept-language`
    예: 사용자가 크롬으로 접속했는지, 한국어로 설정했는지, 어떤 쿠키를 들고 왔는
    지 확인 가능!
---
`2.` 로그인/보안 문제가 있는지 확인할 수 있어요
요청을 보면 로그인 여부나 인증 문제가 있는지 체크할 수 있어요.
- CSRF 토큰이 쿠키에 들어있는지 볼 수 있어요
- 세션 ID (`sessionid`) 가 쿠키에 있는지 확인해서 로그인했는지 알 수 있어요
- JWT 토큰이 `Authorization` 헤더에 들어 있는지 확인 가능해요
	예: 로그인 안 되는 문제가 있다면, 쿠키나 헤더가 빠졌는지 확인 가능!
---
 `3.` 사용자에게 맞는 화면을 보여줄 수 있어요 (맞춤형 응답)
사용자의 정보에 따라 다르게 응답할 수 있어요.
- 언어 설정(`accept-language`) → 한국어로 설정했으면 한국어 페이지 보여주기
- 모바일인지 아닌지(`sec-ch-ua-mobile`) → 모바일이면 모바일 전용 화면 제공
	예: 한국어 사용자에게는 한글로, 아이폰 유저에게는 모바일 UI로 응답 가능!
---
`4.` 개발 중 요청 내용을 직접 확인할 수 있어요
FastAPI에서는 다음처럼 "요청 정보 보기용" API를 자주 만들어요:
```python
# 위에 실습한 내용과 동일한 코드
from fastapi import Request

@app.get("/check-request")
async def check_request(request: Request):
    return {
        "method": request.method,
        "url": str(request.url),
        "headers": dict(request.headers),
        "cookies": request.cookies,
        "client": request.client.host
    }
```
개발할 때, 프론트에서 요청을 제대로 보내는지 확인할 수 있는 아주 유용한 도구!

---
`5.` 프록시/중간 서버를 거치는 경우도 테스트 가능
요청에 따라 프록시(중간 서버) 가 제대로 동작하는지도 확인할 수 있어요.
- `X-Forwarded-For` 같은 헤더를 통해 진짜 사용자 IP가 잘 전달되고 있는지 테스트 가능
	예: 클라우드플레어나 Nginx 등을 사용할 때, 진짜 IP를 잘 받는지 확인할 수 있어요.
---
`6.` 프론트엔드와 백엔드 연결 확인
프론트에서 보낸 요청이 정상적으로 서버에 도착했는지 확인할 수 있어요.
- Axios/fetch로 보낸 요청이 실제로 어떤 헤더, 쿠키, 본문을 가지고 왔는지 확인
- CORS(도메인 허용), 세션 문제, CSRF 문제도 디버깅 가능
	예: 로그인 API 호출했는데 안 될 때, 쿠키나 헤더가 제대로 전달됐는지 확인 가능!

💡 Request와 Header는 어떤 차이가 있을까?
- Request(요청) 은  
    사용자가 브라우저나 앱(예: Chrome, Insomnia, React 앱 등)을 통해  
    서버(FastAPI, Django 등)에게  
    "이 페이지 보여줘", "이 데이터 저장해줘" 같은 명령을 보내는 전체 메시지예요.
    
- Header(헤더) 는  
    이 요청에 추가 정보를 담은 부분이에요.  
    예를 들어, "나는 크롬 브라우저야", "이건 로그인한 사용자야", "JSON 형식이야" 같은 정보를 담아요.

Header는 Request 안에 들어 있는 중요한 정보지만, Request 전체는 Header보다 훨씬 더 넓은 범위를 가진 개념이에요.

###### Django / DRF / FastAPI 비교
| 프레임워크   | 함수 형태 예시                        | 설명                                                                         |
| ------- | ------------------------------- | -------------------------------------------------------------------------- |
| Django  | `def my_view(request):`         | 브라우저나 클라이언트가 보낸 전체 요청이 `request`에 담겨요.                                     |
| DRF     | `def get(self, request):`       | DRF의 `APIView`에서 `request`는 DRF의 `Request` 객체로, 일반 Django보다 조금 더 편리하게 다뤄짐. |
| FastAPI | `def my_api(request: Request):` | `request`는 `starlette.requests.Request` 객체로, 비동기 요청도 잘 처리할 수 있어요.          |
클라이언트가 서버에 `POST`, `GET` 요청을 보내고, 이때 서버에서 그 요청을 처리하는 함수가 실행되면, `request` 객체 안에 모든 요청 정보가 담기고, 서버에서는 이 정보를 로그에 기록하거나 처리에 활용할 수 있어요.

`1.` 클라이언트 → 서버로 요청을 보냄
	예: 프론트엔드에서 버튼 클릭 → POST 요청 발생
```js
// 예: JavaScript에서 axios로 POST 요청
axios.post("/api/items/", { name: "사과" });
```

`2.`서버에서는 해당 요청을 처리하는 함수가 실행됨
```python
# Django 예시
def create_item(request):
    if request.method == "POST":
        data = request.POST  # 또는 request.body에서 JSON 파싱
        # 요청 데이터 처리
```
이때 `request` 객체 안에는:
- 요청 방식 (POST인지 GET인지)
- URL
- 본문 데이터 (예: {"name": "사과"})
- 쿠키, 헤더, 유저 정보 등등
➡️ 모든 요청 관련 정보가 들어 있습니다.

그럼 요청 내용이 "기록"된다는 건 뭘까?
	요청 정보는 서버의 "로그"에 자동으로 남지는 않아요.
	하지만 우리가 `print(request)` 하거나,  
	`logger.info(request.body)`처럼 로그로 남기면 서버에 기록됩니다.

그리고 웹 서버(Nginx, Apache 등)는 기본적으로 요청 URL, IP, 응답코드 등을 자동으로 기록합니다.

HTTP 요청 헤더(Request Header)"의 개념과 FastAPI에서의 활용

`1.` 요청(Request Header) — 클라이언트 → 서버
	클라이언트(브라우저, 앱 등)가 서버로 요청을 보낼 때, 이 요청에 헤더 정보를 담습니다.
예시:
```
GET /items/123 HTTP/1.1
Host: localhost:8000
User-Agent: Chrome/119.0
Accept: application/json
Authorization: Bearer abc.def.ghi
```
 해석:
- Host: 어디로 요청을 보낼 건지
- User-Agent: 누가 보냈는지 (브라우저 정보)
- Accept: 나는 어떤 형식(JSON 등)을 받고 싶어
- Authorization: 로그인 토큰 (인증 정보)
    
→ 이런 요청 헤더 정보는 FastAPI에서 `request.headers`로 확인 가능

---
`2.` 응답(Response Header) — 서버 → 클라이언트
	서버가 클라이언트에게 결과를 보낼 때, 응답 데이터뿐 아니라 헤더 정보도 함께 전달합니다.
예시
```http
HTTP/1.1 200 OK
Content-Type: application/json
X-Process-Time: 0.0041
Cache-Control: no-store
```
이건 FastAPI의 미들웨어나 응답 설정에서 `response.headers["..."]`로 설정 가능

비유로 이해하기
- 전체 Request = 손님이 식당에 온 상황 전체
    - 누가 왔는지(IP), 어떤 요리 주문했는지(URL, body), 어떤 조건으로 왔는지(헤더), 무슨 요구사항이 있는지(query) 등
        
- Header = 손님이 들고 온 명함이나 요청사항 쪽지
    - "나는 Chrome 브라우저를 써요", "토큰은 이거에요", "나는 JSON 응답을 원해요", "비밀번호는 쿠키에 있어요" 같은 요청 설정 정보
