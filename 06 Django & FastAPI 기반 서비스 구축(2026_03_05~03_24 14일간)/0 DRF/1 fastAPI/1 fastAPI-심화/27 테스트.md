테스트의 목적:
	FastAPI로 만든 API 서버의 엔드포인트(라우터)들이 정상 작동하는지 검증하는 통합 테스트(test_main.py)입니다.

테스트 대상:
	FastAPI 앱의 `/items/` 라우터 2가지가 대상입니다:
	- GET : `/items/{item_id}`  특정 아이템 조회
	- POST :	`/items/`  아이템 등록
	
이 라우터들은 다음과 같은 조건 하에서 동작합니다:
- `X-Token` 헤더가 `"coneofsilence"`일 때만 정상 작동
- 존재하지 않는 아이템 요청 시 `404`
- 중복된 아이템 등록 시 `409`

`main.py`
```python
# -------------------------------
# [1] 의존성 및 설정
# -------------------------------

from typing import Annotated  
# 타입 힌트 및 FastAPI 의존성 주입에 사용됨

from fastapi import FastAPI, Header, HTTPException  
# FastAPI 핵심 기능들

from pydantic import BaseModel  
# 요청/응답 모델을 위한 데이터 검증 도구


# 인증에 사용할 가짜 토큰 값 (보안용으로 헤더 검사에 사용)
fake_secret_token = "coneofsilence"

# 가상의 데이터베이스 (딕셔너리 형태) - 실제 DB 대신 테스트 용도로 사용
fake_db = {
    "foo": {"id": "foo", "title": "Foo", "description": "There goes my hero"},
    "bar": {"id": "bar", "title": "Bar", "description": "The bartenders"},
}

# FastAPI 애플리케이션 인스턴스 생성
app = FastAPI()


# -------------------------------
# [2] 데이터 모델 정의
# -------------------------------

# 클라이언트가 보내는 JSON 요청의 구조를 정의하는 데이터 모델
class Item(BaseModel):
    id: str  # 아이템의 고유 ID (문자열)
    title: str  # 제목
    description: str | None = None  # 설명 (옵션 필드, 없어도 됨)


# -------------------------------
# [3] GET /items/{item_id}
#     - 아이템 조회 API
# -------------------------------

# GET 요청 핸들러 - 특정 아이템을 조회하는 API
@app.get("/items/{item_id}", response_model=Item)
async def read_main(item_id: str, x_token: Annotated[str, Header()]):
    """
    특정 아이템을 조회하는 API 엔드포인트입니다.
    - 경로 매개변수: item_id
    - 헤더: X-Token (인증 토큰)
    - 응답: Item 모델(JSON)
    """
    
    # 1. 헤더 토큰이 유효하지 않으면 400 에러 반환
    if x_token != fake_secret_token:
        raise HTTPException(status_code=400, detail="Invalid X-Token header")
    
    # 2. 해당 item_id가 fake_db에 존재하지 않으면 404 에러 반환
    if item_id not in fake_db:
        raise HTTPException(status_code=404, detail="Item not found")
    
    # 3. 정상일 경우, 해당 아이템 데이터를 반환
    return fake_db[item_id]

# -------------------------------
# [4] POST /items/
#     - 아이템 생성 API
# -------------------------------

# POST 요청 핸들러 - 새로운 아이템을 등록하는 API
@app.post("/items/", response_model=Item)
async def create_item(item: Item, x_token: Annotated[str, Header()]):
    """
    새 아이템을 등록하는 API 엔드포인트입니다.
    - 본문 요청: Item 모델(JSON)
    - 헤더: X-Token (인증 토큰)
    - 응답: 생성된 Item 모델(JSON)
    """
     # 1. 헤더 토큰이 유효하지 않으면 400 에러 반환
    if x_token != fake_secret_token:
        raise HTTPException(status_code=400, detail="Invalid X-Token header")
    
     # 2. 이미 존재하는 ID로 등록하려 하면 409 에러 반환
    if item.id in fake_db:
        raise HTTPException(status_code=409, detail="Item already exists")
    
    # 3. 요청 데이터를 dict로 변환해 fake_db에 저장
    fake_db[item.id] = item.model_dump()
    
    # 4. 등록된 아이템 반환 (상태코드 200)
    return item
```

`test_read_item` : 정상 토큰으로 foo 아이템 조회 → 200 OK
`test_read_item_bad_token`	: 잘못된 토큰으로 조회 → 400 Bad Request
`test_read_inexistent_item` : 존재하지 않는 ID 조회 → 404 Not Found
`test_create_item` : 새로운 아이템 등록 → 200 OK
`test_create_item_bad_token` : 잘못된 토큰으로 등록 → 400 Bad Request
`test_create_existing_item` : 중복된 ID 등록 → 409 Conflict

`test_main.py`
```python
# FastAPI 테스트용 클라이언트 임포트
from fastapi.testclient import TestClient
from lastTest.main import app

# 현재 디렉토리 기준 main.py 파일의 FastAPI 앱 인스턴스를 가져옴


# 테스트 클라이언트 생성 (FastAPI 앱을 테스트하기 위한 객체)
client = TestClient(app)

# -----------------------------
# 테스트 1: 정상적인 토큰으로 아이템 조회
# -----------------------------
def test_read_item():
    # "/items/foo" 엔드포인트에 GET 요청, 유효한 헤더 포함
    response = client.get("/items/foo", headers={"X-Token": "coneofsilence"})
    # 응답 상태 코드가 200인지 확인 (정상)
    assert response.status_code == 200
    # 응답 JSON 데이터가 예상 값과 같은지 확인
    assert response.json() == {
        "id": "foo",
        "title": "Foo",
        "description": "There goes my hero",
    }

# -----------------------------
# 테스트 2: 잘못된 토큰으로 아이템 조회
# -----------------------------
def test_read_item_bad_token():
    # 잘못된 토큰으로 요청 → 인증 실패
    response = client.get("/items/foo", headers={"X-Token": "hailhydra"})
    # 400 Bad Request 응답을 기대
    assert response.status_code == 400
    # 반환 메시지가 "Invalid X-Token header"인지 확인
    assert response.json() == {"detail": "Invalid X-Token header"}

# -----------------------------
# 테스트 3: 존재하지 않는 아이템 ID로 조회
# -----------------------------
def test_read_inexistent_item():
    # 존재하지 않는 ID 'baz'로 요청 → 404 응답 예상
    response = client.get("/items/baz", headers={"X-Token": "coneofsilence"})
    # 상태 코드가 404인지 확인
    assert response.status_code == 404
    # 상세 메시지가 "Item not found"인지 확인
    assert response.json() == {"detail": "Item not found"}

# -----------------------------
# 테스트 4: 새 아이템 생성
# -----------------------------
def test_create_item():
    # POST 요청으로 새로운 아이템 등록
    response = client.post(
        "/items/",
        headers={"X-Token": "coneofsilence"},  # 유효한 인증 토큰
        json={"id": "foobar", "title": "Foo Bar", "description": "The Foo Barters"},  # JSON 바디
    )
    # 상태 코드 200인지 확인 (등록 성공)
    assert response.status_code == 200
    # 응답 JSON이 예상한 데이터와 일치하는지 확인
    assert response.json() == {
        "id": "foobar",
        "title": "Foo Bar",
        "description": "The Foo Barters",
    }

# -----------------------------
# 테스트 5: 잘못된 토큰으로 아이템 생성
# -----------------------------
def test_create_item_bad_token():
    # 잘못된 토큰으로 POST 요청 시도
    response = client.post(
        "/items/",
        headers={"X-Token": "hailhydra"},  # 인증 실패 토큰
        json={"id": "bazz", "title": "Bazz", "description": "Drop the bazz"},
    )
    # 400 Bad Request 확인
    assert response.status_code == 400
    # 에러 메시지 확인
    assert response.json() == {"detail": "Invalid X-Token header"}

# -----------------------------
# 테스트 6: 이미 존재하는 아이템 ID로 등록 시도
# -----------------------------
def test_create_existing_item():
    # 이미 등록된 ID "foo"로 중복 생성 요청
    response = client.post(
        "/items/",
        headers={"X-Token": "coneofsilence"},  # 올바른 토큰
        json={
            "id": "foo",  # 이미 존재하는 ID
            "title": "The Foo ID Stealers",
            "description": "There goes my stealer",
        },
    )
    # 상태 코드 409 Conflict 확인 (중복)
    assert response.status_code == 409
    # 에러 메시지 확인
    assert response.json() == {"detail": "Item already exists"}
```

테스트 코드를 짜는 기준은 무엇인가?
	기본적으로는 "명세서(기능 정의서, 요구사항)"를 기준으로 합니다.

테스트 코드를 짜는 목적:
`1.`  요구사항에 부합하는지 ‘검증’하기 위해
	즉, 이 기능은 명세서대로 동작한다는 것을 “증명”하는 코드입니다.
	
예를 들어 요구사항이 다음과 같다면:
	✅ 사용자는 아이템을 등록할 수 있고,  
	❌ 동일한 ID로 중복 등록 시 에러가 발생해야 한다.

➡ 테스트 코드는 이렇게 작성해야 합니다:
- ✅ 성공 케이스: 정상 등록되었는가?
- ❌ 실패 케이스: 중복 시 409 에러가 나는가?

`2.` 기능이 ‘깨지지 않았는지’ 자동으로 확인하기 위해 (회귀 테스트)
- 나중에 코드를 수정해도 원래 기능이 그대로 작동하는지 확인할 수 있음
- 개발자나 팀원이 실수해도 기존 테스트가 깨지면 바로 알 수 있음

`3.` 문서의 역할도 함
- 코드만 봐도 기능이 어떻게 동작해야 하는지 시나리오처럼 확인 가능
- 개발자뿐 아니라 기획자, QA도 쉽게 이해 가능

기능정의서(요구사항 명세서)를 기반으로 테스트 코드 계획도 함께 설계하는 것이 매우 중요합니다.  
이건 단순히 “개발 후 테스트”가 아니라, 개발 전부터 테스트까지 함께 설계해야 한다는 개념입니다.

###### 개발 시 테스트 계획의 일반 흐름:
| 단계            | 설명                    |
| ------------- | --------------------- |
| 1. 기능정의서 작성   | 기획자/PO가 요구사항 정의       |
| 2. 테스트 케이스 도출 | 기능별 입력값/예외/출력 시나리오 정리 |
| 3. 테스트 코드 설계  | 각 시나리오를 코드로 표현할 구조 설계 |
| 4. 개발 진행      | 테스트 통과를 목표로 구현        |
| 5. 자동 테스트     | CI 환경에서 자동 검증 가능      |
