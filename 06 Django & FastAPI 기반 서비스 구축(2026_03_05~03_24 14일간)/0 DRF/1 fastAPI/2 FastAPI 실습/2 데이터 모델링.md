ETL방식에 의한 Django models 하단에 SQL을 매핑하기 위한 작업으로 기존 테이블에 매핑만 하고 마이그레이션은 만들지 않습니다. 

작업시 확인해야 하는 사항은 실제 DB와 일치한지 확인해야 합니다.
- 컬럼 타입/제약
    - `id`가 MySQL에서 `BIGINT AUTO_INCREMENT` 인지 → `BigAutoField`와 일치 확인
    - `name` 길이: 카테고리 100, 타입 20 → DB `VARCHAR` 길이와 동일한지
    - `created_at`, `updated_at`가 `NULL 허용 여부`, `DEFAULT CURRENT_TIMESTAMP` 등의 설정과 맞는지
        지금처럼 `auto_now*` 옵션 없이 두면 새 레코드 생성 시 값을 직접 넣어야 합니다.
- NULL/빈값 허용
    - FK에 `null=True, blank=True` → DB 컬럼이 `NULL` 허용인지 확인
- 인덱스/유니크
    - DB에 유니크/인덱스가 있다면, `Meta.indexes`/`unique_together`(또는 `constraints`)로 읽기 최적화 고려(선택)

---
⚠️ 주의사항
- `managed = False` 모델은 `python manage.py makemigrations` 나 `migrate` 실행해도 테이블이 생성되지 않음
- 단, ORM으로 데이터 조회·추가·수정·삭제는 가능
- `db_table`로 실제 DB 테이블명을 정확히 지정해야 함

        return False

def _user_label(user_id: int):
    """auth_user id를 사람이 읽기 좋은 'id: username'으로 표시"""
    try:
        u = User.objects.only("id", "username").get(id=user_id)
        return f"{u.id}: {u.username}"
    except User.DoesNotExist:
        return f"(missing) {user_id}"
