1) DB 모델 (SQLAlchemy models)
- 실제 DB 테이블과 1:1로 매핑됩니다.
- 컬럼/제약조건/관계(N:1, 1:N, N:M)를 정의하죠.
- 이 코드에선 `src/models/*.py`가 이 레이어입니다.
    
2) 스키마 (Pydantic models)
- API “입력/출력 형태”를 정의합니다. (검증 + 직렬화)
- DB 모델을 그대로 노출하지 않고, 필요한 필드만 안전하게 주고받게 도와줍니다.
- `src/schemas/*.py`가 이 레이어예요. `Config.from_attributes=True`로 SQLAlchemy 객체를 바로 응답 스키마로 변환할 수 있습니다(ORM 모드).
	
3) 라우터/서비스 (FastAPI routers/operators)
- URL → 함수(엔드포인트) 매핑을 하고, 트랜잭션/비즈니스 로직을 호출해 결과를 스키마로 반환합니다.
- (`/users`, `/users/me/followings` 같은 엔드포인트가 여기에 해당)
    
DRF와 비교하면:
- Django 모델 ↔ SQLAlchemy 모델
- Serializer ↔ Pydantic 스키마
- View/ViewSet ↔ FastAPI 라우터 함수
- DRF Router ↔ FastAPI APIRouter/경로 데코레이터

| 개념           | FastAPI + SQLAlchemy + Pydantic                                 | Django + DRF                                                       |
| ------------ | --------------------------------------------------------------- | ------------------------------------------------------------------ |
| 데이터 모델       | `User`, `UserFollow`, `UserLike`, `Restaurant` (SQLAlchemy)     | `models.Model`들 + `ManyToManyField(through=...)`                   |
| N:M(자기참조)    | `UserFollow` 중간 테이블 + `relationship(foreign_keys=...)`          | `ManyToManyField("self", through="UserFollow", symmetrical=False)` |
| N:M(유저↔레스토랑) | `UserLike` 중간 테이블                                               | `ManyToManyField(Restaurant, through="UserLike")`                  |
| 입/출력 검증      | Pydantic 스키마 (`UserCreate`, `User`, `RestaurantSearchResult` 등) | DRF Serializer / ModelSerializer / Nested Serializer               |
| 엔드포인트        | FastAPI 라우터 함수(의존성으로 DB 세션 주입)                                  | DRF View/ViewSet + Router (권한/페이징/필터 기본 제공)                        |
| 객체→JSON      | `from_attributes=True`로 ORM 객체 직렬화                              | Serializer가 `.data`로 직렬화                                           |
| 반대(JSON→객체)  | 요청 바디를 스키마로 검증 후 수동으로 DB에 반영                                    | Serializer의 `is_valid()`, `save()` 로 생성/수정                         |

```python
    for user in users:
        if get_user_by_username(user.username, db) is not None:

        fake_hashed_password = user.password + "notreallyhashed"
        db_user = user_model.User(username=user.username,
                                  password=fake_hashed_password,
                                  first_name=user.first_name,

                                  email=user.email,
                                  is_superuser = False,
                                  is_staff = False,

def authenticate_user(db: Session = Depends(get_db), form_data: OAuth2PasswordRequestForm = Depends(OAuth2PasswordRequestForm)):
    user = get_user_by_username(form_data.username, db)

    if user is None or verify_password(form_data.password, user.password) is False:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Incorrect username or password",
            headers={"WWW-Authenticate": "Bearer"},
        )
    
    expires_delta = timedelta(minutes=get_access_token_expire_minutes())
    expiration_date = datetime.now() + expires_delta
    access_token = create_access_token(
        data={"sub": user.username}, expires_delta=expires_delta
    )


    db_token = access_token_model.AccessToken(user_id=user.id,
                                              access_token=access_token,
                                              expiration_date=expiration_date
                                              )
    db.add(db_token)

    user.last_login = datetime.now()

    db.commit()
    db.refresh(db_token)

    return cast(access_token_schema, db_token)
```

```python
def get_current_user(
    access_token: str = Depends(oauth2_scheme),
    db: Session = Depends(get_db),

    """액세스 토큰의 sub(=username)으로 현재 사용자 반환"""

    return db.query(user_model.User).filter(user_model.User.username == username).first()


def authenticate_user(
    db: Session = Depends(get_db),
    form_data: OAuth2PasswordRequestForm = Depends(OAuth2PasswordRequestForm),
):
    """/login 처리: 비밀번호 검증 → 토큰 생성/저장"""
    user = get_user_by_username(form_data.username, db)

    if user is None or verify_password(form_data.password, user.password) is False:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Incorrect username or password",
            headers={"WWW-Authenticate": "Bearer"},
        )

    expires_delta = timedelta(minutes=get_access_token_expire_minutes())
    expiration_date = datetime.now() + expires_delta
    access_token = create_access_token(data={"sub": user.username}, expires_delta=expires_delta)

    db_token = access_token_model.AccessToken(
        user_id=user.id,
        access_token=access_token,
        expiration_date=expiration_date,
    )
    db.add(db_token)

    user.last_login = datetime.now()
    db.commit()
    db.refresh(db_token)

    return cast(access_token_schema, db_token)

def edit_user(id: int, user: user_schema.UserUpdate, db: Session = Depends(get_db)):
    """사용자 정보 수정 (부분 업데이트 지원)"""
    db_user = db.query(user_model.User).filter(user_model.User.id == id).first()
    if db_user is None:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Not found")

    # Pydantic v2: 부분 업데이트만 반영
    updates = user.model_dump(exclude_unset=True)
    if "password" in updates and updates["password"]:
        updates["password"] = get_password_hash(updates["password"])

    for key, val in updates.items():
        setattr(db_user, key, val)

    db.commit()
    db.refresh(db_user)
    return db_user

```

`1)` Service 작성 (`src/operators/user_operator.py`)
user_operator.py의 역할
- 서비스 레이어이며, 진짜 “업무 로직”이 여기에 있습니다.
- 라우터(`/login`)는 이 함수를 호출만 하고, 실제로는 여기서:
    1. DB에서 사용자 찾기
    2. 비밀번호 확인
    3. JWT 토큰 만들기
    4. 토큰/로그인시간 DB에 저장
    5. 응답을 만들어 돌려줌

사용도구
- `Depends(get_db)`: FastAPI가 DB 세션을 자동으로 넣어줘요.
- `OAuth2PasswordRequestForm`: `username`, `password`를 폼 방식(x-www-form-urlencoded)으로 받아주는 타입이에요.
- `verify_password(입력비번, 저장된_해시)`: 비밀번호가 맞는지 비교해줘요.
- `create_access_token(data, expires_delta)`: 서명된 JWT를 만들어줘요.
- `get_access_token_expire_minutes()`: 토큰이 얼마나 오래 유효한지(분) 알려줘요.

핵심함수 `authenticate_user(...)` 진행 순서
1. 입력 받기
    - `form_data`에서 `username`, `password`를 자동으로 꺼낼 수 있어요.
    - `db`는 `Depends(get_db)` 덕분에 자동으로 주입돼요.
2. 사용자 조회
    `user = get_user_by_username(form_data.username, db)`
    - 없거나, 비밀번호가 틀리면 → HTTP 401(Unauthorized)로 실패 응답을 보냄.
```python
if user is None or not verify_password(form_data.password, user.password):
    raise HTTPException(status_code=401, detail="Incorrect username or password")
```
    
3. 만료시간 계산 & JWT 생성
```python
expires_delta = timedelta(minutes=get_access_token_expire_minutes())
expiration_date = datetime.now() + expires_delta
access_token = create_access_token(data={"sub": user.username}, expires_delta=expires_delta)
```
    - sub는 토큰 주인(여기선 username)이라는 뜻.
    - expiration_date는 사람이 읽기 쉬운 만료 시각(편의용).
        
4. 토큰/로그인 시간 DB 저장
```python
db_token = AccessToken(user_id=user.id, access_token=access_token, expiration_date=expiration_date)
db.add(db_token)
user.last_login = datetime.now()
db.commit()
db.refresh(db_token)
```
- 토큰을 DB에 저장해두면 로그아웃/블랙리스트/감사 로그 같은 걸 만들기 쉬움
        
5. 응답 반환
```python
return db_token
```
- FastAPI가 `access_token_schema`에 맞춰 JSON으로 변환해 줍니다.
    - 보통 이런 형태로 나가요:
```
{   
	"access_token": "<JWT>",   
	"token_type": "bearer",   
	"expiration_date": "2025-08-12T12:34:56" 
}
```

 `6)` 스키마는 “응답만 정의” (`src/schemas/user_schema.py`)
API가 어떤 모양으로 데이터를 보내줄지 적어둔 메뉴판같은 역할을 하는 파일입니다.
- 무엇을 보여줄지 정함: `id, username, email…`
- 무엇을 숨길지 정함: `password` 같은 건 아예 없음 → 응답에 절대 안 나옴
- 타입 체크: `id`는 숫자, `email`은 문자열… 틀리면 에러
- ORM → JSON 변환 규칙: DB에서 가져온 `User` 객체를 깔끔한 JSON으로 바꾸는 법
- 클라이언트에 뭘, 어떤 형태로 줄지 ‘약속’하는 파일이에요.
- DRF와 비교하면 ModelSerializer역할과 비슷합니다.
- 입력/출력 데이터의 모양과 검증을 담당하기 때문에 비슷한 역할을 하고 있어요.

- 공통점
    - 요청 바디 / 응답 바디의 필드·타입 정의와 검증을 맡음
    - 민감정보(예: `password`)를 응답에서 제외하도록 설계 가능
    - 중첩 스키마, 필드 기본값, 커스텀 검증(validator) 지원
- 차이점
    - DRF Serializer: `create()`, `update()`가 있고 `.save()`로 DB 쓰기 로직까지 품기 쉬움.
    - FastAPI + Pydantic: 스키마는 검증/직렬화 전용이어서 DB 작업은 하지 않음.  
        → DB 쓰기/읽기는 보통 서비스(operators)나 리포지토리(SQLAlchemy) 쪽에서 처리.
- FastAPI만의 장점
    - 스키마가 곧 OpenAPI 문서로 반영돼 `/docs`가 자동 생성됨.
    - 타입 힌트 기반이라 에디터 지원이 빵빵.
        
정리: 개념적으로는 DRF Serializer ≈ FastAPI Pydantic 스키마(검증/직렬화).  
하지만 DB 저장 로직은 DRF는 Serializer/뷰에, FastAPI는 서비스/ORM 레이어에 두는 패턴이 일반적입니다.

```js
    const token = data.access_token || data.accessToken || data.token || data;
    store.token = token;           // localStorage 저장
    $('token').value = token;      // 화면에도 반영
    render({ message: '로그인 성공', token_type: data.token_type || 'bearer', access_token: token });
  }catch(err){
    onErr(err);
  }
}
```

공통 `req()`에서 Authorization 헤더 자동 첨부:
```js
if(store.token){ headers['Authorization'] = `Bearer ${store.token}`; }
```

- DRF는 보통 SimpleJWT를 씁니다. 라우트만 연결하면 끝:
```python
# urls.py
from django.urls import path
from rest_framework_simplejwt.views import TokenObtainPairView
urlpatterns = [
  path("login", TokenObtainPairView.as_view(), name="token_obtain_pair"),
]
```

- 프런트는 동일하게 `POST /login` (form/json 상관없이 JSON 권장) → `{access}` 토큰 저장 → `Authorization: Bearer <access>`

- FastAPI: 로그인 로직을 서비스 함수로 직접 작성(비번검증, JWT발급)
