프로젝트 이름: TaskBoard API
> TaskBoard API = 개인/팀용 “업무(Task) 관리 + 파일 + 알림” 통합 백엔드 플랫폼
> TaskBoard API는 사용자별 일정·작업(Todo)을 생성하고, 파일을 첨부하고, 기한이 가까워지면 알림을 받고, 실시간 조회/검색/통계를 제공하는 고성능 FastAPI 기반의 업무 관리 솔루션 백엔드이다.

### 한 줄 요약

- **사용자별 Todo 관리** +
- **이미지/파일 첨부** +
- **JWT 인증·권한** +
- **Redis 캐시 & 비동기 알림** +
- **Swagger 문서 & 모니터링**까지 담는 **실전형 FastAPI 백엔드 서버**

### 만들기 위한 목적

1. **DRF에서 했던 Todo/CRUD 패턴을 FastAPI 스타일로 다시 구현**하면서
    “Serializer ↔ Pydantic, ViewSet ↔ 라우터/경로 함수” 매핑을 몸으로 익힌다.
    
2. **JWT, Redis, SQLAlchemy, 비동기 처리**를 한 프로젝트 안에서 자연스럽게 연결해 본다.
    
3. API 문서(Swagger)·예외 처리·테스트·모듈 분리까지 경험해서
    “**실전 백엔드 API 서버 한 사이클**”을 완주해 본다.

### 🧱 핵심 도메인 / 기능 정의

### 주요 도메인 모델

- **User**
    - id, username, email, password_hash, created_at …
    - JWT 로그인을 통해 인증
- **Todo**
    - id, user_id(FK), title, description, status(todo/in_progress/done), due_date, priority
    - created_at, updated_at
- **TodoAttachment**
    - id, todo_id(FK), file_path or image_url, original_filename, uploaded_at
- **Notification**
    - id, user_id(FK), message, type (deadline_soon, todo_assigned 등)
    - is_read, created_at

선택 확장:
- Tag, Comment 등은 나중에 여유 있으면 추가

### 📚 14개 챕터와 대응되는 기능·학습 목표

아래는 질문에 올려준 14개 항목을 **TaskBoard API에 정확히 매핑**한 기획입니다.

---

### 1. Todo API 프로젝트 개시, Serializer·ViewSet 기초, 자동 문서화 실습(Swagger)

**기능/구조**

- FastAPI 프로젝트 생성 (`app/main.py`)
- 기본 라우터 `/health`, `/` 등 추가
- **Pydantic 스키마**로 Todo 생성/조회용 모델 정의
- `/docs`, `/redoc` 자동 문서 확인
    (DRF의 Swagger 경험과 비교)
    

**학습 포인트**

- DRF Serializer ↔ FastAPI Pydantic 모델 대응
- ViewSet 개념을 **“/todos 경로 + HTTP 메서드별 함수”** 로 나누어 구현해 보기

---

### 2. Todo CRUD 구축, 필터링·정렬·페이지네이션 적용

**기능**
- `/todos/`
    - GET: 전체 Todo 목록 (쿼리로 상태·기한 필터링, 정렬, 페이지네이션)
    - POST: 새 Todo 생성
- `/todos/{todo_id}`
    - GET, PUT/PATCH, DELETE

**학습 포인트**
- Query parameter로 `status`, `due_before`, `order_by` 등 받기
- `limit`, `offset` 기반 페이지네이션 구현
- DRF의 `ListAPIView` 패턴을 FastAPI에서 구현하는 느낌으로 설명

---

### 3. JWT 인증 + 권한 설정, 사용자별 Todo 관리 구현

**기능**
- `/auth/signup`, `/auth/login` API
- 로그인 시 JWT 발급, 헤더로 인증 처리
- Todo API는 **현재 로그인한 사용자 것만 조회/수정** 가능

**학습 포인트**
- `Depends` + Security(예: `OAuth2PasswordBearer`)로 인증 정보 주입
- “DRF의 `IsAuthenticated` + `request.user`” 개념을 FastAPI로 옮겨오기
- 사용자별 데이터 필터링 (where user_id = current_user.id)

---

### 4. 서비스 분리 개념, Auth·Todo 모듈 구조화 실습

**기능/구조**
- 프로젝트 구조 예:
    
```
    app/
      main.py          # FastAPI 앱 생성
      api/
        __init__.py
        routes/
          auth.py
          todos.py
      core/
        config.py
        security.py
      models/
        user.py
        todo.py
      schemas/
        auth.py
        todo.py
```

- 인증 라우터, Todo 라우터를 모듈별로 나누고 `main.py`에서 include
    

**학습 포인트**
- “서비스 분리”를 실제 마이크로서비스까지 가지 않고
    **모듈/폴더 단위로 분리**하는 경험
    
- API Gateway 느낌으로 `main.py`가 하위 라우터들을 **한 곳에 묶어주는 역할**
    
---

### 5. API Gateway 개념 이해, 서비스 간 호출 흐름 학습

**기능**
- `main.py`가 `auth`, `todo`, `files` 등 **서브라우터를 include**하는 형태
- 선택: 내부적으로 “알림 서비스” 모듈을 별도 파일로 분리하고, Todo 생성 시 그 모듈 함수를 호출

**학습 포인트**
- “클라이언트는 항상 `/api/...` 한 군데만 보고 요청하지만,
    내부에서는 **여러 서비스(모듈)**가 협력한다”는 흐름 설명
    
- 나중에 물리적으로 분리하면 **실제 API Gateway - Microservice 구조**로 확장될 수 있음을 언급
    
---

### 6. 쿼리 최적화 기초, Redis·비동기 개념 도입

**기능**
- 가장 많이 조회되는 API 예: `/todos/stats` (완료/미완료 개수, 오늘 마감 개수 등)
- 이 API를 호출할 때마다 DB를 치기보다,
    → 결과를 Redis에 캐싱하고 일정 시간(예: 30초) 동안 재사용
    

**학습 포인트**
- Redis를 **“읽기 많은 데이터의 캐시 계층”**으로 소개
- `async def` + `await`로 비동기 Redis 클라이언트 사용 맛보기
- “쿼리 최적화 = 인덱스 + 캐시 + 불필요한 조회 줄이기”라는 큰 그림

---

### 7. Redis 기반 캐싱 적용, 비동기 알림 처리 구조 이해

**기능**
- Todo 생성/수정 시
    - Redis에 저장된 `/todos/stats` 캐시 무효화
- 마감 시간이 가까운 Todo를 비동기로 체크해서
    Notification 테이블에 “알림” 기록
    - 예: background task, Celery/Redis Queue, 혹은 FastAPI BackgroundTasks

**학습 포인트**

- “DB 쓰기 → 캐시 무효화” 기본 패턴
- 비동기 작업(알림 전송, 외부 API 호출)을
    **요청/응답 사이클 밖에서 처리하는 구조** 이해
    

---

### 8. Todo 이미지 첨부 기능 구현, 업로드 API 설계

**기능**
- `/todos/{todo_id}/attachments`
    - POST: 이미지/파일 업로드 (예: 설명 스크린샷, 영수증 사진 등)
- 파일을 서버 디렉토리나 S3 유사 구조에 저장하고,
    DB에는 경로만 저장
    

**학습 포인트**
- FastAPI의 파일 업로드(`UploadFile`, `File`) 사용법
- “POST /form-data + 파일 + JSON” 조합 처리
- Todo와 파일 사이의 1:N 관계 모델링

---

### 9. FastAPI 설치, 라우팅·Pydantic 스키마 정의

**기능**
- FastAPI + Uvicorn 설치
- 최소 예제에서 `/` 경로에 “Hello TaskBoard” 반환
- Todo, User, Auth 등 **기본 Pydantic 스키마 정의**

**학습 포인트**
- DRF로 치면 “[settings.py](http://settings.py) + [urls.py](http://urls.py) + [serializers.py](http://serializers.py)”에 해당하는 초기 셋업을
    FastAPI에서 어떤 파일 구조로 가져가는지 확인
    

---

### 10. 데이터 수신 API 및 검증, Query·Path 파라미터 실습

**기능**
- `/todos/search`
    - Query 파라미터: `q`, `status`, `due_before` 등
- `/users/{user_id}/todos`
    - Path parameter 사용

**학습 포인트**
- Path, Query, Body를 FastAPI에서 어떻게 구분하고 받는지
- Pydantic 검증으로 잘못된 값이 들어왔을 때 자동 422 응답 확인

---

### 11. SQLAlchemy ORM 연동, 비동기 처리 소개

**기능**
- PostgreSQL 또는 SQLite + SQLAlchemy 연동
- User, Todo, Attachment, Notification 모델 정의
- 동기 방식으로 먼저 작성 후,
    가능하다면 **비동기 SQLAlchemy**도 간단히 맛보기
    

**학습 포인트**
- Django ORM에서 했던 `models.Model`과 비교해서
    SQLAlchemy의 테이블/컬럼 정의 방식 이해
    
- 세션 관리, 트랜잭션 개념 소개
    

---

### 12. 수신데이터 저장 및 조회 API 구성, 간단 모니터링

**기능**
- “사용자 활동 로그” 용도로 `/events` API 추가
    - ex) “사용자가 Todo를 완료했다”, “첨부파일을 업로드했다” 등 기록
- `/metrics` 또는 `/stats` 같은 엔드포인트에서
    - 오늘 생성된 Todo 수, 완료된 수, 요청 수 등 간단 카운터 반환

**학습 포인트**

- 수신 데이터 이벤트 저장 패턴
- 모니터링의 기초: **“몇 개 생성되었는지, 에러는 얼마나 나는지”**를 숫자로 보는 습관

---

### 13. JWT 기반 보안 API 구현, 문서 자동화 실습

**기능**
- JWT 기반 인증 로직 정리
    - 토큰 발급, 갱신(선택), 만료 시간 설정
- Swagger 문서에서 “Authorize” 버튼으로
    토큰 넣고 실제 인증 테스트 해보기
    

**학습 포인트**
- DRF에서 하던 JWT와 개념은 동일하지만,
    FastAPI에서는 `Depends`로 인증 로직을 조립하는 방식을 체감
- `/docs`에서 **요청/응답 Body, status code, security 스키마**가 자동으로 보이는 것 확인
    

---

### 14. 예외처리, 미들웨어, 파일 업로드 확장, 테스트 코드 정리

**기능**
- 공통 예외 처리:
    - 예: `TodoNotFoundError` → 404 JSON 응답으로 변환
- 미들웨어:
    - 요청 시간 로깅, 간단한 요청 ID 삽입 등
- 파일 업로드 검증:
    - 파일 크기 제한, MIME 타입 검증
- `pytest` + FastAPI `TestClient`로
    - 인증 필요한 API 테스트
    - Todo CRUD, 업로드, 캐시 검증 최소 한두 개씩 테스트

**학습 포인트**
- 예외를 “던지고” 한 곳에서 처리하는 패턴 (Django의 `ExceptionMiddleware`와 비교)
- 미들웨어로 **Cross-cutting concern(공통 관심사)** 처리
- 테스트를 통해 기능 동작을 자동으로 확인하는 습관

    - Pydantic, SQLAlchemy, Redis, JWT, Swagger, async 문맥에서 **어떻게 다시 등장하는지** 체감
    
- 최종 결과물:
    - GitHub에 올릴 수 있는 **실전형 FastAPI 포트폴리오 1개**
    - “Todo + 파일 업로드 + 알림 + 캐싱 + JWT + 모니터링”까지 들어간 **백엔드 서버 한 세트**
