1. routers → "URL → 함수 연결" (컨트롤러 역할)
- FastAPI
    - `@router.get("/users")`처럼 URL 경로와 HTTP 메서드를 지정해 API 함수를 등록.
    - 기능별로 파일을 나눠 관리(`/users`, `/restaurants` 등).
- DRF
    - `View` 또는 `ViewSet`에서 함수(`list`, `retrieve`, `create`)를 만들고  
        `urls.py`나 `DefaultRouter`로 URL을 연결.
    - 결국 URL → View 매핑 역할이 같음.
        
쉽게:
> routers = "이 주소로 오면 이 함수를 실행해 주세요" 안내판  
> (FastAPI는 `APIRouter`, DRF는 `urls.py` + View/ViewSet)

---
2. models → "DB와 1:1 연결" (ORM)
- FastAPI
    - SQLAlchemy 모델(`class User(Base)`)로 테이블 구조와 컬럼 정의.
    - `relationship`으로 다른 테이블과의 관계 설정.
- DRF
    - Django ORM의 `models.Model`로 정의.
    - `ForeignKey`, `ManyToManyField` 등 관계 필드 사용.
        
쉽게:
> models = "DB 설계도"  
> (FastAPI는 SQLAlchemy, DRF는 Django ORM 사용)
---
3. operators → "진짜 일하는 곳" (서비스/비즈니스 로직)
- FastAPI
    - 라우터가 너무 복잡해지는 걸 막기 위해 DB 조작, 계산, 외부 API 호출 같은 로직을 따로 분리.
    - 예: `def follow_user(follower_id, target_id): ...`
- DRF
    - 공식 구조에는 없지만, 서비스 레이어를 별도로 만들어 같은 방식으로 사용 가능.
    - 복잡한 로직은 View에서 service 함수를 호출하게 함.
        
쉽게:
> operators = "사무실에서 실제로 일하는 직원"  
> (routers는 손님을 맞이하는 안내 데스크, operators는 뒷방에서 일 처리)
---
4. schemas → "입출력 규격서" (데이터 검증 + 직렬화)
- FastAPI
    - Pydantic 모델로 요청 바디와 응답 형식을 정의.
    - 자동 타입 검증 + Swagger 문서화 가능.
- DRF
    - `Serializer` / `ModelSerializer`가 같은 역할.
    - 유효성 검증(`validate`)과 직렬화(`.data`)를 처리.
        
쉽게:
> schemas = "상자에 뭐가 들어가야 하는지, 꺼낼 때 어떤 모양이어야 하는지 설명서"  
> (FastAPI는 Pydantic, DRF는 Serializer)
---
5. src/app.py → "프로그램의 시작점" (앱 부팅)
- FastAPI
    - `app = FastAPI()`로 앱 생성, 미들웨어(CORS, 예외 처리) 설정, 라우터 등록.
    - `uvicorn src.app:app`으로 실행.
- DRF
    - `asgi.py` / `wsgi.py`에서 Django 앱 부팅, `urls.py`로 라우팅 연결, `settings.py`로 전역 설정.
        
쉽게:
> app.py = "가게 문을 열고, 점원 배치하고, 손님 맞이 준비하는 곳"  
> (FastAPI는 app.py, DRF는 asgi/wsgi + urls + settings)

| 역할        | FastAPI               | DRF                                     |
| --------- | --------------------- | --------------------------------------- |
| URL-엔드포인트 | routers (`APIRouter`) | urls.py + View/ViewSet                  |
| DB 매핑     | models (SQLAlchemy)   | models.py (Django ORM)                  |
| 로직 처리     | operators (선택)        | service 함수(선택)                          |
| 요청/응답 규격  | schemas (Pydantic)    | serializers.py                          |
| 앱 시작점     | src/app.py            | asgi.py/wsgi.py + urls.py + settings.py |
FastAPI 구조에서의 위치
```
[routers]  ---->  [operators]  ---->  [models]
   ↓             (비즈니스 로직)      (DB ORM)
[schemas] <---- 응답데이터

--------------------------------------

클라이언트 요청
   ↓
[routers]    ← URL 매핑 & HTTP 메서드(GET/POST/PUT/DELETE) 정의
   ↓
[operators]   ← 실제 비즈니스 로직 처리 (DB 조작, 외부 API 호출 등)
   ↓
[models]    ← SQLAlchemy ORM 모델로 DB 읽기/쓰기
   ↓
[schemas]  ← 결과를 Pydantic 스키마로 변환해 응답 (Swagger 문서화 포함)
   ↓
클라이언트 응답
```
- routers: API 엔드포인트 정의 (`@router.get("/users")`)  
    → 여기서 `operator`를 불러서 실제 일을 시킴
- operators: DB 조회, 저장, 가공 등 진짜 로직 처리
- models: ORM으로 DB 매핑
- schemas: 요청/응답 형식 검증·직렬화 (serializer역할)
- app.py = `asgi.py` + `urls.py` + settings 결합

```
요청 처리 흐름 (FastAPI 프로젝트 구조)

/src
│
├── app.py
│    └─ FastAPI 앱 생성 & 라우터 등록
│
├── routers/  # [1] 라우터: 엔드포인트 정의 (URL 매핑)
│    ├── users_router.py       →  /users, /users/me ...
│    ├── restaurant_router.py  →  /restaurants ...
│    └── ...
│
├── operators/   # [2] 오퍼레이터: 비즈니스 로직 처리
│    ├── users_operator.py  →  팔로우/언팔, 회원 정보 수정 등
│    ├── restaurant_operator.py →  좋아요 토글, 식당 검색 등
│    └── ...
│
├── models/  # [3] 모델: DB 테이블(SQLAlchemy ORM)
│    ├── user_model.py  →  User, UserFollow, UserLike
│    ├── restaurant_model.py →  Restaurant, 관계 정의
│    └── ...
│
├── schemas/   # [4] 스키마: 요청/응답 데이터 구조(Pydantic)
│    ├── user_schema.py 
│    ├── restaurant_schema.py 
│    └── ...
│
├── core/                     # [5] 핵심 설정/유틸
│    ├── database.py           →  DB 연결 엔진/세션
│    ├── config.py             →  환경변수/설정값
│    └── ...
│
└── dependencies/     # [6] 의존성 주입
     ├── db.py        →  get_db() : DB 세션 제공
     └── auth.py      →  인증/권한 관련 Depends 함수
```

`src/operators/blog_review_operator.py`
```python
from enum import Enum

from fastapi import Depends, HTTPException, status

from sqlalchemy.orm import Session
from sqlalchemy.sql import text
from src.models import blog_review_model

from src.dependencies.database import get_db


class BlogReviewOrderBy(str, Enum):
    title = "title"
    restaurant_id = "restaurant_id"
    published_date = "published_date"
    created_at = "created_at"
    updated_at = "updated_at"

class Sort(str, Enum):
    asc = "asc"
    desc = "desc"


def get_blog_review_by_id(id: int, db: Session = Depends(get_db)):
    blog_review = db.query(blog_review_model.BlogReview).filter(blog_review_model.BlogReview.id == id).first()
    if not blog_review:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Not found")
    return blog_review
    
def get_blog_reviews(skip: int = 0, limit: int =100, order_by: BlogReviewOrderBy = BlogReviewOrderBy.updated_at, sort: Sort = Sort.desc, db: Session = Depends(get_db)):
    blog_reviews = db.query(blog_review_model.BlogReview).order_by(text("%s %s" % (order_by.value, sort.value))).limit(limit).offset(skip).all()
    if not blog_reviews:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Not found")
    return blog_reviews
```

    created_at: datetime
