
### FastAPI에서 응답(Response)을 제어하는 기능이란?
	웹 API를 만들 때 서버는 단순히 데이터만 반환하는 것이 아니라 여러 가지 정보를 함께 
	전달해야 하는 경우가 많습니다.

예를 들어 실제 서비스에서는 다음과 같은 상황이 자주 발생합니다.
- 회원가입이 완료되면 로그인 상태를 유지하기 위한 쿠키를 저장
- API 응답에 버전 정보나 언어 정보 같은 헤더 추가
- 특정 요청이 성공했는지 실패했는지 HTTP 상태코드로 구분
- JSON 응답 구조를 직접 만들어서 반환
    

이러한 작업을 처리하기 위해 FastAPI에서는 다음과 같은 기능을 사용합니다.
- Response 객체 → 응답에 쿠키, 상태코드 등을 설정
- JSONResponse → 응답 형식을 직접 구성
- HTTPException → 오류 발생 시 상태코드와 메시지 반환
- 헤더(Header) → API 버전, 언어, 캐시 정책 전달
- 쿠키(Cookie) → 로그인 세션 정보 저장

---
### 회원가입 처리 흐름

웹 서비스에서 사용자가 회원가입을 하면 서버에서는 보통 다음과 같은 과정을 거칩니다.
1. 사용자가 아이디와 비밀번호를 입력하여 회원가입 요청을 보냅니다.
2. 서버는 보안을 위해 비밀번호를 그대로 저장하지 않고 해싱(Hashing) 과정을 거쳐 암호화된 형태로 변환합니다.
3. 해싱된 비밀번호와 사용자 정보를 데이터베이스에 저장합니다.
4. 사용자가 로그인 상태를 유지할 수 있도록 토큰을 생성합니다.
5. 생성된 토큰을 쿠키에 담아 사용자에게 응답으로 전달합니다.
    

이 과정을 통해 사용자는 회원가입이 완료되고, 이후 로그인 상태를 유지할 수 있게 됩니다.

### 해싱(Hashing)이란?
	해싱이란 비밀번호처럼 중요한 정보를 안전하게 저장하기 위해, 원래 값을 알아볼 수 없는 
	형태로 변환하는 보안 기술입니다.

이 방식의 특징은 다음과 같습니다.
- 같은 입력값이라도 암호화된 문자열로 변환됩니다.
- 한 번 변환되면 원래 값으로 되돌릴 수 없는 일방향 방식입니다.
- 그래서 데이터베이스가 유출되더라도 실제 비밀번호를 바로 알 수 없습니다.
    
예를 들어 사용자가 다음과 같은 비밀번호를 입력했다고 가정하면
```
mypassword123
```

해싱을 거치면 다음과 같은 알 수 없는 문자열로 변환되어 저장됩니다.
```
"ef92b778bafe771e89245b89ecbc08a44a4e166c06659911881f383d4473e94f"
```
즉 서버는 사용자의 실제 비밀번호를 저장하지 않고, 해싱된 값만 저장하여 보안을 강화합니다.

### FastAPI에서 응답(Response)을 제어하는 실습

이 실습은 FastAPI가 클라이언트에게 응답을 어떻게 보내는지 직접 제어하는 방법을 배우는 코드입니다.

보통 우리는 API 응답을 이렇게만 생각합니다.
- 요청 받기
- 데이터 반환하기
    
하지만 실제 서비스에서는 그보다 더 많은 처리가 필요합니다.

예를 들어 회원가입 기능에서는:
1. 사용자가 아이디와 비밀번호를 보냅니다.
2. 서버는 비밀번호를 해싱합니다.
3. 사용자 정보를 저장합니다.
4. 로그인 유지용 토큰을 만듭니다.
5. 그 토큰을 쿠키에 담아 응답합니다.
6. 필요하면 응답 헤더도 같이 보냅니다.
7. 상황에 따라 상태코드도 바꿉니다.

즉, 이 실습은 FastAPI에서 응답 본문(JSON), 쿠키, 헤더, 상태코드를 어떻게 다루는지 배우는 과정입니다.

먼저 설치:
```bash
uv pip install fastapi uvicorn passlib[bcrypt] python-multipart
```

```bash

```
FastAPI 자체에는 비밀번호를 안전하게 해싱하는 기능이 내장되어 있지 않기 때문에, 외부 라이브러리인 `passlib`을 사용합니다.
- `passlib`은 다양한 암호화 알고리즘을 제공하는 Python 라이브러리
- `[bcrypt]`은 추가 옵션으로, `bcrypt`라는 해싱 알고리즘을 포함해서 설치하는 옵션  
    → `passlib`이 `bcrypt`를 내부적으로 사용하기 위해 필요

✔️ 요약: 안전한 비밀번호 저장을 위한 필수 보안 라이브러리

### 1️⃣ 회원가입 + 해싱 + 쿠키
회원가입 요청을 받아서 비밀번호를 해싱하고, 세션 토큰을 쿠키에 담아 응답하는 흐름

- `Form(...)` 으로 사용자 입력 받기
- `passlib` 으로 비밀번호 해싱하기
- `HTTPException` 으로 중복 사용자 예외 처리하기
- `response.set_cookie()` 로 쿠키 설정하기

`response-practice/main1.py`
```python
# FastAPI 웹 프레임워크에서 필요한 기능들을 가져옵니다.
# FastAPI → 웹 API 서버 생성
# Response → 응답 객체 (쿠키, 헤더, 상태코드 설정 가능)
# HTTPException → 오류 발생 시 상태코드와 메시지 반환
# Form → HTML form 데이터 받기
from fastapi import FastAPI, Response, HTTPException, Form

# passlib은 비밀번호를 안전하게 해싱하는 라이브러리입니다.
# CryptContext는 어떤 암호화 알고리즘을 사용할지 설정하는 도구입니다.
from passlib.context import CryptContext


# FastAPI 애플리케이션 객체 생성
# 이 객체가 실제 API 서버 역할을 합니다.
app = FastAPI()


# -----------------------------
# 비밀번호 해싱 설정
# -----------------------------
# bcrypt 알고리즘을 사용하여 비밀번호를 암호화하도록 설정합니다.
# deprecated="auto"는 오래된 알고리즘을 자동으로 교체하도록 설정하는 옵션입니다.
pwd_context = CryptContext(
    schemes=["bcrypt"], 
    deprecated="auto"
)


# -----------------------------
# 가짜 사용자 데이터베이스
# -----------------------------
# 실제 서비스에서는 PostgreSQL, MySQL 같은 DB를 사용하지만
# 교육용 예제이므로 Python 딕셔너리를 DB처럼 사용합니다.
fake_users_db = {}


# -----------------------------
# 회원가입 API
# -----------------------------
# POST /signup 요청을 처리하는 API입니다.
@app.post("/signup")
def signup(
    # Form(...)은 HTML <form>에서 보내는 데이터를 받는 방식입니다.
    # username과 password를 입력받습니다.
    username: str = Form(...), # username 값은 반드시 들어와야 한다는 필수값
    password: str = Form(...), # 필수 값 표시 sentinel 값

    # Response 객체는 FastAPI가 자동으로 주입합니다.
    # 이 객체를 이용해 쿠키, 헤더, 상태코드 등을 설정할 수 있습니다.
    response: Response = None
):

    # -----------------------------
    # 1. 사용자 중복 확인
    # -----------------------------
    # 이미 같은 username이 존재하면 회원가입을 막습니다.
    if username in fake_users_db:
        # HTTPException을 사용하면 FastAPI가 자동으로 에러 응답을 생성합니다.
        raise HTTPException(
            status_code=400,  # HTTP 상태코드 400 (잘못된 요청)
            detail="이미 존재하는 사용자입니다."
        )


    # -----------------------------
    # 2. 비밀번호 해싱
    # -----------------------------
    # 사용자가 입력한 비밀번호를 그대로 저장하면 보안 문제가 발생합니다.
    # 그래서 bcrypt 알고리즘으로 암호화합니다.
    hashed_password = pwd_context.hash(password)


    # -----------------------------
    # 3. 사용자 정보 저장
    # -----------------------------
    # 실제 서비스라면 DB에 저장하지만
    # 여기서는 딕셔너리에 저장합니다.
    fake_users_db[username] = {
        "username": username,
        "hashed_password": hashed_password
    }


    # -----------------------------
    # 4. 로그인 세션 토큰 생성
    # -----------------------------
    # 실제 서비스에서는 JWT 또는 세션ID를 생성합니다.
    # 여기서는 교육용이므로 간단한 문자열을 사용합니다.
    session_token = f"token-{username}"


    # -----------------------------
    # 5. 쿠키에 세션 토큰 저장
    # -----------------------------
    # set_cookie()를 사용하면 브라우저에 쿠키를 저장할 수 있습니다.
    response.set_cookie(
        key="sessionid",      # 쿠키 이름
        value=session_token,  # 저장할 값
        httponly=True,        # JavaScript에서 접근 못하도록 설정 (보안)
        max_age=3600          # 쿠키 유효시간 (초) → 1시간
    )


    # -----------------------------
    # 6. JSON 응답 반환
    # -----------------------------
    # FastAPI는 딕셔너리를 자동으로 JSON으로 변환합니다.
    return {
        "message": f"{username}님, 회원가입이 완료되었습니다."
    }
```

---
실행:
```bash
uvicorn response-practice.main1:app --reload
```

위 코드의 흐름
```
사용자 회원가입 요청
        ↓
Form 데이터 받기
(username / password)
        ↓
아이디 중복 확인
        ↓
비밀번호 해싱(bcrypt)
        ↓
사용자 정보 저장
        ↓
세션 토큰 생성
        ↓
쿠키 저장
        ↓
JSON 응답 반환
```

### 2️⃣ 응답 헤더 설정
이 단계에서는 응답 본문(JSON) 외에 추가 정보인 헤더를 같이 보내는 방법을 배웁니다.

- `response.headers[...]` 로 응답 헤더 설정하기
- API 버전, 언어, 캐시 정책 전달하기

`response-practice/main2.py`
```python
# FastAPI 웹 프레임워크와 Response 객체를 가져옵니다.
# FastAPI → API 서버 생성
# Response → 응답에 헤더, 쿠키, 상태코드 등을 설정할 때 사용
from fastapi import FastAPI, Response


# FastAPI 애플리케이션 생성
# 이 객체가 실제 웹 서버의 중심이 됩니다.
app = FastAPI()


# -----------------------------
# API 정보 조회 API
# -----------------------------
# HTTP GET 요청으로 /api/info 주소에 접근하면 실행되는 함수입니다.
@app.get("/api/info")
def get_api_info(response: Response):

    # -----------------------------
    # 1. API 버전 정보 헤더 추가
    # -----------------------------
    # 응답 헤더에 "X-API-Version" 값을 추가합니다.
    # 클라이언트(프론트엔드, 앱 등)가 현재 API 버전을 확인할 수 있습니다.
    response.headers["X-API-Version"] = "1.0.0"


    # -----------------------------
    # 2. 응답 데이터 언어 정보
    # -----------------------------
    # 이 응답 데이터의 언어가 영어(en-US)라는 것을 알려줍니다.
    # 브라우저나 앱이 참고할 수 있습니다.
    response.headers["Content-Language"] = "en-US"


    # -----------------------------
    # 3. 캐시 금지 설정
    # -----------------------------
    # 이 API 응답을 브라우저나 CDN이 캐시에 저장하지 못하도록 설정합니다.
    # 로그인 정보나 민감한 데이터에서 자주 사용됩니다.
    response.headers["Cache-Control"] = "no-store"


    # -----------------------------
    # 4. JSON 응답 반환
    # -----------------------------
    # FastAPI는 Python 딕셔너리를 자동으로 JSON으로 변환합니다.
    # 이 부분이 실제 API 응답 데이터입니다.
    return {
        "service": "MyApp",  # 서비스 이름
        "description": "This API provides application information.",  # API 설명
        "status": "operational"  # 서비스 상태
    }
```
이 코드는 응답 본문은 그대로 반환하면서, 헤더에 추가 정보를 실어 보내는 예제입니다.

동작흐름
```
클라이언트가 /api/info 요청
        ↓
FastAPI 함수 실행
        ↓
Response 객체에 헤더 추가
        ↓
JSON 데이터 반환
        ↓
클라이언트는 JSON + 헤더 모두 받음
```

응답 헤더의 정책은 주로 브라우저, 프론트엔드, 중간 서버(프록시·CDN), 또는 클라이언트 프로그램이 확인합니다.
즉 사용자가 직접 보는 값이 아니라, 프로그램들이 동작 방식을 결정하기 위해 읽는 정보입니다.

실행:
```bash
uvicorn response-practice.main2:app --reload
```

2번 코드에서 설정한 헤더는 이것입니다.
```python
response.headers["X-API-Version"] = "1.0.0"
response.headers["Content-Language"] = "en-US"
response.headers["Cache-Control"] = "no-store"
```
이것들은 HTTP 응답 헤더(Response Header) 입니다.

HTTP 응답 구조는 이렇게 됩니다.
```
HTTP Response

Header
 ├ Cache-Control
 ├ Content-Language
 └ X-API-Version

Body
 └ JSON 데이터
```

누가 이 값을 확인하는가?

① 브라우저
브라우저는 다음과 같은 헤더를 실제로 사용합니다.

예:
```
Cache-Control  
Content-Type  
Content-Language
```

예를 들어
```
Cache-Control: no-store
```
브라우저는 이 데이터는 캐시하지 말아야겠다 라고 판단합니다.

---
② 프론트엔드 코드 (React / Vue / JS)
프론트엔드에서 응답 헤더를 읽을 수도 있습니다.

예:
```js
const res = await fetch("/api/info")  
  
console.log(res.headers.get("X-API-Version"))
```
그래서 API 버전 같은 정보를 확인할 수 있습니다.

---
③ CDN / 프록시 서버

예:
- Cloudflare
- Nginx
- AWS CloudFront
    
이 서버들도 Cache-Control 같은 헤더를 보고 동작합니다.

예:
```
Cache-Control: no-store
```
이면 CDN도 캐싱을 하지 않습니다.

---
④ 모바일 앱
모바일 앱에서도 헤더를 확인할 수 있습니다.

예:
```
API-Version  
RateLimit  
Language
```

3️⃣ 왜 이런 헤더가 필요한가?
각 헤더는 서버가 클라이언트에게 전달하는 정책 정보입니다.

예를 들어: Cache-Control
```
Cache-Control: no-store
```

의미
브라우저 / CDN / 프록시에게 이 응답을 캐시에 저장하지 말라고 지시

보통 다음에 사용합니다.
- 로그인 응답
- 결제 데이터
- 개인 정보

### 3️⃣ JSONResponse로 응답 객체 직접 만들기
이 단계에서는 응답 객체를 직접 만들어서, 그 안에 본문 + 쿠키 + 헤더를 한 번에 설정하는 방법을 배웁니다.

- `JSONResponse(content=...)` 로 응답 객체 직접 생성하기
- 생성한 응답 객체에 쿠키와 헤더 넣기

`response-practice/main3.py`
```python
# FastAPI 웹 프레임워크에서 필요한 기능을 가져옵니다.
# FastAPI → API 서버 생성
# HTTPException → 오류 발생 시 상태코드와 메시지를 반환
# Form → HTML form 데이터 받기
from fastapi import FastAPI, HTTPException, Form

# passlib은 비밀번호를 안전하게 해싱(암호화)하는 라이브러리입니다.
# CryptContext는 어떤 해싱 알고리즘을 사용할지 설정하는 도구입니다.
from passlib.context import CryptContext

# JSONResponse는 응답 객체를 직접 생성할 때 사용하는 클래스입니다.
# JSON 형식으로 응답을 만들고 쿠키, 헤더 등을 추가로 설정할 수 있습니다.
from fastapi.responses import JSONResponse


# FastAPI 애플리케이션 객체 생성
# 이 객체가 실제 API 서버 역할을 합니다.
app = FastAPI()


# -----------------------------
# 비밀번호 해싱 설정
# -----------------------------
# bcrypt 알고리즘을 사용하여 비밀번호를 해싱하도록 설정합니다.
# deprecated="auto"는 오래된 알고리즘을 자동으로 교체하도록 하는 옵션입니다.
pwd_context = CryptContext(
    schemes=["bcrypt"],
    deprecated="auto"
)


# -----------------------------
# 가짜 사용자 데이터베이스
# -----------------------------
# 실제 서비스에서는 MySQL, PostgreSQL 같은 DB를 사용하지만
# 교육용 예제에서는 Python 딕셔너리를 DB처럼 사용합니다.
fake_users_db = {}


# -----------------------------
# 회원가입 API
# -----------------------------
# POST 요청으로 /signup-json 주소에 접근하면 실행됩니다.
@app.post("/signup-json")
def signup_json(

    # HTML form에서 username 값을 받습니다.
    # Form(...)은 필수 값이라는 의미입니다.
    username: str = Form(...),

    # HTML form에서 password 값을 받습니다.
    password: str = Form(...),
):


    # -----------------------------
    # 1. 사용자 중복 확인
    # -----------------------------
    # 이미 같은 username이 존재하면 회원가입을 막습니다.
    if username in fake_users_db:

        # HTTPException을 발생시키면 FastAPI가 자동으로
        # JSON 형태의 에러 응답을 생성합니다.
        raise HTTPException(
            status_code=400,  # HTTP 상태코드 400 (잘못된 요청)
            detail="이미 존재하는 사용자입니다."
        )


    # -----------------------------
    # 2. 비밀번호 해싱
    # -----------------------------
    # 사용자가 입력한 비밀번호를 그대로 저장하면 보안 문제가 발생합니다.
    # 그래서 bcrypt 알고리즘으로 암호화합니다.
    hashed_password = pwd_context.hash(password)


    # -----------------------------
    # 3. 사용자 정보 저장
    # -----------------------------
    # 실제 서비스라면 DB에 저장하지만
    # 여기서는 딕셔너리에 저장합니다.
    fake_users_db[username] = {
        "username": username,
        "hashed_password": hashed_password
    }


    # -----------------------------
    # 4. 로그인 세션 토큰 생성
    # -----------------------------
    # 실제 서비스에서는 JWT나 세션ID를 생성합니다.
    # 여기서는 교육용으로 간단한 문자열을 사용합니다.
    session_token = f"token-{username}"


    # -----------------------------
    # 5. 응답 본문(JSON 데이터) 생성
    # -----------------------------
    # 클라이언트에게 전달할 JSON 데이터를 먼저 만듭니다.
    content = {
        "message": f"{username}님, 회원가입이 완료되었습니다.",
        "status": "success"
    }


    # -----------------------------
    # 6. JSONResponse 객체 생성
    # -----------------------------
    # JSONResponse는 JSON 형태의 응답 객체입니다.
    # content에 들어있는 데이터를 JSON으로 변환하여 반환합니다.
    response = JSONResponse(content=content)


    # -----------------------------
    # 7. 쿠키 설정
    # -----------------------------
    # set_cookie()를 사용하면 브라우저에 쿠키를 저장할 수 있습니다.
    response.set_cookie(
        key="sessionid",      # 쿠키 이름
        value=session_token,  # 쿠키 값 (세션 토큰)
        httponly=True,        # JavaScript에서 접근 못하도록 설정 (보안)
        max_age=3600          # 쿠키 유효시간 (초) → 1시간
    )


    # -----------------------------
    # 8. 응답 헤더 설정
    # -----------------------------
    # 응답 헤더에 추가 정보를 넣습니다.

    # API 버전 정보
    response.headers["X-API-Version"] = "1.0.0"

    # 응답 데이터 언어
    response.headers["Content-Language"] = "ko-KR"

    # 캐시 저장 금지
    response.headers["Cache-Control"] = "no-store"


    # -----------------------------
    # 최종 응답 반환
    # -----------------------------
    # JSONResponse 객체를 반환하면
    # JSON 데이터 + 쿠키 + 헤더가 함께 클라이언트로 전달됩니다.
    return response
```
2단계에서는 `Response` 객체에 헤더를 붙였고,  
3단계에서는 `JSONResponse` 객체를 직접 만든 뒤 그 객체에 쿠키와 헤더를 붙입니다.

즉, 이 단계는 응답을 더 세밀하게 직접 제어하는 방식입니다.

전체 처리 흐름
```
회원가입 요청
      ↓
username / password 받기
      ↓
사용자 중복 검사
      ↓
비밀번호 해싱(bcrypt)
      ↓
사용자 정보 저장
      ↓
세션 토큰 생성
      ↓
JSON 응답 생성
      ↓
쿠키 설정
      ↓
헤더 설정
      ↓
클라이언트에 응답 반환
```

실행:
```bash
uvicorn response-practice.main3:app --reload
```

### 4️⃣ 상태코드 제어 + upsert
이 단계에서는 같은 엔드포인트에서 수정과 생성을 모두 처리하고, 상태코드로 둘을 구분하는 방법을 배웁니다.

- 기존 데이터가 있으면 수정
- 없으면 생성
- 생성일 때만 `201 Created` 상태코드 반환

`response-practice/main4.py`
```python
# FastAPI 웹 프레임워크와 응답 객체(Response), 상태코드(status)를 가져옵니다.
# FastAPI → API 서버 생성
# Response → 응답의 상태코드, 헤더 등을 직접 설정할 때 사용
# status → HTTP 상태코드를 편하게 사용할 수 있는 상수 모음
from fastapi import FastAPI, Response, status


# FastAPI 애플리케이션 생성
# 이 객체가 실제 API 서버 역할을 합니다.
app = FastAPI()


# -----------------------------
# 가짜 데이터베이스
# -----------------------------
# 실제 서비스에서는 DB(MySQL, PostgreSQL 등)를 사용하지만
# 교육용 예제이므로 Python 딕셔너리를 DB처럼 사용합니다.
items_db = {
    "foo": {"name": "Fighters", "size": 6}
}


# -----------------------------
# 아이템 생성 또는 수정 API
# -----------------------------
# PUT 요청으로 /items/{item_id} 주소에 접근하면 실행됩니다.
# {item_id}는 URL 경로에서 전달되는 값입니다.
@app.put("/items/{item_id}")
async def upsert_item(

    # URL 경로에서 받은 item_id 값
    item_id: str,

    # 요청 파라미터로 전달되는 name 값
    name: str,

    # 요청 파라미터로 전달되는 size 값
    size: int,

    # Response 객체
    # 상태코드를 직접 변경할 때 사용합니다.
    response: Response
):


    # -----------------------------
    # 1. 기존 아이템이 있는지 확인
    # -----------------------------
    # item_id가 이미 존재하면 "수정(update)" 작업을 수행합니다.
    if item_id in items_db:

        # 기존 데이터에 name과 size 값을 업데이트합니다.
        items_db[item_id].update({
            "name": name,
            "size": size
        })

        # 수정된 데이터를 JSON 형태로 반환합니다.
        return {
            "message": "Item updated",
            "item": items_db[item_id]
        }


    # -----------------------------
    # 2. 아이템이 없으면 새로 생성
    # -----------------------------
    # 새로운 아이템 데이터를 생성합니다.
    new_item = {
        "name": name,
        "size": size
    }

    # 딕셔너리에 새 데이터를 저장합니다.
    items_db[item_id] = new_item


    # -----------------------------
    # 3. 상태코드 변경 (201 Created)
    # -----------------------------
    # 새로운 데이터가 생성된 경우
    # HTTP 상태코드를 201(Created)로 설정합니다.
    response.status_code = status.HTTP_201_CREATED


    # -----------------------------
    # 4. 생성 결과 반환
    # -----------------------------
    return {
        "message": "Item created",
        "item": new_item
    }
```

API 동작흐름
```
PUT /items/{item_id}
        ↓
items_db에 item_id가 있는지 확인
        ↓
있다 → 기존 데이터 수정
        ↓
없다 → 새 데이터 생성
        ↓
생성일 때만 HTTP 상태코드 201 설정
        ↓
JSON 응답 반환
```

실행:
```bash
uvicorn response-practice.main4:app --reload
```

upsert란:
```
있으면 update  
없으면 insert
```

그리고 상태코드로 의미를 구분합니다.

- 수정이면 기본 `200 OK`
- 생성이면 `201 Created`

### 5️⃣ 모두 합친 통합 실습 코드
이제 위 4단계를 **하나의 `main.py`** 로 합쳐보겠습니다.

`response-practice/main5.py`
```python
# FastAPI에서 필요한 기능들을 가져옵니다.
# FastAPI         → API 서버 생성
# Response        → 쿠키, 헤더, 상태코드 등을 직접 설정할 때 사용
# HTTPException   → 오류 발생 시 에러 응답 반환
# Form            → HTML form 데이터 받기
# status          → HTTP 상태코드 상수 모음
from fastapi import FastAPI, Response, HTTPException, Form, status

# JSONResponse는 JSON 응답 객체를 직접 만들어서
# 헤더, 쿠키 등을 더 세밀하게 제어할 때 사용합니다.
from fastapi.responses import JSONResponse

# passlib의 CryptContext는 비밀번호를 안전하게 해싱할 때 사용합니다.
from passlib.context import CryptContext


# FastAPI 애플리케이션 생성
# 이 객체가 전체 API 서버의 시작점입니다.
app = FastAPI()


# -----------------------------------
# 1. 공통 준비물
# -----------------------------------

# 비밀번호 해싱 설정
# bcrypt 알고리즘을 사용해서 비밀번호를 암호화합니다.
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# 가짜 사용자 DB
# 실제 프로젝트에서는 MySQL/PostgreSQL 같은 DB를 사용하지만
# 지금은 학습용이므로 딕셔너리로 대신합니다.
fake_users_db = {}

# 가짜 아이템 DB
# item_id를 key로 사용하고,
# 각 아이템은 name, size 정보를 가집니다.
items_db = {
    "foo": {"name": "Fighters", "size": 6}
}


# -----------------------------------
# 2. 회원가입 + 해싱 + 쿠키
# -----------------------------------
# /signup 주소로 POST 요청이 들어오면 실행됩니다.
@app.post("/signup")
def signup(
    # form 데이터에서 username 값을 받습니다.
    # Form(...) 의 ... 은 필수값이라는 뜻입니다.
    username: str = Form(...),

    # form 데이터에서 password 값을 받습니다.
    password: str = Form(...),

    # FastAPI가 Response 객체를 자동으로 넣어줍니다.
    # 이 객체를 사용하면 쿠키나 헤더를 설정할 수 있습니다.
    response: Response = None
):
    # 사용자 중복 확인
    # 이미 같은 username이 존재하면 회원가입을 막습니다.
    if username in fake_users_db:
        raise HTTPException(
            status_code=400,
            detail="이미 존재하는 사용자입니다."
        )

    # 비밀번호 해싱
    # 사용자가 입력한 비밀번호를 그대로 저장하지 않고
    # bcrypt 방식으로 암호화해서 저장합니다.
    hashed_password = pwd_context.hash(password)

    # 사용자 저장
    # 실제 DB 대신 딕셔너리에 저장합니다.
    fake_users_db[username] = {
        "username": username,
        "hashed_password": hashed_password
    }

    # 세션 토큰 생성
    # 실제 서비스에서는 JWT 또는 세션 ID를 사용하지만
    # 지금은 학습용으로 단순 문자열을 만듭니다.
    session_token = f"token-{username}"

    # 쿠키 저장
    # 브라우저가 이 응답을 받으면 sessionid 쿠키를 저장합니다.
    response.set_cookie(
        key="sessionid",       # 쿠키 이름
        value=session_token,   # 쿠키 값
        httponly=True,         # JavaScript 접근 차단 (보안)
        max_age=3600           # 1시간 동안 유지
    )

    # JSON 응답 반환
    # FastAPI는 딕셔너리를 자동으로 JSON으로 변환합니다.
    return {"message": f"{username}님, 회원가입이 완료되었습니다."}


# -----------------------------------
# 3. 응답 헤더 설정
# -----------------------------------
# /api/info 주소로 GET 요청이 들어오면 실행됩니다.
@app.get("/api/info")
def get_api_info():
    # 실제 응답 본문(JSON 데이터)
    content = {
        "service": "MyApp",
        "description": "This API provides service info.",
        "status": "running"
    }

    # 응답 헤더 정보
    # 헤더는 브라우저, 프론트엔드, 앱 등이 읽는 추가 정보입니다.
    headers = {
        "X-API-Version": "1.0.0",   # 현재 API 버전
        "Content-Language": "en-US",# 응답 언어
        "Cache-Control": "no-store" # 캐시 저장 금지
    }

    # JSONResponse 객체를 직접 생성하면서
    # 본문(content)과 헤더(headers)를 같이 넣어서 반환합니다.
    return JSONResponse(content=content, headers=headers)


# -----------------------------------
# 4. JSONResponse + 쿠키 + 헤더 설정
# -----------------------------------
# /signup-json 주소로 POST 요청이 들어오면 실행됩니다.
@app.post("/signup-json")
def signup_json(
    # form 데이터에서 username, password를 받습니다.
    username: str = Form(...),
    password: str = Form(...),
):
    # 사용자 중복 확인
    if username in fake_users_db:
        raise HTTPException(
            status_code=400,
            detail="이미 존재하는 사용자입니다."
        )

    # 비밀번호 해싱
    hashed_password = pwd_context.hash(password)

    # 사용자 저장
    fake_users_db[username] = {
        "username": username,
        "hashed_password": hashed_password
    }

    # 토큰 생성
    session_token = f"token-{username}"

    # 응답 본문
    # 클라이언트에게 전달할 JSON 데이터입니다.
    content = {
        "message": f"{username}님, 회원가입이 완료되었습니다.",
        "status": "success"
    }

    # 응답 객체 생성
    # 단순히 dict를 return 하는 것이 아니라
    # JSONResponse 객체를 직접 만들어서 더 세밀하게 제어합니다.
    response = JSONResponse(content=content)

    # 쿠키 설정
    # signup과 달리, 여기서는 response 객체에 직접 쿠키를 설정합니다.
    response.set_cookie(
        key="sessionid",
        value=session_token,
        httponly=True,
        max_age=3600
    )

    # 헤더 설정
    # 응답 객체에 직접 헤더를 추가합니다.
    response.headers["X-API-Version"] = "1.0.0"
    response.headers["Content-Language"] = "ko-KR"
    response.headers["Cache-Control"] = "no-store"

    # 최종 응답 반환
    # JSON 본문 + 쿠키 + 헤더가 함께 전달됩니다.
    return response


# -----------------------------------
# 5. Upsert + 상태코드 제어
# -----------------------------------
# /items/{item_id} 주소로 PUT 요청이 들어오면 실행됩니다.
# item_id는 URL 경로에서 받습니다.
@app.put("/items/{item_id}")
async def upsert_item(
    item_id: str,      # 경로 파라미터
    name: str,         # 쿼리 파라미터
    size: int,         # 쿼리 파라미터
    response: Response # 상태코드 변경용 Response 객체
):
    # 기존 아이템 수정
    # item_id가 이미 있으면 update 작업을 수행합니다.
    if item_id in items_db:
        items_db[item_id].update({
            "name": name,
            "size": size
        })
        return {
            "message": "Item updated",
            "item": items_db[item_id]
        }

    # 새 아이템 생성
    # item_id가 없으면 새 데이터를 만듭니다.
    new_item = {
        "name": name,
        "size": size
    }
    items_db[item_id] = new_item

    # 생성일 때만 201 상태코드 설정
    # 수정은 기본 200 OK
    # 생성은 201 Created 로 구분합니다.
    response.status_code = status.HTTP_201_CREATED

    return {
        "message": "Item created",
        "item": new_item
    }
```
