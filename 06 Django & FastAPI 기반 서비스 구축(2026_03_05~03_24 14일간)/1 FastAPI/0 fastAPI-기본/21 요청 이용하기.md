### `Request`란?
	Request는 클라이언트(브라우저, React 앱 등)가 FastAPI 서버에 요청을 보낼 때 전달되는 
	모든 정보를 담고 있는 객체입니다.

쉽게 말해:
	누가 언제 어떤 내용으로 요청했는지 다 담겨있는 내용입니다.

### 왜 필요한가?
	FastAPI는 기본적으로 GET, POST 등의 요청을 받아서 응답을 해줘요. 하지만, 어떤 요청인지, 
	누구한테서 왔는지, 어떤 값을 보냈는지 세부 정보가 필요할 때가 많습니다.

예를 들어:
- 어떤 방식으로 요청했는지 (`GET`, `POST`)
- 어떤 주소로 요청했는지 (`/items/3`)
- 누가 요청했는지 (IP)
- 로그인 토큰이 있는지 (Authorization header)
- 쿠키 정보
- 사용자가 보낸 데이터(JSON)
    
이 내용이 바로 Request 객체에 들어 있습니다

###### Request에서 어떤 정보들을 꺼낼 수 있나?
| 항목                     | 예시                                | 설명                                                                          |
| ---------------------- | --------------------------------- | --------------------------------------------------------------------------- |
| `request.method`       | `"GET"`, `"POST"` 등               | 클라이언트가 사용한 HTTP 요청 방식 (GET, POST, PUT, DELETE 등)                            |
| `request.url`          | `http://127.0.0.1/items/3`        | 요청의 전체 URL 주소                                                               |
| `request.headers`      | `User-Agent`, `Authorization` 등   | 요청에 포함된 HTTP 헤더 정보 (브라우저 정보, 인증 토큰 등)                                       |
| `request.cookies`      | 로그인 쿠키 등                          | 요청에 포함된 쿠키 정보 (예: 세션 ID, 로그인 상태 등)                                          |
| `request.query_params` | `?name=abc&age=3`                 | URL에 붙는 쿼리 파라미터들을 key-value 형태로 가져옴                                         |
| `request.path_params`  | `items/{item_id}` 중 `{item_id}` 값 | URL 경로에 포함된 변수 값 (예: `/items/3` → `item_id=3`)                              |
| `request.body()`       | JSON 등 POST로 보내는 본문 데이터           | 요청의 본문(body) 데이터를 비동기적으로 읽어올 때 사용. 일반적으로 JSON 데이터 처리에 사용됨                   |
| `request.form()`       | 폼 데이터를 받을 때                       | `application/x-www-form-urlencoded` 또는 `multipart/form-data` 형식의 폼 데이터를 파싱함 |
| `request.client`       | 요청한 사람의 IP 주소 등                   | 클라이언트의 IP 주소 및 포트 정보 (`(ip, port)` 튜플)                                      |
| `request.app`          | 현재 실행 중인 FastAPI 앱                | 현재 실행 중인 FastAPI 애플리케이션 인스턴스에 접근 가능                                         |
### 언제 사용하는가?
실제 백엔드 기능은 거의 다 Request 기반입니다
- API 디버깅할 때 (요청을 모두 기록하는 로그용)
- 사용자 인증 정보 확인
- 웹 클라이언트가 어떤 기기인지 판단할 때 (`User-Agent`)
- 쿠키 기반 로그인 처리
- 성능 측정용 (미들웨어로 요청 처리 시간 측정)

### 요청의 전체 목적 요약:
아래 요청은 브라우저(Chrome)가 FastAPI 서버의 `/request-info` 경로에 대해 `GET` 요청을 보낸 상황입니다. 서버는 이 요청에 대해 다음을 응답했습니다:

---
#### 개발자가 가장 많이 확인하는 Request 정보
1️⃣ 요청 방식 (GET / POST)
```python
request.method
```
예
```python
if request.method == "POST":
    print("데이터 저장 요청")
```

2️⃣ 요청 URL
```python
request.url
```
예
```python
print(request.url)
```
출력
```
http://127.0.0.1:8000/request-info
```

3️⃣ 사용자 IP
```python
request.client.host
```
예
```python
ip = request.client.host  
print("접속 사용자:", ip)
```

4️⃣ 쿼리 파라미터 (검색 / 필터)
url
```
/items?name=apple&price=1000
```
코드
```python
params = request.query_params  
  
name = params.get("name")  
price = params.get("price")
```

5️⃣ 요청 헤더 (로그인 토큰 확인)
```
Authorization: Bearer token
```
코드
```python
token = request.headers.get("authorization")
```
로그인 인증에서 자주 사용합니다.

백엔드에서 Request는 보통 이 4가지를 가장 많이 사용합니다.
```python
request.method # 요청 방식  
request.query_params # URL 파라미터  
request.headers # 인증 토큰  
request.client.host # 사용자 IP
```

---
요청에 대한 전체 메타정보(메서드, 헤더, 쿠키 등)를 JSON 형태로 반환
```python
# request_info.py
from fastapi import FastAPI, Request

app = FastAPI()

@app.get("/request-info")
async def get_request_info(request: Request):
    return {
        "method": request.method,
        "url": str(request.url),
        "client_ip": request.client.host,
        "query": dict(request.query_params),
        "headers": dict(request.headers),
    }
```

실행:
```bash
uvicorn request_info:app --reload
```

브라우저 접속
```
http://127.0.0.1:8000/request-info?name=banana&price=3000
```

![[Pasted image 20260310152940.png]]

`method` : 데이터를 조회
- GET → 조회
- POST → 데이터 저장
- PUT → 수정
- DELETE → 삭제

`url` : 사용자가 접속한 전체 주소

`client_ip` : 요청한 사용자의 IP 주소
- 지금은 127.0.0.1 내 컴퓨터에서 요청한 것

`query` : URL 뒤에 붙은 추가 데이터 `?name=banana&price=3000`
```json
"query": {
  "name": "banana",
  "price": "3000"
}
```

`headers` : 어떤 브라우저가 요청했는지 `"user-agent": "Chrome ..."`
- Chrome 현재 크롬이란뜻
- Safari
- 모바일 앱

`"accept-language": "ko-KR"` : 사용자 언어 설정 

`"host": "127.0.0.1:8000"` : 어느 서버로 요청했는지 

즉 지금 화면은 브라우저가 서버에 보낸 요청 정보를 서버가 그대로 보여준 것입니다.

### Django 방식 vs FastAPI 방식

Django 방식:
Django에서는 항상 `request`가 기본으로 들어옵니다.
```python
def my_view(request):
    print(request.method)
    print(request.GET)
    print(request.POST)
```
즉, request 객체 안에 모든 정보가 들어 있음. 그래서 필요한 것을 직접 꺼내서 사용합니다.

예
```python
request.GET  
request.POST  
request.user  
request.COOKIES
```

FastAPI방식:
FastAPI는 타입 힌트 기반 자동 처리를 합니다.
```python
@app.post("/items/")
async def create_item(item: Item):
    return item
```
이 코드에서
```
JSON 요청 → Item 객체로 자동 변환
```

즉 FastAPI가 내부적으로
```
request.body → Item
```
로 변환해 줍니다. 그래서 request를 직접 쓰지 않아도 되는 경우가 많습니다.

FastAPI에서도 request를 필요하면 Django처럼 사용 가능합니다.
```python
from fastapi import Request

@app.get("/info")
async def info(request: Request):
    return {
        "method": request.method,
        "url": str(request.url)
    }
```
즉
```
request.headers
request.cookies
request.client
request.query_params
```

###### 둘의 차이 핵심
| Django       | FastAPI            |
| ------------ | ------------------ |
| request 중심   | 타입 기반 자동 파싱        |
| request.GET  | 함수 파라미터            |
| request.POST | Pydantic/dataclass |
| request.user | Depends            |
> Django는 request 객체에서 데이터를 직접 꺼내 사용하는 방식이고,  
> FastAPI는 함수 파라미터와 타입 힌트를 이용해 자동으로 데이터를 변환해주는 방식입니다.

그래서 FastAPI가 더 선언적이고 코드가 짧아지는 특징이 있습니다.

### Request로 할 수 있는 것들
	Request 객체를 사용하면 사용자가 서버에 어떤 요청을 보냈는지 확인할 수 있습니다.
	즉, 서버는 Request를 통해 누가 어떤 정보를 보내왔는지 파악할 수 있습니다.

대표적으로 다음과 같은 것들을 확인할 수 있습니다.

1️⃣ 누가 요청했는지 확인할 수 있습니다
	요청을 보낸 사용자의 정보를 확인할 수 있습니다.

예를 들어
- 어떤 브라우저로 접속했는지 (`User-Agent`)
- 어디에서 접속했는지 (`client.host`)
- 어떤 쿠키를 가지고 왔는지 (`request.cookies`)
- 어떤 헤더 정보를 보냈는지 (`request.headers`)
    
이 정보를 통해 사용자의 접속 환경을 확인할 수 있습니다.

예
- 크롬 브라우저로 접속했는지
- 모바일 기기인지
- 한국어 환경인지

2️⃣ 로그인이나 보안 문제를 확인할 수 있습니다
	Request에는 로그인과 관련된 정보도 포함될 수 있습니다.

예를 들어
- 쿠키에 세션 ID가 있는지
- 헤더에 JWT 토큰이 있는지
- CSRF 토큰이 있는지
    
이 정보를 확인하면 사용자가 로그인 상태인지 또는 인증 문제가 있는지 확인할 수 있습니다.

예  
로그인이 되지 않을 때  
→ 쿠키나 토큰이 요청에 포함되어 있는지 확인할 수 있습니다.

3️⃣ 사용자 상황에 맞게 응답을 다르게 할 수 있습니다
	Request 정보를 이용하면 사용자에게 맞춤형 응답을 제공할 수 있습니다.

예를 들어
- 사용자의 언어 설정 확인
- 모바일 기기인지 확인
    
예
- 한국어 사용자에게는 한국어 페이지 제공
- 모바일 사용자에게는 모바일 화면 제공

4️⃣ 개발 중 요청 내용을 확인할 수 있습니다
	개발할 때는 요청 정보를 확인하는 API를 만들어서 테스트하기도 합니다.
```python
# 위에 실습한 내용과 동일한 코드
from fastapi import Request

@app.get("/check-request")
async def check_request(request: Request):
    return {
        "method": request.method,
        "url": str(request.url),
        "headers": dict(request.headers),
        "cookies": request.cookies,
        "client": request.client.host
    }
```
이 API를 호출하면 클라이언트가 어떤 요청을 보냈는지 확인할 수 있습니다.

그래서
- 프론트엔드 요청이 제대로 오는지
- 헤더나 쿠키가 잘 전달되는지
    
확인할 때 매우 유용합니다.

5️⃣ 프록시 서버 환경을 확인할 수 있습니다
	서비스에서는 종종 Nginx 같은 중간 서버(프록시)를 사용합니다.

이때 요청 헤더를 확인하면
- 실제 사용자 IP
- 프록시 서버 전달 정보 등을 확인할 수 있습니다.

예  
`X-Forwarded-For` 헤더를 통해 실제 사용자 IP를 확인할 수 있습니다.

6️⃣ 프론트엔드와 백엔드 연결을 확인할 수 있습니다
	프론트엔드에서 보낸 요청이 정상적으로 서버에 도착했는지 확인할 수 있습니다.

예를 들어
- Axios 요청이 정상인지
- 쿠키가 전달되는지
- CORS 문제가 있는지 같은 문제를 Request 정보를 통해 확인할 수 있습니다.

### Request와 Header의 차이

Request (요청)
	Request는 클라이언트가 서버에 보내는 전체 메시지입니다.

예를 들어
- 어떤 주소로 요청했는지
- 어떤 데이터를 보냈는지
- 누가 요청했는지
- 어떤 쿠키나 헤더가 있는지
    
이 모든 정보가 Request 안에 포함됩니다.

Header (헤더)
	Header는 Request 안에 들어 있는 추가 정보입니다.

예를 들어
- 어떤 브라우저인지
- 로그인 토큰이 있는지
- 어떤 데이터 형식을 원하는지
    
같은 정보를 담고 있습니다.

✔ 정리
- Request → 서버로 보내는 전체 요청 정보
- Header → 요청 안에 포함된 추가 정보

###### Django / DRF / FastAPI에서 요청(Request)을 받는 방식 비교
	웹 서버는 클라이언트(브라우저, 앱)가 보낸 요청(Request)을 함수에서 받아 처리합니다.  
	각 프레임워크는 이 요청을 함수에서 받는 방식이 조금씩 다릅니다.

|프레임워크|함수 형태 예시|설명|
|---|---|---|
|Django|`def my_view(request):`|Django에서는 요청 정보가 `request` 객체에 담겨서 함수로 전달됩니다.|
|DRF|`def get(self, request):`|DRF에서는 `APIView` 클래스 안에서 `request` 객체를 받아 요청을 처리합니다.|
|FastAPI|`def my_api(request: Request):`|FastAPI에서는 `Request` 타입을 사용해 요청 정보를 받을 수 있습니다.|
세 프레임워크 모두 클라이언트가 보낸 요청(Request)을 함수에서 받아 처리한다는 점은 동일합니다. 다만 요청을 받는 함수의 형태가 조금씩 다릅니다.
