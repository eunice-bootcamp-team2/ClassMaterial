1️⃣ FastAPI는 사실 파일 하나로도 충분히 동작하는 구조
```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/hello")
def hello():
    return {"message": "hello"}
```
앞에서 봤듯이 main.py 하나만 있어도 서버가 실행됩니다

```bash
uvicorn main:app --reload
```

2️⃣ 실제 프로젝트에서는 파일을 나누는 이유는 유지보수 및 협업의 어려움 때문입니다.
```bash
ai-server/
│
├── main.py
│   # FastAPI 앱의 시작점
│   # Django와 비유:
│   # - 프로젝트의 urls.py + 앱 실행 진입점 느낌
│   # 역할:
│   # - app = FastAPI() 생성
│   # - include_router()로 각 기능 라우터 연결
│   # - 서버 실행의 기준이 되는 파일
│
├── routers/
│   ├── sentiment.py
│   │   # 감정분석 API 주소를 작성하는 파일
│   │   # Django와 비유:
│   │   # - views.py + urls.py가 합쳐진 느낌
│   │   # 역할:
│   │   # - /sentiment/predict 같은 URL 정의
│   │   # - 요청 받기
│   │   # - service 호출하기
│   │   # - 결과 응답하기
│   │
│   └── keyword.py
│       # 키워드 추출 API 주소를 작성하는 파일
│       # Django와 비유:
│       # - views.py + urls.py가 합쳐진 느낌
│       # 역할:
│       # - /keywords/extract 같은 URL 정의
│       # - 요청 받기
│       # - service 호출하기
│       # - 결과 응답하기
│
├── services/
│   ├── sentiment_service.py
│   │   # 감정분석 "실제 처리 로직" 파일
│   │   # Django와 비유:
│   │   # - services.py
│   │   # 역할:
│   │   # - 모델 로딩
│   │   # - 예측 함수 실행
│   │   # - 전처리 / 후처리
│   │   # - router에서 받은 데이터를 실제로 분석
│   │
│   └── keyword_service.py
│       # 키워드 추출 "실제 처리 로직" 파일
│       # Django와 비유:
│       # - services.py
│       # 역할:
│       # - 텍스트에서 키워드 추출
│       # - 분석 함수 실행
│       # - router에서 받은 요청을 실제 처리
│
├── schemas/
│   └── sentiment_schema.py
│       # 요청/응답 데이터 형식을 정의하는 파일
│       # Django와 비유:
│       # - serializers.py 와 가장 비슷함
│       # 역할:
│       # - request body 구조 정의
│       # - response body 구조 정의
│       # - Pydantic으로 타입 검증
│       # 예:
│       #   text: str
│       #   label: str
│       #   score: float
│
└── models/
    # Django로 치면:
    # - models.py
    # 역할:
    # - DB 모델
    # - 또는 AI 모델 파일 관리용 모듈
```


### FastAPI 기능과 실제 파일 위치 정리
| FastAPI 기능       | 실제 작성 파일        | 코드 예시 위치                | 역할 설명                  | Django/DRF 비교             |
| ---------------- | --------------- | ----------------------- | ---------------------- | ------------------------- |
| FastAPI 앱 생성     | `main.py`       | `app = FastAPI()`       | FastAPI 서버 <br>시작점     | `urls.py` + 프로젝트 시작       |
| Router <br>등록    | `main.py`       | `app.include_router()`  | API <br>라우터 <br>연결     | `urls.py`                 |
| URL 정의           | `routers/*.py`  | `@router.get("/items")` | API endpoint 생성        | `views.py` + `urls.py`    |
| Path Parameter   | `routers/*.py`  | `/items/{id}`           | URL에서 값 받기             | `path("items/<int:id>/")` |
| Query Parameter  | `routers/*.py`  | `def get_items(q: str)` | URL 쿼리값 처리             | `request.GET`             |
| Header Parameter | `routers/*.py`  | `Header()`              | 요청 <br>헤더 읽기           | `request.headers`         |
| Cookie Parameter | `routers/*.py`  | `Cookie()`              | 쿠키 <br>값 읽기            | `request.COOKIES`         |
| Request Body     | `schemas/*.py`  | `BaseModel`             | 요청 JSON <br>구조 정의      | `serializers.py`          |
| 데이터 <br>검증       | `schemas/*.py`  | `class Item(BaseModel)` | 타입 <br>검사 / validation | `Serializer validation`   |
| CRUD API 작성      | `routers/*.py`  | `@router.post()`        | 실제 API endpoint 작성     | `APIView / ViewSet`       |
| 비즈니스 로직          | `services/*.py` | 함수 작성                   | 실제 처리 로직               | `services.py`             |
| 응답 <br>데이터<br>구조 | `schemas/*.py`  | Response Model          | 응답 JSON <br>구조         | `Serializer`              |

위의 파일의 프로젝트 구조
```
ai-server
│
├── main.py
├── routers/
│    ├── sentiment.py
│    └── keyword.py
│
├── services/
│    ├── sentiment_service.py
│
├── schemas/
│    └── sentiment_schema.py
```

###### 각 파일 역할을 다시 정리하면
|파일|역할|Django 비교|
|---|---|---|
|main.py|FastAPI 시작점, 라우터 연결|urls.py|
|routers/sentiment.py|API endpoint|views.py|
|services/sentiment_service.py|실제 AI 로직|services.py|
|schemas/sentiment_schema.py|요청/응답 구조|serializers.py|
실제 코드 흐름으로 예를 들어 감정분석 API 요청이 들어오면
```
Client
   │
   ▼
routers/sentiment.py
(API endpoint)

   │
   ▼
schemas/sentiment_schema.py
(Request 데이터 검증)

   │
   ▼
services/sentiment_service.py
(AI 모델 실행)

   │
   ▼
응답 반환
```

### Django 기준으로 1:1 비교
|Django|FastAPI|
|---|---|
|models.py|models.py|
|serializers.py|schemas.py|
|views.py|routers|
|services.py|services|
|urls.py|main.py|

###### FastAPI 구조는 크게 **4가지 레이어**로 이해하면 쉽습니다.
|레이어|역할|
|---|---|
|main|앱 시작 / router 등록|
|routers|API endpoint|
|schemas|데이터 구조|
|services|실제 로직|
