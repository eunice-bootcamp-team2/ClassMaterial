FastAPI에서 에러 처리(Error Handling)는 클라이언트가 잘못된 요청을 보냈을 때나 서버 내부에서 예기치 못한 일이 발생했을 때 적절한 HTTP 상태 코드와 메시지를 돌려줘서, 
API 소비자(프론트엔드나 다른 서비스)가 무슨 일이 생겼는지 알 수 있도록 돕는 기능입니다.

###### 1️⃣ 예외처리 vs 에러처리 (차이)
| 용어                         | 의미                          |
| -------------------------- | --------------------------- |
| 예외 처리 (Exception Handling) | 코드에서 발생하는 예외(Exception)를 처리 |
| 에러 처리 (Error Handling)     | 시스템 전체에서 발생하는 모든 오류를 처리     |
즉 예외처리는 에러 처리의 한 종류입니다.

2️⃣ Python 기준 예외처리 : 예외처리는 보통 이런 구조입니다.
```python
try:
    result = 10 / 0
except ZeroDivisionError:
    print("0으로 나눌 수 없습니다")
```
이것은 우리가 잘 알고 있는 예외 처리 (Exception Handling) 입니다.

3️⃣ 반면 FastAPI에서 에러처리 : astAPI에서는 보통 이렇게 합니다.
```python
from fastapi import HTTPException

if item_id not in items:
    raise HTTPException(status_code=404, detail="Item not found")
```

이것은 HTTP 에러를 발생시키는 방식입니다.

즉, 
- 서버 내부 오류
- 잘못된 요청
- 데이터 없음
    
같은 상황에서 클라이언트에게 상태코드를 알려주는 방식입니다.

###### 4️⃣ FastAPI에서 에러 처리 종류
| 방법                | 설명          |
| ----------------- | ----------- |
| HTTPException     | 가장 기본적인 에러  |
| Custom Exception  | 내가 만든 예외    |
| Exception Handler | 특정 예외 처리    |
| Override Handler  | 전체 에러 처리 변경 |
```
404 → 데이터 없음  
401 → 인증 실패  
403 → 권한 없음  
422 → 데이터 검증 실패  
500 → 서버 오류
```
이런 상태 코드를 반환합니다

5️⃣ Django 기준으로 보면  같은 개념입니다.
```python
from django.http import Http404

if not product:
    raise Http404("상품 없음")
    
# 또는
try:
    product = Product.objects.get(id=id)
except Product.DoesNotExist:
    raise Http404()
```
이것도 예외 처리 + 에러 처리입니다.

---
### HTTP 상태 코드(Status Code)란?
	HTTP 상태 코드는 서버가 요청 처리 결과를 클라이언트에게 알려주는 숫자 코드입니다.

주요 구분은 다음과 같습니다.
- 200번대 → 요청이 정상적으로 처리됨
- 400번대 → 클라이언트 요청에 문제가 있음
- 500번대 → 서버 내부에서 오류가 발생함
    
예를 들어:
- `404 Not Found` → 요청한 데이터가 없음
- `422 Unprocessable Entity` → 요청 데이터 검증 실패
- `500 Internal Server Error` → 서버에서 예기치 못한 오류 발생
---
### FastAPI에서 에러 발생시키기 (`HTTPException`)
	FastAPI에서는 HTTPException을 사용하여 특정 상황에서 에러를 발생시키고 
	상태 코드를 반환할 수 있습니다.

```python
raise HTTPException(status_code=404, detail="Item not found")
```
이 코드는 404 상태 코드와 함께 에러 메시지를 클라이언트에게 전달합니다.

즉, 문제가 발생했을 때 클라이언트가 상황을 알 수 있도록 상태 코드와 메시지를 보내는 방법입니다.

---
Django는 웹 페이지 중심 프레임워크이기 때문에 기본적인 에러 처리를 프레임워크가 자동으로 수행하고 기본 HTML 에러 페이지도 함께 제공합니다.

반면 FastAPI는 API 중심 프레임워크이기 때문에 에러 상황에 맞는 상태 코드와 응답을 개발자가 직접 지정해 주는 경우가 많습니다.

---
### FastAPI에서 에러를 처리하는 4가지 대표적인 방법:
	FastAPI에서는 에러를 처리할 때 상황에 따라 적절한 방식이 달라집니다.
	아래 코드는 그에 따른 4가지 대표적인 처리 방식을 보여줍니다.
---
#### 1️⃣ 기본 `HTTPException` 사용하기
```python
# handling_exception.py

from fastapi import FastAPI, HTTPException

app = FastAPI()

items = {    
	"apple": "사과입니다",
    "banana": "바나나입니다",
    "grape": "포도입니다"
    }

@app.get("/items/{item_id}") # items의 딕셔너리 키
async def read_item(item_id: str):
    if item_id not in items:
        # 아이템이 없으면 404 에러를 발생시킵니다.
        raise HTTPException(status_code=404, detail="Item not found")
    return {"item": items[item_id]}
```
- 가장 기본적이고 자주 쓰는 방식
- 특정 조건에서 예외를 던지고 → FastAPI가 자동으로 JSON 에러 응답을 만들어 줌
- 예: 404 Not Found, 403 Forbidden, 401 Unauthorized 등
	- 간단한 예외 처리에 적합  
	- 별도 설정 없이 바로 사용 가능

```bash
uvicorn handling_exception:app --reload
```

Swagger 주소:
```
http://127.0.0.1:8000/docs
```

정상값
```
apple
```

결과:
```json
{
  "item": "사과입니다"
}
```

에러값:
```
orange
```

결과:
- 상태코드: `404`
- 응답:
```json
{  
  "detail": "Item not found"  
}
```

#### 2️⃣ `HTTPException` + 커스텀 헤더
```python
# http_exception_with_custom_headers.py

from fastapi import FastAPI, HTTPException

app = FastAPI()

items = {    
	"apple": "사과입니다",
    "banana": "바나나입니다",
    "grape": "포도입니다"
    }

@app.get("/items-header/{item_id}")
async def read_item_header(item_id: str):
    if item_id not in items: # items 안에 item_id가 없으면 
        # 헤더를 직접 지정해서 반환할 수 있습니다.
        raise HTTPException(
            status_code=404,
            detail="Item not found",
            headers={"X-Error": "There goes my error"},
        )
    return {"item": items[item_id]}
```

- 에러 응답에 특정 헤더를 추가해서 전달하고 싶은 경우 사용
- 예: 클라이언트에게 에러 코드나 상태를 헤더로 전달할 때
	✔ 보안, 상태, 오류 추적 등 목적의 메타정보 전달에 유용
- `raise` 는 예외(Exception)를 발생시키는 키워드입니다.

#### `content-length: 26`
- 응답 본문의 바이트 크기입니다.
- 즉, JSON 응답의 길이가 26바이트라는 뜻이에요.
예: 응답 내용이
```json

```
같은 경우, 이 문자열의 길이를 byte 단위로 계산한 값입니다.

#### `content-type: application/json`
- 응답의 데이터 형식을 알려줍니다.
- 여기서는 JSON 형식이라는 뜻이에요.
- 브라우저나 앱은 이걸 보고 JSON으로 파싱하게 됩니다.

- 클라이언트는 이걸 보고 응답 시점이나 캐시 처리에 참고할 수 있어요.

#### 3️⃣ 커스텀 예외 클래스 + 전용 핸들러
```python
# custom_exception_handler.py

from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

# 1) 커스텀 예외 클래스 정의
class UnicornException(Exception):
    def __init__(self, name: str):
        self.name = name

app = FastAPI()

# 2) 해당 예외 전용 핸들러 등록
@app.exception_handler(UnicornException)
async def unicorn_exception_handler(request: Request, exc: UnicornException):
    return JSONResponse(
        status_code=418,
        content={"message": f"Oops! {exc.name} did something. There goes a rainbow..."},
    )

# 3) 라우트에서 예외 발생
@app.get("/unicorns/{name}")
async def read_unicorn(name: str):
    if name == "yolo":
        raise UnicornException(name=name)
    return {"unicorn_name": name}
```
- 내가 정의한 특정 예외 클래스가 발생했을 때만,  
    → 맞춤 응답 형식이나 메시지를 줄 수 있음
- JSON 구조도 완전히 내 마음대로 조절 가능
    
	✔ 특정 조건에서 전용 에러 메시지나 로직을 처리하고 싶을 때  
	✔ 사용자 친화적인 에러 메시지 필요할 때

```bash
uvicorn custom_exception_handler:app --reload
```

정상값:
```
tom
```

에러 발생값:
```
yolo
```

#### 4️⃣ 기본(Starlette) 핸들러 오버라이드
FastAPI의 기본 에러 처리 방식을 전체적으로 바꾸는 예제
```python
# override_exception_handlers.py

from fastapi import FastAPI, HTTPException, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import PlainTextResponse
from starlette.exceptions import HTTPException as StarletteHTTPException

app = FastAPI()

# 1) Starlette의 HTTPException 핸들러 오버라이드 (HTTP 에러 처리 방식 변경)
@app.exception_handler(StarletteHTTPException)
async def http_exception_handler(request: Request, exc: StarletteHTTPException):
    return PlainTextResponse(str(exc.detail), status_code=exc.status_code)
# PlainTextResponse(...) → JSON 대신 텍스트 형태로 에러 메시지 응답
'''
에러종류
	400
	401
	403
	404
	405
	422
	500
	503
'''
# 2) 요청 검증 에러(RequestValidationError) 핸들러 오버라이드
# (입력값 검증 에러 처리 방식 변경)
@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request: Request, exc: RequestValidationError):
    return PlainTextResponse(str(exc), status_code=400)

# 3) 테스트용 엔드포인트 (테스트용 API (예외 발생 확인))
@app.get("/items/{item_id}")
async def read_item(item_id: int):
    # item_id가 3이면 418 에러 발생
    if item_id == 3:
        raise HTTPException(status_code=418, detail="Nope! I don't like 3.")
    return {"item_id": item_id}
```
- FastAPI 내부에서 기본적으로 사용하는 에러 핸들러 자체를 덮어쓰기(override)
- 모든 에러의 응답 형식을 전역적으로 통일하고 싶을 때 사용
- `@app.exception_handler(...)`의 의미
	- 특정 예외가 발생했을 때 실행할 함수를 등록(register)하는 것

```bash
uvicorn override_exception_handlers:app --reload
```

정상값
```
1
```

직접 발생시키는 HTTPException
```
3
```
결과:
- 상태코드: `418`
- 응답: JSON이 아니라 텍스트
```json
Nope! I don't like 3.
```

`item_id` 자리에 정수가 아닌 문자열 입력
```
abc
```
결과:
원래는 FastAPI가 422 JSON 검증 오류를 주지만, 이 코드에서는 검증 오류도 텍스트 형태로 바꿔서 반환합니다.

---
즉 1), 2)는 설정이고 3)은 테스트 코드입니다.
### Django와 완전히 1:1로 비교하면
| FastAPI                           | Django 비유                         |
| --------------------------------- | --------------------------------- |
| 1) HTTPException handler override | 404.html / 500.html 전체 커스터마이징     |
| 2) RequestValidationError handler | Serializer validation error 형식 통일 |
| 3) 테스트 endpoint                   | 테스트용 view                         |

### 만약 코드 분할을 통해 에러처리를 사용할때 활용예시

1️⃣ exception_handler.py (에러 처리 등록 파일)
```python
# core/exception_handler.py

from fastapi import Request
from fastapi.responses import JSONResponse

class MyError(Exception):
    pass

def register_exception_handlers(app):

    @app.exception_handler(MyError)
    async def my_error_handler(request: Request, exc: MyError):
        return JSONResponse(
            status_code=400,
            content={"error": "내가 만든 에러입니다"}
        )
```
설명
- `MyError` → 내가 만든 예외
- `register_exception_handlers()` → 예외 처리 등록 함수

2️⃣ main.py (FastAPI 시작 파일)
```python
from fastapi import FastAPI
from core.exception_handler import register_exception_handlers # 모듈호출

app = FastAPI()

register_exception_handlers(app) # 예외 처리기를 FastAPI에 등록
```

3️⃣ router.py (비즈니스 로직) 에러처리 사용처
```python
from fastapi import APIRouter
from core.exception_handler import MyError

router = APIRouter()

@router.get("/test")
def test():
    raise MyError()
```
- `raise MyError()` → 예외 발생

4️⃣ 실제 실행 흐름
```
클라이언트 요청
      ↓
router 실행
      ↓
raise MyError()
      ↓
FastAPI
      ↓
등록된 exception handler 실행
      ↓
JSON 응답 반환
```

1️⃣ 예외 handler 등록 → 2️⃣ 로직에서 raise → 3️⃣ FastAPI가 자동 처리

---

| 번호  | 방법                                | 설명              |
| --- | --------------------------------- | --------------- |
| 1   | HTTPException 사용                  | 가장 기본적인 에러 처리   |
| 2   | HTTPException + header 추가         | 에러 응답에 추가 정보 전달 |
| 3   | Custom Exception + handler        | 내가 만든 예외 처리     |
| 4   | Global Exception Handler override | 기본 에러 처리 방식 변경  |
각각은 사용 목적이 다릅니다.
