### 비동기 프로그램이란?
	비동기 프로그래밍은 어떤 작업이 오래 걸려도 그 작업이 끝날 때까지 기다리지 않고, 
	다른 작업들을 그 사이에 동시에 처리할 수 있게 해주는 방식이에요.
	
즉, 누군가를 기다리는 동안 딴 일을 할 수 있습니다. 
비유 예시: 세탁기 돌려놓고, 설거지하고, TV도 보고!

### 비동기 프로그램의 대표적인 특징:

`1.` 응답성이 좋다
	사용자가 무언가 요청했을 때, 백엔드 서버가 느리게 반응하거나 멈추지 않아요.  
	시간이 오래 걸리는 작업이 있어도 다른 요청을 계속 처리할 수 있어요.
	
`2.` 확장하기 쉽다
	작업을 잘게 나눠서 따로따로 실행하니까, 나중에 작업을 더 추가해도  
	시스템이 무너지지 않고 유연하게 확장할 수 있어요.
	
`3.` 자원을 아낀다
	하나의 서버가 처리할 수 있는 일을 더 많이 하게 되니,  
	CPU나 메모리를 덜 쓰고도 더 많은 요청을 처리할 수 있어요.
	
`4.` 동시에 여러 작업 처리 가능
	한꺼번에 여러 작업을 실행해서 전체 처리 속도를 줄이고,  
	사용자 입장에서는 빠르게 응답 받는 느낌이 들어요.

### 비동기 방식이 특히 효과적인 작업들:
첫째, 파일 읽기/쓰기
- 예: CSV 파일이나 로그 파일을 읽거나 저장할 때
- 오래 걸리는 동안 다른 요청을 동시에 처리할 수 있어요.
    
둘째, 데이터베이스 작업
- DB에 저장하거나 조회하는 작업은 속도가 느릴 수 있으므로, 기다리는 동안 다른 작업을 처리할 수 있어요.
    
셋째, 예약된 작업(스케줄 작업)
- 주기적으로 돌아가는 작업(ex. 하루 한 번 이메일 보내기)도  
    메인 서버 흐름을 방해하지 않고 따로 처리할 수 있어요.
	
넷째, 원격 서버 작업
- 외부 API에 요청을 보내고 응답을 기다리는 경우,  
    다른 작업을 멈추지 않고 그 사이에 계속 진행할 수 있어요.
    
실험코드(비동기 vs 동기 비교)
```python
# async_demo.py

from fastapi import FastAPI
import time
import asyncio

app = FastAPI()

# 동기식 작업 함수
def sync_job(number: int):
    for i in range(1, number + 1):
        print(f"Job: #{number} | Task #{i}")
        time.sleep(1)  # blocking (다음 코드 실행 멈춤)
    print(f"> Job: #{number} Done!")

# 비동기식 작업 함수
async def async_job(number: int):
    for i in range(1, number + 1):
        print(f"Job: #{number} | Task #{i}")
        await asyncio.sleep(1)  # non-blocking (다른 작업과 병렬 실행 가능)
    print(f"> Job: #{number} Done!")

# 테스트 라우터
@app.get("/")
async def root():
    print("=" * 80)
    start = time.time()
    
    # 동기 작업 순차 실행 (총 약 6초 소요)
    sync_job(3)
    sync_job(2)
    sync_job(1)

    end = time.time()
    print(f">>> Processing time of sync_job: {end - start:.4f}초")
    print("=" * 80)

    print("=" * 80)
    start = time.time()
    
    # 비동기 작업 병렬 실행 (총 약 3초 소요)
    await asyncio.wait([
        asyncio.create_task(async_job(3)),
        asyncio.create_task(async_job(2)),
        asyncio.create_task(async_job(1)),
    ])

    end = time.time()
    print(f">>> Processing time of async_job: {end - start:.4f}초")
```

### 외부 API 여러 개를 동시에 조회하기

예를 들어 쇼핑몰이나 리뷰 서비스에서,
- 상품 정보 API
- 재고 정보 API
- 리뷰 요약 API
    
이렇게 3개를 각각 불러와서 한 화면에 보여줘야 한다고 가정해보겠습니다.

동기 방식이면 하나 끝나고 다음 것, 또 끝나고 다음 것을 불러오지만,  
비동기 방식이면 동시에 요청해서 전체 응답 시간을 줄일 수 있습니다.

`main5.py`
```python
# FastAPI 웹 프레임워크를 가져옵니다.
# FastAPI → API 서버를 생성하는 핵심 클래스
# HTTPException → API 실행 중 오류 발생 시 HTTP 상태코드와 메시지를 반환할 때 사용
from fastapi import FastAPI, HTTPException

# httpx는 Python에서 HTTP 요청을 보내는 라이브러리입니다.
# requests와 비슷하지만 비동기(async)를 지원하는 것이 특징입니다.
import httpx

# asyncio는 Python의 비동기 프로그래밍을 위한 표준 라이브러리입니다.
# 여러 비동기 작업을 동시에 실행할 때 사용합니다.
import asyncio


# FastAPI 애플리케이션 객체 생성
# 이 객체가 전체 API 서버의 시작점입니다.
app = FastAPI()


# ---------------------------------------------
# 비동기 외부 API 요청 함수
# ---------------------------------------------
# 외부 API 서버에 요청을 보내서 JSON 데이터를 받아오는 함수입니다.
# async 키워드를 사용했기 때문에 비동기 함수입니다.
async def fetch_json(client: httpx.AsyncClient, url: str) -> dict:

    # try-except를 사용하여 외부 API 호출 중 오류가 발생할 경우 처리합니다.
    try:

        # client.get()을 사용하여 외부 API 서버에 GET 요청을 보냅니다.
        # await 키워드는 비동기 작업이 끝날 때까지 기다리지만
        # 그 동안 다른 작업을 처리할 수 있도록 이벤트 루프에 제어권을 넘깁니다.
        response = await client.get(url, timeout=10.0)

        # HTTP 상태코드가 200번대가 아닐 경우 예외를 발생시킵니다.
        # 예: 404, 500 등의 오류 발생 시 자동으로 에러 처리
        response.raise_for_status()

        # API 응답을 JSON 형식으로 변환하여 반환합니다.
        return response.json()

    # httpx 요청 중 발생하는 모든 HTTP 관련 오류를 잡습니다.
    except httpx.HTTPError as e:

        # FastAPI의 HTTPException을 사용하여
        # 클라이언트에게 API 오류 메시지를 전달합니다.
        raise HTTPException(
            status_code=502,  # 외부 서버 오류 → 보통 502 Bad Gateway 사용
            detail=f"외부 API 호출 실패: {str(e)}"
        )


# ---------------------------------------------
# 대시보드 데이터 조회 API
# ---------------------------------------------
# 클라이언트가 /dashboard URL로 GET 요청을 보내면 실행됩니다.
@app.get("/dashboard")
async def get_dashboard():

    # 예시용 테스트 API 주소들입니다.
    # 실제 서비스에서는 아래처럼 여러 마이크로서비스 API를 호출할 수 있습니다.
    product_url = "https://jsonplaceholder.typicode.com/posts/1"
    stock_url = "https://jsonplaceholder.typicode.com/users/1"
    review_url = "https://jsonplaceholder.typicode.com/comments/1"

    # AsyncClient는 비동기 HTTP 요청을 보내기 위한 httpx 객체입니다.
    # async with를 사용하면 요청이 끝난 뒤 자동으로 연결을 정리합니다.
    async with httpx.AsyncClient() as client:

        # asyncio.gather()는 여러 비동기 작업을 동시에 실행하는 함수입니다.
        # 아래 세 개의 API 요청이 동시에 실행됩니다.
        product_data, stock_data, review_data = await asyncio.gather(

            # 상품 정보 API 요청
            fetch_json(client, product_url),

            # 재고 정보 API 요청
            fetch_json(client, stock_url),

            # 리뷰 정보 API 요청
            fetch_json(client, review_url),
        ) # 이 3개의 함수가 동시에 실행됩니다.

    # 세 개의 API 응답을 하나의 JSON 응답으로 합쳐서 반환합니다.
    # 실제 서비스에서는 이런 구조로 대시보드 데이터를 구성하는 경우가 많습니다.
    return {
        "product": product_data,  # 상품 정보
        "stock": stock_data,      # 재고 정보
        "review": review_data,    # 리뷰 정보
    }
```

uvicorn main5:app --reload

### 테스트 방법1: 시간으로 비동기 느낌 확인
현재 코드는 `asyncio.gather()`를 쓰고 있으므로 세 요청을 동시에 실행합니다.
비동기 테스트를 체감하려면 일부러 지연을 넣어보면 됩니다.

가장 테스트하기 좋은 위치는 HTTP 요청 직전에 넣는 것입니다.
```python
from fastapi import FastAPI, HTTPException
import httpx
import asyncio
import time  # 비동기 처리 시간을 측정하기 위해 추가한 라이브러리 (로그 확인용)

app = FastAPI()


async def fetch_json(client: httpx.AsyncClient, url: str) -> dict:

    start = time.time()  # 각 API 요청이 시작되는 시간을 기록하여 실행 시간을 로그로 확인하기 위한 코드

    try:
	    
	    # 비동기 확인을 위한 2초 대기
        await asyncio.sleep(2)

        response = await client.get(url, timeout=10.0)
        response.raise_for_status()

        print(url, "실행시간:", round(time.time() - start, 2), "초")  
        # 각 API 요청이 완료되었을 때 걸린 시간을 터미널에 출력하여
        # 여러 요청이 동시에 실행되었는지 확인하기 위한 비동기 테스트 로그

        return response.json()

    except httpx.HTTPError as e:
        raise HTTPException(
            status_code=502,
            detail=f"외부 API 호출 실패: {str(e)}"
        )


@app.get("/dashboard")
async def get_dashboard():

    total_start = time.time()  
    # 전체 요청이 시작되는 시간을 기록하여
    # 여러 비동기 작업이 동시에 처리되는지 확인하기 위한 로그 측정 코드

    product_url = "https://jsonplaceholder.typicode.com/posts/1"
    stock_url = "https://jsonplaceholder.typicode.com/users/1"
    review_url = "https://jsonplaceholder.typicode.com/comments/1"

    async with httpx.AsyncClient() as client:
        product_data, stock_data, review_data = await asyncio.gather(
            fetch_json(client, product_url),
            fetch_json(client, stock_url),
            fetch_json(client, review_url),
        )

    print("전체 요청 실행시간:", round(time.time() - total_start, 2), "초")
    # 모든 비동기 요청이 끝난 후 전체 처리 시간을 출력하여
    # 개별 요청 시간과 비교해 비동기 동시 실행 여부를 확인하기 위한 로그

    return {
        "product": product_data,
        "stock": stock_data,
        "review": review_data,
    }
```
이쪽에 지연코드를 넣는 이유는 
```
t=0초  
fetch_json(product)  
fetch_json(stock)  
fetch_json(review)
```
함수 호출로 인해 `await asyncio.sleep(2)` 지연코드가 실행이 되고 
```
product → 2초 대기  
stock → 2초 대기  
review → 2초 대기
```
이런 일이 벌어집니다. 하지만 동시에 대기합니다. 그래서 2초후 로그에 약간의 시간차이로 실행되는 결과를 확인할 수 있습니다.

### FastAPI 내부 API일 경우는 같은 FastAPI 서비스 안에서 여러 router / 파일로 나누어 만든 API일 수 있습니다.
```
fastapi_project
│
├ main.py
├ routers
│   ├ product_api.py
│   ├ stock_api.py
│   ├ review_api.py
│   └ recommend_api.py
```
이런 API를 FastAPI에서 서로 호출하거나 집계할 수 있습니다.

### 다른 서비스 API일 경우 (실무에서 더 흔함)
```
Client
   │
   ▼
FastAPI Gateway
   │
   ├ 상품 API (Product Service)
   ├ 재고 API (Inventory Service)
   ├ 리뷰 API (Review Service)
   └ 추천 API (AI Service)
```
이때 API들은 다른 서버일 수도 있습니다.

예
```
상품 API → Django DRF
재고 API → Node.js
리뷰 API → Django DRF
추천 API → FastAPI
```
FastAPI는 외부 API들을 모아서 하나의 응답으로 만들어주는 역할을 합니다.

이걸 보통
```
API Gateway  
Aggregation API
```
라고 합니다.

### DRF + FastAPI 구조에서 실제 많이 쓰는 패턴
```
Client
   │
   ▼
FastAPI
   │
   ├ DRF API 호출
   │
   ├ 상품 API (DRF)
   ├ 주문 API (DRF)
   ├ 리뷰 API (DRF)
   │
   └ 추천 API (FastAPI AI)
```
즉
```
DRF → 서비스 데이터  
FastAPI → AI / 집계 / 비동기
```
FastAPI가 DRF API를 호출하는 구조입니다.

### 전체 흐름

1️⃣ 클라이언트가 API 요청
```
GET /dashboard
```

2️⃣ FastAPI가 `get_dashboard()` 실행

3️⃣ 내부에서 외부 API 3개 준비
```
product API  
stock API  
review API
```

4️⃣ `asyncio.gather()`가 세 API를 동시에 실행
```
fetch_json(product)  
fetch_json(stock)  
fetch_json(review)
```

5️⃣ 응답이 모두 도착하면 하나의 JSON으로 합쳐서 반환
```
{  
  product: ...  
  stock: ...  
  review: ...  
}
```

---
### 핵심 비동기 포인트

1️⃣ async 함수
```
async def fetch_json(...)
```
비동기 함수입니다.

---
2️⃣ await
```
response = await client.get(url)
```
외부 API 응답을 기다리는 동안 서버는 다른 요청을 처리할 수 있습니다.

---
3️⃣ asyncio.gather()
```
await asyncio.gather(...)
```
여러 비동기 작업을 동시에 실행합니다.

동기 방식이라면
```
API1 → 끝  
API2 → 끝  
API3 → 끝
```

비동기 방식은
```
API1  
API2   동시에 실행  
API3
```
그래서 전체 응답 속도가 빨라집니다.

---
실무에서 여러 API를 동시에 호출하는 비동기가 사용되는 곳
이 구조는 실제 서비스에서 매우 많이 사용됩니다.

예를 들어
1️⃣ 쇼핑몰 대시보드
```
상품정보 API  
재고 API  
리뷰 API  
추천상품 API
```

2️⃣ 마이페이지
```
주문내역 API  
포인트 API  
알림 API  
쿠폰 API
```

3️⃣ AI 서비스
```
텍스트 분석 API  
추천 API  
유저 데이터 API
```
