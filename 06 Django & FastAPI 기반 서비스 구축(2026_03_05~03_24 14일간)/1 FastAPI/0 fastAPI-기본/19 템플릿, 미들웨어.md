### Jinja(진자)란?
Jinja(진자)는 파이썬에서 사용하는 HTML 템플릿 엔진입니다.
- HTML 안에 `{% ... %}`, `{{ ... }}` 같은 파이썬 코드나 변수를 넣어서 웹페이지를 자동으로 만들어주는 도구예요.
- 예: 장고(Django), 플라스크(Flask), FastAPI에서 HTML을 자동 생성할 때 사용됩니다.
	
쉽게 설명하면: 
Jinja = HTML 코드 속에 파이썬 변수를 껴 넣어서 웹페이지를 만들어주는 도구입니다.

###### Jinja2는 Django 템플릿과 거의 똑같은 역할을 하는 템플릿 엔진입니다.
|항목|Jinja2 (FastAPI, Flask 등)|Django 템플릿|
|---|---|---|
|사용 목적|HTML + 변수/제어문 섞어서 웹페이지 생성|동일|
|문법|`{{ 변수 }}`, `{% for %}`, `{% if %}`|거의 동일|
|장점|가볍고 빠름, 다양한 프레임워크에 사용됨|Django에 최적화됨|
|내장 함수|`range()`, `len()`, `default()` 등 다양|비슷하지만 Django는 자체 필터 많음|
|사용자 정의 필터|`@app.template_filter` 등으로 직접 추가 가능|Django도 `custom filter` 가능|

일반 HTML
```html
<h1>안녕하세요!</h1>
```
이건 항상 "안녕하세요!"만 출력돼요. 사용자 이름을 바꿀 수 없죠.

Jinja 템플릿 (파이썬 변수 삽입)
```html
<h1>안녕하세요, {{ username }}님!</h1>
```
그리고 Python에서 이렇게 보내줍니다.
```python
from fastapi import FastAPI, Request
from fastapi.templating import Jinja2Templates

app = FastAPI()

templates = Jinja2Templates(directory="templates")

@app.get("/hello")
def say_hello(request: Request):
    return templates.TemplateResponse("hello.html", {
        "request": request,
        "username": "Eunice"
    })
```
이 코드를 실행하면 "안녕하세요, Eunice님!" 이라고 실제로 HTML이 바뀌어 렌더링돼요.

필요한 패키지 설치 `uvicorn[standard]`
```bash
uv pip install fastapi jinja2 "uvicorn[standard]"
```
FastAPI는 자체 웹서버가 없기 때문에, 서버 실행을 위해 **uvicorn**이라는 ASGI 서버가 필요합니다.

```python
from fastapi.responses import HTMLResponse

app = FastAPI()

# 템플릿 디렉토리 설정
templates = Jinja2Templates(directory="templates")

@app.get("/", response_class=HTMLResponse)
def read_root(request: Request):

        "request": request,
        "username": "유정이"

@app.get("/users", response_class=HTMLResponse)
def show_users(request: Request):
    user_list = ["Alice", "Bob", "Charlie", "David"]
    return templates.TemplateResponse("users.html", {
        "request": request,
        "users": user_list
    })
```

### 미들웨어(Middleware)란?
	미들웨어는 요청과 응답 사이에서 중간 처리를 해주는 프로그램입니다.

웹사이트에 요청이 들어오면 보통 이런 순서로 동작합니다
```
사용자 → 서버 → View(API) → 응답 → 사용자
```
그런데 실제로는 그 사이에 중간에서 처리하는 단계가 하나 더 있습니다.
```
사용자 → 미들웨어 → View(API) → 미들웨어 → 사용자
```
이 중간에서 요청이나 응답을 검사하거나 수정하는 역할을 하는 것이 바로 미들웨어입니다.

쉽게 말하면  
	요청과 응답을 지나가는 검문소 같은 역할이라고 생각하시면 됩니다.

###### 미들웨어가 하는 일
| 기능     | 설명                           |
| ------ | ---------------------------- |
| 보안     | 로그인한 사용자인지 확인합니다             |
| 로깅     | 누가 언제 어떤 요청을 했는지 기록합니다       |
| 오류 처리  | 서버에서 에러가 발생하면 정리된 메시지를 보여줍니다 |
| CORS   | 다른 사이트에서 요청해도 되는지 확인합니다      |
| 데이터 압축 | 응답 데이터를 압축해서 빠르게 전송합니다       |
즉, 실제 기능(View)이 실행되기 전에 필요한 공통 작업을 처리하는 역할입니다.

```bash
mkdir -p mid/
touch mid/main.py
```

아래 코드는 요청이 처리되는 데 걸린 시간을 측정해서 응답 헤더에 추가하는 미들웨어입니다.
```python
# mid/main.py
import time
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

app = FastAPI()

# 미들웨어 구현
@app.middleware("http")
async def add_process_time_header(request: Request, call_next):
    start_time = time.time()  # 요청 시작 시간 기록
    response = await call_next(request)  # 실제 라우터 함수 실행
    process_time = time.time() - start_time  # 처리 시간 계산
    response.headers["X-Process-Time"] = str(process_time)  # 응답 헤더에 추가
    return response

# 테스트용 엔드포인트
@app.get("/ping")
async def ping():
    return {"message": "ping"}
```


사용자의 요청을 처리하는 데 서버가 얼마나 시간이 걸렸는지 계산해서 응답에 넣어주는 기능

```python
process_time = time.time() - start_time

```
즉 서버가 이렇게 말해주는 것입니다. 이 요청을 처리하는 데 서버에서 0.00041초가 걸렸습니다

왜 응답 헤더에 넣을까요?
이 값은 사용자에게 보여주기 위한 것이 아니라 개발자가 확인하기 위한 정보입니다.
즉 서버 성능을 확인하기 위한 용도입니다.

---
1️⃣ 서버 속도 확인

예를 들어 API가 너무 느릴 때
```
/users → 0.02초  
/products → 0.50초  
/reviews → 2.10초
```
이렇게 나오면 reviews API가 느리다는 것을 알 수 있습니다.

그래서 개발자는
- DB 쿼리를 줄이거나
- 캐시를 사용하거나
- 코드를 최적화합니다.

2️⃣ 서버 병목 찾기 : 예를 들어 평소에는 0.003초 였는데
```
0.003초 -> 1.2초
```
어느날 1.2초로 늘어나면 서버 내부에서 문제가 생겼다는 것을 알 수 있습니다.
예를 들면
- DB가 느림
- 외부 API 호출이 느림
- 코드 로직 문제

3️⃣ 모니터링 시스템과 연결
실제 서비스에서는 API 요청 처리 시간과 같은 성능 정보를 측정하여 모니터링 시스템에서 확인합니다.
- Prometheus : 서버의 성능 데이터를 수집하는 모니터링 시스템
- Grafana : 수집된 데이터를 그래프로 시각화하는 도구
- APM(NewRelic, Datadog) : 애플리케이션 성능을 분석하는 전문 모니터링 서비스
이러한 도구들은 API 처리 시간, 요청 수, 오류 발생 수 등 다양한 성능 지표를 수집하여 그래프로 보여주기 때문에, 개발자는 서버가 느려지는 문제나 성능 이슈를 쉽게 확인할 수 있습니다.

정리하면 미들웨어는 개발 중 API 처리 시간을 확인하기 위한 간단한 성능 체크용이고,  
Prometheus와 Grafana는 실제 서비스 운영 중 서버 성능을 지속적으로 모니터링하기 위한 시스템입니다.

### 미들웨어를 별도 파일로 분리한 구조

실제 FastAPI 프로젝트구조에서 미들웨어 코드 위치:
```
myproject/
├── mid/
│   ├── __init__.py
│   ├── main.py
│   ├── middleware/
│   │   ├── __init__.py
│   │   └── process_time.py
│   └── routes/
│       ├── __init__.py
│       └── ping.py
├── run.py
└── requirements.txt
```

```bash
mkdir -p mid/middleware mid/routes  
touch mid/__init__.py  
touch mid/middleware/__init__.py  
touch mid/routes/__init__.py  
touch mid/main.py  
touch mid/middleware/process_time.py  
touch mid/routes/ping.py  
touch run.py
```

`mid/middleware/process_time.py`
```python
import time
from fastapi import Request

async def add_process_time_header(request: Request, call_next):
    start_time = time.time()  # 요청 시작 시각 기록
    response = await call_next(request)  # 실제 라우터 함수 실행
    process_time = time.time() - start_time  # 처리 시간 계산
    response.headers["X-Process-Time"] = str(process_time)  # 응답 헤더에 추가
    return response
```

`mid/routes/ping.py`
```python
from fastapi import APIRouter

router = APIRouter()


@router.get("/")
async def root():
    return {"message": "Welcome to the API"}


@router.get("/ping")
async def ping():
    return {"message": "pong"}
```

`mid/main.py`
```python
from fastapi import FastAPI
from mid.middleware.process_time import add_process_time_header
from mid.routes.ping import router as ping_router

app = FastAPI()

# 미들웨어 등록
app.middleware("http")(add_process_time_header)

# 라우터 등록
app.include_router(ping_router)
```
- `app.middleware("http")` FastAPI 앱 객체(`app`)가 가지고 있는 메서드이며 데코레이터 방식으로 미들웨어를 등록하는 문법입니다.

- `include_router()`는 FastAPI가 제공하는 메서드로 `app = FastAPI()`에서 만든 app 객체의 메서드입니다.
	- FastAPI 앱에 `ping_router` 라우터를 등록한다는 뜻입니다.

`run.py`
```python
import uvicorn

if __name__ == "__main__":
    uvicorn.run("mid.main:app", host="127.0.0.1", port=8000, reload=True)
```

서버실행
```
python run.py
```

| 요청 메서드 | `GET` — 데이터 조회용 요청                                         |
| 상태 코드  | `200 OK` — 정상 응답                                           |
| 원격 주소  | `127.0.0.1:8000` — 로컬 서버                                   |
| 리퍼러 정책 | `strict-origin-when-cross-origin` — 크로스 도메인 요청 시 리퍼러 제어 정책 |
###### 2. 응답 헤더
| 키                | 값                               | 설명                           |
| ---------------- | ------------------------------- | ---------------------------- |
| `Content-Length` | 32                              | 응답 데이터 바이트 수                 |
| `Content-Type`   | `application/json`              | 응답 데이터가 JSON 형식임             |
| `Date`           | `Wed, 23 Jul 2025 19:19:08 GMT` | 응답한 시간 (UTC)                 |
| `Server`         | `uvicorn`                       | FastAPI 서버 백엔드가 `uvicorn`임   |

| 키                 | 값                                                                         | 설명                        |
| ----------------- | ------------------------------------------------------------------------- | ------------------------- |
| `Accept`          | `text/html,...`                                                           | 브라우저가 수용 가능한 응답 타입들       |

주요 포인트
- FastAPI 서버 정상 작동 중 (`200 OK`, `application/json`, `uvicorn`)
- `X-Process-Time` 헤더는 미들웨어가 응답 시간 측정에 성공했다는 의미
- 요청 헤더에는 브라우저 기본 정보와 함께 `cookie`에 세션/CSRF 토큰이 자동 포함됨
- 개발용 환경이기 때문에 `127.0.0.1`에서 테스트 중

---
헤더는 서버와 클라이언트 간의 약속입니다. 헤더는 택배 상자의 운송장이라고 앞전에 언급했습니다. 

- 택배 상자 안에는 우리가 보내고 싶은 데이터(body) 가 들어 있고,
- 바깥에는 운송장(header) 이 붙어 있어요.
    - 어디로 보내는지 (Host)
    - 누가 보냈는지 (Authorization)
    - 어떤 포장인지 (Content-Type)
    - 뭘로 받고 싶은지 (Accept)
        
> 즉, 서버가 그 요청을 올바르게 이해하고 처리하려면,  
> 운송장(헤더)을 꼭 붙여야 하는 거예요!

비유하자면 클라이언트(사용자)는 택배를 보내는 사람이고, 헤더는 운송장이며 미들웨어는 택배 창구 직원입니다.

사용자가 택배를 보내면, 창구 직원(미들웨어)이 운송장(헤더)을 보고:
- 주소가 잘 되었는지 확인하고
- 무게를 재서 처리 시간(`X-Process-Time`)을 붙이고
- 보안 검사도 하고
- 스티커(응답 헤더)를 하나 더 붙여서 서버에 전달하는 것!

우리가 연습한 코드는 FastAPI의 미들웨어 기능중 일부이며 응답 헤더에 처리 시간(`X-Process-Time`)을 기록하는 미들웨어를 테스트해본 것입니다.

그외에도 이런것들을 사용할수 있어요:
- `요청 전 검사` : IP 제한, 토큰 확인, 요청 헤더 검사 등
- `요청 처리 시간 측정` : time.time()으로 경과 시간 계산
- `응답 헤더 추가` : X-Process-Time, X-API-Version 등 삽입
- `로그 출력` : 요청/응답 정보를 로그로 기록
- `예외 처리` : 에러 응답 포맷 지정
- `CORS, GZip, 세션` : 기본 내장 미들웨어 (자동 등록 또는 설정 필요)

---
헤더 정보에 추가할 수 있는 주요 항목:
	
인증 관련
- `Authorization`: 인증 토큰 (예: `Bearer <token>`, `Basic ...`)
- `Cookie`: 세션 정보 포함
- `X-CSRFToken`: CSRF 보안 토큰 (주로 POST/PUT 등에서)
    
데이터 형식 관련
- `Content-Type`: 요청 본문의 타입 (예: `application/json`, `multipart/form-data`)
- `Accept`: 원하는 응답 타입 (예: `application/json`, `text/html`)
    
보안 및 출처 확인
- `Origin`: 요청이 발생한 출처 (CORS 정책에 사용)
- `Referer`: 사용자가 방금 전에 있던 페이지 주소
- `X-Requested-With`: Ajax 요청 여부 확인 (예: `XMLHttpRequest`)
    
클라이언트 정보
- `User-Agent`: 브라우저/앱 종류 및 버전
- `Host`: 요청 대상 서버 호스트 (예: `example.com`)
    
커스텀 헤더 (개발자 정의 가능)
- `X-API-Version`: API 버전 명시
- `X-App-Name`: 앱 이름 또는 클라이언트 종류 식별
- 기타 `X-` 접두사로 시작하는 자유 정의 헤더 가능
