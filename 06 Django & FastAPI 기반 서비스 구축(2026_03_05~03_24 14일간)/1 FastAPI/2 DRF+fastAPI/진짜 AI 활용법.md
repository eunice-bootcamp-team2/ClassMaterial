# 🔥 핵심 

AI를 잘 쓰는 게 아니라 서비스 흐름 안에 자연스럽게 녹이는 것이 핵심입니다

- ❌ 모델 성능 = 성공 ❌
- ✅ 데이터 + 로직 + UX + 아키텍처 = 성공

---

# 1️⃣ AI 적용의 3단계

## ① AI 없이도 돌아가는 구조 먼저 만들기

이게 80%입니다

예를 들어 현재 프로젝트 기준
```
리뷰 작성 → DB 저장 → 조회 → 추천 로직 (rule-based)
```
여기까지 완성해야 함

💡 이유  
AI는 보조 엔진이지 핵심 로직이 아님  
→ AI 없어도 서비스는 돌아가야 함

---

## ② AI는 특정 문제만 해결하게 넣는다

❌ 잘못된 방식
```
우리 서비스에 AI 넣자 → 뭐라도 하자
```

✅ 올바른 방식
```
문제 정의 → AI 필요 여부 판단 → 해당 기능만 AI 적용
```

현재구조

|기능|AI 필요 여부|
|---|---|
|리뷰 CRUD|❌|
|추천|✅|
|유사도 분석|✅|
|자동 태깅|✅|

AI는 특정 기능 하나 해결용으로 넣는다

---

## ③ AI를 API 서비스로 분리한다

```
Django (서비스)  
        ↓  
FastAPI (AI 서버)  
        ↓  
모델
```

이게 현업 표준 구조입니다  
AI는 마이크로서비스로 분리
마이크로서비스란 기능을 잘게 쪼개서 각각 독립적으로 운영하는 구조를 말합니다.

➡ 이유:
- 교체 가능 (모델 바꾸기 쉬움)
- 확장 가능
- 장애 분리

실제로 기업도 이렇게 함  
→ API / 이벤트 기반 구조 사용

---

# 2️⃣ 진짜 중요한 포인트

## ✔ 1. 모델보다 데이터가 더 중요

대부분 실패 이유
- 데이터 없으면 AI 의미 없음
- 더러운 데이터 → 결과 쓰레기

실제 문제:
- 데이터 불일치
- 최신성 없음
- 구조 안 맞음

AI 실패 80%는 데이터 문제

---

## ✔ 2. AI는 결과가 아니라 흐름에 연결해야 함

❌ 잘못된 구조
```
AI 결과 출력 → 끝
```

✅ 올바른 구조
```
AI 결과 → DB 저장 → 추천 → UI 반영 → 사용자 행동 변화
```
AI는 기능이 아니라 흐름이다

---

## ✔ 3. 무조건 비동기 처리 (Celery)

이거 안하면 서비스 망함

현재 프로젝트 구조의 예:
```
리뷰 등록 → Celery → AI 분석 → 결과 저장
```
현업 구조입니다.

---

## ✔ 4. 모니터링 필수

AI는 배포 후가 시작

봐야 할 것:
- 응답 시간
- 실패율
- 정확도
- 데이터 드리프트

👉AI는 계속 관리해야 함

---

## ✔ 5. 모델 교체 가능 구조 만들기
```
embedding_model = e5-small  
→ 나중에 변경 가능
```

👉 이 구조가 핵심
- 모델은 계속 바뀜
- 기술은 계속 바뀜

---

# 3️⃣ 현재 플랫폼 기준 정답 구조

```
[Frontend]  
    ↓  
[Django]  
    ↓  
[Celery]  
    ↓  
[FastAPI AI 서버]  
    ↓  
[모델 (HuggingFace)]
```

1. AI 결과 저장 테이블
```
ReviewAIResult  
- review_id  
- embedding  
- similarity_score  
- label
```
---
2. AI 결과 활용 로직
```
유사도 기반 추천  
비슷한 리뷰 묶기  
태그 자동 생성
```
---
3. fallback 로직
```
AI 실패 → rule-based 추천
```
안정성 핵심

---
4. 캐싱
```
이미 분석된 리뷰 → 다시 호출 안함
```

# 4️⃣ AI 잘 붙이는 사람 vs 못 붙이는 사람

❌ 못하는 사람
- 모델만 바꿈
- 정확도만 신경씀
- 서비스 흐름 없음
- 그냥 AI 넣었다 느낌

---
✅ 잘하는 사람
- 문제 정의부터 시작
- AI는 일부 기능만 담당
- API 구조로 분리
- 데이터 흐름 설계
- 운영까지 고려

핵심:  
AI 엔지니어가 아니라 서비스 설계자입니다.

---
# 5️⃣ AI 적용단계


1단계
✔ AI 붙이기

2단계
✔ AI 결과를 서비스에 활용
- 추천 시스템
- 사용자 행동 기반 개선

---
3단계
AI 운영
- drift 감지
- 재학습
- A/B 테스트

|개념|의미|
|---|---|
|파인튜닝|모델을 다시 학습시키는 것|
|drift 감지|모델 성능이 떨어지는지 감시|
|재학습|필요할 때 모델 다시 학습|
|A/B 테스트|어떤 모델이 더 좋은지 비교|
drift 감지란 
```
- 모델 정확도 변화  
- 입력 데이터 분포 변화  
- 결과 품질 변화
```
즉 AI 성능 모니터링입니다

---
4단계
멀티 AI 구조
- 추천 모델 + 감정 분석
- hybrid 시스템

Hybrid 시스템 = 여러 방식(AI + 규칙 등)을 섞어서 사용하는 구조

쉽게 비유하면
🎬 영화 추천
❌ AI만
비슷한 영화 추천  
→ 이상한 결과 나올 수도 있음

❌ 규칙만
인기순 추천  
→ 개인화 없음

✅ Hybrid
- 기본: 인기순
	- AI: 취향 반영
	- 필터: 장르 제한
