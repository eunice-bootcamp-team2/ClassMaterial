### 1️⃣ Nginx 보안 강화
Nginx는 사용자가 웹사이트에 접속할 때 가장 먼저 만나는 입구입니다.  
그래서 Django나 FastAPI까지 요청이 들어가기 전에, Nginx에서 1차로 걸러주면 불필요한 공격 요청을 많이 줄일 수 있습니다.

Nginx에서 이번에 보강할 것은 크게 3가지입니다.
```
1. 보안 헤더 추가 (브라우저 보호)  
2. 요청 제한 (DDOS / 봇 차단)  
3. 이상한 경로 차단 (해킹 시도 방어)
```

수정 위치
```
backend/nginx/nginx.conf
```
중요한 점은, 지금은 CI/CD가 연결된 상태이므로 서버에서 nano로 직접 수정하는 것이 아니라  
로컬 프로젝트의 nginx.conf를 수정한 뒤 GitHub에 push해서 반영하는 방식이 정석입니다.

① 보안 헤더 추가
보안 헤더는 브라우저에게 이 사이트는 이렇게 동작해야 한다고 알려주는 설정입니다.  
즉, 사용자가 사이트를 열었을 때 브라우저가 위험한 동작을 하지 않도록 도와주는 역할입니다.

|헤더|역할|
|---|---|
|X-Frame-Options|다른 사이트가 내 페이지를 iframe으로 감싸는 것을 막아 클릭재킹 공격을 줄입니다|
|X-Content-Type-Options|브라우저가 파일 타입을 멋대로 추측하지 못하게 하여 MIME 공격을 줄입니다|
|X-XSS-Protection|오래된 브라우저에서 XSS 공격 방어에 도움을 줍니다|
|Referrer-Policy|사용자가 다른 페이지로 이동할 때 referrer 정보가 과하게 노출되는 것을 줄입니다|
|Content-Security-Policy (CSP)|외부 스크립트 실행 범위를 제한하여 악성 스크립트 삽입 위험을 줄입니다|
쉽게 말하면:
- X-Frame-Options → 내 사이트 화면을 다른 사이트가 몰래 덮어씌우는 것 방지
- X-Content-Type-Options → 브라우저가 파일을 잘못 해석하지 않게 방지
- X-XSS-Protection → 스크립트 공격 일부 방어
- CSP → 어디서 온 스크립트만 허용할지 제한

즉, 보안 헤더는 사용자 브라우저 쪽 보안 규칙이라고 생각하시면 됩니다.

② Rate Limit (요청 제한) 봇/공격 차단 핵심
이 부분은 봇이나 자동 공격을 막는 데 중요합니다.

공격 봇은 보통 아주 짧은 시간에 같은 서버로 요청을 엄청 많이 보냅니다.  
예를 들어 로그인 페이지, 관리자 페이지, 존재하지 않는 취약한 경로를 계속 두드려봅니다.

그래서 Nginx에서 한 IP가 너무 빠르게 요청하면 제한하자는 규칙을 둘 수 있습니다.

http 블록에 추가
```nginx
http {
    # 요청 제한 설정
    limit_req_zone $binary_remote_addr zone=one:10m rate=5r/s;
```
의미:
- `$binary_remote_addr`  
    → 요청한 사람의 IP 주소 기준으로 제한하겠다는 뜻
- `zone=one:10m`  
    → 요청 기록을 저장할 메모리 공간 이름과 크기
- `rate=5r/s`  
    → 1초에 5번 정도만 정상 요청으로 허용

즉, 같은 IP가 1초에 5번을 넘어서 너무 빠르게 요청하면 제한하겠다는 뜻입니다.

server 또는 location 안에 적용
```nginx
location / {
    limit_req zone=one burst=10 nodelay;

    proxy_pass http://web:8000;
}
```
의미:
- `zone=one`  
    → 위에서 만든 제한 규칙 사용
- `burst=10`  
    → 순간적으로 몰리는 요청 10개 정도는 추가 허용
- `nodelay`  
    → 허용 범위를 넘는 요청은 기다리게 하지 않고 바로 제한

쉽게 말하면:
```
평소에는 초당 5개 허용  
잠깐 몰릴 때는 10개 정도 추가 허용  
그 이상은 차단
```
이 설정이 필요한 이유는,  
정상 사용자도 클릭을 빨리 하거나 페이지 리로드를 할 수 있기 때문에 무조건 딱 끊어버리면 불편합니다. 그래서 약간의 여유(`burst`)를 주는 것입니다.

위의 상황을 쉽게 비유해서 설명해 보겠습니다.
정상 사용자
```
페이지 들어감 (1번)  
상품 클릭 (2번)  
리뷰 보기 (3번)
```
1초에 많아야 2~3번 요청

그러나 공격 봇은 이렇게 행동합니다.
```
로그인 시도 100번  
관리자 페이지 접근 200번  
이상한 URL 계속 요청
```
1초에 수십~수백 번 요청하면 발생되는 문제는 서버 과부하와 해킹시도로 간주됩니다.

그래서 Nginx가 하는 일은 한사람당 속도를 제한을 하는 겁니다.
```
정상 사용자는 1초에 3번 클릭
조금 빠른 사용자는 1초에 8번 클릭
```

공격봇으로 간주되는 경우
```
1초에 50번 요청
```
그래서 사람이 너무 빠르게 요청하면 서버를 보호하기 위해 제한하는 것을 작성하는 부분입니다.

③ 공격 경로 차단
인터넷에 서버를 공개하면, 봇들이 자동으로 이런 경로들을 계속 요청합니다.
- `/wp-admin`
- `/phpunit`
- `/vendor/...`
- `/cgi-bin`
- `/.env`
- `.php` 파일들

그런데 우리 프로젝트는 Django/FastAPI 기반이라서 이런 PHP, WordPress, Tomcat, ThinkPHP 관련 경로는 원래 존재하지 않습니다.

즉, 이런 요청은 거의 대부분 정상 사용자가 아니라 자동 공격 시도입니다.  
그래서 Nginx에서 미리 차단하는 것이 좋습니다.
```
# PHP 공격 차단
location ~* \.php$ {
    return 444;
}

# 관리자/백업 경로 차단
location ~* /(wp-admin|phpunit|vendor|cgi-bin|backup|\.env) {
    return 444;
}

# 숨김 파일 차단 (.git 등)
location ~ /\. {
    deny all;
}
```

PHP 파일 차단
- `.php`로 끝나는 요청을 차단
- 우리는 PHP 서버가 아니므로 이런 요청은 거의 공격성 요청

자주 공격받는 경로 차단
- WordPress, phpunit, vendor, backup, 환경파일 등
- 공격 봇이 취약점 찾을 때 자주 두드리는 경로들

숨김 파일 차단
- `.git`, `.env`, `.htaccess` 같은 숨김 파일 접근 차단
- 이런 파일이 노출되면 큰 사고가 날 수 있음

`444`는 무엇인가?
- `404` → 없음
- `403` → 접근 금지
- `444` → Nginx가 응답을 주지 않고 바로 연결을 끊는 방식
즉, 공격 봇 입장에서는 서버가 어떻게 동작하는지 더 알기 어려워집니다.  
그래서 자동 공격 차단에 종종 사용합니다.

---
수정된 전체 nginx.conf
```nginx
# ================================
# 🔥 요청 제한 (Rate Limit) 설정
# ================================
# [추가] IP 기준 요청 제한 (5 req/sec)
limit_req_zone $binary_remote_addr zone=one:10m rate=5r/s;

server {
    listen 80;
    server_name _;

    client_max_body_size 20M;

    # ================================
    # 🔒 보안 헤더 추가
    # ================================
    # [추가] 클릭재킹 방지
    add_header X-Frame-Options "SAMEORIGIN";

    # [추가] MIME 타입 공격 방지
    add_header X-Content-Type-Options "nosniff";

    # [추가] XSS 방어
    add_header X-XSS-Protection "1; mode=block";

    # [추가] referrer 정책
    add_header Referrer-Policy "strict-origin-when-cross-origin";

    # [추가] CSP (Content Security Policy)
    add_header Content-Security-Policy "default-src 'self' 'unsafe-inline' 'unsafe-eval' data:;";

    # [추가] nginx 버전 숨김
    server_tokens off;

    # ================================
    # 🚫 공격 경로 차단
    # ================================

    # [추가] PHP 실행 차단 (우리는 Django라 필요 없음)
    location ~* \.php$ {
        return 444;
    }

    # [추가] 흔한 공격 경로 차단
    location ~* /(wp-admin|phpunit|vendor|cgi-bin|backup|\.env) {
        return 444;
    }

    # [추가] 숨김파일 (.git 등) 접근 차단
    location ~ /\. {
        deny all;
    }

    # ================================
    # 📁 static 파일
    # ================================
    location /static/ {
        alias /app/staticfiles/;
    }

    # ================================
    # 📁 media 파일
    # ================================
    location /media/ {
        alias /app/media/;
    }

    # ================================
    # 🤖 FastAPI 서버
    # ================================
    location /ai/ {
        proxy_pass http://fastapi-server:8001/;

        # [기존 유지]
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        # [추가] 요청 제한 적용
        limit_req zone=one burst=10 nodelay;
    }

    # ================================
    # 🌐 Django 서버
    # ================================
    location / {
        proxy_pass http://drf-web:8000;

        # [기존 유지]
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        # [추가] 요청 제한 적용
        limit_req zone=one burst=10 nodelay;
    }
}
```

그다음에 phsh하기
git push
```bash
git add backend/nginx/nginx.conf
git commit -m "feat: nginx security 강화"
git push origin main
```

##### 이제 두번째 버킷을 만듦니다
버킷을 두개 만드는 이유는 파일의 성격이 완전히 다르기 때문에 버킷을 분리하는 겁니다.

##### static vs media 차이 (핵심 이해)
static (정적인 파일)
```
CSS / JS / 기본 이미지
```
특징:
- 개발자가 만든 파일
- 배포할 때만 바뀜
- 사용자와 관계 없음
- 항상 동일
```
style.css  
app.js  
logo.png
```

media (동적인 파일)
```
media (동적인 파일)
```
특징:
- 계속 생성됨
- 삭제/수정됨
- 사용자마다 다름
- 서비스 데이터
```
리뷰 이미지  
상품 이미지  
프로필 사진
```

왜 분리해야 하냐 (진짜 이유)
① 보안 정책이 다르다
```
static은 100% 공개 가능

media는
👉 경우에 따라 다름  
- 공개 (상품 이미지)  
- 비공개 (개인 이미지)
```
한 버킷이면? 보안 설정이 꼬입니다.

② 삭제/유실 위험 분리
```
static은 삭제되면 → 다시 deploy하면 복구됨

media는 삭제되면 → 영구 손실 💀

같은 버킷이면: 실수로 날리면 둘 다 날아감
```

③ 캐싱 전략이 다름
```
static은 Cache: 1년 가능

media는 짧게 or 없음
```
이유:
- static → 변하지 않음
- media → 바뀔 수 있음

④ 배포와 완전히 분리
```
static은 deploy 때 업로드 (collectstatic)

media는 운영 중 계속 업로드됨
```

⑤ CDN 적용 전략 다름
나중에 CloudFront 붙이면:
- static → aggressively 캐싱
- media → 조건부 캐싱
👉 분리 안하면 설정 지옥됨

```python
from storages.backends.s3 import S3Storage
import os

class StaticStorage(S3Storage):
    bucket_name = os.getenv("AWS_STORAGE_BUCKET_NAME_STATIC")
    location = "static"
    default_acl = None
    querystring_auth = False

class MediaStorage(S3Storage):
    bucket_name = os.getenv("AWS_STORAGE_BUCKET_NAME_MEDIA")
    location = "media"
    default_acl = None
    querystring_auth = False
```

### HTTPS 적용하기

그 다음 Certbot으로 인증서 발급
EC2에서:
```bash
sudo apt update  
sudo apt install -y certbot python3-certbot-nginx  
sudo certbot --nginx -d product-review-youjung.duckdns.org
```
진행 중에:
- 이메일 입력
- 약관 동의 `Y`
- 리다이렉트 선택은 2번 선택

작업중 아래와 에러가 발생되면 에러를 수정하며 진행합니다.
```
nginx: [emerg] bind() to 0.0.0.0:80 failed (98: Address already in use)
............
```
즉 지금 구조는:
- Docker nginx 컨테이너가 80 사용 중
- certbot이 호스트 nginx를 띄우거나 재시작하려 함
- 포트 충돌 발생

만약 에러가 발생되었다면 nginx 컨테이너 잠깐 내리고 `standalone`으로 인증서 발급합니다.
```bash
cd ~/product_review_service/backend
docker compose -f docker-compose.prod.yml stop nginx
sudo certbot certonly --standalone -d product-review-youjung.duckdns.org
```

이제 다음 단계는 Nginx가 저 인증서를 사용해서 HTTPS로 서비스하도록 연결하는 것입니다.

이제 `nginx.conf` 또는 배포용 nginx 설정 파일에서 SSL 경로를 넣어야 합니다.

### 마지막으로 해야 할일

`1.` nginx 설정 파일에 HTTPS 서버 블록 추가
지금 nginx는 아마 80 포트 HTTP만 처리하고 있을 가능성이 큽니다.  
이제 nginx 설정에 아래 2개가 있어야 합니다.
- `80 → 443으로 리다이렉트`
- `443에서 ssl_certificate / ssl_certificate_key 사용`
```nginx
# ================================
# 🔥 요청 제한 (Rate Limit) 설정
# ================================
# [유지] IP 기준 요청 제한 (5 req/sec)
limit_req_zone $binary_remote_addr zone=one:10m rate=5r/s;


# ================================
# 🌐 HTTP → HTTPS 리다이렉트
# ================================
server {
    listen 80;
    # [수정] 기존 server_name _; → 실제 도메인으로 변경
    server_name product-review-youjung.duckdns.org;

    # [유지]
    client_max_body_size 20M;

    # [수정] HTTP 접속은 전부 HTTPS로 돌림
    location / {
        return 301 https://$host$request_uri;
    }
}


# ================================
# 🔐 HTTPS 서버
# ================================
server {
    # [추가] 443 ssl 설정
    listen 443 ssl;
    # [수정] 기존 _ 대신 실제 도메인
    server_name product-review-youjung.duckdns.org;

    # [유지]
    client_max_body_size 20M;

    # ================================
    # 📜 SSL 인증서 경로
    # ================================
    # [추가] certbot 발급 인증서 연결
    ssl_certificate /etc/letsencrypt/live/product-review-youjung.duckdns.org/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/product-review-youjung.duckdns.org/privkey.pem;

    # [추가] 기본적인 SSL 설정
    ssl_session_timeout 1d;
    ssl_session_cache shared:SSL:10m;
    ssl_session_tickets off;

    # [추가] TLS 버전 제한
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;

    # ================================
    # 🔒 보안 헤더 추가
    # ================================
    # [유지] 클릭재킹 방지
    add_header X-Frame-Options "SAMEORIGIN" always;

    # [유지] MIME 타입 공격 방지
    add_header X-Content-Type-Options "nosniff" always;

    # [유지] XSS 방어
    add_header X-XSS-Protection "1; mode=block" always;

    # [유지] referrer 정책
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # [유지] CSP에 jsDelivr CDN 허용 추가
    add_header Content-Security-Policy "default-src 'self' data:; script-src 'self' 'unsafe-inline' 'unsafe-eval' https://cdn.jsdelivr.net https://product-review-static.s3.amazonaws.com https://product-review-static.s3.ap-northeast-2.amazonaws.com; style-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net https://product-review-static.s3.amazonaws.com https://product-review-static.s3.ap-northeast-2.amazonaws.com; connect-src 'self' https://cdn.jsdelivr.net; img-src 'self' data: https://product-review-static.s3.amazonaws.com https://product-review-static.s3.ap-northeast-2.amazonaws.com https://product-review-media.s3.amazonaws.com https://product-review-media.s3.ap-northeast-2.amazonaws.com; font-src 'self' data: https://product-review-static.s3.amazonaws.com https://product-review-static.s3.ap-northeast-2.amazonaws.com;" always;

    # [추가] HTTPS 강제 알림 헤더
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # [유지] nginx 버전 숨김
    server_tokens off;

    # ================================
    # 🚫 공격 경로 차단
    # ================================
    # [유지] PHP 실행 차단
    location ~* \.php$ {
        return 444;
    }

    # [유지] 흔한 공격 경로 차단
    location ~* /(wp-admin|phpunit|vendor|cgi-bin|backup|\.env) {
        return 444;
    }

    # [유지] 숨김파일 접근 차단
    location ~ /\. {
        deny all;
    }

    # ================================
    # 📁 static 파일
    # ================================
    location /static/ {
        # [유지] 기존 alias 유지
        alias /app/staticfiles/;
    }

    # ================================
    # 📁 media 파일
    # ================================
    location /media/ {
        # [유지] 기존 alias 유지
        alias /app/media/;
    }

    # ================================
    # 🤖 FastAPI 서버
    # ================================
    location /ai/ {
        # [유지]
        proxy_pass http://fastapi-server:8001/;

        # [유지]
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        # [추가] Django/FastAPI가 HTTPS 원본 요청임을 알 수 있게 전달
        proxy_set_header X-Forwarded-Proto $scheme;

        # [유지]
        limit_req zone=one burst=10 nodelay;
    }

    # ================================
    # 🌐 Django 서버
    # ================================
    location / {
        # [유지]
        proxy_pass http://drf-web:8000;

        # [유지]
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        # [추가] Django가 https 요청으로 인식하도록 전달
        proxy_set_header X-Forwarded-Proto $scheme;

        # [유지]
        limit_req zone=one burst=10 nodelay;
    }
}
```
핵심 변경
- `80포트 server`는 HTTPS로 리다이렉트하도록 수정
- `443포트 server`를 새로 추가
- `ssl_certificate`, `ssl_certificate_key` 추가
- `proxy_set_header X-Forwarded-Proto $scheme;` 추가
- 기존 보안 헤더 / 요청 제한 / 공격 경로 차단은 유지

`2.`  `docker-compose.prod.yml`에 443과 인증서 마운트 확인
`backend/docker-compose.prod.yml`
```yml
# [수정] version은 최신 docker compose에서는 생략 가능
# version: "3.9"

services:
  db:
    image: ankane/pgvector:v0.5.1
    container_name: product_review_postgres
    restart: always
    environment:
      POSTGRES_DB: product_review_db
      POSTGRES_USER: product_review_user
      POSTGRES_PASSWORD: product_review_password
    volumes:
      - product_review_postgres_data:/var/lib/postgresql/data
    networks:
      - app-network

  redis:
    image: redis:7
    container_name: redis-server
    restart: always
    networks:
      - app-network

  web:
    build: .
    container_name: drf-web
    command: >
      sh -c "python manage.py migrate &&
             python manage.py collectstatic --noinput &&
             gunicorn mysite.wsgi:application --bind 0.0.0.0:8000"
    restart: always
    env_file:
      - .env
    depends_on:
      - db
      - redis
    volumes:
      - static_volume:/app/staticfiles
      - media_volume:/app/media
    expose:
      - "8000"
    networks:
      - app-network

  celery:
    build: .
    container_name: celery-worker
    command: celery -A mysite worker --loglevel=info --pool=solo
    restart: always
    env_file:
      - .env
    depends_on:
      - db
      - redis
      - web
      - fastapi
    networks:
      - app-network

  fastapi:
    build:
      context: ../ai-server
    container_name: fastapi-server
    command: uvicorn main:app --host 0.0.0.0 --port 8001
    restart: always
    expose:
      - "8001"
    networks:
      - app-network

  nginx:
    image: nginx:stable-alpine
    container_name: nginx-server
    restart: always
    depends_on:
      - web
      - fastapi
    ports:
      - "80:80"
      - "443:443"   # [추가] HTTPS 포트 오픈
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - /etc/letsencrypt:/etc/letsencrypt:ro   # [추가] 호스트 인증서를 컨테이너에 마운트
      - static_volume:/app/staticfiles
      - media_volume:/app/media
    networks:
      - app-network

volumes:
  product_review_postgres_data:
  static_volume:
  media_volume:

networks:
  app-network:
    driver: bridge
```
- `ports`에 **443:443** 추가
- `/etc/letsencrypt` 마운트 추가
- `version:` 은 지워도 됨

(1) `443:443` 추가
기존:
```
ports:  
  - "80:80"
```

수정:
```
ports:  
  - "80:80"  
  - "443:443"
```
이게 있어야 브라우저의 HTTPS 요청이 nginx 컨테이너까지 들어옵니다.

---
(2) `/etc/letsencrypt` 마운트 추가

기존:
```
volumes:  
  - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro  
  - static_volume:/app/staticfiles  
  - media_volume:/app/media
```

수정:
```
volumes:  
  - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro  
  - /etc/letsencrypt:/etc/letsencrypt:ro  
  - static_volume:/app/staticfiles  
  - media_volume:/app/media
```

이게 있어야 nginx 컨테이너가 아래 인증서를 읽을 수 있습니다.
```
/etc/letsencrypt/live/product-review-youjung.duckdns.org/fullchain.pem  
/etc/letsencrypt/live/product-review-youjung.duckdns.org/privkey.pem
```
---
(3) `version:` 은 지워도 됨
```
version: "3.9"
```
지워도 동작에는 문제 없습니다.
