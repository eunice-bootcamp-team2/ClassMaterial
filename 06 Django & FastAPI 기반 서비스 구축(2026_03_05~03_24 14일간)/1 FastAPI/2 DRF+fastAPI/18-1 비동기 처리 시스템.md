### Celery를 써야 하는 기준?
요청-응답 흐름에서 분리해야 할 정도로 무겁고, 백그라운드에서 관리해야 하는 작업이면 Celery를 씁니다.

요청 끝나도 계속 돌아야 하는 작업

### SNS / 커뮤니티 플랫폼의 상황에서
사례: 쇼핑몰 주문 처리
```
주문 요청  
→ 결제 승인 (동기)  
→ 응답 바로 반환  
  
그 이후:  
→ 이메일 발송  
→ 포인트 적립  
→ 재고 로그 저장
```

이건 요청 끝나도 계속 실행됨
```
→ Celery Task로 분리
```

### 실패 시 재시도가 필요한 작업
핵심 포인트 (Celery 사용하는 가장 큰 이유)
사례: 이메일 / 외부 API
```
문제:  
SMTP 서버 다운  
외부 API timeout
```
동기라면 → 그냥 실패

Celery라면
```
retry 3번  
실패 로그 기록  
나중에 재처리 가능
```

실제 회원가입 흐름
회원가입 + 이메일 인증: 어떤 사이트에 가입했다고 가정
- 회원가입 버튼 클릭 : 브라우저  → Django 서버로 요청
- Django에서 처리 → 유저 DB 저장, 이메일 인증 코드 생성 → 인증코드: 123456 (인증코드를 메일로 받음)
- Django는 직접 이메일을 보낼 수 없음 그래서 이렇게 합니다:
```
Django → SMTP 서버 → 사용자 이메일
```
실제 흐름
```
[내 서버 (Django)]  
   ↓  
[SMTP 서버 (Gmail, Naver 등)]  
   ↓  
[사용자 이메일 inbox]
```
이걸 실행하면 내부적으로 SMTP 서버에 접속해서 메일을 보내는 것

SMTP는 외부 서버라서 문제 생길 수 있음
```
- Gmail 서버 잠깐 다운  
- 네트워크 끊김  
- 응답 없음 (timeout)
```

동기로 처리하면?
```
회원가입  
→ 이메일 보내기 실패  
→ 그냥 끝
```
그러나 Celery 쓰면?
```
회원가입 성공  
→ 바로 응답  
→ 이메일은 뒤에서 계속 재시도
```
즉 SMTP = 이메일을 대신 보내주는 서버입니다.

### 작업 시간이 길고 서버를 점유할 때: 단순 async로도 가능하지만, 한계 있음
사례: AI / 추천 / 대량 처리
```
요청 하나가 5~10초
```

문제:
```
Celery worker로 분리
```

### 작업 상태를 관리해야 할 때: 이건 Celery 아니면 거의 불가능
사례: 영상 처리 / AI 분석
```
상태:  
PENDING  
STARTED  
SUCCESS  
FAILURE
```

사용자 화면:
```
"분석중입니다"  
→ 완료되면 결과 표시
```

### 작업이 독립적이고 분리 가능한 경우
요청과 강하게 묶여 있지 않음
사례:
- 알림 전송
- 로그 저장
- 추천 계산
- 통계 집계
특징
```
이거 없어도 서비스는 돌아감
```
Celery 적합

### ❌ Celery 쓰면 안 되는 경우
- 로그인
- 회원가입
- 결제 승인
- 댓글 작성
```
결과를 즉시 알아야 함
```

### Celery 써야 하는 경우
- AI 분석
- 이메일 발송
- 대량 데이터 처리
- 추천 시스템
- 크롤링
- 로그/통계 처리

### 판단 기준
```
1. 요청 안에서 끝나야 함?
   → YES → 동기 (끝)

   → NO ↓

2. 나중에 해도 됨?
   → YES ↓

3. 재시도 필요?
4. 상태 추적 필요?
5. 오래 걸림?

→ 하나라도 YES면 Celery
```

### 역할 분리
- views.py = 사용자가 요청하면 Celery 작업을 시작시키는 역할
- tasks.py = Celery가 실행할 실제 작업 로직을 작성하는 파일
- celery.py = Celery를 Django 프로젝트에 연결하고 동작하게 만드는 설정 파일
- settings.py = Celery와 Redis 연결 정보(주소 등)를 설정하는 파일
- Redis = Celery 작업을 저장하고 전달하는 대기열 시스템 (직접 설치해서 실행) 
	- 즉, 작업을 저장해두는 서버
- Celery Worker (실행) = Redis에서 작업을 가져와 `tasks.py`를 실행하는 프로세스

---
기능별로 Celery를 여러개 붙여야 하는 상황에서
```
Celery는 하나
tasks는 여러 개
```
즉 셀러리는 프로젝트당 1개만 만들면 됩니다.
이유는 Celery는 시스템(엔진)이기 때문입니다.
```
mysite/celery.py ← 딱 하나
```

tasks.py는 몇 개?
```
✔ 앱마다 만들어도 됨 (여러 개 가능)
```

```
apps/
 ├── users/
 │     └── tasks.py
 ├── reviews/
 │     └── tasks.py
 ├── payments/
 │     └── tasks.py
```

예를들어 기능에 셀러리를 여러개 붙여야 하는 상황일때
- 이메일 전송
- AI 분석
- 알림 발송
```
celery.py → 1개 (공통 설정)

tasks.py
→ send_email_task
→ analyze_ai_task
→ send_notification_task
```
이렇게 하나의 tasks.py에 여러개 넣어도 되고

또는
```
users/tasks.py  
ai/tasks.py  
notification/tasks.py
```
이렇게 앱별로 나눠도 됩니다.
