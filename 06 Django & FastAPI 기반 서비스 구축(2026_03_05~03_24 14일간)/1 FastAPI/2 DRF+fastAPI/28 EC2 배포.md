EC2와 S3, 그리고 엔지닉스(Nginx)를 조합한 배포 방식은 성능과 보안을 모두 잡을 수 있는 현업의 표준적인 아키텍처 중 하나입니다. 요청하신 각 서비스의 역할과 연결 방법, 그리고 핵심인 Nginx 설정 코드를 상세히 정리해 드립니다.

1. 서비스별 역할 및 배포 구조

이 구조에서 각 서비스는 다음과 같은 명확한 역할을 수행합니다.

- AWS EC2 (애플리케이션 서버): 실제 백엔드 로직(FastAPI, Django 등)이 돌아가는 "손과 발" 역할을 하는 가상 서버입니다.
- AWS S3 (정적 파일 저장소): 이미지, CSS, 자바스크립트 등 변하지 않는 정적 파일을 저장합니다. 서버의 하드디스크 대신 S3를 쓰면 EC2의 부하를 줄이고 파일 전송 속도를 높일 수 있습니다.
- Nginx (리버스 프록시 및 게이트웨이): 클라이언트의 요청을 가장 먼저 받는 "정문" 역할을 합니다. 보안(SSL), 부하 분산, 정적 파일 캐싱 등을 담당하며, 요청의 종류에 따라 EC2의 백엔드 앱으로 보낼지 S3로 보낼지 결정합니다.

2. 서비스 연결 및 배포 방식

배포는 크게 두 갈래로 진행됩니다.

1. 정적 파일: 개발 PC에서 S3로 직접 업로드합니다.
2. 백엔드 앱: EC2에 배포하고 Nginx를 통해 연결합니다.

--------------------------------------------------------------------------------

3. Nginx 설정 및 실제 코드 (Nginx Config)

보안을 강화하고 S3와 연결하기 위한 핵심 설정 파일 예시입니다. 보통 `/etc/nginx/sites-available/default` 또는 `/etc/nginx/nginx.conf` 경로의 파일을 수정합니다.

```
server {
    listen 80;
    server_name demo.local; # 실제 도메인이 있다면 해당 도메인 입력 [5]

    # 1. 보안 강화: 헤더 추가
    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-XSS-Protection "1; mode=block";
    add_header X-Content-Type-Options "nosniff";

    # 2. 백엔드 API 요청 전달 (EC2 내부의 앱)
    location /api/ {
        proxy_pass http://127.0.0.1:8000; # FastAPI/Django 포트 [6]
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # 3. 정적 파일 요청을 S3로 프록시 (또는 리다이렉트)
    location /static/ {
        # S3 버킷 주소로 연결하여 서버 부하 감소
        proxy_pass https://your-s3-bucket-name.s3.amazonaws.com/static/;
    }

    # 4. 모니터링을 위한 상태 페이지 (선택)
    location /metrics {
        stub_status on; # Nginx 기본 상태 노출
        allow 127.0.0.1; # 보안을 위해 로컬에서만 접근 허용 [7]
        deny all;
    }
}
```

4. 배포 시 시너지 효과 및 주의사항

- 보안 강화: Nginx를 앞단에 두면 백엔드 서버의 실제 IP를 숨길 수 있으며, 특정 경로(/metrics 등)에 대한 접근 제어가 가능해집니다.
- 모니터링 연동: 이 환경에서 Prometheus와 Grafana를 사용하면 더욱 강력해집니다.
    - **Node Exporter:** EC2의 CPU와 메모리 상태를 감시합니다.
    - **Nginx Exporter:** Nginx를 통과하는 요청 수(RPS)와 에러율을 시각화할 수 있습니다.
- **무중단 배포:** 쿠버네티스의 롤링 업데이트 방식처럼, Nginx의 설정을 변경하고 `nginx -s reload` 명령을 사용하면 서비스 중단 없이 설정을 반영할 수 있습니다.

5. 연결 확인 테스트

배포 후에는 다음 명령어로 서비스들이 잘 연결되었는지 확인해야 합니다.

- **Nginx 설정 확인:** `sudo nginx -t` (오타가 없는지 검사)
- **백엔드 연결 확인:** `curl http://localhost/api/healthz`
- **정적 파일 확인:** 브라우저에서 S3 경로의 이미지 등이 정상적으로 보이는지 체크합니다.
