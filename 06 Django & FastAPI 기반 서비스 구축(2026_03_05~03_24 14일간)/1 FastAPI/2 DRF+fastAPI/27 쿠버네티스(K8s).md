`1.` 쿠버네티스란 무엇인가?

쿠버네티스는 다수의 컨테이너를 효율적으로 배포, 확장 및 관리하기 위한 컨테이너 오케스트레이션(관리) 시스템입니다. 쉽게 비유하자면, 도커 컨테이너들을 지휘하는 '함대 사령관'이나 시스템 관리 로봇과 같습니다.

`2.` 일반 서버(또는 단순 도커)와 쿠버네티스의 차이

개발자들이 왜 일반 서버 대신 쿠버네티스를 선택하는지 그 차이점을 이해하는 것이 중요합니다.

- **명령 기반 vs 선언적 상태 관리:**
    - **일반 서버/도커:** 사용자가 직접 "컨테이너를 실행해라"라고 명령합니다. 만약 서버가 죽으면 사용자가 다시 켜야 합니다.
    - **쿠버네티스:** 사용자가 "이 앱이 항상 3개 떠 있어야 해"라고 **원하는 상태(Desired State)**를 선언합니다. 그러면 쿠버네티스가 실제 상태를 감시하다가, 앱이 죽으면 자동으로 새로 띄워 숫자를 맞춥니다.
- **자가 치유(Self-healing):** 서버나 컨테이너에 장애가 나면 쿠버네티스가 이를 감지하고 자동으로 복구하여 서비스 중단을 막습니다.
- **무중단 배포:** 서비스 중지 없이 새로운 버전의 앱을 조금씩 교체하는 **롤링 업데이트**가 가능합니다.

`3.` 쿠버네티스의 핵심 기초 개념 (오브젝트)

연습할 때 반드시 알아야 할 6가지 핵심 리소스입니다:

1. 파드(Pod): 쿠버네티스에서 실행되는 **가장 작은 단위**로, 하나 이상의 컨테이너가 들어있습니다.
2. 디플로이먼트(Deployment): 파드의 개수를 유지하고 업데이트(버전 관리)하며 자가 복구를 담당하는 관리자입니다.
3. 서비스(Service): 파드들이 죽고 살아나면서 바뀌는 IP 대신, **고정된 주소**를 부여하여 내부/외부에서 접근할 수 있게 해주는 창구입니다.
4. 인그레스(Ingress): 클러스터 외부에서 들어오는 요청을 도메인이나 경로에 따라 적절한 서비스로 연결해 주는 정문(Gateway) 역할입니다.
5. 컨피그맵(ConfigMap) & 시크릿(Secret): 설정값이나 비밀번호 같은 민감 정보를 이미지 밖에서 주입해 주는 저장소입니다.
6. HPA(Horizontal Pod Autoscaler): 부하가 많아지면 파드 개수를 자동으로 늘리고, 줄어들면 다시 줄이는 자동 확장기입니다.

`4.` 실제 현업에서 어떻게 활용되는가?
- 마이크로서비스 아키텍처(MSA): API 서버와 AI 서버처럼 서로 다른 요구사항을 가진 앱들을 독립적으로 배포하고 확장할 때 사용합니다.
- 안정적인 운영: 24시간 서비스가 중단되지 않아야 하는 환경에서 서버 장애 시 자동 복구 기능을 활용합니다.
- 효율적인 자원 관리: 서버의 CPU나 메모리 사용량에 맞춰 앱의 위치를 자동으로 배치(Scheduling)하여 자원 낭비를 줄입니다.

`5.` 초보자가 연습해봐야 할 단계별 로드맵

이론을 배웠다면 미니쿠베(minikube)를 활용해 로컬 환경에서 다음과 같이 실습해보는 것을 추천합니다:

- **레벨 0 (앱 배포):** Deployment를 통해 내 앱을 컨테이너로 띄워보고 `kubectl` 명령어로 상태를 확인합니다.
- **레벨 1 (네트워크 연결):** Service를 붙여 내부에서 고정된 주소로 통신이 되는지 확인합니다.
- **레벨 2 (통신 실습):** API 앱이 AI 앱을 호출하는 내부 통신 환경을 구축해 봅니다.
- **레벨 3 (외부 접속):** Ingress를 설정하고 로컬 도메인(예: `demo.local`)으로 브라우저에서 접속해 봅니다.
- **레벨 4 (오토스케일링):** 강제로 부하를 걸어 파드 개수가 자동으로 늘어나는 **HPA**를 경험해 봅니다.

**정리하자면:** 개발자가 쿠버네티스를 선택하는 이유는 **"잠든 사이에도 서버가 알아서 복구되고 확장되게 만들기 위해서"**입니다.

이제 이 쿠버네티스 환경 위에 이전에 배운 프로메테우스와 그라파나를 올려서 전체 시스템을 모니터링하는 통합 환경을 구축해 보고 싶으신가요?
