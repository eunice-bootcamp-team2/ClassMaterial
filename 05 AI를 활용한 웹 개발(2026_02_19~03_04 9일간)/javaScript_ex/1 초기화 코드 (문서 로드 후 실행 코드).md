DOM 생성 완료 대기
```js
document.addEventListener('DOMContentLoaded', function () {
// 코드  
});
```

jQuery
```js
$(document).ready(function() {  
// 코드  
});
```

축약형:
```js
$(function() {  
// 코드  
});
```

`DOMContentLoaded` 이벤트는 HTML 문서의 구조(DOM 트리)가 모두 만들어졌을 때 실행됩니다. 
- HTML 태그들을 브라우저가 전부 읽고
- DOM 객체 생성이 끝난 시점에 콜백 함수가 실행됩니다.

아직 이미지 / CSS / 외부 리소스 로딩이 끝나지 않아도 실행됩니다.

이렇게 감싸는 이유는 딱 하나입니다 DOM 요소가 존재한 뒤에 접근하기 위해서
예를 들어 이런 코드가 있다면:
```js
const button = document.getElementById('changeBtn');
```
만약 버튼 HTML이 아직 안 읽힌 상태라면:
```html
<button id="changeBtn">Click Me!</button>
```
JS가 먼저 실행되면 `button === null` 이 되어 버립니다.

그래서 안전하게:
✔ 문서 로딩 완료 후 실행  
✔ DOM 생성 완료 후 실행하도록 감싸는 것입니다.

# 변수선언방식

JavaScript에서 변수 선언 방식은 **3가지**가 핵심입니다.
```js
var  
let  
const
```


`var` – 옛날 방식 (지금은 거의 사용 안 함)
```js
var name = "Eunice";
```
✔ 함수 스코프(function scope)  
✔ 재선언 가능  
✔ 재할당 가능  
✔ 호이스팅 발생 (초보자 혼란 원인)


⚠ 문제점 (왜 잘 안 쓰냐면)
```js
var a = 10;  
var a = 20; // 에러 없음 😨
```
→ 같은 변수를 또 선언해도 오류가 안 남  
→ 대형 버그 발생 원인


스코프 특징
```js
if (true) {  
var x = 1;  
}  
console.log(x); // 1 😨 밖에서도 접근됨
```
👉 블록 `{}` 무시됨


`let` – 현대적인 기본 변수
```js
let count = 0;
```
✔ 블록 스코프(block scope)  
✔ 재선언 ❌ 불가  
✔ 재할당 ✅ 가능  
✔ 호이스팅 있지만 안전하게 동작


재선언 불가
```js
let a = 10;  
let a = 20; // ❌ 에러 발생 (좋은 동작)
```
👉 실수 방지


블록 스코프
```js
if (true) {  
let x = 1;  
}  
console.log(x); // ❌ 에러 (정상)
```
👉 블록 밖 접근 불가 → 안전


재할당 가능
```js
let a = 10;  
a = 20; // 가능
```
👉 값 변경 필요할 때 사용


`const` – 변경 불가 변수 (가장 많이 사용)
```js
const API_URL = "http://localhost:8000";
```
✔ 블록 스코프  
✔ 재선언 ❌ 불가  
✔ 재할당 ❌ 불가  
✔ 반드시 초기값 필요

재할당 불가
```js
const a = 10;  
a = 20; // ❌ 에러
```
👉 값 보호

초기값 필수
```js
const a; // ❌ 에러
```

많이 오해하는 부분 (중요)
```js
const user = { name: "Eunice" };  
user.name = "Lee"; // ✅ 가능
```
왜 가능?
👉 const는 객체 자체 재할당만 금지  
👉 내부 값 변경은 허용

이렇게 변수 자체를 변경하는것은 금지입니다.
```js
const user = { name: "Eunice" };  
user = { name: "lee" }; // ❌ 에러 발생
```

# 선택자(selector)
	HTML 요소를 "집어서 지정하는 규칙

JavaScript / CSS 모두 동일 개념을 사용합니다.

예:
- 버튼 하나만 찾고 싶다
- 특정 div만 찾고 싶다
- 모든 p 태그 찾고 싶다
    
이때 선택자를 사용합니다.

### querySelector – 현대적인 표준 방식 (가장 중요)

1️⃣ ID 선택자 (가장 정확 / 하나만 존재)
```html
<div id="title">Hello</div>
```

CSS 선택자:
```css
#title
```

JS 선택자:
```js
document.querySelector("#title")
```

✔ 페이지에서 유일해야 함 (중복 금지)  
✔ 가장 강력하고 정확  
✔ 딱 하나 요소 지정
비유: 주민등록번호

2️⃣ 클래스 선택자 (여러 개 가능 / 가장 많이 사용)

HTML:
```html
<div class="card">A</div>  
<div class="card">B</div>
```

CSS 선택자:
```css
.card
```

js 선택자:
```js
document.querySelector(".card")  
document.querySelectorAll(".card")
```
✔ 여러 요소에 사용 가능  
✔ 재사용 목적  
✔ UI 스타일링 핵심
비유: 그룹 이름 / 소속

태그 선택자 (HTML 타입 기준)
HTML:
```html
p  
div  
button  
span
```

CSS 선택자:
```css
p  
button  
div
```

js 선택자:
```js
document.querySelector("button")  
document.querySelectorAll("p")
```
✔ 해당 태그 전부 선택  
✔ 가장 넓은 범위  
✔ 세밀 제어 어려움
비유: 직업 분류 (모든 의사 / 모든 학생)

---
### getElementById – 가장 오래된 기본 방식

```html
<div id="title">Hello</div>
```

JavaScript:
```js
const el = document.getElementById("title");
```

##### 🔥 매우 중요한 규칙
기호(#)를 쓰지 않습니다
```js
document.getElementById("title") // ✅ 맞음  
document.getElementById("#title") // ❌ 틀림
```
이유는 함수 이름 자체가 이미 "ID 찾기"이기 때문입니다

getElementsByClassName / TagName (참고용)
```js
document.getElementsByClassName("card")  
document.getElementsByTagName("div")
```
✔ 여러 개 반환  
✔ HTMLCollection 반환  
✔ 요즘은 querySelectorAll이 대체

### jQuery 선택자 설명 (중요)
	jQuery는 내부적으로 CSS 선택자 기반입니다.

```html
<div id="title">Hello</div>  
<div class="card">A</div>
```

jQuery:
```js
$("#title") // ID 선택  
$(".card") // 클래스 선택  
$("div") // 태그 선택
```

### jQuery vs 순수 JS 비교 (직관적 이해)

ID 선택:
```js
document.getElementById("title")  
document.querySelector("#title")  
$("#title")
```

클래스 선택:
```js
document.querySelectorAll(".card")  
$(".card")
```

태그 선택:
```js
document.querySelectorAll("div")  
$("div")
```

# 이벤트(Event)
	사용자 행동(클릭, 입력, 스크롤 등)에 반응하는 메커니즘

- 버튼 클릭
- 키보드 입력
- 마우스 이동
- 페이지 로딩 완료
    
이런 순간을 감지해서 특정 코드를 실행하는 것이 이벤트 처리입니다.

1️⃣ 순수 JavaScript 이벤트 문법 (현대 표준)
```js
element.addEventListener("이벤트종류", 실행할함수);
```

✅ 클릭 이벤트 (가장 많이 사용)
```js
<script>
    const btn = document.querySelector("#saveBtn");  
  
    btn.addEventListener("click", function () {  
        console.log("버튼 클릭됨");  
    });    
</script> 
```
✔ click 발생 시 함수 실행

함수 분리 방식 (실무 추천)
```js
<script>
function onSaveClick() {  
console.log("저장 버튼 눌림");  
}  
  
btn.addEventListener("click", onSaveClick);
</script> 
```
✔ 가독성 / 재사용성 증가

✅ input 이벤트
```js
$("#username").on("input", function () {
    console.log($(this).val());
});
```


✅ submit 이벤트
```js
$("#myForm").on("submit", function (e) {
    e.preventDefault();
});
```


✅ JS vs jQuery 이벤트 비교 (중요)
클릭 이벤트
```js
// 순수 JS  
btn.addEventListener("click", handler);  
  
// jQuery  
$("#btn").on("click", handler);
```

값 읽기 차이
```js
// JS  
event.target.value  
  
// jQuery  
$(this).val()
```


실무에서 매우 중요한 패턴
⭐ 이벤트 핸들러 분리 (가독성 핵심)

❌ 나쁜 예
```js
btn.addEventListener("click", function () {
    fetch(...)
    render(...)
    alert(...)
});
```

✅ 좋은 예
```js
btn.addEventListener("click", onSaveClick);

function onSaveClick() {
    saveData();
}
```

이벤트 위임 (Dynamic UI에서 필수)

동적으로 생성된 요소 대응:
```js
document.addEventListener("click", function (e) {
    if (e.target.matches(".deleteBtn")) {
        console.log("삭제 버튼 클릭");
    }
});
```
👉 나중에 만들어진 버튼도 동작함

jQuery 버전:
```js
$(document).on("click", ".deleteBtn", function () {
    console.log("삭제");
});
```


✅ 가장 많이 쓰는 이벤트 TOP 5 (실무 기준)
⭐ click  
⭐ input  
⭐ change  
⭐ submit  
⭐ DOMContentLoaded
