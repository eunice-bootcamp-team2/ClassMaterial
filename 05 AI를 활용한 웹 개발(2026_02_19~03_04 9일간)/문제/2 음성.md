### 문제 3) 음성: STT(음성→텍스트) + 후처리 API (Sync / Redis / Async)

허깅페이스 모델링크:
https://huggingface.co/openai/whisper-small
- 파이프라인: `automatic-speech-recognition`
- 한국어 포함 다국어 STT 지원
- 실습 목적(10초 Sync / 30초~ Async)에 적합

목표
허깅페이스 ASR(음성 인식) 모델로 아래 3가지를 직접 비교한다.
1. 동기(Sync): 짧은 음성(10초 이하) 업로드 즉시 STT
2. 비동기(Async + Celery): 긴 음성(30초 이상) STT를 작업 큐로 처리하고 상태 조회
3. Redis 적용: chunk 단위 캐시 또는 job progress(진행률) 저장으로 안정성/UX 비교

위 모델로 구현할 수 있는 주제들
- 음성 메모 자동 텍스트 변환 API
- 강의/회의 녹음 STT 처리 API (긴 파일은 async로)
- 콜센터 녹취 STT + 간단 후처리(문장 정리/공백 정리) API

0️⃣ 고정 엔드포인트 (문서 전체에서 이 3개만 사용)
1. Sync 동기
- `POST /api/speech/sync/transcribe/` (wav/mp3 업로드)
    
2. Async 비동기
- `POST /api/speech/async/transcribe/` (wav/mp3 업로드) → job_id 반환
    
3. Job 상태 조회
- `GET /api/speech/jobs/<job_id>/`

### 작업 순서

STEP 1) 모델만 단독 실행 (Django/DRF 코드 작성 금지)
- 위치: `speech/hf_model.py`
- 해야 할 일:
    - `pipeline("automatic-speech-recognition", model=MODEL_ID)` 전역 1회 로딩
    - `transcribe(audio_path_or_file)` 함수로 감싸기
- 성공 기준:
    - 파이썬에서 `transcribe("test.wav")` 실행하면 텍스트가 나온다.
        
---
STEP 2) Sync API 구현 (캐시/셀러리 없음)
- 위치
    - `speech/serializers.py` : 업로드 파일 검증 (`audio` 필수, 확장자 제한 wav/mp3)
    - `speech/views/api_sync.py` : APIView post
    - `speech/urls/api_sync.py` : URL 연결
    - `mysite/urls.py` : speech url include
        
✅ Sync API 동기
POST `/api/speech/sync/transcribe/`
Body: `multipart/form-data`
- key: `audio` (file: wav/mp3)
    
Response (200) 예시:
```json
{
  "model_id": "openai/whisper-small",
  "text": "인식된 텍스트",
  "latency_ms": 1234,
  "cached": false
}
```

성공 기준:
- Insomnia로 호출 시 200 OK
- text 문자열이 옴
- latency_ms 숫자가 옴
- cached는 일단 false로 고정
    
---
STEP 3) Redis 적용 (진행률 또는 중복 방지 중 1개 이상)
- 위치: `speech/services.py`
    
✅ 선택지 A) progress 저장(권장: 초보자에게 직관적)
- Redis Key: `speech:job:<job_id>:progress`
- 값: 0~100 (정수)
- TTL: 1시간(예: 3600초)
    
Async 작업이 진행될 때:
- 0 → 10 → 50 → 100 처럼 업데이트
    
✅ 선택지 B) 동일 파일 중복 방지(해시 기반)
- 업로드 파일 bytes → sha256
- Redis Key: `speech:audio:<sha256>`
- 값: text 결과
- TTL: 600초(10분)
    
성공 기준(둘 중 1개만 만족해도 OK):
- A: job 조회 시 progress(0~100)가 보인다
- B: 같은 파일 재요청 시 cached=true 또는 즉시 결과 반환
    
---
STEP 4) Async API 추가 (Celery enqueue + Job 조회)
- 위치
    - `speech/models.py` : Job 저장 모델 (status, result_text, created_at 등)
    - `speech/tasks.py` : Celery task (STT 실행 + progress 업데이트)
    - `speech/views/api_async.py` : enqueue + status
    - `speech/urls/api_async.py` : URL 연결

✅ Async 비동기 스펙
**POST** `/api/speech/async/transcribe/`
Body: `multipart/form-data`
- key: `audio` (file)

Response (202):
```json
{"job_id": 15, "status": "QUEUED"}
```

✅ Job 조회 스펙
**GET** `/api/speech/jobs/<job_id>/`
Response (200) 예시:
```json
{
  "job_id": 15,
  "status": "SUCCESS",
  "progress": 100,
  "result_text": "인식된 텍스트"
}
```

성공 기준:
- enqueue 시 202 + job_id
- worker 실행 후 job 조회하면 status가 SUCCESS로 바뀌고 result_text가 나온다
- (progress 선택지 A를 했다면) progress가 0~100으로 변한다
    
---
URL 라우팅

speech/urls/api_sync.py
- `/api/speech/sync/transcribe/` 만 담당
    
speech/urls/api_async.py
