### 문제 2) 컴퓨터비전: 이미지 분류 API (Sync / Redis Cache / Async)

허깅페이스 모델링크:
https://huggingface.co/google/vit-base-patch16-224
image-classification 파이프라인으로 바로 사용 가능하며(초보자 실습에 적합), 업로드 이미지를 즉시 분류하는 Sync/Async/Cache 비교 실습에 맞습니다. (문제 2 목표/요구사항 취지에 맞게 CV 분류 모델로 고정)


목표
허깅페이스 CV 모델(이미지 분류)을 사용해 아래 3가지를 직접 비교한다.
1. 동기(Sync): 이미지 업로드 즉시 추론했을 때
2. 비동기(Async + Celery): 작업을 큐에 넣고 결과를 Job 조회로 받았을 때
3. Redis 캐시 적용 전/후: 동일 이미지 재요청(중복)을 막았을 때 성능/UX 차이
    

위 모델로 구현할 수 있는 주제들 (예시)
1. 상품 이미지 자동 태깅/분류 API (의류/가방/전자제품 등)
2. 반려동물 사진 분류 API (동물/품종/카테고리 분류)
3. 중복 이미지 업로드 방지 시스템 (같은 이미지 반복 업로드 차단)

0️⃣ 고정 엔드포인트 (문서 전체에서 이 3개만 사용)
문제 1과 동일하게, 아래 3개만 고정 사용합니다. (중간에 섞이면 404/혼란 발생)

컴퓨터 비전
1. Sync 동기
- `POST /api/cv/sync/predict/` (multipart/form-data)
    
2. Async 비동기
- `POST /api/cv/async/predict/` (multipart/form-data) → job_id 반환
    
3. Job 상태 조회
- `GET /api/cv/jobs/<job_id>/`

### 작업 순서

STEP 1) 모델만 단독 실행 (Django/DRF 코드 작성 금지)
- 위치: `cv/hf_model.py`
    
- 해야 할 일:
    - `pipeline("image-classification", model=MODEL_ID)` 전역 1회 로딩
    - `predict_image(img)` 같은 함수로 감싸기 (`PIL.Image` 입력 → 결과(list/dict) 반환)
        
- 성공 기준:
    - 파이썬에서 `predict_image(Image.open("아무이미지.jpg"))` 실행하면
    - `[{ "label": "...", "score": ...}, ...]` 형태 결과가 나온다.
        
---
STEP 2) Sync API 구현 (캐시/셀러리 없음)
- 위치
    - `cv/serializers.py` : 이미지 업로드 검증 (`image` 필수)
    - `cv/views/api_sync.py` : APIView post 구현
    - `cv/urls/api_sync.py` : URL 연결
    - `mysite/urls.py` : cv url include
        
✅ Sync API 동기
POST `/api/cv/sync/predict/`
Body: `multipart/form-data`
- key: `image` (file)
    
Response (200) 예시:
```json
{
  "model_id": "google/vit-base-patch16-224",
  "top1": {"label": "tabby", "score": 0.97},
  "all": [{"label": "tabby", "score": 0.97}],
  "latency_ms": 123,
  "cached": false
}
```

성공 기준:
- Insomnia로 호출 시 200 OK
- `top1`(label/score)이 존재
- `latency_ms` 숫자가 옴
- cached는 일단 false로 고정
    
---
STEP 3) Redis 캐시 추가 (동일 이미지 중복 방지)
- 위치: `cv/services.py`
    
캐시 규칙
- 이미지 bytes로 `sha256` 해시 생성
- Redis Key: `cv:predict:<sha256(image_bytes)>`
- TTL: 600초(10분)
- 저장값: top1 결과(JSON 문자열 또는 dict 직렬화)
    
Sync 요청 흐름:
1. 업로드 파일 bytes → sha256 계산
2. Redis 조회 → 있으면 바로 반환(cached=true)
3. 없으면 모델 추론 → Redis 저장 → 반환(cached=false)
    
Response 예시:
```json
{
  "model_id": "google/vit-base-patch16-224",
  "top1": {"label": "tabby", "score": 0.97},
  "latency_ms": 4,
  "cached": true
}
```

성공 기준:
- 같은 이미지를 2번 업로드
    - 1회차 cached=false
    - 2회차 cached=true
    - latency_ms가 확 줄어듦
        
---
STEP 4) Async API 추가 (Celery enqueue + Job 조회)
- 위치
    - `cv/models.py` : Job 저장 모델
    - `cv/tasks.py` : Celery task
    - `cv/views/api_async.py` : enqueue + status
    - `cv/urls/api_async.py` : URL 연결
        
✅ Async 비동기 스펙
POST `/api/cv/async/predict/`
Body: `multipart/form-data`
- key: `image` (file)
    
Response (202):
```json
{"job_id": 15, "status": "QUEUED"}
```

✅ Job 조회 스펙
GET `/api/cv/jobs/<job_id>/`

Response (200) 예시:
```json
{
  "job_id": 15,
  "status": "SUCCESS",
  "result": {
    "model_id": "google/vit-base-patch16-224",
    "top1": {"label": "tabby", "score": 0.97}
  },
  "cached": false
}
```

> 여기서 cached는 최종 결과를 만들 때 캐시를 사용했는가?인데, 초보자용 실습에서는 우선 false로 두고 나중에 확장해도 됩니다.

성공 기준:
- enqueue 시 202 + job_id
- worker 실행 후 job 조회하면 status가 SUCCESS로 바뀌고 result(top1)가 나온다
