02번에서 한 일:
✔ 과거 패턴 관찰  
✔ 언제 이상 거래가 많았는지 확인

그러면 자연스럽게 등장하는 질문:
> “이 패턴이 미래에도 유지될까?”

정상성 검정이란 시계열 데이터의 통계적 성질(평균, 분산 등)이 시간에 따라 안정적인지 확인하는 과정입니다.

정상성 검정이 답하려는 질문은 이 데이터의 성질이 안정적인가? 입니다.

즉, 
- 평균이 계속 변하는가?
- 패턴이 계속 바뀌는가?
- 과거를 기준으로 미래를 예측해도 되는가?

그래서 03 정상성 검정에서 하고싶은 일은 이상 거래 시계열이 예측 가능한 구조인지 검사하는 것입니다. 정상성 검정을 수행할 때는 통계의 기본 규칙을 따릅니다.

통계 검정은 항상 두 가지 가정을 세워놓고 시작합니다.

✅ 귀무가설 (H₀) — 기본 가정
	먼저 이렇게 가정하고 시작합니다:
		- ❌ 이 시계열 데이터는 안정적이지 않다  
		- ❌ 시간에 따라 성질이 변하는 데이터이다

즉, 원래 문제 있는 데이터라고 가정하고 시작합니다.
이것이 통계 검정의 기본 방식입니다.
왜냐하면 통계는 보수적으로 판단하기 때문입니다.

✅ 대립가설 (H₁) — 우리가 확인하고 싶은 상태
	우리가 기대하는 이상적인 상태는 이것입니다:
		- ⭕ 이 시계열 데이터는 안정적이다  
		- ⭕ 시간에 따라 성질이 크게 변하지 않는다

즉, 정상적인 데이터일 가능성을 의미합니다.

그러면 정상성 검정의 목표는 무엇인가?
	귀무가설(비정상 데이터 가정)을 기각할 수 있는지 판단하는 것입니다.

✔ 귀무가설을 기각할 수 있다  
	→ 데이터가 안정적일 가능성 높음  
	→ 정상성 인정 가능  
	→ 예측 모델 적용 가능

✔ 귀무가설을 기각하지 못한다  
	→ 데이터가 불안정할 가능성  
	→ 비정상 데이터로 판단  
	→ 차분 등 추가 변환 필요

2️⃣ 정상성 검정을 위한 시계열 선택 (핵심 단계)

왜 이체방식 AT만 다시 필터링할까요? (중요 포인트)
이미 p1에는 날짜별 이상 거래 건수가 계산되어 있습니다.  
하지만 p1 데이터에는 여러 이체방식이 함께 포함되어 있습니다.

정상성 검정(ADF 테스트)은 하나의 시계열 데이터에 대해서만 수행할 수 있습니다.
따라서 특정 이체방식 하나만 선택하여 단일 시계열을 만드는 과정이 필요합니다.

단일 시계열을 만드는 과정
```python
cond1 = (p1['이체방식'] =='AT') 
p2 = p1.loc[cond1]

`cond1` : AT인 행 위치 표시표 (True / False)
- True → AT 맞음  
- False → AT 아님

그래서 AT 하나만 선택 → 단일 시계열 생성한것입니다.

✔ p1 → 여러 방식 섞인 집계표  
✔ p2 → 하나의 방식만 분리한 시계열  
✔ 목적 → 정상성 검정 준비

0.05보다 훨씬 작음
판단 규칙: 통계에서 사용하는 의사결정 기준
- p-value < 0.05 → 귀무가설 기각 
	이정도로 작으면 우연이라고 보기 어렵다는 뜻입니다. 즉 합의된 기준값입니다.
	그러면 왜 하필 0.05냐면 역사적 실무적 관례라고 생각하면 됩니다.
	통계학의 기준에서는 5%보다 작으면 우연이라고 보기 어렵다고 판단합니다
	동전던지기에서 앞면이 100번 연속 나올 확율이 거의 0에 가깝기에 우연 가능성을 5%로 이하로 제안하는 안전선을 만든것이며 `p-value < 0.05` 이건 그냥 우연이라고 보기엔 너무 드문 결과라고 가정을 세운 기준입니다.
- 귀무가설 → 비정상 데이터

따라서 비정상 가설 기각 성공

정상성 검정을 왜 하는가? (관제 시점)
정상성 검정은 복잡한 통계가 아니라 센서 흐름이 평소 상태와 같은지 확인하는 검사입니다.
지금 센서 움직임이 평소와 비슷한가?

센서 데이터는 항상 변동합니다.
예:
- 온도 센서
- CO 센서
- 진동 센서
- 전력 센서
    
문제는 이것입니다:
- 변동이 정상적인 흔들림인가?  
- 아니면 상태 변화인가?

귀무가설 (H₀) — 기본 상태 가정

관제 시스템의 기본 가정:
✔ 현재 센서 데이터는 정상 상태다  
✔ 시스템 환경은 변하지 않았다

즉, 평소와 동일한 상태라고 가정합니다.

대립가설 (H₁) — 의심 시나리오
우리가 의심하는 상황:
❌ 센서 패턴이 이전과 다르다  
❌ 시스템 상태가 변했을 수 있다

예:
- 설비 노후
- 환경 변화
- 센서 이상
- 이상 징후 발생

ADF 검정은 결국 이것을 묻습니다:
지금 데이터는 기존 상태(정상 상태)와 통계적으로 같은가?

```
즉,
- 02번: “무슨 일이 있었나?”
- 03번: “지금도 정상 흐름인가?”

- 압력 센서 …

각 센서마다:

✔ 패턴 따로 학습

센서마다 특성이 다르기 때문에
- CO → 급변 위험
- 온도 → 완만한 변화 정상
- 진동 → 주기성 중요
- 가스 센서 → 외부 환경 영향 큼
- 정상 패턴 자체가 센서별로 다름

금융 데이터는 다양한 사용자, 이벤트, 거래 유형 등이 혼합되어 있어 구조 복잡도가 높은 편입니다.  

반면 센서 데이터는 구조 자체는 비교적 단순하지만, 센서 종류와 측정 대상이 증가할수록 운영 복잡도가 커질 수 있습니다.  

그러나 데이터 구조를 올바르게 설계하면 이후에는 값(수치)만 달라질 뿐 처리 방식은 동일하게 유지되므로, 안정적인 운영 및 확장이 가능합니다.
