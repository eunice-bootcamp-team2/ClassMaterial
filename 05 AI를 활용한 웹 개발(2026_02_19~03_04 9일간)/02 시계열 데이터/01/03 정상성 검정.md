> 그럼 이 데이터로 미래를 예측해도 돼?

바로 이 질문 때문에 03번 ‘정상성 검정’이 등장합니다.

03번 문제에서 우리가 하려는 것
> 시간에 따라 기록된 이상 거래 시계열 데이터가 예측 모델에 사용해도 되는 상태인지 확인한다

즉, 질문은 딱 하나입니다.

> ❓ 이 시계열 데이터는 안정적인가?  
> ❓ 시간이 지나도 성질이 크게 변하지 않는가?

이걸 확인하는 과정이 정상성 검정입니다.

### 🤔 왜 예측 전에 정상성을 확인해야 할까?

시계열 예측 모델(ARIMA, ETS 등)은 공통적으로 이런 가정을 합니다.

> 과거의 패턴은 미래에도 비슷하게 유지될 것이다.

그런데 만약 데이터가…
- 시간이 갈수록 계속 증가만 하거나
- 변동 폭이 점점 커지거나
- 평균 수준이 계속 바뀐다면?
    
❌ 과거 패턴을 믿을 수 없고  
❌ 예측 결과도 흔들립니다.

그래서 모델을 쓰기 전에 먼저 묻는 거예요.

> 이 데이터, 과거를 기준으로 미래를 예측해도 될 만큼 안정적인가?

---
🧪 그래서 사용하는 방법: ADF 정상성 검정

ADF (Augmented Dickey-Fuller) Test란?
- 시계열 데이터가 정상적인지 / 비정상적인지를 판단하는
- 가장 기본적이고 널리 쓰이는 통계 검정 방법
    
👉 이 데이터, 시간에 따라 성질이 변하냐 안 변하냐를 묻는 시험

---
📌 ADF 검정의 핵심 아이디어 (아주 중요)

ADF는 가설 검정입니다.

🔹 귀무가설 (H₀)
> ❌ 이 시계열 데이터는 비정상성이다  
> (시간이 지나면서 성질이 변한다)

🔹 대립가설 (H₁)
> ⭕ 이 시계열 데이터는 정상성이다  
> (시간이 지나도 안정적이다)

👉 우리의 목표는?
> 귀무가설을 기각하고 정상성이라고 말하고 싶습니다.

2️⃣ 왜 데이터를 다시 한 번 걸러내는가? (중요 포인트)

이미 p1에 날짜별 이상 거래 건수가 있는데  왜 또 이체방식 AT만 골라?

핵심이유는 정상성 검정은 하나의 시계열에 대해서만 할 수 있기 때문입니다.
```python
cond1 = (p1['이체방식'] =='AT')
p2 = p1.loc[cond1]
```
이 코드의 의미
- 02번 문제에서 만든 `p1` 데이터 중에서
- 이체방식이 AT인 데이터만 추출
❓ 왜 굳이 하나만 고르나?
- 정상성 검정은 하나의 시계열에 대해서만 수행하기 때문입니다.
즉, 모든 이체방식을 섞어서 AT라는 하나의 흐름만 놓고 검정합니다.

###### p1 데이터는 아래와 같은 구조였습니다.
| Date       | 이체방식 | 이상거래여부 |
| ---------- | ---- | ------ |
| 2024-02-16 | AT   | 35     |
| 2024-02-16 | MP   | 40     |
| 2024-02-17 | AT   | 38     |
| 2024-02-17 | MP   | 42     |
| ...        | ...  | ...    |

👉 즉,
- 날짜는 하나인데
- 이체방식마다 값이 따로 있음
- 여러 개의 시계열이 섞여 있음

이런 상태로는 정상성 검정을 하면 안됩니다. ADF 검정은 이렇게 묻는 도구입니다.
- 이 하나의 시간 흐름은 안정적인가?

그런데 지금 데이터는:
- AT 시계열 ❌
- MP 시계열 ❌
- CCT 시계열 ❌  
    → 전부 섞여 있어서 하나만 골라야 합니다.
    
하나만 골라야 하는 이유는 
정상성 검정이 전제하는 질문 자체가 깨지기 때문입니다.
즉, 데이터 품질 문제가 아니라 질문 구조의 문제예요.

정상성 검정이 실제로 묻는 질문은 이것 하나입니다
ADF 검정은 이런 질문을 합니다:
❓ 이 하나의 시계열은 시간이 지나도 같은 성질을 유지하는가?
- 여기서 중요한 단어는 하나의 시계열입니다.

시계열이란 정확히 뭐냐면 시계열 = 같은 대상을 시간 순서대로 계속 관측한 값의 흐름
- AT 이체 방식의 하루별 이상 거래 건수
- MP 이체 방식의 하루별 이상 거래 건수
즉 각각이 서로 다른 시계열입니다.

p1은 성질이 다른 두 흐름이 동시에 존재합니다.

```python
adfuller(p2['이상거래여부'])
```
의미:
AT 이체 방식에서 날짜별 이상 거래 발생 건수는 시간에 따라 안정적인가?

즉,
- 평균이 계속 바뀌는지?
- 점점 증가/감소하는지?
- 과거 패턴이 미래에도 유지될 수 있는지? 를 통계적으로 시험하는 것입니다.

4️⃣ ADF 결과 해석 (문제 풀이 포인트)

아래 결과는 ADF 정상성 검정의 원시 출력값
```
(np.float64(-5.078785234945017),
 np.float64(1.5463396451301483e-05),  # <- 여기가 p-value입니다.
 2,
 152,
 {'1%': np.float64(-3.474120870218417),
  '5%': np.float64(-2.880749791423677),
  '10%': np.float64(-2.5770126333102494)},
 np.float64(1199.5423548341773))
```
	이건 6개의 값이 순서대로 들어 있는 튜플입니다.

✨ 이 결과를 생성형을 시켜 해석하면

> AT 이체 방식의 날짜별 이상 거래 시계열은  
> p-value가 0.05보다 훨씬 작으므로  
> 정상성을 만족하며,  
> 예측 모델에 바로 사용할 수 있는 데이터이다. 이렇게 해석됩니다.

---
ADF 결과에는 위와 같이 여러 값이 나오지만 이 단계에서는 p-value만 보면 충분합니다.

✅ P-value 기준 해석 기준
- p-value < 0.05
    - 귀무가설 기각
    - 👉 정상성 있음
- p-value ≥ 0.05
    - 귀무가설 기각 실패
    - 👉 비정상성

이번 결과에서는:
```
p-value ≈0.000015
```
➡️ 0.05보다 훨씬 작음
✔️ 귀무가설 기각
✔️ 정상성 만족

### 관제 / 이상 탐지 관점에서 보면

```
센서 수집

```
즉,
- 02번: “무슨 일이 있었나?”
- 03번: “지금도 정상 흐름인가?”

1️⃣ 이 센서 흐름, 평소랑 같은가? 판단
	
상황
- CO 센서의 일별 이상 알람 개수 시계열
    
정상성 검정 결과
- 정상성 유지 ✔  
    → 환경 변화 없음
    
- 정상성 붕괴 ❌  
    → 환경/설비 상태가 바뀌었을 가능성
    
📌 관제 의미
> 지금은 단순한 잡음이 아니라 시스템 상태 자체가 변하고 있다

---
2️⃣ 예측 모델을 써도 되는지 판단하는 관문

관제 시스템에서의 질문
> 이 센서 데이터를 예측 기반 경고(사전 알람)에 써도 될까?

- 정상성 ✔ → ARIMA, 통계 기반 예측 가능
- 비정상성 ❌ →
    - 추세 제거
    - 차분
    - 기준선 재설정 필요
        
📌 관제 의미
> 모델을 돌리기 전에  데이터 상태부터 검사

4️⃣ 경고 레벨을 바꾸는 트리거

관제 정책 예시
```
정상성 유지

```

> 정상성은 관제 시스템의 상태 전환 스위치
