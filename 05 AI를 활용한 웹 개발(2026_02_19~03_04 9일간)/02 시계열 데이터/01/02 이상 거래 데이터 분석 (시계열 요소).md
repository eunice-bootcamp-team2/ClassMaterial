3 시계열 분석의 첫 단계: 시간 컬럼 정리

❓ 지금 우리가 부딪힌 문제는?
거래 데이터에는 거래가 발생한 정확한 시각이 `Datetime` 컬럼에 들어 있습니다.
예시
```
2024-06-14 22:00:10
2024-05-20 20:39:57
....
```
이 값은 날짜 + 시간이 함께 섞여 있는 형태입니다.

🚨 왜 이게 문제일까?
우리는 지금 이런 질문을 하고 싶습니다.
- 하루에 이상 거래가 몇 건 발생했을까?
- 어느 날짜에 이상 거래가 많았을까?
    
하지만 `Datetime`을 그대로 사용하면:
- `2024-06-14 22:00:10`
- `2024-05-20 20:39:57`
    
👉 같은 날인데도 서로 다른 값으로 인식됨  
👉 하루 단위로 묶어서 계산하기가 어려움

즉, 하루 단위 분석을 하려면 시간이 오히려 방해가 됩니다.


✅ 해결 방법: 날짜만 따로 분리하기
```python
df1['Date'] = pd.to_datetime(df1['Datetime']).dt.date
```

이 코드가 정확히 하는 일

1️⃣ `pd.to_datetime(df1['Datetime'])`
- 문자열로 되어 있는 날짜/시간 데이터를
- 파이썬이 이해할 수 있는 날짜 타입으로 변환
    
2️⃣ `.dt.date`
- 날짜 + 시간 중에서
- 날짜(YYYY-MM-DD)만 추출
    
3️⃣ `df1['Date'] = ...`
- 추출한 날짜를
- `Date`라는 새로운 컬럼에 저장

말로 풀면 이렇게 이해하면 됩니다

> 거래가 발생한 정확한 시각에서  
> 시간은 잠시 무시하고,  
> 몇 월 며칠에 발생했는지’만 따로 기록해두자

###### 판다스 전용 접근자들
|접근자|대상 데이터|용도|
|---|---|---|
|`.str`|문자열 Series|문자열 처리|
|`.dt`|날짜/시간 Series|날짜·시간 처리|
|`.cat`|범주형 Series|범주 처리|
```
.dt.date
```
→ DatetimeProperties 객체를 반환  
→ 그 객체 안에 `.date`, `.year`, `.hour` 같은 속성들이 들어 있음

구조를 보면
```
 → .dt (DatetimeProperties 객체)
     → .date
     → .year
     → .month
     → .hour
```

🔹 그럼 이제 날짜별로 계산해야 함.

|Date|이상 거래 건수|

이걸 만들기 위해 사용하는 도구가 **`pivot_table`** 입니다.

🔹 pivot_table은 무슨 역할을 하나?

한 줄 요약하면:
> 기준이 되는 컬럼으로 데이터를 묶어서, 숫자를 요약(집계)해주는 함수

🔹 코드 한 줄씩 풀어보기
```python
df1.pivot_table(
    index='Date',
    values='이상거래여부',
    aggfunc='sum'
)
```

1️⃣ `index='Date'`
- 데이터를 날짜(Date) 기준으로 묶겠다
- 같은 날짜의 거래들은 하나의 그룹이 됨
👉 하루 단위로 보겠다는 뜻

2️⃣ `values='이상거래여부'`
- 계산에 사용할 값은  👉 `이상거래여부` 컬럼
    
즉,
- 정상 거래(0)
- 이상 거래(1)
    
이 숫자들을 가지고 계산하겠다는 의미

3️⃣ `aggfunc='sum'`
- 묶인 데이터에 대해  👉 합계(sum)를 구하겠다
    
다시 말해,
> 같은 날짜에 발생한 거래들의 이상거래여부(0/1)를 전부 더해라

이 코드가 실제로 하는 일 (말로 풀면)
> 같은 날짜(Date)끼리 거래를 묶은 뒤, 그 날짜에 발생한 이상 거래(1)가 총 몇 건인지 계산한다.

- 방식별 패턴 차이(추세)가 있는지를 더 명확하게 볼 수 있습니다.

① `index=['Date', '이체방식']`
	데이터를 날짜별로 먼저 묶고, 같은 날짜 안에서 다시 이체 방식별로 나눠서 묶습니다

즉 그룹이 이렇게 생김:
- (2024-02-16, MP)
- (2024-02-16, AT)
- (2024-02-17, MP)
- (2024-02-17, AT)
- …

② `values='이상거래여부'`
- 묶인 그룹마다 이상거래여부(0/1) 값을 계산하겠다

③ `aggfunc='sum'`
- 0/1 값을 더해서 이상 거래 건수로 만들겠다

왜 sum이 건수냐면:
- 1 = 이상 거래 1건
- 0 = 이상 거래 0건  
    → 합 = 이상 거래가 총 몇 번(몇 건) 있었는지

④ `.reset_index()`
pivot_table 결과는 `Date`와 `이체방식`이 “인덱스”로 붙어있는데,  그래프 도구(plotly)가 편하게 쓰려면 보통 컬럼 형태가 좋습니다
그래서 인덱스를 다시 컬럼으로 꺼내는 작업이 `reset_index()`야.

4️⃣ 선택한 이체 방식의 일자별 이상 거래 합계 계산

p2 = df1.loc[cond1].pivot_table(

1. `df1.loc[cond1]`
    - 선택한 이체 방식의 거래만 남김
2. `.loc` = label-based indexer (라벨 기반 선택 도구)
	- 행은 조건으로
	- 열은 이름으로 데이터를 골라내는 도구
	- 기본형태: `df.loc[행조건, 열이름]`
3. `index='Date'`
    - 날짜(Date) 기준으로 묶음
4. `values='이상거래여부'`
    - 이상 거래 여부(0/1)를 계산 대상으로 사용
5. `aggfunc='sum'`
    - 1의 개수를 더해서  
        → 날짜별 이상 거래 건수 계산

3️⃣ 문제 2 → 센서 데이터에서의 활용

거래 분석 문제 2
> 이체 방식별로, 시간에 따라 이상 거래가 어떻게 변하는가?

센서 데이터로 바꾸면
> 센서 종류(또는 위치)별로, 시간에 따라 이상 징후가 어떻게 변하는가?

예시
- 센서 종류: `CO`, `H2S`, `Temperature`
- 색상 = 센서 종류
```python
sensor_pivot = sensor_df.pivot_table(
    index=['Date', '센서종류'],
    values='이상여부',
    aggfunc='sum'
).reset_index()

px.line(sensor_pivot, x='Date', y='이상여부', color='센서종류')
```
활용
- 어떤 센서가 항상 문제를 일으키는지
- 특정 기간에 특정 센서만 급증했는지
- 설비/라인별 위험 패턴 비교

문제 3 → 센서 데이터에서의 활용 (가장 중요)

거래 분석 문제 3
> 특정 이체 방식 하나를 골라 집중 분석

센서 데이터로 바꾸면
> 특정 센서 하나를 골라서 시간 흐름에 따른 이상 패턴을 집중 분석

예시
- 사용자 선택: `CO 센서`
```python
cond = (sensor_df['센서종류'] == 'CO')

co_daily = sensor_df.loc[cond].pivot_table(
    index='Date',
    values='이상여부',
    aggfunc='sum'
).reset_index()

px.line(co_daily, x='Date', y='이상여부')
```
활용
- CO 센서에서 이상 알람이 증가하는 추세인지
- 특정 날짜에 급격한 Spike 발생 여부
- 실제 사고 전조 신호 탐지

---
실시간 센서에서 특히 중요한 포인트
이상 거래 분석에서 배운 개념들이 센서 데이터에서는 이렇게 바로 쓰입니다 

✅ (1) Level (수준)
- 평소 하루 평균 이상 알람 수
- 기준보다 계속 높아지면 위험 신호
    
✅ (2) Trend (추세)
- 시간이 갈수록 이상 발생이 증가/감소
- 설비 노후화, 환경 변화 신호
    
✅ (3) Spike (급증)
- 갑작스러운 이상 폭증
- 즉시 알람 & 대응 필요

+ 대상 (거래, 센서, 사용자, 장비, 서버)
