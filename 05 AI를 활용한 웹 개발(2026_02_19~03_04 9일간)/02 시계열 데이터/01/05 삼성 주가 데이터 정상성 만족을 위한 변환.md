### 📌 정상성 검정 결과가 실패한 상황

흐름은 이렇게 됩니다.
```
데이터 확인
   ↓
정상성 검정 (ADF)
   ↓
정상성 불만족 (p-value > 0.05)
   ↓
비정상 시계열로 판단
```

이 의미는 다음과 같습니다.

- 평균이 계속 변하고 있을 가능성
- 장기 추세가 존재할 가능성
- 분산이 일정하지 않을 가능성
- 과거 패턴이 그대로 유지되지 않을 가능성

즉, 이 데이터는 통계 기반 시계열 모델의 전제를 만족하지 않는다 라는 결론이 됩니다.

```
① 그냥 머신러닝으로 간다
② 통계 기반 모델을 쓰기 위해 데이터를 변환한다
```

### 📌 04 단계에서의 선택

> 정상성이 완벽하지 않아도 머신러닝 모델(RandomForestRegressor)은 학습이 가능하다

머신러닝은 정상성을 전제로 하지 않습니다.
```

```

그래서 ML 접근은 여전히 유효합니다.

ARIMA, Naive Forecast 같은 모델은 계산이 단순하고 빠르며 해석이 쉽습니다.
하지만 조건이 있습니다.
```
데이터

```

지금은 정상성을 만족하지 못한 상태입니다.

### 📌 05 단계의 목적 (정상성 불만족 가정)

05 단계는 모델을 더 잘 만드는 단계가 아닙니다.
05 단계는 다음을 확인하는 단계입니다.
```
비정상 데이터
   ↓
로그 변환 / Box-Cox
   ↓
계절성 분해 (STL)
   ↓
차분
   ↓
정상성 재검정
```

목적은 단 하나입니다. 이 데이터를 통계 기반 모델이 사용 가능한 상태로 만들 수 있는가?

---

### 📌 왜 이런 과정을 배우는가?

이 과정은 단순한 변환 연습이 아닙니다.
이것은 모델 선택 능력을 기르는 과정입니다.

---

### ① 모델을 아무거나 쓰지 않기 위해서입니다
```
데이터 상태 파악
   ↓
모델 조건 확인
   ↓
적절한 모델 선택
```

데이터가 비정상인데 ARIMA를 바로 쓰면 이론적으로 맞지 않는 모델을 사용하는 것입니다.

---
### ② 통계 모델을 쓸 수 있다면 더 효율적이기 때문입니다

통계 기반 모델은:

- 계산이 빠르고
- 실시간 적용이 쉽고
- 해석이 명확합니다.

관제 시스템에서는 “빠르고 안정적인 판단”이 중요할 수 있습니다.

---

### ③ 관제 관점에서는 ‘상태 변화’를 구분해야 하기 때문입니다

정상성 붕괴는 단순 예측 문제가 아닙니다.
```
정상성 유지
→ 단기 변동

정상성 붕괴
→ 시스템 상태 변화 가능성
```

관제 시스템에서는 정상성 자체가 하나의 경고 신호가 될 수 있습니다.

---

### 📌 전체 흐름 (정상성 실패 가정)
```
02 패턴 관찰
   ↓
03 정상성 검정
   ↓
비정상 판정
   ↓
04 머신러닝으로 예측 시도
   ↓
05 변환을 통해 통계 모델 가능성 재검토
```

---

이번 흐름에서 05 단계는

- 04 모델을 개선하기 위한 단계가 아니라
- 통계 기반 모델을 사용할 수 있는지 다시 평가하는 단계입니다.

그리고 이 단계를 배우는 이유는

> 데이터를 보고 지금 이 상황에 어떤 접근이 맞는지 판단할 수 있는 능력을 기르기 위함입니다.

코드를 더 많이 아는 것이 목적이 아니라, 데이터의 상태에 따라 전략을 바꿀 수 있는 사고력을 기르는 것이 목적입니다.

---
### 📌 통계 기반 시계열 모델이란?

통계 기반 시계열 모델은
> 과거의 시간 흐름 자체를 이용해서 미래를 예측하는 모델입니다.
즉, 시간의 순서가 가장 중요한 정보입니다.

이 모델들은 구조가 단순하고 해석이 쉽지만, 반드시 정상성(데이터 성질이 일정함) 을 전제로 합니다.

대표적인 모델은 다음 두 가지입니다.

- Naive Forecast
- ARIMA

---
### 1️⃣ Naive Forecast (가장 단순한 모델)

가장 최근 값을 그대로 다음 값으로 예측하는 방식입니다.

예를 들어,
- 오늘 값이 100이면 → 내일 예측값도 100
- 오늘 값이 102이면 → 내일 예측값도 102
아무 복잡한 계산이 없습니다.

### 왜 이런 단순한 모델을 쓰나요?

성능이 목적이 아니라, 이 데이터에 최소한의 시간적 규칙성이 있는지를 확인하기 위한 기준선 
모델(Baseline) 이기 때문입니다.

즉, 이 데이터가 정말 예측이라는 것을 할 수 있는 구조인가? 를 확인하는 가장 기본 단계입니다.

---
### 2️⃣ ARIMA (대표적인 통계 시계열 모델)

ARIMA는 과거 값과 변화량을 조합하여 미래를 예측하는 모델입니다.

핵심 구조는 다음과 같습니다.
- AR: 과거 값이 현재에 영향을 준다
- I: 차분을 통해 데이터를 안정화한다
- MA: 과거 오차를 반영해 보정한다
쉽게 말하면, 과거 값 + 변화량 + 오차 구조를 이용해 예측하는 모델입니다.

---
### 📌 중요한 전제 조건

Naive Forecast와 ARIMA는 공통적으로
- 데이터의 평균과 분산이 일정해야 하거나
- 차분 등을 통해 그렇게 만들 수 있어야 합니다.

이것이 바로 정상성 조건입니다.
그래서 05 단계에서 정상성 검정과 변환을 먼저 수행하는 것입니다.

---
### 📌 머신러닝과의 차이
| 구분      | 통계 시계열 모델 | 머신러닝 모델   |
| ------- | --------- | --------- |
| 정상성 필요  | 필요        | 불필요       |
| 해석      | 쉬움        | 어려움       |
| 계산량     | 가벼움       | 상대적으로 무거움 |
| 데이터 요구량 | 적음        | 많음        |

즉,
- 데이터가 안정적이면 → 통계 모델이 효율적
- 데이터가 복잡하고 계속 변하면 → 머신러닝이 유리

---
### 📌 그래서 05 단계의 역할은 무엇인가요?

05 단계는 모델을 만드는 단계가 아닙니다.
다음 질문에 답하는 단계입니다.

> 이 데이터로 통계 기반 모델을 써도 되는가?

절차는 간단합니다.
```
① 시계열 데이터 준비
② 시각화
③ 정상성 검정 (ADF)
④ 비정상이면 변환
⑤ 재검정
⑥ 모델 적용 가능 여부 판단
```

즉,
> 모델을 돌리기 전에 데이터 상태부터 확인하는 단계입니다.

---
### 📌 관제 시스템에 비유하면

관제 플랫폼에서는 이렇게 생각할 수 있습니다.

- 지금 센서 데이터가 일정한 기준선 안에서 움직이고 있는가?
- 아니면 상태 자체가 계속 변하고 있는가?

기준선이 유지된다면
→ 통계 기반 모델로 충분합니다.

기준선이 계속 변한다면
→ 머신러닝처럼 더 유연한 모델이 필요합니다.

- Naive Forecast는 최소한의 기준선 모델입니다.
- ARIMA는 정식 통계 시계열 모델입니다.
- 두 모델 모두 정상성이 전제 조건입니다.
- 05 단계는 “모델 선택을 위한 데이터 상태 점검 단계”입니다.

이 과정을 배우는 목적은 코드를 많이 아는 것이 아니라,
> 데이터 상태에 따라 적절한 예측 전략을 선택할 수 있는 사고력을 기르는 것입니다.

---
### 아래 코드는 어떤 상황에서 쓰나요?

다음처럼 시간 순서가 있는 값(시계열) 을 다룰 때 사용합니다.
- 센서 값(가스 농도, 전력 사용량, 진동, 온도 등)
- 주가/매출/트래픽 같은 시계열
- 하루 이상 알람 개수 같은 집계 시계열

그리고 목표가 이런 경우에 특히 씁니다.
- Naive Forecast / ARIMA로 예측을 해보고 싶다
- 또는 통계 모델로 빠르게 예측 가능한지 먼저 판단하고 싶다

---
### 아래 코드가 진행하는 과정(간략)

(1) 시계열 준비
- `ts = df["value"]`
- 시간 순서대로 정렬된 1개의 값 시계열을 만든다는 뜻입니다.
- (현업에서는 `timestamp` 기준 정렬, 결측 처리까지 같이 합니다.)

(2) 정상성 검사(ADF 테스트)
- `adfuller(ts)`를 돌려서
    - p-value가 작으면(보통 0.05 이하) 정상성에 가깝다고 판단
    - p-value가 크면 비정상(추세/분산 변화/계절성 등)이 강하다고 판단

(3) 비정상이면 변환 시도
- Log 변환: 값이 커질수록 변동 폭이 커지는(분산이 커지는) 경우 완화
- Box-Cox 변환: log보다 일반적인 안정화 변환(단, 값이 양수여야 함)

---
#### Log 변환의 추가 설명:

로그(Log) 변환이란? 공식: y=log(x)
로그 변환은 값의 크기를 압축하여 값이 커질수록 변동폭이 커지는 현상(분산 증가)을 완화하는 방법입니다.

시계열 데이터에서 로그를 쓰는 경우

시계열 데이터 중 일부는 다음과 같은 특징을 가집니다:
- 값이 점점 커짐
- 값이 커질수록 흔들림(변동폭)도 커짐
- 절대 증가량이 점점 커지는 구조
    
예:
- 주가
- 매출
- 트래픽
- 사용자 수
- 누적 카운트 데이터
    
이런 데이터는 비율(%) 기반 성장 구조를 가질 가능성이 높습니다.
```
100 → 110 → 121 → 133
```
10%씩 증가하지만  절대 증가량은 점점 커집니다.
```
+10 → +11 → +12
```
이 경우 로그를 취하면 증가 구조가 더 안정적으로 변합니다.


센서 데이터에서는?

대부분의 센서 데이터는:
- 현재 상태값을 측정하는 구조
- 복리 성장 구조가 아님
- 절대값 기반 경보 시스템

예:
- 온도
- 압력
- 가스 농도
- 진동
    
이 경우 로그가 반드시 필요한 것은 아닙니다.

센서 데이터에서 로그를 사용하는 경우
	다만, 아래와 같은 상황에서는 사용할 수 있습니다:

🔹 가스 농도
- 평소: 0~5 ppm
- 사고 상황: 100 ppm 이상
    
값의 범위 차이가 매우 크다면 로그를 사용해 스케일을 줄일 수 있습니다.

🔹 진동 에너지
진동 에너지는 물리적으로 제곱값으로 증가할 수 있습니다.
값이 급격히 커지는 구조라면 로그 스케일을 적용해 분산을 안정화할 수 있습니다.

결론
✔ 로그는 시계열이라서 쓰는 것이 아닙니다.  
✔ 로그는 분산이 값 크기에 비례해서 증가할 때 씁니다.  
✔ 센서 데이터는 보통 로그가 필요 없습니다.  
✔ 필요 여부는 데이터를 보고 판단합니다.

---
Box-Cox 변환이란?
	데이터의 흔들림(분산)을 안정시키기 위해 값을 압축하는 수학적 변환 방법

왜 쓰나요?
작을 때는 조금 흔들림 클 때는 많이 흔들림
즉 값이 커질수록 변동폭이 커지면  모델이 다루기 어려워집니다.
👉 이걸 안정시키려고 씁니다.

로그는 고정된 형태의 압축 변환이고,  
Box-Cox는 데이터에 맞는 압축 강도(λ)를 자동으로 추정하는 변환 방법입니다.

언제 쓰나요?
- 로그로도 안정이 안 될 때
- 더 정규분포에 가깝게 만들고 싶을 때
- 값이 모두 양수일 때만 가능

---
(4) 변환 후 다시 정상성 검사
- 변환한 시계열에 다시 ADF를 돌려서
    - 이제 정상성에 가까워졌나?를 확인합니다.

(5) 판단
- 변환 후 정상성 만족 → Naive/ARIMA 적용 후보
- 여전히 비정상 → 차분(STL 포함) 추가 또는 ML/이상탐지로 방향 전환

> 참고: 실무에서는 보통 로그/Box-Cox → (필요 시) 차분/계절차분/STL → 재검정 순서를 많이 씁니다.

### 현업에서는 이걸 어떻게 활용하나요?

✅ 현업 사고방식은 모델부터가 아니라 데이터 상태 진단부터

현업에서는 이런 흐름으로 짭니다.

2. 안 되면
    - 변환/차분으로 통계 모델이 가능한 상태로 만들 수 있는가?
3. 그래도 안 되면
    - ML 또는 이상탐지로 전환 (더 유연하지만 무겁고 관리 비용 증가)

즉, 이 코드는 게이트(관문) 입니다.

### 관제 플랫폼에서의 실전 예시(진짜 쓰는 방식)

- 매 1분마다 가스 센서 값이 들어온다
- 1시간 단위로 집계해서 시계열을 만든다
- 매일/매주 한 번(또는 모델 재학습 시점)에 이 점검을 돌려서

✅ ARIMA로 예측 운영 가능인지 판단하고, 가능하면 ARIMA 파이프라인으로 보내고
❌ 불가능하면 차분/STL 적용 또는 이상탐지(예: 임계치+모델)로 보냅니다.

즉 자동화로 돌리는 단계 : 코드 + 규칙 + 자동 파이프라인으로 자동화
```python
[실시간 센서 수집]
        ↓
[전처리 + 집계]
        ↓
[자동 정상성 검사]
        ↓
if 정상성 유지:
    ARIMA 예측 모드
else:
    차분/STL 자동 적용
    → 재검정
    if 여전히 불안정:
        이상탐지 모드 전환
```

센서 관제에서 가장 중요한 것은
> 예측 정확도보다 시스템 안정성입니다.

그래서 보통은:
- 1차: 규칙 기반 자동화
- 2차: 모델 성능 모니터링
- 3차: 일정 조건 이상에서만 모델 교체 이렇게 단계적으로 갑니다.

전체코드
```python
# =========================================================
# 05 삼성 주가 데이터 정상성 만족을 위한 변환 (전체 코드)
# =========================================================

# ---------------------------------------------------------
# (0) 준비: 라이브러리 불러오기
# ---------------------------------------------------------
# - numpy: 수학/변환(log 등)
# - pandas: 데이터 로딩/가공
# - plotly.express: 시계열 라인 그래프 시각화
# - scipy.stats: Box-Cox 변환
# - adfuller: ADF(정상성) 검정 함수
import numpy as np
import pandas as pd

import plotly.express as px
import scipy.stats as stats

from statsmodels.tsa.stattools import adfuller


# ---------------------------------------------------------
# [Skeleton 1️⃣] 시계열 데이터 준비
# ---------------------------------------------------------
# 목표:
# 1) CSV 파일을 DataFrame으로 읽는다(df1)
# 2) '날짜' 컬럼을 datetime으로 변환해서 Date 컬럼을 만든다
# 3) Date를 기준으로 '시가'를 모아 "날짜-값" 형태의 시계열(p1)을 만든다
# 4) 분석할 기간(예: 2020년 이후)만 잘라서 df2를 만든다
# 5) ADF 정상성 검정에 넣을 최종 시계열은 df2["시가"]가 된다

# (1) 데이터 불러오기
df1 = pd.read_csv("samsung_stock.csv")   # CSV 파일 읽기
print(df1.shape)                         # (행, 열) 크기 확인
df1.head(2)                              # 상위 2개 행 확인 (노트북에서는 출력)

# (2) 날짜 컬럼 처리: 문자열 -> datetime
# - 시계열 분석은 날짜가 "문자열"이 아니라 "시간 타입(datetime)" 이어야 함
df1["Date"] = pd.to_datetime(df1["날짜"])  # 문자열 날짜 -> datetime 변환
print(df1["Date"].describe())              # Date 컬럼 분포 요약(터미널에서도 출력)

# (3) 시계열 형태로 만들기: pivot_table
# - Date를 인덱스로 두고 '시가' 값만 뽑아서 날짜 순서의 시계열 데이터 만들기
# - 같은 날짜가 여러 행으로 존재할 수 있으므로 aggfunc="sum"으로 합산 처리
p1 = df1.pivot_table(
    index="Date",       # 날짜 기준으로 묶기
    values="시가",      # 사용할 값 컬럼
    aggfunc="sum"       # 같은 날짜가 여러 개면 합계로 처리
).reset_index()

# (선택) 시계열 시각화
# - 추세(상승/하락), 분산 변화(변동성 증가/감소)를 눈으로 확인하는 용도
px.line(p1, x='Date', y='시가')

# (4) 분석 구간 제한: 예) 2020년 이후 데이터만 사용
# - 너무 오래된 구간을 포함하면 최근 패턴과 섞여 분석이 어려울 수 있음
cond1 = p1["Date"] >= pd.to_datetime("2020-01-01") # 2020년 이후 조건
df2 = p1.loc[cond1].copy()                         # 조건 만족 행만 필터링 (copy로 경고 방지)
print(df2.shape)                                   # 필터링 후 크기 확인
display(df2.head(2))                               # 상위 2개 행 확인

# ✅ 정상성 검정에 사용할 "원본 시계열" 변수(ts)
# - Skeleton 구조에서는 ts = df["value"] 처럼 이름을 ts로 통일해서 씀
ts = df2["시가"]


# ---------------------------------------------------------
# [Skeleton 2️⃣] 정상성 검정 함수 정의 (관례)
# ---------------------------------------------------------
# ADF(Augmented Dickey-Fuller) 검정 결과는 튜플로 나오기 때문에,
# 초보자가 확인하기 좋게 'ADF Statistic'과 'p-value'를 보기 쉽게 출력하는 함수로 감싼다.
#
# - series.dropna(): 결측치가 있으면 ADF가 실패할 수 있어서 제거
# - result[0]: ADF 통계량
# - result[1]: p-value
def check_stationarity(series, name="data"):
    result = adfuller(series.dropna())
    print(f"[{name}] ADF Statistic :", result[0])
    print(f"[{name}] p-value       :", result[1])
    print("-" * 40)
    return result


# ---------------------------------------------------------
# [Skeleton 3️⃣] 원본 데이터 정상성 확인
# ---------------------------------------------------------
# df2["시가"] = ts(원본 시계열)에 대해 ADF 테스트 수행
# 결과 해석의 핵심은 p-value
# - p-value <= 0.05 : 정상성 있다고 볼 가능성 ↑ (귀무가설 기각)
# - p-value >  0.05 : 정상성이 없다고 볼 가능성 ↑ (귀무가설 기각 못함)
res_original = check_stationarity(ts, "original")


# ---------------------------------------------------------
# [Skeleton 4️⃣] 정상성이 없으면 변환 시도
# ---------------------------------------------------------
# 원본 시계열이 비정상일 때 자주 시도하는 대표 변환 2가지:
# (1) Log 변환: 큰 값의 변동을 눌러서 분산을 안정화하려는 목적
# (2) Box-Cox 변환: log보다 더 일반화된 변환(양수 데이터에 한해 적용)
#
# 변환 후에도 동일하게 ADF 테스트를 수행하여 정상성 개선 여부를 확인한다.

# (1) Log 변환 + 정상성 재검정
df2["시가_log"] = np.log(df2["시가"])       # 로그 변환 컬럼 생성
px.line(df2, x="Date", y="시가_log")        # 변환 후 시계열 시각화
res_log = check_stationarity(df2["시가_log"], "log")

# (2) Box-Cox 변환 + 정상성 재검정
# - stats.boxcox(...)는 (변환값 배열, lambda) 형태를 반환할 수 있음
# - 여기서는 변환값만 쓰기 위해 [0] 인덱싱
df2["시가_boxcox"] = stats.boxcox(df2['시가'])[0]
px.line(df2, x="Date", y="시가_boxcox")
res_boxcox = check_stationarity(df2["시가_boxcox"], "boxcox")


# ---------------------------------------------------------
# [Skeleton 5️⃣] 판단(해석 기준 정리)
# ---------------------------------------------------------
# ADF 검정의 기본 해석:
# - 귀무가설(H0): 단위근이 존재한다 → 비정상(정상성 없음)
# - 대립가설(H1): 단위근이 없다 → 정상(정상성 있음)
#
# 따라서 p-value 기준:
# - p-value > 0.05  -> 귀무가설 기각 못함 -> 비정상(정상성 X)
# - p-value <= 0.05 -> 귀무가설 기각 -> 정상(정상성 O)
#
# ✅ 결론:
# - 정상성 만족 → ARIMA 같은 통계 시계열 모델 적용을 고려할 수 있음
# - 여전히 비정상 → 추가 변환(차분 등) 또는 ML 기반 접근을 유지
```

### `[Skeleton 2️⃣]` 정상성 검정 함수 정의 (관례)

```python
def check_stationarity(series, name="data"):
    result = adfuller(series.dropna())
    print(f"[{name}] ADF Statistic :", result[0])
    print(f"[{name}] p-value       :", result[1])
    print("-" * 40)
    return result
```
	이 코드는 정상성 검정을 매번 편하게 하기 위해 만들어두는 도우미 함수입니다.

series는 아래 함수 호출에서 ts가 들어갈 매개변수입니다.
`dropna()` : 결측치(NaN)가 들어있는 행(또는 열)을 제거하는 pandas 메서드
즉, 시가 데이터가 비어있는건 그 행 전체가 사라집니다.

위의 코드는 증명을 하기 위한 이 시계열 데이터가 정상성(stationary)을 가지는가?를 확인하기 위한 헬퍼 함수입니다.

그 판단 기준은:
- ADF 통계값
- p-value

특히 우리가 실제로 보는 건 p-value 입니다.

정상성 판단 기준
```python
p-value > 0.05  → 정상성 없음
p-value ≤ 0.05  → 정상성 있음
```
즉, 이 함수는 이 데이터로 ARIMA 같은 시계열 모델을 써도 되는지를 확인하는 코드입니다.

✔ adfuller 호출  
✔ dropna 처리  
✔ result 인덱스 접근  
✔ print formatting  
✔ 구분선 출력 이걸 자동으로 해줍니다.


- `stats`는 scipy 라이브러리의 통계 모듈입니다.
- Box-Cox는 데이터의 분포를 더 안정적이고 정규분포에 가깝게 만들어주는 변환 방법입니다.
- 쉽게 말하면 데이터의 모양을 더 예쁜 형태로 바꿔주는 수학 공식

왜 쓰나요? 시계열이나 통계 모델은 보통 이런 걸 좋아합니다
✔ 분산이 일정함  
✔ 정규분포에 가까움  
✔ 변동 폭이 일정함

그런데 실제 데이터는:
- 한쪽으로 치우쳐 있고
- 값이 점점 커지고
- 분산이 계속 증가합니다

그래서 Box-Cox를 써서
👉 분산을 안정화  
👉 정규성 개선  
👉 모델이 다루기 쉽게 만듭니다

로그랑 뭐가 달라요?
로그도 분산을 줄이는 변환입니다. 하지만 Box-Cox는 더 일반적인 형태입니다.
공식:
![[Pasted image 20260211131914.png]]
λ(람다)가 0이면 = 로그  
λ(람다)가 0이 아니면 = 다른 압축 방식
즉 조건식 같은것이 Box-Cox입니다.
```python
if λ != 0:
    y = (x**λ - 1) / λ
else:
    y = log(x)
```
즉,
- λ가 0이 아니면 → 일반 Box-Cox 공식 사용
- λ가 0이면 → 로그 공식 사용
그래서 로그는 Box-Cox 안에 포함된 특수한 경우라고 말하는 것입니다.

---
```python
df2["시가_boxcox"] = stats.boxcox(df2['시가'])[0]
```
1️⃣ 시가 데이터를 가져옴  
2️⃣ Box-Cox 공식으로 변환  
3️⃣ 변환된 값만 가져옴  
4️⃣ 새로운 컬럼에 저장

Box-Cox는 데이터의 분산을 안정화하고 정규성에 가깝게 만들기 위한 수학적 변환 방법이며, 로그의 확장 버전입니다.

### `[Skeleton 5️⃣]` 판단(해석 기준 정리)

```python
# ---------------------------------------------------------
# [Skeleton 5️⃣] 판단(해석 기준 정리)
# ---------------------------------------------------------
# ADF 검정의 기본 해석:
# - 귀무가설(H0): 단위근이 존재한다 → 비정상(정상성 없음)
# - 대립가설(H1): 단위근이 없다 → 정상(정상성 있음)
#
# 따라서 p-value 기준:
# - p-value > 0.05  -> 귀무가설 기각 못함 -> 비정상(정상성 X)
# - p-value <= 0.05 -> 귀무가설 기각 -> 정상(정상성 O)
#
# ✅ 결론:
# - 정상성 만족 → ARIMA 같은 통계 시계열 모델 적용을 고려할 수 있음
# - 여전히 비정상 → 추가 변환(차분 등) 또는 ML 기반 접근을 유지
```

1️⃣ ADF 검정이 묻는 질문 
이 데이터는 정상적인(안정적인) 시계열인가?

2️⃣ 가설 의미
- 귀무가설(H0)  
    → 정상성이 없다 (추세가 있다, 불안정하다)
    
- 대립가설(H1)  
    → 정상성이 있다 (평균과 분산이 일정하다)

3️⃣ p-value로 판단
- p-value > 0.05  
    → 정상성 없음 ❌  
    → 아직 모델 쓰기 어려움
    
- p-value ≤ 0.05  
    → 정상성 있음 ✅  
    → ARIMA 같은 모델 사용 가능
