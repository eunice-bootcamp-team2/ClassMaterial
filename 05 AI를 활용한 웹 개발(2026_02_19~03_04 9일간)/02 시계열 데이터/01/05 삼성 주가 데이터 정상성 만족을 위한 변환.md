05 파트는  
04에서 만든 모델을 더 잘 만들기 위한 단계가 아니라,  
다른 종류의 모델을 써도 되는지 판단하기 위한 단계입니다.

전체 흐름을 초보자 관점으로 다시 정리하면
```
02 데이터는 어떤 모습인가?
   ↓
03 이 데이터는 통계 모델 전제가 맞는가?
   ↓
04 (전제가 안 맞아도 되는) 머신러닝으로 예측 시도
   ↓
05 그렇다면, 통계 기반 모델은 쓸 수 있을까?
```

04에서는 이 데이터는  정상성이 완벽하지 않아도  머신러닝 회귀 모델로는 어느 정도 예측이 가능하다고 판단이 되어 ML 기반 접근은 유효하다는 결론을 얻었습니다.

그런데 이런 질문이 생깁니다.
그럼  Naive Forecast, ARIMA 같은 통계 기반 시계열 모델도 써볼 수 있을까?

통계 기반 시계열 모델은:
- 계산이 단순하고
- 빠르고
- 해석이 쉬운 대신
    
👉 데이터가 ‘정상성’을 만족해야만 합니다.

### 통계 기반 시계열 모델이란?
> 과거의 시간 흐름 자체를 이용해 미래를 예측하는 모델

특징:
- 데이터가 시간 순서를 가진다는 점이 핵심
- “왜 이런 값이 나왔는지” 해석이 비교적 쉬움
- 대신 데이터가 일정한 성질(정상성)을 가진다는 가정이 필요
    
이 범주에 속하는 가장 대표적인 모델이 바로 Naive Forecast와 ARIMA입니다.

---
1️⃣ Naive Forecast (가장 단순한 시계열 예측)
	가장 최근 값이 다음 시점의 값과 같을 것이다”라고 가정하는 모델

작동 방식 예시
- 오늘 값 = 100  
    → 내일 예측값 = 100
    
- 오늘 값 = 102  
    → 내일 예측값 = 102

아무 계산도 하지 않고 마지막 관측값을 그대로 사용

왜 이런 단순한 모델을 쓰나?
Naive Forecast는 “성능 좋은 모델”이 목적이 아니고 
이 데이터에 최소한의 시간적 규칙성이라도 있는가?”를 확인하는 기준선(baseline)입니다.

장점
- 계산이 매우 단순
- 학습 과정이 없음
- 실시간 시스템에서도 즉시 적용 가능
- 기준선 모델로 매우 유용

한계
- 추세가 강하면 성능 급격히 저하
- 계절성, 패턴 반영 불가
- 데이터가 정상성에 가까울수록 의미 있음
    
그래서 정상성 검정이 먼저 필요합니다.

2️⃣ ARIMA (가장 대표적인 통계 시계열 모델)

이름부터 풀어보면
ARIMA =  
AR (AutoRegressive)
- I (Integrated)
- MA (Moving Average)

AR (자기회귀)
	과거의 값들이 현재 값에 영향을 준다
예:
- 오늘 값은  
    어제 값, 그제 값의 영향을 받는다

I (차분)
	값 자체가 아니라 변화량을 사용한다
예:
- 오늘 − 어제
- 어제 − 그제
    
비정상 데이터를 정상에 가깝게 만드는 핵심 장치

MA (이동평균)
	과거의 예측 오차를 평균 내어 보정한다

ARIMA의 핵심 아이디어
> 과거 값 + 변화량 + 오차 구조를 조합해서 미래를 예측한다

ARIMA가 강력한 이유
- 추세를 수학적으로 모델링 가능
- 비교적 적은 데이터로도 작동
- 해석 가능성 높음

ARIMA의 전제 조건 (아주 중요)
- 데이터가 정상성을 만족하거나
- 차분을 통해 정상성에 가깝게 만들 수 있어야 함
    
그래서 05 파트에서 정상성 변환을 먼저 다룬 것

Naive Forecast와 ARIMA의 관계

관계를 한 줄로 요약하면
> Naive Forecast는 “최소한의 기준선 모델”,  
> ARIMA는 “그 기준선을 확장한 정식 통계 모델”

###### 머신러닝 회귀모델과의 차이점
|구분|Naive / ARIMA|머신러닝 모델|
|---|---|---|
|전제|정상성 필요|정상성 불필요|
|해석|쉬움|어려움|
|계산|가벼움|무거움|
|데이터 요구|적음|많음|
|실시간성|매우 좋음|상대적으로 느림|

	이 센서 데이터는 고정된 기준선으로 감시해도 되는 상태인가?

🔹 04 단계 (머신러닝 기반 예측)

> 머신러닝으로 패턴을 학습하면 이상 여부를 예측할 수 있겠다.

- 정상성은 불필요하고
- 기준선 고정도 필요없고
- 대신 ML이 패턴을 학습 필요합니다.
- 복잡하지만 유연한 감시 방식
    
👉 예:
- 온도, 트래픽, 전력 사용량이 계속 변하는 상황
- ML 모델이 상황 맥락까지 고려해 판단

🔹 그런데 여기서 생기는 질문 (05의 출발점)

즉:

Naive / ARIMA를 위한 뼈대 코드 (Skeleton)

```python
# =====================================================
# [Skeleton] 통계 시계열 모델 적용 전 정상성 점검
# =====================================================

import numpy as np
import pandas as pd
from statsmodels.tsa.stattools import adfuller
import scipy.stats as stats

# 1️⃣ 시계열 데이터 준비
# ----------------------
# 반드시 시간 순서가 있어야 함
ts = df["value"]   # 예: 센서값, 주가, 트래픽 등


# 2️⃣ 정상성 검정 함수 정의 (도우미 함수)
# ----------------------
def check_stationarity(series, name="data"):
    result = adfuller(series.dropna())
    print(f"[{name}] ADF Statistic :", result[0])
    print(f"[{name}] p-value       :", result[1])
    print("-" * 40)
	return result

# 3️⃣ 원본 데이터 정상성 확인
# ----------------------
check_stationarity(ts, "original")


# 4️⃣ 정상성이 없으면 변환 시도
# ----------------------

# (1) Log 변환
ts_log = np.log(ts)
check_stationarity(ts_log, "log")

# (2) Box-Cox 변환 (양수일 때만)
ts_boxcox, lam = stats.boxcox(ts)
check_stationarity(ts_boxcox, "boxcox")


# 5️⃣ 판단
# ----------------------
# - 정상성 만족 → Naive / ARIMA 적용 가능
# - 여전히 비정상 → ML 기반 접근 유지
```

전체코드
```python
# =========================================================
# ✅ 05 삼성 주가 데이터 정상성 만족을 위한 변환 (전체 코드)
#    - Skeleton(1~5) 흐름 그대로
#    - "코드 내용은 유지"하고, 주석만 초보자 관점으로 정리한 버전
# =========================================================

# ---------------------------------------------------------
# (0) 준비: 라이브러리 불러오기
# ---------------------------------------------------------
# - numpy: 수학/변환(log 등)
# - pandas: 데이터 로딩/가공
# - plotly.express: 시계열 라인 그래프 시각화
# - scipy.stats: Box-Cox 변환
# - adfuller: ADF(정상성) 검정 함수
import numpy as np
import pandas as pd

import plotly.express as px
import scipy.stats as stats

from statsmodels.tsa.stattools import adfuller


# ---------------------------------------------------------
# [Skeleton 1️⃣] 시계열 데이터 준비
# ---------------------------------------------------------
# 목표:
# 1) CSV 파일을 DataFrame으로 읽는다(df1)
# 2) '날짜' 컬럼을 datetime으로 변환해서 Date 컬럼을 만든다
# 3) Date를 기준으로 '시가'를 모아 "날짜-값" 형태의 시계열(p1)을 만든다
# 4) 분석할 기간(예: 2020년 이후)만 잘라서 df2를 만든다
# 5) ADF 정상성 검정에 넣을 최종 시계열은 df2["시가"]가 된다

# (1) 데이터 불러오기
df1 = pd.read_csv("samsung_stock.csv")   # CSV 파일 읽기
print(df1.shape)                         # (행, 열) 크기 확인
df1.head(2)                              # 상위 2개 행 확인 (노트북에서는 출력)

# (2) 날짜 컬럼 처리: 문자열 -> datetime
# - 시계열 분석은 날짜가 "문자열"이 아니라 "시간 타입(datetime)" 이어야 함
df1["Date"] = pd.to_datetime(df1["날짜"])  # 문자열 날짜 -> datetime 변환
print(df1["Date"].describe())              # Date 컬럼 분포 요약(터미널에서도 출력)

# (3) 시계열 형태로 만들기: pivot_table
# - Date를 인덱스로 두고 '시가' 값만 뽑아서 날짜 순서의 시계열 데이터 만들기
# - 같은 날짜가 여러 행으로 존재할 수 있으므로 aggfunc="sum"으로 합산 처리
p1 = df1.pivot_table(
    index="Date",       # 날짜 기준으로 묶기
    values="시가",      # 사용할 값 컬럼
    aggfunc="sum"       # 같은 날짜가 여러 개면 합계로 처리
).reset_index()

# (선택) 시계열 시각화
# - 추세(상승/하락), 분산 변화(변동성 증가/감소)를 눈으로 확인하는 용도
px.line(p1, x='Date', y='시가')

# (4) 분석 구간 제한: 예) 2020년 이후 데이터만 사용
# - 너무 오래된 구간을 포함하면 최근 패턴과 섞여 분석이 어려울 수 있음
cond1 = p1["Date"] >= pd.to_datetime("2020-01-01") # 2020년 이후 조건
df2 = p1.loc[cond1].copy()                         # 조건 만족 행만 필터링 (copy로 경고 방지)
print(df2.shape)                                   # 필터링 후 크기 확인
display(df2.head(2))                               # 상위 2개 행 확인

# ✅ 정상성 검정에 사용할 "원본 시계열" 변수(ts)
# - Skeleton 구조에서는 ts = df["value"] 처럼 이름을 ts로 통일해서 씀
ts = df2["시가"]


# ---------------------------------------------------------
# [Skeleton 2️⃣] 정상성 검정 함수 정의 (관례)
# ---------------------------------------------------------
# ADF(Augmented Dickey-Fuller) 검정 결과는 튜플로 나오기 때문에,
# 초보자가 확인하기 좋게 'ADF Statistic'과 'p-value'를 보기 쉽게 출력하는 함수로 감싼다.
#
# - series.dropna(): 결측치가 있으면 ADF가 실패할 수 있어서 제거
# - result[0]: ADF 통계량
# - result[1]: p-value
def check_stationarity(series, name="data"):
    result = adfuller(series.dropna())
    print(f"[{name}] ADF Statistic :", result[0])
    print(f"[{name}] p-value       :", result[1])
    print("-" * 40)
    return result


# ---------------------------------------------------------
# [Skeleton 3️⃣] 원본 데이터 정상성 확인
# ---------------------------------------------------------
# df2["시가"] = ts(원본 시계열)에 대해 ADF 테스트 수행
# 결과 해석의 핵심은 p-value
# - p-value <= 0.05 : 정상성 있다고 볼 가능성 ↑ (귀무가설 기각)
# - p-value >  0.05 : 정상성이 없다고 볼 가능성 ↑ (귀무가설 기각 못함)
res_original = check_stationarity(ts, "original")


# ---------------------------------------------------------
# [Skeleton 4️⃣] 정상성이 없으면 변환 시도
# ---------------------------------------------------------
# 원본 시계열이 비정상일 때 자주 시도하는 대표 변환 2가지:
# (1) Log 변환: 큰 값의 변동을 눌러서 분산을 안정화하려는 목적
# (2) Box-Cox 변환: log보다 더 일반화된 변환(양수 데이터에 한해 적용)
#
# 변환 후에도 동일하게 ADF 테스트를 수행하여 정상성 개선 여부를 확인한다.

# (1) Log 변환 + 정상성 재검정
df2["시가_log"] = np.log(df2["시가"])       # 로그 변환 컬럼 생성
px.line(df2, x="Date", y="시가_log")        # 변환 후 시계열 시각화
res_log = check_stationarity(df2["시가_log"], "log")

# (2) Box-Cox 변환 + 정상성 재검정
# - stats.boxcox(...)는 (변환값 배열, lambda) 형태를 반환할 수 있음
# - 여기서는 변환값만 쓰기 위해 [0] 인덱싱
df2["시가_boxcox"] = stats.boxcox(df2['시가'])[0]
px.line(df2, x="Date", y="시가_boxcox")
res_boxcox = check_stationarity(df2["시가_boxcox"], "boxcox")


# ---------------------------------------------------------
# [Skeleton 5️⃣] 판단(해석 기준 정리)
# ---------------------------------------------------------
# ADF 검정의 기본 해석:
# - 귀무가설(H0): 단위근이 존재한다 → 비정상(정상성 없음)
# - 대립가설(H1): 단위근이 없다 → 정상(정상성 있음)
#
# 따라서 p-value 기준:
# - p-value > 0.05  -> 귀무가설 기각 못함 -> 비정상(정상성 X)
# - p-value <= 0.05 -> 귀무가설 기각 -> 정상(정상성 O)
#
# ✅ 결론:
# - 정상성 만족 → ARIMA 같은 통계 시계열 모델 적용을 고려할 수 있음
# - 여전히 비정상 → 추가 변환(차분 등) 또는 ML 기반 접근을 유지
```

### `[Skeleton 2️⃣]` 정상성 검정 함수 정의 (관례)

```python
def check_stationarity(series, name="data"):
    result = adfuller(series.dropna())
    print(f"[{name}] ADF Statistic :", result[0])
    print(f"[{name}] p-value       :", result[1])
    print("-" * 40)
    return result
```
	이 코드는 정상성 검정을 매번 편하게 하기 위해 만들어두는 도우미 함수입니다.

위의 코드는 증명을 하기 위한 이 시계열 데이터가 정상성(stationary)을 가지는가?를 확인하기 위한 헬퍼 함수입니다.

그 판단 기준은:
- ADF 통계값
- p-value

특히 우리가 실제로 보는 건 p-value 입니다.

정상성 판단 기준
```python
p-value > 0.05  → 정상성 없음
p-value ≤ 0.05  → 정상성 있음
```
즉, 이 함수는 이 데이터로 ARIMA 같은 시계열 모델을 써도 되는지를 확인하는 코드입니다.

✔ adfuller 호출  
✔ dropna 처리  
✔ result 인덱스 접근  
✔ print formatting  
✔ 구분선 출력 이걸 자동으로 해줍니다.

- `np`는 NumPy 라이브러리의 줄임말(별명)로 수학 계산을 빠르게 해주는 라이브러리
- `log()`는 로그(logarithm) 계산 함수 `log(x)` 

시계열에서 로그를 쓰는 이유는?
✔ 값이 너무 빠르게 증가할 때  
✔ 변동 폭이 커질 때  
✔ 분산을 안정화시키기 위해

|원래 값|로그 값|
|---|---|
|100|4.60|
|1000|6.90|
|10000|9.21|
큰 값 차이가 줄어듭니다.
변화값(변동 폭)이 크면 뭐가 문제인가?

예를 들어 원래 데이터가 아래와 같다고 가장하면...

|날짜|시가|
|---|---|
|1일|1,000|
|2일|2,000|
|3일|4,000|
|4일|8,000|
변화량:
```
+1000
+2000
+4000
```
👉 점점 변화폭이 커지고 있고, 변동성이 시간이 갈수록 증가
	이걸 이분산(heteroscedasticity) 이라고 합니다.

변동성이 커지면 생기는 문제
- 정상성 깨짐 : 시계열 모델(ARIMA 등)은 평균과 분산이 일정해야 한다 즉, 분산이 일정해야 정상성 조건을 만족합니다.
- 모델이 후반 데이터에 과도하게 끌림 : 초반 오차 50, 후반 오차 500 → 모델이 후반만 중요하게 학습
- 예측 오차 폭이 계속 커짐 : 변동성이 커지면 예측 신뢰구간도 넓어짐 → 예측이 불안정

로그는: 절대 변화량 → 상대 변화율 형태로 바꿔줌
✔ 지수적으로 증가하는 데이터  
✔ 주가  
✔ 매출  
✔ 인구  
✔ 트래픽

이런 데이터는 대부분 로그를 먼저 시도합니다.
결론은 변화 폭이 커지면 분산이 일정하지 않아서 정상성이 깨지고, 로그는 그 변동 폭을 안정화시켜 모델링을 쉽게 만든다.

- `stats`는 scipy 라이브러리의 통계 모듈입니다.
- Box-Cox는 데이터의 분포를 더 안정적이고 정규분포에 가깝게 만들어주는 변환 방법입니다.
- 쉽게 말하면 데이터의 모양을 더 “예쁜 형태”로 바꿔주는 수학 공식

왜 쓰나요? 시계열이나 통계 모델은 보통 이런 걸 좋아합니다
✔ 분산이 일정함  
✔ 정규분포에 가까움  
✔ 변동 폭이 일정함

그런데 실제 데이터는:
- 한쪽으로 치우쳐 있고
- 값이 점점 커지고
- 분산이 계속 증가합니다

그래서 Box-Cox를 써서
👉 분산을 안정화  
👉 정규성 개선  
👉 모델이 다루기 쉽게 만듭니다

로그랑 뭐가 달라요?
로그도 분산을 줄이는 변환입니다. 하지만 Box-Cox는 더 일반적인 형태입니다.

👉 λ(람다) 값을 자동으로 찾아줍니다.  
👉 가장 적절한 변환 강도를 선택합니다.

df2["시가_boxcox"] = stats.boxcox(df2['시가'])[0]

3️⃣ 변환된 값만 가져옴  
4️⃣ 새로운 컬럼에 저장

Box-Cox는 데이터의 분산을 안정화하고 정규성에 가깝게 만들기 위한 수학적 변환 방법이며, 로그의 확장 버전입니다.

❌ 헬퍼 함수 없이 작성
```python
from scipy import stats
from statsmodels.tsa.stattools import adfuller
import plotly.express as px

# 1️⃣ Box-Cox 변환
df2["시가_boxcox"] = stats.boxcox(df2["시가"])[0]

# 2️⃣ 그래프 확인
px.line(df2, x="Date", y="시가_boxcox")

# 3️⃣ ADF 검정 직접 실행
result_boxcox = adfuller(df2["시가_boxcox"].dropna())

print("[boxcox] ADF Statistic :", result_boxcox[0])
print("[boxcox] p-value       :", result_boxcox[1])
print("-" * 40)
```

### `[Skeleton 5️⃣]` 판단(해석 기준 정리)

```python
# ---------------------------------------------------------
# [Skeleton 5️⃣] 판단(해석 기준 정리)
# ---------------------------------------------------------
# ADF 검정의 기본 해석:
# - 귀무가설(H0): 단위근이 존재한다 → 비정상(정상성 없음)
# - 대립가설(H1): 단위근이 없다 → 정상(정상성 있음)
#
# 따라서 p-value 기준:
# - p-value > 0.05  -> 귀무가설 기각 못함 -> 비정상(정상성 X)
# - p-value <= 0.05 -> 귀무가설 기각 -> 정상(정상성 O)
#
# ✅ 결론:
# - 정상성 만족 → ARIMA 같은 통계 시계열 모델 적용을 고려할 수 있음
# - 여전히 비정상 → 추가 변환(차분 등) 또는 ML 기반 접근을 유지
```

1️⃣ ADF 검정이 묻는 질문 
이 데이터는 정상적인(안정적인) 시계열인가?

2️⃣ 가설 의미
- 귀무가설(H0)  
    → 정상성이 없다 (추세가 있다, 불안정하다)
    
- 대립가설(H1)  
    → 정상성이 있다 (평균과 분산이 일정하다)

3️⃣ p-value로 판단
- p-value > 0.05  
    → 정상성 없음 ❌  
    → 아직 모델 쓰기 어려움
    
- p-value ≤ 0.05  
    → 정상성 있음 ✅  
    → ARIMA 같은 모델 사용 가능

최종 정리
- p-value가 0.05보다 작아야 정상성 있다고 판단
- 크면 → 차분 등 추가 변환 필요

결론:
p-value가 0.05 이하이면 정상성, 0.05보다 크면 비정상이다.
