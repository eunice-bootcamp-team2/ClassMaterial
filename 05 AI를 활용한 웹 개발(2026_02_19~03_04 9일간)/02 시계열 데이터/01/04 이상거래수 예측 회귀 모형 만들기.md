    - 너무 불규칙하지 않은지
    - 완전히 랜덤처럼 보이지는 않는지
- 정상성 검정 등을 통해 확인

### 회귀모델 개발 코드 작성 패턴

(1) 문제정의(컬럼 고정)
- 입력(X): 무엇을 넣을 건가?
- 정답(Y): 무엇을 맞출 건가?
- 회귀인지/분류인지, 예측 단위(1건? 1시간? 1일?)를 확정
    
✅ 체크 문장
- X를 보면 Y를 숫자로 맞춥니다.
    
---
(2) 데이터 로드 + 최소 검증(필수) : 데이터 확인
- shape 확인, 컬럼 존재 확인
- 결측치/타입 확인 (문자/숫자)
- 타겟(Y) 분포 확인(0이 많나? 큰 값 있나?)
    
✅ 필수 출력 3개
- `df.head()`  : 데이터의 앞부분 5행을 보여준다
- `df.info()`  : 데이터의 구조 요약 정보를 보여줘
- `df.isna().sum()`  : 각 컬럼별 결측치(NaN)가 몇 개 있는지 정확한 숫자로 보여준다
    
---
(3) 문제 형태로 데이터 만들기 (가장 중요) : 문제 형태 만들기 (groupby/pivot 등)

원본 로그가 있으면 학습용 표 형태로 바꾸는 단계가 필요합니다.
- 예: pivot_table, groupby, resample 등
- 1행 = 1상황(or 1시간 or 1일)이 되게 만듦니다.
    
✅ 너의 케이스  
`pivot_table`로 상황 1개당 이상거래 건수 만들기
- `pivot_table`는 데이터를 ==요약·집계해서== 새로운 테이블을 만들어주는 메서드
---
(4) X / Y 분리

- X에 들어갈 컬럼 리스트를 먼저 선언(실수 방지)
- Y는 시리즈로 따로
    
✅ 규칙
- X 컬럼은 미래에도 알 수 있는 정보만 넣기  
    (예: 거래시간/요일/이체방식은 가능, 결과/사후 정보는 금지)
- Y에는 우리가 맞히고 싶은 결과만 둔다.

(5) 학습/검증 분리 (절대 건너뛰지 않기)

- `train_test_split`
- 시간 순서가 중요한 진짜 시계열이면 `TimeSeriesSplit` 고려
    
✅ 원칙
- 모델 개발은 시험지(test)가 있어야 합니다.

(6) 전처리 설계 (숫자 / 범주 / 날짜)
	모델이 데이터를 이해할 수 있도록 데이터를 어떻게 정리할지 미리 정해두는 단계입니다

머신러닝 모델(회귀모델 포함)은 숫자 계산만 할 수 있기 때문에,  
데이터를 그대로 넣기 전에 정리 규칙이 필요합니다.

그래서 보통 이렇게 정리합니다
- 숫자 데이터
    - 비어 있으면 → 가운데 값(median)으로 채운다
    - (이상한 큰 값에 덜 흔들리기 위해)
        
- 문자(종류) 데이터
    - 비어 있으면 → 가장 많이 나온 값으로 채운다
    - 문자는 계산이 안 되므로 → 숫자로 바꾼다(One-Hot)
        
- 날짜/시간 데이터
    - 그대로 쓰기보다
    - 월 / 요일 / 시간대 같은 정보로 쪼개서 사용한다

전처리 설계란?  
이 데이터는 앞으로 항상 이런 규칙으로 정리해서 모델에 넣겠다 
라고 약속하는 단계입니다.


탭형 회귀에서는 데이터를 모델이 계산할 수 있게 정리하는 게 가장 중요합니다.
그래서 보통 이렇게 정리합니다.
- 숫자 데이터  
    → 비어 있으면 가운데 값(median)으로 채운다
    
- 문자(종류) 데이터  
    → 비어 있으면 가장 많은 값으로 채우고  
    → 숫자로 바꿔서 사용한다(One-Hot)
    
- 날짜·시간 데이터  
    → 그대로 쓰기보다  
    → 월, 요일, 시간대 같은 정보로 나눠서 쓴다
    
✅ 규칙
	학습할 때 정한 전처리 방법을 예측할 때도 똑같이 사용해야 합니다.
    
---
(7) 전처리 + 모델을 Pipeline으로 묶기 (필수 습관)

전처리 따로, 모델 따로 하면 실무에서 사고 납니다.
✅ 무조건 이렇게:
- `pipe = make_pipeline(preprocess, model)`

`make_pipeline`란?
전처리와 모델을 ‘한 덩어리 작업 순서’로 묶어주는 함수입니다.
전처리와 모델을 묶음으로써 순서를 강제로 지켜주는 안전장치입니다.

`RandomForestRegressor`란?
랜덤포레스트 회귀 모델입니다.

---
(8-1) 기준선(Baseline) 모델부터 선택하기
회귀 모델은 처음부터 복잡한 모델로 시작하지 않습니다.  
성능 비교 기준이 될 기본 모델(Baseline)부터 정합니다.

Baseline을 두는 이유
- 지금 모델이 잘 만든 건지 판단하기 위해
- 아무렇게나 찍어도 나오는 점수보다 나은지 확인하기 위해

회귀모델은 아주 많이 존재합니다.
예를 들어
- LinearRegression
- Ridge / Lasso / ElasticNet
- DecisionTreeRegressor
- RandomForestRegressor
- GradientBoostingRegressor
- XGBoost / LightGBM / CatBoost
- SVR
- Neural Network(MLPRegressor)
- … 등등
👉 수십 개 이상 있음

---
그러나 모델의 종류에서 베이스라인 모델 선택이란?
여러 회귀모델 중에서  난이도가 다른 모델들을 비교 기준으로 삼아  
데이터에 맞는 모델을 고르는 과정입니다.

✅ 추천 Baseline 순서
1. DummyRegressor  
    → 항상 평균값으로 예측 (최저 기준선)
    
2. LinearRegression / Ridge  
    → 단순한 선형 관계 학습
    
3. RandomForestRegressor  
    → 비선형 패턴까지 학습 가능

✔️ 항상 질문해야 함  
	이 모델이 Baseline보다 좋아졌는가?

그래서 Baseline 모델 선택은 난이도가 다른 모델들을 기준으로 비교해  
이 데이터에 맞는 모델을 고르는 과정입니다.

---
(8-2) 선택한 모델을 학습시키기 (fit)
```python
pipe.fit(X_train, y_train)
```
선택한 Baseline 모델과 전처리 규칙을 사용해  실제로 데이터를 학습시키는 단계입니다.

이 한 줄이 하는 일:
1. 전처리 규칙 학습 (중앙값, 최빈값, 원핫 구조)
2. 전처리된 데이터로 모델 학습
3. 입력(X) → 결과(Y) 패턴 기억
    
👉 이때는 전략이 아니라 실행 단계

(9) 평가 단계
모델이 외운 것인지, 진짜로 이해한 것인지 확인하는 단계입니다.

모델은 학습 데이터를 보면 너무 잘 외워버릴 수 있어요.
그래서 우리는 이렇게 묻습니다.
- 처음 보는 문제에도 잘 맞힐까?
- 이 모델을 실제로 써도 될까?
    
그 답을 얻기 위해 평가를 합니다.

평가 단계에서 실제로 하는 일
```python
pred = pipe.predict(X_test)
```
학습에 사용하지 않은 데이터(X_test)를 넣어서 모델이 낸 답(pred)을 확인합니다. 즉 시험 문제를 풀게 합니다.

평가 지표는 왜 필요한가?
모델의 답이 맞는지 숫자로 판단해야 하기 때문입니다
그래서 “점수표”가 필요합니다.

---
R² (결정계수) — 설명력 점수
```python
r2_score(y_test, pred)
```
쉽게 말하면
> 이 모델이 전체 패턴을 얼마나 잘 설명하고 있는가?

- 1에 가까울수록 좋음
- 0이면 → 평균으로 찍은 것과 비슷
- 음수면 → 아예 엉망

초보자 기준 감각
- R² ≈ 0.0 → 거의 의미 없음
- R² ≈ 0.3 → 조금 설명함
- R² ≈ 0.6 이상 → 꽤 쓸 만함  
    (데이터 난이도에 따라 다름)

---
MSE — 틀린 정도의 평균 크기
```python
mean_squared_error(y_test, pred)
```
쉽게 말하면 얼마나 크게 틀렸는가?의 평균

- 작을수록 좋음
- 단위는 Y의 단위²
    
예:
- 실제 이상거래 = 5
- 예측 = 8  
    → 3만큼 틀림 → 제곱해서 9
    
👉 큰 실수를 더 크게 벌점 주는 방식


평가 규칙을 다시 쉽게 쓰면
- 항상 같은 지표로 비교한다  
    (R² + MSE 같이)
    
- train / test 둘 다 본다
    
- train만 좋고 test가 나쁘면  
    → 모델을 믿지 않는다
---
### 코드가 하는 일을 말로 다시 쓰면:

```python
pred = pipe.predict(X_test)
```
→ 시험 문제를 풀게 한다

```python
r2_score(y_test, pred)
```
→ 설명력은 몇 점인가?

```python
mean_squared_error(y_test, pred)
```
→ 얼마나 크게 틀렸나?

평가 단계는 이 모델을 실제로 써도 되는지를 숫자로 확인하는 시험 단계입니다.
그래서 학습 다음에 반드시 이 과정을 거쳐야 합니다.

실제로 우리가 모델을 고를때 성능지표는 판단 기준표가 됩니다.
회귀모델은 시험 점수처럼 정답이 딱 하나가 없기 때문에 얼마나 잘 맞췄는지를 숫자로 표현해야 합니다.

### 우리가 모델을 선택할때 봐야하는 대표적인 회귀 성능 지표
🔹 R² (결정계수)
	이 모델이 전체 패턴을 얼마나 설명했는가?

- 높을수록 좋다
- 1에 가까울수록 잘 설명
- 0이면 평균으로 찍은 것과 비슷
- 음수면 평균보다도 못함
    
👉 모델의 설명력 점수

🔹 MSE / MAE (오차 크기)
	얼마나 크게 틀렸는가?

- 작을수록 좋다
- 단위는 Y의 단위 기준
- MSE는 큰 실수에 더 큰 벌점
    
👉 실수의 크기를 보는 점수

그래서 이렇게 판단하는것이 중요합니다.
① Baseline과 비교
- DummyRegressor보다 좋나?
- Linear보다 좋아졌나?
    
② train / test 비교
- train만 좋고 test 나쁘면 ❌
- 둘 다 안정적이면 ⭕
    
③ 모델 간 비교

|모델|R²(test)|MSE(test)|
|---|---|---|
|Dummy|0.00|15.2|
|Linear|0.32|9.8|
|RandomForest|0.61|4.1|
👉 RandomForest 선택

(10) 튜닝(옵션) → 저장(필수) → 재현성 확보
잘 만든 모델을 다시 만들 필요 없게  그대로 보관해 두는 단계입니다.

- 튜닝: GridSearchCV / RandomizedSearchCV / BayesSearchCV
- 저장: `pickle` or `joblib`
- 재현성: random_state 고정, 버전 기록(requirements)
    
✅ 규칙
- best_model = 전처리+모델 통째로 저장
- 그래야 API에서 그대로 쓸 수 있음
---
튜닝은 뭐냐면 (선택 사항)
	모델의 세부 설정을 조금씩 바꿔보면서 가장 성능이 좋은 설정을 찾는 과정

이걸 사람이 하나하나 해보면 힘드니까
컴퓨터가 대신 해주는 도구가 아래 도구들입니다.
- `GridSearchCV`
- `RandomizedSearchCV`
- `BayesSearchCV`

저장은 왜 “필수”일까?
모델 학습은 시간이 들고, 예측은 바로 써야 하기 때문

이 코드가 하는 일 (아주 쉽게)
```python
pickle.dump(pipe, open("model.sav", "wb"))
```
이걸 말로 풀면:
전처리 규칙 + 학습된 모델을 통째로 파일(`model.sav`)로 저장한다

여기서 중요한 점 ❗

- `pipe` 안에는
    - 전처리(`preprocess`)
    - 학습된 모델
- 둘 다 함께 들어 있음

왜 전처리 + 모델을 통째로 저장해야 할까?
❌ 모델만 저장하면 생기는 문제
- 예측할 때
    - 전처리 규칙을 다시 만들어야 함
    - 실수 가능성 ↑
    - 학습 때와 다른 방식이 될 위험 ↑

파이프라인 전체를 저장하면
```python
loaded_model = pickle.load(open("model.sav", "rb"))
loaded_model.predict(new_X)
```
- 전처리 자동
- 학습 때와 완전히 동일한 규칙 적용
- API에서도 바로 사용 가능

재현성이란 말, 쉽게 풀면
	다시 실행해도 결과가 똑같이 나오게 하는 것

그래서 보통 이렇게 함:
- `random_state=1234` 고정
- 사용한 라이브러리 버전 기록  
    (`requirements.txt`)
    
👉 그래야
- 오늘 만든 모델
- 내일 다시 써도
- 다른 사람이 써도 결과가 바뀌지 않음

전체코드
```python
# =========================================================
# ✅ [0] 목표: "거래 상황 정보(X)" -> "이상거래 발생 건수(Y)" 예측하는 회귀 모델
# =========================================================
# ✅ 매핑:
#   - 뼈대(1~10) : (0은 준비 단계, 1부터 본격)
#   - 흐름도(A~I): [A]~[I]
#   - 섹션표기([0]~[I]): [0]~[I]
# =========================================================

# ---------------------------------------------------------
# (0) 준비 단계 / [0] / (해당 흐름도 단계 없음 - 전체 준비)
#   - 라이브러리 불러오기
# ---------------------------------------------------------
# 분석·학습에 필요한 라이브러리 불러오기
import pandas as pd
import pickle


# ---------------------------------------------------------
# (3) 문제 형태 만들기 / [A] 집계 전처리 / (A) 집계 전처리: pivot_table
#   - 원본 로그 df1 -> "상황 1개당 이상거래 건수" 테이블(p3) 생성
# ---------------------------------------------------------
# -------------------------------
# ✅ [A] 집계 전처리(문제 형태 만들기)
#   - 여러 거래 로그(df1)를
#   - "상황 1개당 이상거래 총 몇 건?" 형태(p3)로 변환
# -------------------------------
# df1: 원본 거래 로그 DataFrame (너가 미리 준비해야 하는 데이터)
# 필수 컬럼 예시: ['이체방식','거래월','거래일','거래요일','거래시간','이상거래여부']

p3 = df1.pivot_table(
    index=['이체방식', '거래월', '거래일', '거래요일', '거래시간'],
    values='이상거래여부',
    aggfunc='sum'
).reset_index()


# ---------------------------------------------------------
# (4) X/Y 분리 / [B] 입력(X)/정답(Y) 분리 / (B) 입력(X)/정답(Y) 분리
# ---------------------------------------------------------
# -------------------------------
# ✅ [B] 학습용 입력(X) / 정답(Y) 분리  (전처리의 일부)
# -------------------------------
X = p3[['이체방식', '거래월', '거래요일', '거래일', '거래시간']]
Y = p3['이상거래여부']  # "이상거래 건수" (숫자) -> 회귀 문제



# ---------------------------------------------------------
# (5) split (학습/검증 분리) / [C] 학습/검증 분리 / (C) train_test_split
# ---------------------------------------------------------
# -------------------------------
# ✅ [C] 학습/검증 데이터 분리 (학습 준비)
# -------------------------------
from sklearn.model_selection import train_test_split

X_train, X_test, Y_train, Y_test = train_test_split(
    X, Y, test_size=0.3, random_state=1234
)


# ---------------------------------------------------------
# (6) preprocess (전처리 설계/구성) / [D] 전처리 파이프라인 / (D) pipe1~pipe3 구성
#   - (D-1) pipe1: 숫자 결측 처리(median)
#   - (D-2) pipe2: 범주 결측 처리(most_frequent) + 원핫
#   - (D-3) pipe3: ColumnTransformer로 컬럼별 전처리 결합
# ---------------------------------------------------------
# -------------------------------
# ✅ [D] 전처리 파이프라인 구성 (전처리)
#   - 숫자 컬럼: 결측치 -> 중앙값
#   - 범주 컬럼: 결측치 -> 최빈값, 문자 -> 원핫인코딩(숫자화)
# -------------------------------
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder
from sklearn.compose import make_column_transformer
from imblearn.pipeline import make_pipeline

# 숫자 전처리(결측치 중앙값)
pipe1 = make_pipeline(
    SimpleImputer(strategy='median')
)

# 범주 전처리(결측치 최빈값 + 원핫인코딩)
pipe2 = make_pipeline(
    SimpleImputer(strategy='most_frequent'),
    OneHotEncoder(handle_unknown='ignore')
)

# 컬럼별로 다른 전처리 적용 후 합치기
pipe3 = make_column_transformer(
    (pipe_num, ['거래월', '거래일', '거래시간']),
    (pipe_cat, ['이체방식', '거래요일'])
)


# ---------------------------------------------------------
# (7) 전처리 + 모델 Pipeline으로 묶기 / [E] 학습 파이프라인 / (E) pipe_model 구성
#   - 전처리(pipe3 또는 preprocess) + 모델(RandomForestRegressor) 결합
# ---------------------------------------------------------
# -------------------------------
# ✅ [E] 전처리 + 모델을 하나로 묶기 (학습 파이프라인)
# -------------------------------
from sklearn.ensemble import RandomForestRegressor

pipe_model = make_pipeline(
    pipe3,
    RandomForestRegressor()
)


# ---------------------------------------------------------
# (8-학습+튜닝) 하이퍼파라미터 튜닝을 포함한 학습 / [F] 튜닝 / (F) BayesSearchCV
#   - 기존 단순 학습(pipe_model.fit) 대신
#     하이퍼파라미터 튜닝을 포함한 학습을 수행
#   - 여러 설정을 반복 학습하여
#     가장 성능이 좋은 파이프라인(best_model)을 선택
# ---------------------------------------------------------
# -------------------------------
# ✅ [F] 하이퍼파라미터 튜닝 기반 학습 (학습 + 최적화)
#   - BayesSearchCV가 여러 조합을 시험하고
#     최적의 전처리+모델 파이프라인을 선택
# -------------------------------
from skopt.searchcv import BayesSearchCV

hyper = {
    'randomforestregressor__max_depth': (5, 10),
    'randomforestregressor__min_samples_leaf': (30, 50),
}

bayes_model = BayesSearchCV(
    pipe_model,
    search_spaces=hyper,
    cv=3,
    scoring='r2',
    n_iter=5,
    n_jobs=-1,
    random_state=1234
)

bayes_model.fit(X_train, Y_train)
best_model = bayes_model.best_estimator_


# ---------------------------------------------------------
# (9) eval (평가) / [G] 성능 평가 / (G) train/test 성능 확인
# ---------------------------------------------------------
# -------------------------------
# ✅ [G] 성능 평가 (평가)
#   - train(본 문제) vs test(처음 보는 문제) 점수 비교
# -------------------------------
from sklearn.metrics import r2_score, mean_squared_error

Y_train_pred = best_model.predict(X_train)
Y_test_pred  = best_model.predict(X_test)

print("[TRAIN] R2 :", r2_score(Y_train, Y_train_pred))
print("[TRAIN] MSE:", mean_squared_error(Y_train, Y_train_pred))

print("[TEST ] R2 :", r2_score(Y_test, Y_test_pred))
print("[TEST ] MSE:", mean_squared_error(Y_test, Y_test_pred))


# ---------------------------------------------------------
# (10-저장 필수) 모델 저장 / [H] 저장 / (H) pickle 저장
# ---------------------------------------------------------
# -------------------------------
# ✅ [H] 모델 저장 (배포/재사용 준비)
#   - best_model 안에 "전처리 + 모델"이 통째로 들어있음
# -------------------------------
pickle.dump(best_model, open('model_RF_regressor.sav', 'wb'))


# ---------------------------------------------------------
# (11) 재검증/해석 단계 / [I] 해석 / (I) Feature Importance
#
# 목적:
#   - 학습이 끝난 최종 모델(best_model)이
#     어떤 입력 변수를 중요하게 사용했는지 확인
#   - 모델 저장 후(API/재사용 시)에도
#     "이 모델이 무엇을 보고 판단하는지" 설명 가능하게 하기 위함
#   - 성능 점수(R2/MSE)만으로는 알 수 없는
#     모델의 내부 판단 기준을 해석하는 단계
# ---------------------------------------------------------
# -------------------------------
# ✅ [I] 변수 중요도 해석 (모델 해석/검증 단계)
#   - 전처리 이후 실제 모델이 사용하는 feature 이름 추출
#   - 각 feature가 예측에 기여한 상대적 중요도 확인
# -------------------------------
df_importance = pd.DataFrame()
df_importance['Feature'] = best_model['columntransformer'].get_feature_names_out()
df_importance['Importance'] = best_model['randomforestregressor'].feature_importances_

# 중요도가 높은 변수부터 정렬
df_importance = df_importance.sort_values('Importance', ascending=False)

# 상위 20개 중요 변수 확인
print(df_importance.head(20))
```

즉, 과거 데이터를 분석하는 것이 아니라  
주어진 거래 상황을 입력하면 이상 거래 발생 건수를 숫자로 예측하는 문제입니다.

이 질문의 특징:
- 미래의 “값”을 예측
- 결과가 숫자 (0건, 3건, 10건 …)
    
👉 그래서 회귀(regression) 문제입니다.

```python
# 🌳 여러 개의 결정트리를 결합한 회귀 모델
# → 거래 상황 정보를 바탕으로 이상 거래 "발생 건수(숫자)"를 예측하기 위한 핵심 모델
from sklearn.ensemble import RandomForestRegressor

# ✂️ 데이터를 학습용(train)과 테스트용(test)으로 나누는 도구
# → 모델이 과거 데이터만 외워서 맞추는 것을 방지하기 위해 사용
from sklearn.model_selection import train_test_split

# 🔗 전처리 + 모델을 하나의 흐름(파이프라인)으로 묶는 도구
# → 학습과 예측 시 항상 동일한 전처리 규칙을 적용하기 위해 사용
from imblearn.pipeline import make_pipeline

# 🧩 컬럼별로 서로 다른 전처리를 적용하기 위한 도구
# → 숫자 컬럼과 문자(범주형) 컬럼을 구분해서 처리할 때 사용
from sklearn.compose import make_column_transformer

# 🩹 결측값(비어 있는 값)을 채우는 전처리 도구
# → 숫자 컬럼의 결측값을 평균/중앙값 등으로 대체
from sklearn.impute import SimpleImputer

# 📏 숫자 데이터의 범위를 0~1 사이로 맞추는 스케일링 도구
# → 변수 크기 차이로 인해 모델이 특정 변수에 치우치는 것을 방지
from sklearn.preprocessing import MinMaxScaler

# 🔍 하이퍼파라미터(모델 설정값)를 자동으로 탐색하는 도구
# → 사람이 직접 설정하지 않고, 성능이 좋은 조합을 찾아줌
from skopt import BayesSearchCV
```
	이 import 블록은 데이터를 깨끗하게 정리 → 모델에 학습 → 설정을 자동으로 최적화 → 예측  
	이 전체 과정을 자동화하기 위한 도구 모음입니다.
---
1️⃣ 문제에서 주어진 조건은 다음과 같습니다.

> 거래가 어떤 방식으로, 언제(월·일·요일·시간) 발생했는지가 주어질 때, 그 상황에서 이상 거래가 몇 건 나올지를 예측하라.

이걸 모델 입장에서 보면 이렇게 나뉩니다

🔹 입력값(X) — 상황 설명 : 모델이 미리 알고 있는 정보들입니다.
- 이체 방식
- 거래월
- 거래일
- 거래요일
- 거래시간
👉 거래가 발생한 ‘상황’을 설명하는 정보

🔹 출력값(Y) — 우리가 알고 싶은 답 : 모델이 맞혀야 하는 값입니다.
- 해당 상황에서 이상 거래가 몇 건 발생했는지

🔹 전처리 파이프라인이란?

머신러닝 모델은 숫자 계산으로 동작합니다.

##### ✅ `[D] 전처리 파이프라인 구성 (전처리) `: 전처리 파이프라인 구성

🔹 숫자 전처리
```python
pipe1 = make_pipeline(
    SimpleImputer(strategy='median')
)
```
이 코드는 뭐 하는 걸까?
	숫자 컬럼에 비어 있는 값(NaN)이 있으면 중앙값으로 채운다

왜 중앙값(median)을 쓸까?
	숫자 데이터에는 튀는 값(이상치) 이 자주 있음.

예:
```
거래시간: 1, 2, 3, 4, 23
```
- 평균(mean) → 6.6 ❌ (이상함)
- 중앙값(median) → 3 ⭕ (현실적)
    
👉 그래서 이상치에 덜 흔들리는 중앙값을 사용합니다.

`make_pipeline`의 역할
```python
make_pipeline(SimpleImputer(strategy='median'))
```
이건 말로 하면 이 뜻이에요 👇
> 앞으로 이 데이터가 들어오면 항상 이 규칙(중앙값 채우기)을 먼저 적용해라

- 학습할 때도
- 예측할 때도
- 나중에 새 데이터가 들어와도
    
👉 항상 같은 방식으로 처리되도록 고정

이 전처리가 적용되는 컬럼
- 거래월
- 거래일
- 거래시간
    
📌 공통점
- 숫자 컬럼
- 비어 있으면 계산 불가
- 중앙값으로 채워도 큰 문제 없음

즉, 숫자 데이터가 비어 있으면, 이상치에 덜 흔들리는 중앙값으로 자동으로 채우는 규칙을 만든 것입니다.

정리 문장:
숫자 컬럼에는 값이 비어 있는 경우가 있으므로, 모델 학습 전에 이를 처리해야 합니다.  
이 단계에서는 결측값이 발생하면 중앙값(median)으로 채우도록 규칙을 정의하고,  
이후 학습·예측 과정에서 항상 동일한 방식으로 적용되도록 파이프라인으로 구성합니다.

##### ✅ `[D] 전처리 파이프라인 구성 (전처리)` : 범주형 컬럼 처리용 pipe2
```python
from sklearn.preprocessing import OneHotEncoder

pipe2 = make_pipeline(
    SimpleImputer(strategy='most_frequent'),
    OneHotEncoder(handle_unknown='ignore')
)
```
이 파이프라인이 하는 일
	문자 데이터의 빈 값은 가장 많이 나온 값으로 채우고, 모델이 계산할 수 있도록 숫자로 바꾼다.

왜 이게 필요할까?
머신러닝 모델은 숫자만 이해합니다.
하지만 데이터에는 이런 값이 있음:
- 이체방식: `AT`, `MP`, `CCT`
- 거래요일: `Monday`, `Tuesday`
    
👉 그대로는 모델이 못 씀 → 전처리 필요


1단계: 결측치 처리 (문자 데이터)
```python
SimpleImputer(strategy='most_frequent')
```
- 비어 있으면 가장 자주 나온 값으로 채움
- 문자는 평균/중앙값 ❌ → 최빈값이 가장 안전 ⭕


예시
```
AT, AT, MP, (비어있음)
→ AT
```
	비어 있는 값은 AT로 채움 (가장 많이 등장했기 때문)

---
2단계: 문자 → 숫자 변환 (One-Hot Encoding)
```python
OneHotEncoder(handle_unknown='ignore')
```
문자에 순서·크기 의미를 주지 않고, 종류만 전달하기 위해 0/1로 바꿈

예:

| 이체방식 | AT  | MP  | CCT |
| ---- | --- | --- | --- |
| AT   | 1   | 0   | 0   |
| MP   | 0   | 1   | 0   |
| CCT  | 0   | 0   | 1   |
- 해당하면 1
- 아니면 0
    
📌 이렇게 하면
- 크기 비교 ❌
- 순서 의미 ❌
- 순수한 “종류” 정보만 전달 ⭕
    

`handle_unknown='ignore'`는 왜 필요할까?
```python
OneHotEncoder(handle_unknown='ignore')
```
- 학습 때 없던 값이
- 예측할 때 새로 나오면
    
👉 에러 없이 그냥 0 처리  
👉 실무·실시간 시스템에서 필수

정리하면,
문자 컬럼은 모델이 이해 못 하니까 빈 값은 최빈값으로 채우고,  
종류만 남기도록 0/1 숫자로 바꾼다.

| 새로운 이체방식 등장 | 새 장비 타입 추가       |

👉 실시간 시스템에서 필수 옵션

이 파이프라인이 적용되는 컬럼
`pipe2`는 아래 문자(범주형) 컬럼에 적용됩니다.
- 이체방식
- 거래요일

정리
> 문자로 이루어진 범주형 컬럼은 모델이 바로 이해할 수 없기 때문에 전처리가 필요하다.  
> 먼저 결측값이 있을 경우 가장 많이 등장한 값으로 채우고,  
> 이후 One-Hot Encoding을 사용해 각 범주를 숫자 형태로 변환한다.  
> 또한 예측 시 학습에 없던 값이 들어와도 오류가 발생하지 않도록 `handle_unknown='ignore'` 옵션을 사용한다.

🔹 `pipe3`는 뭐 하는 역할일까?
	지금까지 만든 규칙은 두 가지입니다.

- `pipe1` → 숫자 컬럼 전처리  
    (비어 있으면 중앙값으로 채움)
    
- `pipe2` → 문자(범주형) 컬럼 전처리  
    (비어 있으면 최빈값 + 문자 → 숫자)
    
하지만 실제 입력 데이터(X)는 숫자랑 문자가 섞여서 한 번에 들어옵니다.

그래서 `pipe3`가 필요함
`pipe3`는 이렇게 말할 수 있어요
	컬럼마다 맞는 전처리를 자동으로 골라서 적용해주는 관리자

##### ✅ `[D] 전처리 파이프라인 구성 (전처리)` : 컬럼별 전처리 결합 
```python
from sklearn.compose import make_column_transformer

pipe3 = make_column_transformer(
    (pipe1, ['거래월', '거래일', '거래시간']),
    (pipe2, ['이체방식', '거래요일'])
)
```
이 코드가 하는 일
- 숫자 컬럼은 pipe1로 처리하고,  
- 문자 컬럼은 pipe2로 처리한 뒤,  
 - 다시 하나로 합쳐서 모델에 전달한다.

괄호 구조 해석하기
```python
(pipe1, ['거래월', '거래일', '거래시간'])
```
이건 말 그대로: pipe1 규칙을 이 컬럼들에 적용해라 라는 뜻이고,

```python
(pipe2, ['이체방식', '거래요일'])
```
이건: pipe2 규칙을 이 컬럼들에 적용해라 라는 뜻입니다.

센서 데이터도 사실 구조가 비슷합니다.
- 숫자형: 온도, 압력, CO 농도…
- 범주형: 장비ID, 라인번호, 설비상태코드…

> 결과를 하나로 합쳐서 모델에 넣어라

정리하면:

- `pipe3`는 ColumnTransformer로, 여러 종류의 컬럼에 서로 다른 전처리를 자동 적용하기 위해 사용한다.  
- 숫자형 컬럼(거래월/거래일/거래시간)은 `pipe1` 규칙(중앙값으로 결측치 채우기)을 적용하고,  
- 범주형 컬럼(이체방식/거래요일)은 `pipe2` 규칙(최빈값 채우기 + 원핫 인코딩)을 적용한다.  

이렇게 하면 학습과 예측 과정에서 동일한 전처리가 자동으로 수행되어 실수와 중복 코드를 줄일 수 있다.

🔹 전처리 + 모델을 하나로 묶는다는 게 무슨 뜻일까?
	지금까지 우리는 이런 준비를 했어요.

1. 숫자 컬럼 전처리 규칙 (`pipe1`)
2. 문자 컬럼 전처리 규칙 (`pipe2`)
3. 컬럼별로 전처리 적용 (`pipe3`)

이제 마지막 질문이 남습니다.
	❓ 이 전처리를 언제, 어떻게 모델에 적용할까?

답은 단순합니다.
	모델에 넣기 전에 항상 적용되게 하자

그래서 전처리 + 모델을 하나로 묶는 것이 필요합니다.

##### ✅ `[E] 전처리 + 모델을 하나로 묶기 (학습 파이프라인)` :  최종 파이프라인
```python
from sklearn.ensemble import RandomForestRegressor

pipe_model = make_pipeline(
    pipe3,
    RandomForestRegressor()
)
```
이 코드가 하는 일을 말로 풀면
> 이 코드는 
> 전처리를 먼저 하고 → 그 다음 랜덤포레스트로 학습·예측한다는  
> 작업 순서를 미리 정해두는 코드입니다. 즉 이 시점까지는 빈 머신이라고 보면 됩니다.

🔹 `make_pipeline(pipe3, RandomForestRegressor())`의 의미: 이 한 줄이 하는 일
```
원본 X 데이터 (전처리를 전혀 하지 않은 상태의 입력 데이터)
 ↓
[pipe3]  ← 숫자/문자 전처리 자동 수행
 ↓
[RandomForestRegressor] ← 사용할 모델
```
👉 이 흐름을 순서만 정의한 상태


🔹 `pipe_model`이 한 덩어리라는 말의 진짜 의미

`pipe_model` 안에는 아직 학습 결과는 없고,
- 어떤 컬럼에
- 어떤 전처리를 적용할지 (`pipe3`)
- 어떤 모델을 사용할지 (`RandomForestRegressor`)
- 어떤 순서로 처리할지 (전처리 → 모델)

즉, 앞으로 학습하거나 예측할 때 이 순서와 이 규칙을 반드시 사용하겠다는 약속 묶음

##### ✅`[F] 하이퍼파라미터 튜닝 (학습/최적화)` : BayesSearchCV로 하이퍼 파라미터 튜닝
```python
from skopt.searchcv import BayesSearchCV

hyper = {
    'randomforestregressor__max_depth': (5, 10),
    'randomforestregressor__min_samples_leaf': (30, 50)
}

bayes_model = BayesSearchCV(
    pipe_model,
    hyper,
    cv=3,
    scoring='r2',
    n_iter=5,
    n_jobs=-1
)

bayes_model.fit(X_train, Y_train)
best_model = bayes_model.best_estimator_
```
전처리 + 모델을 묶은 뒤, 설정값을 자동으로 최적화하는 단계

앞 단계에서 우리는 이미 이것을 만들어 두었습니다.
- 컬럼별 전처리 규칙 (`pipe3`)
- 전처리 → 모델 적용 순서 (`pipe_model`)
    
이제 모델에게 묻는 질문이 바뀝니다.

> ❓ 이 구조는 유지하되,  
> 모델 설정값은 어떻게 해야 가장 잘 맞을까?

이 질문에 답해주는 단계가 하이퍼파라미터 튜닝입니다.

❓ 하이퍼파라미터란 무엇인가?
하이퍼파라미터는 모델이 학습하기 전에 사람이 정해줘야 하는 설정값입니다.

RandomForest 예시:
- 트리를 얼마나 깊게 만들까?
- 한 갈래(leaf)에 최소 몇 개의 데이터가 있어야 할까?
    
이 값들은
- 너무 작으면 → 과적합
- 너무 크면 → 패턴을 못 배움
    
👉 데이터에 맞는 적당한 값을 찾아야 합니다.

---
### 코드 해석
```python
from skopt.searchcv import BayesSearchCV
```
BayesSearchCV는 말 그대로 여러 설정을 무작정 다 해보지 말고, 성능이 좋아질 가능성이 높은 쪽을 중심으로 똑똑하게 실험해주는 도구입니다.

튜닝 대상 설정값(hyper) 살펴보기
```python
hyper = {
    'randomforestregressor__max_depth': (5, 10),
    'randomforestregressor__min_samples_leaf': (30, 50)
}
```
① `randomforestregressor__`가 붙는 이유
- 우리는 파이프라인을 튜닝 중입니다.
- 파이프라인 안에는:
    - `pipe3`
    - `RandomForestRegressor`
        
그래서 이 뜻은 파이프라인 안에 있는 `RandomForestRegressor`의 `max_depth`를 조정해
`__`는 안에 들어 있는 객체의 옵션”을 지정하는 문법

② 각 하이퍼파라미터의 의미
- `max_depth`
    - 트리의 최대 깊이
    - 너무 깊으면 데이터를 외워버림(과적합)
        
- `min_samples_leaf`
    - 하나의 잎 노드에 남길 최소 데이터 수
    - 너무 작으면 노이즈까지 학습
        
👉 둘 다 과적합을 막기 위한 핵심 제어 장치

---
BayesSearchCV 설정 코드 해석
```python
bayes_model = BayesSearchCV(
    pipe_model,
    hyper,
    cv=3,
    scoring='r2',
    n_iter=5,
    n_jobs=-1
)
```
이 코드를 말로 풀면:
- `pipe_model`
    - 튜닝 대상은 전처리 + 모델 전체
        
- `hyper`
    - 시험해볼 설정값 범위
        
- `cv=3`
    - 데이터를 3조각으로 나눠
    - 번갈아가며 학습/검증
        
- `scoring='r2'`
    - 성능 판단 기준은 R² 점수
        
- `n_iter=5`
    - 설정 조합을 5번 실험
        
- `n_jobs=-1`
    - CPU 전부 사용 (속도 ↑)
    - scikit-learn은 GPU 미지원이며 CPU기반 라이브러리입니다.

사이킷런이 CPU만 써도 대부분 문제 없지만, OneHot 폭발 / 대용량 트리모델 / CV 반복 같은 조건이면 느려질 수 있어요. 그건 GPU가 없어서가 아니라 문제 구조가 무거워서입니다.
그래서 사이킷런=CPU만이어도 많은 경우 충분히 빠르고 실무에서도 엄청 많이 씁니다.

---
실제 학습 + 튜닝이 일어나는 순간
```python

```
이 한 줄에서 실제로 벌어지는 일:
1. X_train이 들어옴
2. `pipe3` 전처리 수행

4. 학습
5. 검증
6. 점수 기록
7. 다시 다른 설정값으로 반복
    
👉 이 과정을 BayesSearchCV가 자동으로 관리

##### ✅ `[G] 성능 평가 (평가)` : 학습 데이터 / 검증 데이터에 대한 예측 수행
```python
Y_train_pred = best_model.predict(X_train)
Y_test_pred = best_model.predict(X_test)
```
의미
- 학습 데이터
    - 모델이 이미 본 데이터
    - 얼마나 잘 외웠는지 확인
        
- 검증 데이터
    - 모델이 처음 보는 데이터
    - 실제로 써먹을 수 있는지 확인

`predict`는 이미 학습된 모델에게 "이 입력 데이터에 대한 답을 내놔라"라고 요청하는 메서드입니다.

머신러닝의 3단계 메서드로 보면 머신러닝 모델은 보통 이 3단계로 사용됩니다.

|단계|메서드|의미|
|---|---|---|
|① 설계|`make_pipeline()`|처리 순서 정의|
|② 학습|`fit(X, y)`|데이터로 패턴 학습|
|③ 예측|`predict(X)`|새로운 데이터에 대한 답 생성|

---
최종 성능 출력
```python
print('학습 데이터 결정 계수 : ', r2_score(Y_train, Y_train_pred))
print('학습 데이터 MSE : ', mean_squared_error(Y_train, Y_train_pred))

print('검증 데이터 결정 계수 : ', r2_score(Y_test, Y_test_pred))
print('검증 데이터 MSE : ', mean_squared_error(Y_test, Y_test_pred))
```

결과
```
학습 데이터 결정 계수 : 0.2926
학습 데이터 MSE : 2.1359

검증 데이터 결정 계수 : 0.2598
검증 데이터 MSE : 2.0081
```
결과 해석
- 학습 데이터
    - 모델이 과거 데이터의 패턴을 약 29% 정도 설명함
        
- 검증 데이터
    - 처음 보는 데이터에서도 약 26% 정도 설명함
        
✔️ 둘 다 0보다 충분히 큼  
✔️ 완전히 랜덤은 아님

쉽게 이해하기
- R² ≈ 0.0 → 거의 의미 없음 ❌
- R² ≈ 0.2 ~ 0.3 → 패턴은 조금 잡음 ⭕
- R² ≈ 0.6 이상 → 꽤 잘 맞춤
    
👉 이 모델은 약 0.29 정도로
“완벽하지는 않지만, 패턴은 분명히 일부 잡고 있다” 수준

MSE 해석 — “얼마나 크게 틀렸나?” (예측이 실제 값과 얼마나 많이 어긋났는지의 평균)
- 작을수록 좋음
- 단위는 “오차²”

- 학습 데이터 : 2.1359
- 검증 데이터 : 2.0081

쉽게 해석하면:
- 평균적으로 약 2 정도의 오차 제곱
- 실제 오차 크기로 생각하면  
    → 대략 1~2건 정도 차이라고 보면 됨
    
✔️ 학습과 검증 MSE가 비슷함  
✔️ 검증이 오히려 약간 더 낮음
