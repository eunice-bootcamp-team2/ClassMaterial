목표
	거래 상황 정보를 입력했을 때, 이상 거래 발생 수준을 예측할 수 있는 회귀 모델을 구성한다.

즉,
- 거래 조건이 주어졌을 때  
- 이상 거래가 얼마나 발생할 가능성이 있는지 추정하는 것이 목적입니다.

---
✅ 02단계: 과거를 이해하는 단계 (분석)

이 단계에서는 데이터를 정리하고 관찰합니다.
- 이상 거래 데이터를 날짜 기준으로 정리
- 어떤 시점에서 이상 거래가 많았는지 확인
    
핵심 질문:
	❓ 과거에는 이상 거래가 언제 많이 발생했는가?
    
이 단계의 역할
- 데이터 현상 파악
- 패턴을 눈으로 확인하는 단계
- 문제의 특징을 이해하는 과정
---
✅ 3단계: 데이터를 점검하는 단계 (검증)

이 단계에서는 데이터를 바로 믿지 않고 검사합니다.
- 특정 이체 방식의 시계열이 지나치게 불규칙하지 않은지
- 완전히 랜덤 데이터는 아닌지 확인
- 정상성 검정 등을 활용
    
핵심 질문:
	❓ 이 데이터는 예측에 사용할 수 있는 상태인가?

이 단계의 역할
- 데이터 상태 점검
- 예측 모델 적용 가능성 확인
- 분석의 안전장치
    
여기서 정상성을 확인했다는 말의 진짜 의미
- 데이터가 완벽하다는 뜻은 아닙니다.
- 패턴을 학습할 여지는 있다는 최소 조건을 만족했다는 뜻입니다.
---
✅ 04단계 (지금 단계): 미래를 대비하는 단계 (예측)

이제 분석의 관점이 바뀝니다.

이전 단계 질문:
- 과거에는 언제 이상 거래가 많았는가? (02단계)
- 데이터는 예측에 적합한가? (03단계)

이제는 이렇게 묻습니다:
	❓ 앞으로, 특정 거래 상황이 주어졌을 때 이상 거래가 몇 건이나 발생할까?

이 질문에 답하기 위해 예측 모델을 만듭니다.
- 예측 모델 구성
- 미래 위험 추정
- 의사결정 지원

현재까지의 흐름
```
과거 이해 → 데이터 검증 → 미래 예측
```

✅ Baseline 모델이란 무엇인가?

Baseline = 비교 기준 모델입니다. 
즉,
- 이 정도 성능은 최소한 나와야 한다
- 지금 모델이 잘 만든 건지 판단하기 위한 기준선

왜 Baseline이 필요할까?
모델 성능은 숫자로 나오는데  
그 숫자가 좋은지 나쁜지 판단 기준이 필요합니다.

예를 들어:
- R² = 0.32  이게 좋은 걸까요? 나쁜 걸까요?
비교 대상이 없으면 판단이 불가합니다.

그래서 Baseline을 먼저 둡니다.

Baseline 모델 선택 원칙:
	처음부터 어려운 모델을 선택하지 말고
	단순 → 조금 똑똑 → 복잡 순서로 비교

1️⃣ DummyRegressor (최저 기준선)
	가장 단순한 모델입니다.

이 모델은:
✔ 아무것도 학습하지 않음  
✔ 항상 평균값만 예측

이 모델은 아무 생각 없이 평균으로 찍으면 이 정도 점수 나오는 모델입니다.

2️⃣ LinearRegression / Ridge (기본 구조 학습)
	조금 더 똑똑한 모델입니다.

이모델은:
✔ 변수 간 선형 관계 학습  
✔ 가장 기본적인 패턴 학습

이 모델은 데이터가 단순한 규칙이라면 이 모델로 충분합니다.

3️⃣ RandomForestRegressor (비선형 학습 가능)
	조금 더 복잡한 모델입니다.

이모델은:
✔ 복잡한 패턴 학습 가능  
✔ 비선형 관계 대응 가능

이 모델은 현실 데이터의 굴곡 있는 패턴 대응에 적합합니다.

모델 선택을 쉽게 기억하는 법
모델 성능 평가는 시험 점수 비교와 같습니다.

| 모델                    | 한글 이름         | 의미                           |
| --------------------- | ------------- | ---------------------------- |
| DummyRegressor        | 더미 회귀 모델      | 아무 학습 없이 평균값만 예측하는 기준 모델     |
| LinearRegression      | 선형 회귀 모델      | 변수 간 직선 관계를 학습하는 가장 기본 회귀 모델 |
| RandomForestRegressor | 랜덤 포레스트 회귀 모델 | 여러 의사결정나무를 이용하는 비선형 회귀 모델    |

모델 종류를 이해했다면 이제 중요한 질문이 남습니다.

❓ 그 모델에게 무엇을 학습시킬 것인가?

머신러닝 모델은 아무 데이터나 넣는다고 동작하지 않습니다.  
먼저 문제를 수학적으로 정의된 형태로 바꾸는 작업이 필요합니다.

즉,
- 어떤 정보를 입력(X)으로 사용할 것인지
- 무엇을 정답(Y)으로 예측할 것인지
    
이 구조를 명확히 정해야 합니다.

이 단계가 바로 문제 정의 단계이며,  
모델 선택보다 더 중요한 출발점입니다.

왜냐하면,
✔ 같은 모델이라도  
✔ 어떤 컬럼을 X / Y로 설정하느냐에 따라  
✔ 완전히 다른 문제가 되기 때문입니다.

예를 들어,
- 거래 시간 / 요일 / 방식 → 이상 거래 "건수" 예측 → 회귀 문제
- 거래 정보 → 정상 / 이상 여부 예측 → 분류 문제 처럼 문제 성격 자체가 바뀌게 됩니다.

그래서 회귀 모델을 만들 때 가장 먼저 해야 할 일은 컬럼(변수) 역할을 고정하는 것입니다.

이제 회귀 모델 개발의 표준적인 코드 패턴을 살펴보겠습니다.

---
1️⃣ 문제를 먼저 정합니다 (가장 중요합니다)

모델을 만들기 전에 반드시 결정해야 합니다.
- 무엇을 입력(X)으로 사용할지
- 무엇을 정답(Y)으로 예측할지
    
간단 기준:
- X = 상황 설명 정보
- Y = 맞히고 싶은 숫자 값
    
👉숫자를 예측하는 문제인가? → 회귀 문제입니다

---
2️⃣ 데이터를 확인합니다 (바로 학습하지 않습니다)
	데이터를 불러온 뒤 바로 모델에 넣지 않습니다.

최소한 아래는 확인합니다.
- 데이터가 잘 읽혔는지
- 컬럼 구조가 정상인지
- 비어 있는 값이 있는지
    
기본 확인 방법:
- `df.head()`
- `df.info()`
- `df.isna().sum()`
    
👉 데이터 상태를 눈으로 점검하는 단계입니다.

---
3️⃣ 학습 가능한 형태로 데이터를 정리합니다
	원본 로그 데이터는 그대로 쓰기 어려운 경우가 많습니다.

그래서 보통:
- groupby
- pivot_table 등을 사용해서

✔ 1행 = 하나의 상황 형태로 만듭니다.
	모델이 이해하기 쉬운 표 형태로 변환하는 단계입니다.

---
4️⃣ 입력(X)과 정답(Y)을 나눕니다
	모델이 볼 정보와 맞힐 값을 분리합니다.
- X → 참고할 정보
- Y → 예측할 값
    
주의:
	X에는 미래에도 알 수 있는 정보만 사용합니다.

---
5️⃣ 학습용 / 시험용 데이터를 나눕니다 (필수 단계입니다)

모델 성능을 확인하려면 데이터를 나눠야 합니다.
- 일부 → 학습(train)
- 일부 → 검증(test)

---
6️⃣ 전처리를 합니다 (데이터 정리 규칙 만들기)
	모델은 숫자 계산만 할 수 있습니다.

그래서:
- 숫자 컬럼 → 결측값 처리
- 문자 컬럼 → 숫자로 변환
- 날짜 컬럼 → 의미 있는 숫자로 변환등의 작업을 합니다.

👉 데이터를 모델이 계산 가능하게 만드는 단계입니다.

---
7️⃣ 전처리와 모델을 하나로 묶습니다 (Pipeline)

실무에서는 반드시 함께 묶습니다.

이유:
✔ 학습할 때와 예측할 때 동일한 처리 보장  
✔ 실수 방지  
✔ 저장 / 재사용 용이

---
8️⃣ Baseline 모델로 성능을 비교합니다
	처음부터 복잡한 모델을 사용하지 않습니다.

회귀 모델은 처음부터 복잡한 모델로 시작하지 않습니다.  
성능 비교 기준이 될 기본 모델(Baseline)부터 정합니다.

Baseline을 두는 이유
- 지금 모델이 잘 만든 건지 판단하기 위해
- 아무렇게나 찍어도 나오는 점수보다 나은지 확인하기 위해

회귀모델은 아주 많이 존재합니다.
예를 들어
- LinearRegression
- Ridge / Lasso / ElasticNet
- DecisionTreeRegressor
- RandomForestRegressor
- GradientBoostingRegressor
- XGBoost / LightGBM / CatBoost
- SVR
- Neural Network(MLPRegressor)
- … 등등
👉 수십 개 이상 있음

---
그러나 모델의 종류에서 베이스라인 모델 선택이란?
여러 회귀모델 중에서  난이도가 다른 모델들을 비교 기준으로 삼아  
데이터에 맞는 모델을 고르는 과정입니다.

✅ 추천 Baseline 순서
1. DummyRegressor  
    → 항상 평균값으로 예측 (최저 기준선)
    
2. LinearRegression / Ridge  
    → 단순한 선형 관계 학습
    
3. RandomForestRegressor  
    → 비선형 패턴까지 학습 가능

✔️ 항상 질문해야 함  
	이 모델이 Baseline보다 좋아졌는가?

그래서 Baseline 모델 선택은 난이도가 다른 모델들을 기준으로 비교해  
이 데이터에 맞는 모델을 고르는 과정입니다.

---
9️⃣ 모델 성능을 평가합니다
	시험 데이터(test)에 대해 예측을 수행하고 점수를 확인합니다.

대표 지표:
- R² (결정계수) → 얼마나 잘 설명하는지
- MSE → 얼마나 틀렸는지
    
👉 모델이 실제로 쓸 수 있는지 판단하는 단계입니다.

평가 지표는 왜 필요한가?
모델의 답이 맞는지 숫자로 판단해야 하기 때문입니다
그래서 점수표가 필요합니다.

추가자료 확인하기 바로가기 링크 🔗 [[8 모델 학습 및 평가 - 모델 학습 및 검증]]

우리가 모델을 선택할때 봐야하는 대표적인 회귀 성능 지표

🔹 R² (결정계수)
	이 모델이 전체 패턴을 얼마나 설명했는가?

- 높을수록 좋다
- 1에 가까울수록 잘 설명
- 0이면 평균으로 찍은 것과 비슷
- 음수면 평균보다도 못함
    
👉 모델의 설명력 점수

🔹 MSE / MAE (오차 크기)
	얼마나 크게 틀렸는가?

- 작을수록 좋다
- 단위는 Y의 단위 기준
- MSE는 큰 실수에 더 큰 벌점
    
👉 실수의 크기를 보는 점수

그래서 이렇게 판단하는것이 중요합니다.
① Baseline과 비교
- DummyRegressor보다 좋나?
- Linear보다 좋아졌나?
    
② train / test 비교
- train만 좋고 test 나쁘면 ❌
- 둘 다 안정적이면 ⭕
    
③ 모델 간 비교

| 모델           | R²(test) | MSE(test) |
| ------------ | -------- | --------- |
| Dummy        | 0.00     | 15.2      |
| Linear       | 0.32     | 9.8       |
| RandomForest | 0.61     | 4.1       |
그래서 우리는 성능 지표를 통한 모델간의 비교를 통해 RandomForest 선택합니다.

🔟 모델을 저장합니다
	학습이 끝난 모델은 파일로 저장합니다.

이유:
✔ 다시 학습할 필요 없음  
✔ 서비스 / API에서 바로 사용 가능

---
✅ 핵심 기억 공식

회귀 모델 개발은 아래 순서로 진행됩니다.
```
문제 정의 → 데이터 확인 → 데이터 정리 → X/Y 분리  
→ 학습/검증 분리 → 전처리 → Pipeline → 모델 학습  
→ 성능 평가 → 저장
```

---
✅ 가장 중요한 한 문장

회귀 모델은 아무 데이터나 넣는 것이 아니라,  
정리된 데이터와 명확한 문제 정의가 먼저 필요합니다.

---

회귀모델 코드 뼈대 템플릿 (이 순서 그대로 쓰면 됨)
```python
# 1) 문제정의(컬럼 고정)
X_COLS = [...]
Y_COL = "..."

# 2) 데이터 확인
# df.head(), df.info(), df.isna().sum()

# 3) 문제 형태 만들기 (groupby/pivot 등)
# df_model = ...

# 4) X/Y 분리
X = df_model[X_COLS]
y = df_model[Y_COL]

# 5) split 데이터를 학습용과 시험용으로 나누는 작업
from sklearn.model_selection import train_test_split
X_train, X_test, y_train, y_test = train_test_split(...)

# 6) preprocess 전처리
from sklearn.compose import make_column_transformer
from sklearn.pipeline import make_pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder

# 먼저 컬럼을 나눈다 (가장 중요)
num_cols = [...]
cat_cols = [...]


preprocess = make_column_transformer(
	
	# 숫자 컬럼 전처리 규칙
    (make_pipeline(SimpleImputer(strategy="median")), num_cols),
    
    # 범주형 컬럼 전처리 규칙
    (make_pipeline(SimpleImputer(strategy="most_frequent"),
				   
				   # 예측 시 처음 보는 값이 나와도 에러 없이 넘어가라
                   OneHotEncoder(handle_unknown="ignore")), cat_cols)
)

# 7) model pipeline 전처리 + 모델을 하나로 묶는 단계
from sklearn.ensemble import RandomForestRegressor
pipe = make_pipeline(preprocess, RandomForestRegressor(random_state=1234))


# 8-1) Baseline 모델 선택
# Baseline 모델 = 이 정도는 나와야 한다는 최소 기준선


# 8-2) fit 학습
pipe.fit(X_train, y_train)

# 9) eval 평가 지표 고정 + 해석 
# 시험 데이터(X_test)로 예측을 해보고 점수로 모델 성능을 판단하는 단계
from sklearn.metrics import r2_score, mean_squared_error
pred = pipe.predict(X_test)
print("R2:", r2_score(y_test, pred))
print("MSE:", mean_squared_error(y_test, pred))

# 10) save 저장
import pickle
pickle.dump(pipe, open("model.sav", "wb"))

# 11) 재검증/해석 단계
# - 저장된 모델(전처리+모델)이 "무엇을 보고 예측했는지" 확인
# - 점수(R2/MSE)만으로는 알 수 없는 모델의 판단 근거(중요 변수) 점검
# - 배포(API) 전에 sanity check 용도로 자주 사용

import pandas as pd

df_importance = pd.DataFrame()
df_importance["Feature"] = pipe["columntransformer"].get_feature_names_out()
df_importance["Importance"] = pipe["randomforestregressor"].feature_importances_

df_importance = df_importance.sort_values("Importance", ascending=False)
print(df_importance.head(20))
```

```python
# =========================================================
# ✅ [0] 목표: "거래 상황 정보(X)" -> "이상거래 발생 건수(Y)" 예측하는 회귀 모델
# =========================================================
# ✅ 매핑:
#   - 뼈대(1~10) : (0은 준비 단계, 1부터 본격)
#   - 흐름도(A~I): [A]~[I]
#   - 섹션표기([0]~[I]): [0]~[I]
# =========================================================

# ---------------------------------------------------------
# (0) 준비 단계 / [0] / (해당 흐름도 단계 없음 - 전체 준비)
#   - 라이브러리 불러오기
# ---------------------------------------------------------
# 분석·학습에 필요한 라이브러리 불러오기
import pandas as pd
import pickle


# ---------------------------------------------------------
# (3) 문제 형태 만들기 / [A] 집계 전처리 / (A) 집계 전처리: pivot_table
#   - 원본 로그 df1 -> "상황 1개당 이상거래 건수" 테이블(p3) 생성
# ---------------------------------------------------------
# -------------------------------
# ✅ [A] 집계 전처리(문제 형태 만들기)
#   - 여러 거래 로그(df1)를
#   - "상황 1개당 이상거래 총 몇 건?" 형태(p3)로 변환
# -------------------------------
# df1: 원본 거래 로그 DataFrame (너가 미리 준비해야 하는 데이터)
# 필수 컬럼 예시: ['이체방식','거래월','거래일','거래요일','거래시간','이상거래여부']

p3 = df1.pivot_table(
    index=['이체방식', '거래월', '거래일', '거래요일', '거래시간'],
    values='이상거래여부',
    aggfunc='sum'
).reset_index()


# ---------------------------------------------------------
# (4) X/Y 분리 / [B] 입력(X)/정답(Y) 분리 / (B) 입력(X)/정답(Y) 분리
# ---------------------------------------------------------
# -------------------------------
# ✅ [B] 학습용 입력(X) / 정답(Y) 분리  (전처리의 일부)
# -------------------------------
X = p3[['이체방식', '거래월', '거래요일', '거래일', '거래시간']]
Y = p3['이상거래여부']  # "이상거래 건수" (숫자) -> 회귀 문제



# ---------------------------------------------------------
# (5) split (학습/검증 분리) / [C] 학습/검증 분리 / (C) train_test_split
# ---------------------------------------------------------
# -------------------------------
# ✅ [C] 학습/검증 데이터 분리 (학습 준비)
# -------------------------------
from sklearn.model_selection import train_test_split

X_train, X_test, Y_train, Y_test = train_test_split(
    X, Y, test_size=0.3, random_state=42
)
# ✔ 0.2 (가장 많이 사용)  
# ✔ 0.25 / 0.3 (데이터 충분할 때)



# ---------------------------------------------------------
# (6) preprocess (전처리 설계/구성) / [D] 전처리 파이프라인 / (D) pipe1~pipe3 구성
#   - (D-1) pipe1: 숫자 결측 처리(median)
#   - (D-2) pipe2: 범주 결측 처리(most_frequent) + 원핫
#   - (D-3) pipe3: ColumnTransformer로 컬럼별 전처리 결합
# ---------------------------------------------------------
# -------------------------------
# ✅ [D] 전처리 파이프라인 구성 (전처리)
#   - 숫자 컬럼: 결측치 -> 중앙값
#   - 범주 컬럼: 결측치 -> 최빈값, 문자 -> 원핫인코딩(숫자화)
# -------------------------------
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder
from sklearn.compose import make_column_transformer
from imblearn.pipeline import make_pipeline

# 숫자 전처리(결측치 중앙값)
pipe1 = make_pipeline(
    SimpleImputer(strategy='median')
)

# 범주 전처리(결측치 최빈값 + 원핫인코딩)
pipe2 = make_pipeline(
    SimpleImputer(strategy='most_frequent'),
    OneHotEncoder(handle_unknown='ignore')
)

# 컬럼별로 다른 전처리 적용 후 합치기
pipe3 = make_column_transformer(
    (pipe_num, ['거래월', '거래일', '거래시간']),
    (pipe_cat, ['이체방식', '거래요일'])
)


# ---------------------------------------------------------
# (7) 전처리 + 모델 Pipeline으로 묶기 / [E] 학습 파이프라인 / (E) pipe_model 구성
#   - 전처리(pipe3 또는 preprocess) + 모델(RandomForestRegressor) 결합
# ---------------------------------------------------------
# -------------------------------
# ✅ [E] 전처리 + 모델을 하나로 묶기 (학습 파이프라인)
# -------------------------------
from sklearn.ensemble import RandomForestRegressor

pipe_model = make_pipeline(
    pipe3,
    RandomForestRegressor()
)


# ---------------------------------------------------------
# (8-학습+튜닝) 하이퍼파라미터 튜닝을 포함한 학습 / [F] 튜닝 / (F) BayesSearchCV
#   - 기존 단순 학습(pipe_model.fit) 대신
#     하이퍼파라미터 튜닝을 포함한 학습을 수행
#   - 여러 설정을 반복 학습하여
#     가장 성능이 좋은 파이프라인(best_model)을 선택
# ---------------------------------------------------------
# -------------------------------
# ✅ [F] 하이퍼파라미터 튜닝 기반 학습 (학습 + 최적화)
#   - BayesSearchCV가 여러 조합을 시험하고
#     최적의 전처리+모델 파이프라인을 선택
# -------------------------------
from skopt.searchcv import BayesSearchCV

hyper = {
    'randomforestregressor__max_depth': (5, 10),
    'randomforestregressor__min_samples_leaf': (30, 50),
}

bayes_model = BayesSearchCV(
    pipe_model,
    search_spaces=hyper,
    cv=3,
    scoring='r2',
    n_iter=5,
    n_jobs=-1,
    random_state=1234
)

bayes_model.fit(X_train, Y_train)
best_model = bayes_model.best_estimator_


# ---------------------------------------------------------
# (9) eval (평가) / [G] 성능 평가 / (G) train/test 성능 확인
# ---------------------------------------------------------
# -------------------------------
# ✅ [G] 성능 평가 (평가)
#   - train(본 문제) vs test(처음 보는 문제) 점수 비교
# -------------------------------
from sklearn.metrics import r2_score, mean_squared_error

Y_train_pred = best_model.predict(X_train)
Y_test_pred  = best_model.predict(X_test)

print("[TRAIN] R2 :", r2_score(Y_train, Y_train_pred))
print("[TRAIN] MSE:", mean_squared_error(Y_train, Y_train_pred))

print("[TEST ] R2 :", r2_score(Y_test, Y_test_pred))
print("[TEST ] MSE:", mean_squared_error(Y_test, Y_test_pred))


# ---------------------------------------------------------
# (10-저장 필수) 모델 저장 / [H] 저장 / (H) pickle 저장
# ---------------------------------------------------------
# -------------------------------
# ✅ [H] 모델 저장 (배포/재사용 준비)
#   - best_model 안에 "전처리 + 모델"이 통째로 들어있음
# -------------------------------
pickle.dump(best_model, open('model_RF_regressor.sav', 'wb'))


# ---------------------------------------------------------
# (11) 재검증/해석 단계 / [I] 해석 / (I) Feature Importance
#
# 목적:
#   - 학습이 끝난 최종 모델(best_model)이
#     어떤 입력 변수를 중요하게 사용했는지 확인
#   - 모델 저장 후(API/재사용 시)에도
#     "이 모델이 무엇을 보고 판단하는지" 설명 가능하게 하기 위함
#   - 성능 점수(R2/MSE)만으로는 알 수 없는
#     모델의 내부 판단 기준을 해석하는 단계
# ---------------------------------------------------------
# -------------------------------
# ✅ [I] 변수 중요도 해석 (모델 해석/검증 단계)
#   - 전처리 이후 실제 모델이 사용하는 feature 이름 추출
#   - 각 feature가 예측에 기여한 상대적 중요도 확인
# -------------------------------
df_importance = pd.DataFrame()
df_importance['Feature'] = best_model['columntransformer'].get_feature_names_out()
df_importance['Importance'] = best_model['randomforestregressor'].feature_importances_

# 중요도가 높은 변수부터 정렬
df_importance = df_importance.sort_values('Importance', ascending=False)

# 상위 20개 중요 변수 확인
print(df_importance.head(20))
```

🔹 전처리 파이프라인이란?

머신러닝 모델은 숫자 계산으로 동작합니다.  
그런데 실제 데이터에는 이런 문제가 자주 있습니다.

- 값이 비어 있음 (`NaN`)

그래서 모델에 넣기 전에 반드시 해야 할 일이 있습니다.
> 비어 있는 값을 어떻게 처리할지 정하는 것 
> 이걸 전처리(preprocessing) 라고 합니다.

🔹 지금 전처리 파이프라인코드가 하는 일 한 줄 요약
> 숫자 컬럼에 값이 비어 있으면 중앙값(median)으로 자동 채우는 규칙을 만든다

클래스 불균형 데이터 처리용 라이브러리 설치: 터미널에서

```python
from sklearn.impute import SimpleImputer
```

##### ✅ `[D] 전처리 파이프라인 구성 (전처리) `: 전처리 파이프라인 구성

🔹 숫자 전처리
```python
pipe1 = make_pipeline(
    SimpleImputer(strategy='median')
)
```
이 코드는 뭐 하는 걸까?
	숫자 컬럼에 비어 있는 값(NaN)이 있으면 중앙값으로 채운다

왜 중앙값(median)을 쓸까?
	숫자 데이터에는 튀는 값(이상치) 이 자주 있음.

예:
```
거래시간: 1, 2, 3, 4, 23
```
- 평균(mean) → 6.6 ❌ (이상함)
- 중앙값(median) → 3 ⭕ (현실적)
    
👉 그래서 이상치에 덜 흔들리는 중앙값을 사용합니다.

`make_pipeline`의 역할
```python
make_pipeline(SimpleImputer(strategy='median'))
```
이건 말로 하면 이 뜻이에요 👇
> 앞으로 이 데이터가 들어오면 항상 이 규칙(중앙값 채우기)을 먼저 적용해라

- 학습할 때도
- 예측할 때도
- 나중에 새 데이터가 들어와도
    
👉 항상 같은 방식으로 처리되도록 고정

`SimpleImputer` : 비어 있는 값(NaN)을 자동으로 채워주는 도구
- 숫자 컬럼 → 중앙값 / 평균값 등으로 채움
- 문자 컬럼 → 가장 많이 나온 값으로 채움
✔ 목적: 결측치 때문에 모델 오류 나는 것 방지

`make_pipeline` : 여러 작업 단계를 순서대로 묶는 도구
예: 전처리 → 모델 학습 → 예측 처럼 작업 흐름을 하나로 연결
✔ 목적: 학습과 예측 시 동일한 순서 보장 / 실수 방지

`make_pipeline(SimpleImputer(...))` : 결측치 처리 과정을 파이프라인 단계로 넣는 것으로 
                                 데이터가 들어오면 먼저 빈칸부터 채워라는 뜻입니다.

이 전처리가 적용되는 컬럼
- 거래월
- 거래일
- 거래시간
    
📌 공통점
- 숫자 컬럼
- 비어 있으면 계산 불가
- 중앙값으로 채워도 큰 문제 없음

즉, 숫자 데이터가 비어 있으면, 이상치에 덜 흔들리는 중앙값으로 자동으로 채우는 규칙을 만든 것입니다.

| 거래시간 누락 | 센서 순간 결측     |
| 거래일 누락  | 통신 오류        |

정리 문장:
숫자 컬럼에는 값이 비어 있는 경우가 있으므로, 모델 학습 전에 이를 처리해야 합니다.  
이 단계에서는 결측값이 발생하면 중앙값(median)으로 채우도록 규칙을 정의하고,  
이후 학습·예측 과정에서 항상 동일한 방식으로 적용되도록 파이프라인으로 구성합니다.

##### ✅ `[D] 전처리 파이프라인 구성 (전처리)` : 범주형 컬럼 처리용 pipe2
```python
from sklearn.preprocessing import OneHotEncoder

pipe2 = make_pipeline(
    SimpleImputer(strategy='most_frequent'),
    OneHotEncoder(handle_unknown='ignore')
)
```
이 파이프라인이 하는 일
	문자 데이터의 빈 값은 가장 많이 나온 값으로 채우고, 모델이 계산할 수 있도록 숫자로 바꾸는 일을 합니다.

왜 이게 필요할까?
머신러닝 모델은 숫자만 이해합니다.
하지만 데이터에는 이런 값이 있음:
- 이체방식: `AT`, `MP`, `CCT`
- 거래요일: `Monday`, `Tuesday`
    
👉 그대로는 모델이 못 씀 → 전처리 필요합니다.


1단계: 결측치 처리 (문자 데이터)
```python
SimpleImputer(strategy='most_frequent')
```
- 비어 있으면 가장 자주 나온 값으로 채움
- 문자는 평균/중앙값 ❌ → 최빈값(가장 많이 등장한 값)이 가장 안전 ⭕

예시
```
AT, AT, MP, (비어있음)
→ AT
```
	비어 있는 값은 AT로 채움 (가장 많이 등장했기 때문)

---
2단계: 문자 → 숫자 변환 (One-Hot Encoding)
```python
OneHotEncoder(handle_unknown='ignore')
```
문자에 순서·크기 의미를 주지 않고, 종류만 전달하기 위해 0/1로 바꿈니다.
One-Hot Encoding의 목적은 문자를 숫자로 바꾸되, 의미 왜곡을 막는 방법입니다.

| 이체방식    |
| ------- |
| AT = 1  |
| MP = 2  |
| CCT = 3 |
이걸 억지로 숫자로 바꾸면 오델 입장에서는 
- 3이 1보다 크다?
- 2가 1보다 크다?
존재하지 않는 크기 / 순서 의미가 생겨서 오류가 발생할수 있습니다.

###### 그래서 One-Hot 방식은 이렇게 해결합니다
| 이체방식 | AT  | MP  | CCT |
| ---- | --- | --- | --- |
| AT   | 1   | 0   | 0   |
| MP   | 0   | 1   | 0   |
| CCT  | 0   | 0   | 1   |
- 해당하면 1
- 아니면 0
    
모델이 보는 값은 이제 이런 형태입니다.
- AT 컬럼 → 0 또는 1
- MP 컬럼 → 0 또는 1
- CCT 컬럼 → 0 또는 1

여기에는:
✔ 누가 더 크다 의미 없음  
✔ 순서 개념 없음  
✔ 그냥 해당 여부만 존재


`handle_unknown='ignore'`는 왜 필요할까?
```python
OneHotEncoder(handle_unknown='ignore')
```
이 옵션은 예측 단계에서 발생할 수 있는 오류를 막기 위해 사용합니다.

머신러닝 모델은 학습할 때 본 값들만 기억합니다.  
그런데 실제 서비스 환경에서는 학습 데이터에 없던 새로운 값이 등장할 수 있습니다.

예를 들어,
- 학습 데이터에는 `AT`, `MP`만 있었는데
- 예측 시점에 `CCT`라는 새로운 이체방식이 들어오는 경우
    
기본 설정이라면 모델이 오류를 발생시키게 됩니다.

하지만 `handle_unknown='ignore'` 옵션을 사용하면,
✔ 처음 보는 값이 등장해도  
✔ 에러를 발생시키지 않고  
✔ 해당 값을 모두 0으로 처리하여 예측을 계속 진행합니다.

👉 실무 환경이나 실시간 예측 시스템에서는 매우 중요한 안전장치입니다.

정리하면,
✔ SimpleImputer → 빈 값 채우기 담당  
✔ OneHotEncoder → 문자 → 숫자 변환 담당  
✔ handle_unknown='ignore' → 처음 보는 값이 와도 에러 방지

---
###### 관제 / 실무 관점으로 보면

머신러닝 모델은 학습할 때 사용한 데이터 기준으로 동작합니다.  
하지만 실제 운영 환경(관제 시스템, 실시간 플랫폼 등)에서는 예상하지 못한 값이 등장하는 상황이 매우 흔합니다.

예를 들어 비교해 보면:

| 금융 데이터 상황          | 관제 / 센서 시스템 상황       |
| ------------------ | -------------------- |
| 학습에 없던 새로운 이체방식 등장 | 새 장비 타입 또는 새 센서 추가   |
| 요일 같은 문자열 데이터 존재   | 장비 상태 코드 / 운영 모드 값   |
| 알 수 없는 값 입력 가능성    | 실시간 데이터 변화 / 신규 값 발생 |
이처럼 운영 환경에서는 학습 당시 존재하지 않던 값이 들어오는 것이 정상적인 상황입니다.

왜 `handle_unknown='ignore'`가 중요할까요?

One-Hot Encoding은 학습할 때 등장한 값 기준으로만 변환 구조를 만듭니다.  
따라서 예측 단계에서 새로운 값이 들어오면 기본 설정에서는 오류가 발생합니다.

하지만 `OneHotEncoder(handle_unknown='ignore')` 사용하면:
✔ 학습에 없던 값이 등장하더라도  
✔ 모델이 멈추지 않고  
✔ 해당 값을 안전하게 처리하면서 예측을 계속 수행합니다.

👉 실시간 시스템 / 관제 플랫폼 / 운영 환경에서는 사실상 필수 옵션입니다.


정리
> 문자로 이루어진 범주형 컬럼은 모델이 바로 이해할 수 없기 때문에 전처리가 필요합니다.  
> 먼저 결측값이 있을 경우 가장 많이 등장한 값으로 채우고,  
> 이후 One-Hot Encoding을 사용해 각 범주를 숫자 형태로 변환합니다. 
> 또한 예측 시 학습에 없던 값이 들어와도 오류가 발생하지 않도록 
> `handle_unknown='ignore'`옵션을 사용합니다.

🔹 지금까지 만든 전처리 규칙 정리
	우리는 데이터 종류에 따라 서로 다른 처리 방법을 만들었습니다.

✔ pipe1  
	→ 숫자 전용 규칙  
	→ 값이 비어 있으면 중앙값(median) 으로 채움

✔ pipe2  
	→ 문자(범주형) 전용 규칙  
	→ 값이 비어 있으면 최빈값(가장 많이 나온 값) 으로 채움  
	→ 문자를 One-Hot Encoding으로 숫자로 변환

그런데 실제 데이터는 어떻게 들어올까요?
현실의 입력 데이터(X)는 이런 구조입니다.

| 거래월 | 거래시간 | 이체방식 | 거래요일 |
| --- | ---- | ---- | ---- |
| 숫자  | 숫자   | 문자   | 문자   |
즉,
✅ 숫자 컬럼도 있고  
✅ 문자 컬럼도 섞여 있습니다.

문제는 여기입니다.
👉 모델에 데이터를 넣을 때  
👉 어떤 컬럼에 어떤 규칙을 적용해야 할까요?

사람이 일일이 구분하면 번거롭고 실수도 발생합니다.

그래서 등장하는 것이 pipe3 입니다
pipe3의 역할을 한 문장으로 말하면: 
- 여러 컬럼 중에서  
- 어떤 컬럼은 pipe1로,  
- 어떤 컬럼은 pipe2로 처리하도록  
- 자동으로 분배해주는 관리자 역할입니다.

비유로 이해하면 훨씬 쉽습니다
pipe1, pipe2 = 작업자  
pipe3 = 작업 지시 관리자

예를 들어 데이터가 들어오면:
- 거래월 → 숫자니까 pipe1에게 전달
- 거래시간 → 숫자니까 pipe1에게 전달
- 이체방식 → 문자니까 pipe2에게 전달
- 거래요일 → 문자니까 pipe2에게 전달
    
이 과정을 자동으로 수행합니다.

우리는 단지 이렇게 규칙만 써두는 것입니다.
- 이 컬럼들은 숫자 처리해 주세요
- 이 컬럼들은 문자 처리해 주세요

그러면 pipe3가 알아서 처리합니다.

##### ✅ `[D] 전처리 파이프라인 구성 (전처리)` : 컬럼별 전처리 결합 
```python
from sklearn.compose import make_column_transformer

pipe3 = make_column_transformer(
    (pipe1, ['거래월', '거래일', '거래시간']),
    (pipe2, ['이체방식', '거래요일'])
)
```
이 코드가 하는 일
- 숫자 컬럼은 pipe1로 처리하고,  
- 문자 컬럼은 pipe2로 처리한 뒤,  
- 다시 하나로 합쳐서 모델에 전달한다.

괄호 구조 해석하기
```python
(pipe1, ['거래월', '거래일', '거래시간'])
```
이건 말 그대로: pipe1 규칙을 이 컬럼들에 적용해라 라는 뜻이고,

```python
(pipe2, ['이체방식', '거래요일'])
```
이건: pipe2 규칙을 이 컬럼들에 적용해라 라는 뜻입니다.

---
관제 시스템의 센서 데이터에는
- 숫자 값 → 온도, 압력, 농도
- 문자 값 → 장비ID, 상태코드
    
처럼 서로 다른 종류의 데이터가 섞여 있습니다.

ColumnTransformer는

> 숫자 데이터는 숫자 규칙으로 처리하고  
> 문자 데이터는 문자 규칙으로 처리한 뒤  
> 결과를 하나로 합쳐 모델에 전달하는 역할을 합니다.

즉, 데이터 종류별 처리 담당을 자동으로 나눠주는 관리자입니다

예시코드
```python
from sklearn.compose import make_column_transformer  
  
pipe3 = make_column_transformer(  
# 숫자형 센서 데이터 처리  
(pipe1, ['온도', '압력', 'CO농도']),  
  
# 범주형(문자) 장비 정보 처리  
(pipe2, ['장비ID', '설비상태코드'])  
)
```
- 온도 / 압력 / CO농도 → 숫자 데이터 → `pipe1` 규칙 적용
- 장비ID / 설비상태코드 → 문자 데이터 → `pipe2` 규칙 적용
    
즉,
> 센서 측정값은 숫자 방식으로 처리하고  
> 장비 정보는 범주 방식으로 처리한 뒤  
> 결과를 하나로 합쳐 모델에 전달하는 구조입니다

---
🔹 전처리 + 모델을 하나로 묶는다는 게 무슨 뜻일까?
	지금까지 우리는 이런 준비를 했어요.

1. 숫자 컬럼 전처리 규칙 (`pipe1`)
2. 문자 컬럼 전처리 규칙 (`pipe2`)
3. 컬럼별로 전처리 적용 (`pipe3`)

이제 마지막 질문이 남습니다.
	❓ 이 전처리를 언제, 어떻게 모델에 적용할까?

답은 단순합니다.
	모델에 넣기 전에 항상 적용되게 하자

그래서 전처리 + 모델을 하나로 묶는 것이 필요합니다.

##### ✅ `[E] 전처리 + 모델을 하나로 묶기 (학습 파이프라인)` :  최종 파이프라인
```python
from sklearn.ensemble import RandomForestRegressor

pipe_model = make_pipeline(
    pipe3,
    RandomForestRegressor()
)
```

이 코드가 하는 일을 말로 풀면
> 이 코드는 
> 전처리를 먼저 하고 → 그 다음 랜덤포레스트로 학습·예측한다는  
> 작업 순서를 미리 정해두는 코드입니다. 즉 이 시점까지는 빈 머신이라고 보면 됩니다.

🔹 `make_pipeline(pipe3, RandomForestRegressor())`의 의미: 이 한 줄이 하는 일
```
원본 X 데이터 (전처리를 전혀 하지 않은 상태의 입력 데이터)
 ↓
[pipe3]  ← 숫자/문자 전처리 자동 수행
 ↓
[RandomForestRegressor] ← 사용할 모델
```
👉 이 흐름을 순서만 정의한 상태

🔹 `pipe_model`이 한 덩어리라는 말의 진짜 의미

`pipe_model` 안에는 아직 학습 결과는 없고,
- 어떤 컬럼에
- 어떤 전처리를 적용할지 (`pipe3`)
- 어떤 모델을 사용할지 (`RandomForestRegressor`)
- 어떤 순서로 처리할지 (전처리 → 모델)

즉, 앞으로 학습하거나 예측할 때 이 순서와 이 규칙을 반드시 사용하겠다는 약속 묶음

---
관제 / 실무 시스템 관점

이 구조는 바로 이런 형태입니다.
```
입력 데이터
→ 전처리
→ 모델 예측
→ 결과 출력
```

관제 시스템에서는:
- 센서 데이터 들어오면
- 전처리 규칙 자동 적용
- 예측 결과 생성
- 임계치 초과 시 알람
    
👉 사람 개입 없이 자동 처리

##### ✅`[F] 하이퍼파라미터 튜닝 (학습/최적화)` : BayesSearchCV로 하이퍼 파라미터 튜닝
```python
from skopt.searchcv import BayesSearchCV

hyper = {
    'randomforestregressor__max_depth': (5, 10),
    'randomforestregressor__min_samples_leaf': (30, 50)
}

bayes_model = BayesSearchCV(
    pipe_model,
    hyper,
    cv=3,
    scoring='r2',
    n_iter=5,
    n_jobs=-1
)

bayes_model.fit(X_train, Y_train)
best_model = bayes_model.best_estimator_
```
전처리 + 모델을 묶은 뒤, 설정값을 자동으로 최적화하는 단계

앞 단계에서 우리는 이미 이것을 만들어 두었습니다.
- 컬럼별 전처리 규칙 (`pipe3`)
- 전처리 → 모델 적용 순서 (`pipe_model`)
    
이제 모델에게 묻는 질문이 바뀝니다.

> ❓ 이 구조는 유지하되,  
> 모델 설정값은 어떻게 해야 가장 잘 맞을까?

이 질문에 답해주는 단계가 하이퍼파라미터 튜닝입니다.

❓ 하이퍼파라미터란 무엇인가?
하이퍼파라미터는 모델이 학습하기 전에 사람이 정해줘야 하는 설정값입니다.

RandomForest 예시:
- 트리를 얼마나 깊게 만들까?
- 한 갈래(leaf)에 최소 몇 개의 데이터가 있어야 할까?
    
이 값들은
- 너무 작으면 → 과적합
- 너무 크면 → 패턴을 못 배움
    
👉 데이터에 맞는 적당한 값을 찾아야 합니다.

---
### 코드 해석
```python
from skopt.searchcv import BayesSearchCV
```
BayesSearchCV는 말 그대로 여러 설정을 무작정 다 해보지 말고, 성능이 좋아질 가능성이 높은 쪽을 중심으로 똑똑하게 실험해주는 도구입니다.

튜닝 대상 설정값(hyper) 살펴보기
```python
hyper = {
    'randomforestregressor__max_depth': (5, 10),
    'randomforestregressor__min_samples_leaf': (30, 50)
}
```
① `randomforestregressor__`가 붙는 이유
- 우리는 파이프라인을 튜닝 중입니다.
- 파이프라인 안에는:
    - `pipe3`
    - `RandomForestRegressor`
        
그래서 이 뜻은 파이프라인 안에 있는 `RandomForestRegressor`의 `max_depth`를 조정해
`__`는 안에 들어 있는 객체의 옵션을 지정하는 문법입니다.

② 각 하이퍼파라미터의 의미
- `max_depth`
    - 트리의 최대 깊이
    - 너무 깊으면 데이터를 외워버림(과적합)
        
- `min_samples_leaf`
    - 하나의 잎 노드에 남길 최소 데이터 수
    - 너무 작으면 노이즈까지 학습
        
👉 둘 다 과적합을 막기 위한 핵심 제어 장치

---
BayesSearchCV 설정 코드 해석
```python
bayes_model = BayesSearchCV(
    pipe_model,
    hyper,
    cv=3,
    scoring='r2',
    n_iter=5,
    n_jobs=-1
)
```
이 코드를 말로 풀면:
- `pipe_model`
    - 튜닝 대상은 전처리 + 모델 전체
        
- `hyper`
    - 시험해볼 설정값 범위
        
- `cv=3`
    - 데이터를 3조각으로 나눠
    - 번갈아가며 학습/검증
        
- `scoring='r2'`
    - 성능 판단 기준은 R² 점수
        
- `n_iter=5`
    - 설정 조합을 5번 실험
        
- `n_jobs=-1`
    - CPU 전부 사용 (속도 ↑)
    - scikit-learn은 GPU 미지원이며 CPU기반 라이브러리입니다.

사이킷런이 CPU만 써도 대부분 문제 없지만, OneHot 폭발 / 대용량 트리모델 / CV 반복 같은 조건이면 느려질 수 있어요. 그건 GPU가 없어서가 아니라 문제 구조가 무거워서입니다.
그래서 사이킷런=CPU만이어도 많은 경우 충분히 빠르고 실무에서도 엄청 많이 씁니다.

---
실제 학습 + 튜닝이 일어나는 순간
```python
bayes_model.fit(X_train, Y_train)
```
이 한 줄에서 실제로 벌어지는 일:
1. X_train이 들어옴
2. `pipe3` 전처리 수행
3. RandomForest 설정값을 하나 선택
4. 학습
5. 검증
6. 점수 기록
7. 다시 다른 설정값으로 반복
    
👉 이 과정을 BayesSearchCV가 자동으로 관리

최종 결과: best_model

이 한 줄의 의미는:

그래서 `best_model` 안에는:
- pipe3 (전처리 규칙)

모델의 내부 설정값만 바꿔가며 가장 성능이 좋은 조합을 자동으로 찾는 과정입니다.

> ❓ 이 모델, 얼마나 잘 예측하고 있는가?

```python
from sklearn.metrics import r2_score, mean_squared_error
```

##### ✅ `[G] 성능 평가 (평가)` : 학습 데이터 / 검증 데이터에 대한 예측 수행
```python
Y_train_pred = best_model.predict(X_train)
Y_test_pred = best_model.predict(X_test)
```
의미
- 학습 데이터
    - 모델이 이미 본 데이터
    - 얼마나 잘 외웠는지 확인
        
- 검증 데이터
    - 모델이 처음 보는 데이터
    - 실제로 써먹을 수 있는지 확인

`predict`는 이미 학습된 모델에게 "이 입력 데이터에 대한 답을 내놔라"라고 요청하는 메서드입니다.

머신러닝의 3단계 메서드로 보면 머신러닝 모델은 보통 이 3단계로 사용됩니다.

|단계|메서드|의미|
|---|---|---|
|① 설계|`make_pipeline()`|처리 순서 정의|
|② 학습|`fit(X, y)`|데이터로 패턴 학습|
|③ 예측|`predict(X)`|새로운 데이터에 대한 답 생성|

---
최종 성능 출력
```python
print('학습 데이터 결정 계수 : ', r2_score(Y_train, Y_train_pred))
print('학습 데이터 MSE : ', mean_squared_error(Y_train, Y_train_pred))

print('검증 데이터 결정 계수 : ', r2_score(Y_test, Y_test_pred))
print('검증 데이터 MSE : ', mean_squared_error(Y_test, Y_test_pred))
```

결과
```
학습 데이터 결정 계수 : 0.2926
학습 데이터 MSE : 2.1359

검증 데이터 결정 계수 : 0.2598
검증 데이터 MSE : 2.0081
```
결과 해석
- 학습 데이터
    - 모델이 과거 데이터의 패턴을 약 29% 정도 설명함
        
- 검증 데이터
    - 처음 보는 데이터에서도 약 26% 정도 설명함
        
✔️ 둘 다 0보다 충분히 큼  
✔️ 완전히 랜덤은 아님

쉽게 이해하기
- R²(결정계수) ≈ 0.0 → 거의 의미 없음 ❌
- R²(결정계수) ≈ 0.2 ~ 0.3 → 패턴은 조금 잡음 ⭕
- R²(결정계수) ≈ 0.6 이상 → 꽤 잘 맞춤
    
👉 이 모델은 약 0.29 정도로
“완벽하지는 않지만, 패턴은 분명히 일부 잡고 있다” 수준입니다.

MSE 해석 — “얼마나 크게 틀렸나?” (예측이 실제 값과 얼마나 많이 어긋났는지의 평균)
- 작을수록 좋음
- 단위는 “오차²”

- 학습 데이터 : 2.1359
- 검증 데이터 : 2.0081

쉽게 해석하면:
- 평균적으로 약 2 정도의 오차 제곱
- 실제 오차 크기로 생각하면  
    → 대략 1~2건 정도 차이라고 보면 됨
    
✔️ 학습과 검증 MSE가 비슷함  
✔️ 검증이 오히려 약간 더 낮음

- `pipeline-1__거래시간` (≈ 0.41) : 거래가 언제 발생했는지(시간대) 가 이상거래 판단에 압도적으로 중요 : 해석하면 이상한 거래는 특정 시간대에 많이 몰린다
- `pipeline-2__이체방식_AT` (≈ 0.27) : 이체 방식이 매우 중요 : 해석하면 특정 이체방식(AT)이 이상거래와 강하게 연결되었으며 이체 방식만 봐도 위험도가 달라진다
- `pipeline-2__이체방식_MP` (≈ 0.20) : 모든 이체방식이 동일하게 안전하지 않다
- `거래일`, `거래월` : 요일 자체는 이상거래 판단에 거의 도움 안 됨

전체 해석 요약문장: 이 모델은 ‘언제 거래했는지(시간)’와 ‘어떤 방식으로 이체했는지’를 가장 중요하게 보고, 요일은 거의 보지 않는다.

코드 해석

1️⃣ 빈 표 만들기
```python
df_importance = pd.DataFrame()
```
	변수 이름과 중요도를 담을 빈 테이블을 하나 만든 것

Feature 이름 가져오기
```python
df_importance['Feature'] = (
    best_model['columntransformer']
    .get_feature_names_out()
)
```
✔️ 무슨 일이 일어나고 있나?
- `best_model`은 파이프라인
- 그 안에는:
    - `columntransformer` (pipe3)
    - `randomforestregressor` 가 들어 있음
    
👉 전처리 과정에서:
- OneHotEncoder 때문에
- 원래 컬럼이 여러 개의 숫자 컬럼으로 쪼개짐
    
예:
```
이체방식_AT
이체방식_MP
거래요일_Monday
거래요일_Tuesday
...
```
`get_feature_names_out()`은:
	전처리까지 끝난 후 실제로 모델이 보고 있는 컬럼 이름들을 가져옵니다.

변수 중요도 값 가져오기
```python
df_importance['Importance'] = (
    best_model['randomforestregressor']
    .feature_importances_
)
```
✔️ 이건 뭔가요?
- `RandomForestRegressor`가 계산한 값
- 각 변수마다:
    - 예측에 얼마나 기여했는지
    - 상대적인 중요도를 숫자로 표현
        
📌 특징:
- 값이 클수록 → 더 중요
- 모든 중요도의 합 = 1

그래프로 보기
```python
px.bar(df_importance, x='Importance', y='Feature')
```
	표로만 보면 어려우니까 막대 그래프로 한눈에 보이게 시각화

예를 들어 그래프에서 이런 결과가 보인다면:
- 거래시간 ↑
- 이체방식_AT ↑
