7. AI 데이터 구조 (확장 구조)

✔️ 개념
	AI는 별도의 독립 기능이 아니라  

기존 핵심 데이터에 연결되는 확장 데이터 구조입니다.
```
핵심 데이터 → AI 결과가 추가로 연결되는 구조
```


✔️ 기본 구조
```
핵심 데이터 (중심 모델)  
  ↓  
 ├─ AI 분석 결과  
 ├─ 추천 / 유사도 결과
```


✔️ 구조 설명

- 핵심 데이터 - AI 분석 결과  
    → 요약, 분류, 키워드, 감정 등 AI 결과 저장
- 핵심 데이터 - 추천 / 유사도 결과  
    → 유사 데이터, 추천 콘텐츠 연결


✔️ 설계 기준 (중요)
```
AI 결과는 "덮어쓰기"가 아니라    
"이력 또는 확장 데이터"로 저장하는 것을 권장
```


✔️ 한 줄 핵심
```
AI는 새로운 테이블이 아니라    
기존 데이터에 연결되는 확장 구조다
```

8. 비동기 작업 구조 (운영 데이터)

✔️ 개념
AI 처리 및 대용량 작업은  
👉 반드시 비동기 구조로 처리해야 합니다.


✔️ 기본 구조
```
작업 요청 → 작업 처리 → 결과 저장 → 상태 관리
```


✔️ 상태값 구조 (필수)
```
PENDING     → 요청됨  
PROCESSING  → 처리중  
SUCCESS     → 완료  
FAIL        → 실패
```


✔️ 데이터 흐름
```
사용자 요청  
  ↓  
Task 생성 (DB 저장)  
  ↓  
Celery 작업 실행  
  ↓  
FastAPI 호출 (AI 처리)  
  ↓  
결과 DB 저장  
  ↓  
상태 변경 (SUCCESS / FAIL)
```


✔️ 설계 기준
- 작업(Task)은 반드시 DB에 기록
- 상태값으로 흐름 관리
- 실패 시 재시도 가능 구조 고려


✔️ 한 줄 핵심
```
AI는 요청 → 처리 → 저장이 아니라    
요청 → 작업 → 상태 관리 구조다
```

✔️ 개념

✔️ 기본 구조
```
외부 데이터  
  ↓  
 ├─ 원본 데이터 (raw)
```

✔️ 구조 설명
- 원본 데이터 (raw)  
    → 크롤링 / API 그대로 저장
- 가공 데이터 (processed)  
    → 분석 / 정제 / 변환된 데이터


✔️ 설계 기준 (중요)
```
원본 데이터는 절대 수정하지 않는다    
가공 데이터는 별도로 저장한다
```


✔️ 활용 예시
- 크롤링 데이터 저장
- 외부 API 데이터 적재
- AI 학습 데이터 구성


✔️ 전체 확장 구조
```
User
  ↓
핵심 데이터
  ↓
 ├─ 파일
 ├─ 댓글
 ├─ 좋아요 / 북마크
 ├─ 태그 / 카테고리
 ├─ AI 분석 결과        ← (추가)
 ├─ 추천 / 유사도 결과  ← (추가)
 └─ Task (비동기 작업)  ← (추가)
```

✔️ 최종 핵심 정리
```
4차 데이터베이스의 목표는  
새로운 기능 추가가 아니라

```

#### G. 배포 / 인프라 기능

🔹 개요
	이 영역은 내 프로젝트를 실제 서비스로 띄울 수 있는가를 보여주는 단계입니다.

```
개발 완료 ≠ 서비스 가능    
배포 구조까지 있어야 실무형 프로젝트
```


✔️ 반드시 포함해야 하는 요소
- Docker Compose
- 서비스별 컨테이너 분리
    - Django
    - FastAPI
    - Redis
    - PostgreSQL
- CI 구축 (선택 → 권장)
- 수동 배포 또는 CD
- 운영 보안 설정
- Nginx 또는 Ingress 구조
- Kubernetes 배포 (확장 단계)


✔️ 한 줄 핵심
```
서비스는 코드가 아니라 구조로 실행된다
```


✔️ 기본 실행 구조 (로컬)
```
Docker Compose  
  ↓  
Django + FastAPI + Redis + PostgreSQL  
  ↓  
서비스 동작 확인
```


✔️ 운영 확장 구조 (중요)
```
Kubernetes  
  ↓  
namespace  
  ↓  
deployment  
  ↓  
service  
  ↓  
ingress
```


구현 기준 (간단 정리)

1. Docker Compose (필수)
- 모든 서비스를 컨테이너로 실행
- 한 번의 명령으로 전체 실행

```
docker compose up
```


2. 서비스 분리 (필수)
```
Django     → API 서버    
FastAPI    → AI 서버    
Redis      → 메시지 브로커    
PostgreSQL → DB
```


3. 배포 방식
```
- 수동 배포 → 기본
- CI/CD → 확장
```


4. 네트워크 구조
- Nginx 또는 Ingress 사용
- 외부 요청 → 내부 서비스 연결


4. Kubernetes (확장)
- namespace → 프로젝트 분리
- deployment → 서버 실행
- service → 내부 연결
- ingress → 외부 접근
- configmap / secret → 설정 관리
- HPA → 자동 확장


🚀 실제 작업 순서 (권장)

1. Docker Compose 구성  
2. 서비스 컨테이너 분리  
3. 로컬 실행 테스트  
4. 배포 방식 선택 (수동 또는 CI)  
5. Nginx 또는 Ingress 연결  
6. Kubernetes 적용 (확장)

### 4. 창업용과 취업용에서 강조점 차이

🔹 개요
	같은 프로젝트라도 목적에 따라 평가 기준이 달라집니다.

```
취업용 → 기술력 증명    
창업용 → 서비스 가치 증명
```


🔹 취업용 프로젝트 강조 포인트
	이 개발자는 실무에 투입 가능한가?


✔️ 핵심 체크 요소
- API 설계가 명확한가?
- 앱 구조가 잘 분리되어 있는가? (Django / FastAPI 등)
- 인증 구조가 안정적인가? (JWT 등)
- 비동기 처리 구조를 이해하고 있는가? (Celery + Redis)
- 운영 로그 및 메트릭을 수집하는가?
- Docker / Kubernetes 경험이 있는가?
- 장애 발생 시 추적 및 해결이 가능한가?

✔️ 한 줄 핵심
```
기술 깊이 + 구조 이해 + 운영 경험
```

🔹 창업용 프로젝트 강조 포인트
	이 서비스는 실제로 쓸 가치가 있는가?


✔️ 핵심 체크 요소
- 이 서비스가 왜 필요한가?
- 어떤 사용자 문제를 해결하는가?
- AI 기능이 실제 사용자 가치와 연결되는가?
- 확장 가능한 구조인가?
- 수익화(유료화) 가능성이 있는가?
- 실제 운영 가능한 수준인가?


✔️ 한 줄 핵심
```
문제 해결력 + 사용자 가치 + 서비스 가능성
```


🔹 3차 → 4차 연결 관점
```
3차 = 기능 완성 (동작하는 서비스)    
4차 = 운영/확장 (살아있는 서비스)
```


✔️ 연결 구조
```
- 3차  
    → CRUD + AI + 비동기 + 결과 출력
- 4차  
    → 배포 + 모니터링 + 확장 + 운영 안정성
```


✔️ 최종 핵심 정리

같은 프로젝트라도    
어떻게 보여주느냐에 따라 결과가 달라집니다
```
취업용 → 기술을 증명    
창업용 → 가치를 증명
```

### 5. 최종 정리
	주제는 자유롭게 정해도 됩니다.
	하지만 포트폴리오는 아래 기준을 만족해야 강해집니다.

꼭 보여야 하는 것
- 서비스 서버를 설계할 수 있다
- AI 서버를 분리할 수 있다
- 비동기 처리 구조를 만들 수 있다
- 데이터를 관계형 DB로 설계할 수 있다
- 결과를 다시 사용자 화면에 연결할 수 있다
- Docker로 실행 환경을 나눌 수 있다
- Prometheus / Grafana로 상태를 볼 수 있다
- Kubernetes로 확장 가능한 구조를 만들 수 있다

즉, 이 포트폴리오는
단순 CRUD 프로젝트가 아니라  
AI가 연결된 실무형 백엔드 서비스를 만드는 것이 목적입니다.

### 6. 자신이 만든 프로젝트를 기술문서로 작성

NotebookLM활용 아키텍처이나 전체 흐름도 참고용
![[Pasted image 20260322110018.png]]
`[기술문서 목차]` 고성능 비동기 AI 리뷰 분석 플랫폼 개발 보고서


##### 1. 프로젝트 개요 (Project Overview)
- 서비스 비전  
- 문제 정의  
- 해결 방향  
- 기술 스택 선정 이유  
    → 예시) Django(생산성) + FastAPI(고성능 추론) + Celery(비동기 처리)

##### 2. 시스템 아키텍처 설계 (System Architecture)
- 서버 분리 전략  
    → Django(서비스) / FastAPI(AI) 분리 구조
- 전체 흐름
```
사용자 요청 → Django → Celery → FastAPI → DB 저장 → 결과 반환
```

- 인프라 구성  
    → Docker 기반 멀티 컨테이너 구조  
    → Nginx / Ingress 기반 라우팅

#### 3. 데이터베이스 설계 (Database Design & ERD)
- ERD 설계  
    → 예시) Accounts / Products / Reviews / Interactions 분리
- DB 전략  
    → SQLite(개발) → PostgreSQL(운영)
- 데이터 정책  
    → Soft Delete 적용 (데이터 복구 및 안정성 확보)

##### 4. 데이터 수집 및 처리 (Data Pipeline)
- 크롤링 구조  
    → Collector / Service / Repository 패턴 적용
- 자동화  
    → Cron + Django command 기반 수집
- 안정성  
    → 요청 제한 / User-Agent 관리

##### 5. AI 시스템 및 연동 (AI Intelligence)
- 모델  
    → 예시) `e5-small-korean` 임베딩 기반 유사도 분석
- 연동 구조  
    → 예시) DRF → FastAPI API 호출 방식
- 성능 최적화  
    → 예시) pgvector 기반 벡터 검색

##### 6. 비동기 및 실시간 처리 (Async & Realtime)
- 비동기 처리  
    → Celery + Redis 기반 작업 큐
- 실시간 알림  
    → WebSocket 기반 결과 전달
- 목적  
    → 사용자 응답과 AI 처리 분리

##### 7. API 설계 및 인증 (API & Auth) 
- REST API 설계  
    → 리소스 중심 URL 구조
- 주요 엔드포인트 예시) 
    → `/ai/reviews/{id}/analyze/`  
    → `/ai/tasks/{id}/status/`
- 인증  
    → JWT 기반 인증 처리

##### 8. 운영 및 모니터링 (Ops & Monitoring)
- 메트릭 수집  
    → Prometheus (Django / FastAPI)
- 시각화  
    → Grafana 대시보드
- 주요 지표  
    → 요청 수 / 평균 응답 / p95 / 에러율
- 커스텀 메트릭  
    → AI 처리 시간 / DB 저장 시간 / task 전체 시간

##### 9. 배포 및 인프라 (Deployment)
- Docker Compose 기반 로컬 실행
- GitHub Actions CI/CD 구축
- Kubernetes 배포 (Deployment / Service / Ingress / HPA)

##### 10. 장애 대응 및 트러블슈팅 (Troubleshooting)
- FastAPI 모듈 누락 → 이미지 재빌드로 해결
- Gunicorn timeout → worker 설정 조정
- 메트릭 NO DATA → PromQL 수정

👉 장애 발생 시 로그 + 메트릭 기반 원인 분석

##### 11. 결론 및 성장 포인트 (Conclusion)
- 아키텍처 개선  
    → 동기 → 비동기 → 실시간 구조로 발전
- 핵심 성과  
    → AI + 비동기 + 모니터링 통합 경험 확보
- 향후 과제  
    → 대규모 트래픽 대응 및 성능 최적화
