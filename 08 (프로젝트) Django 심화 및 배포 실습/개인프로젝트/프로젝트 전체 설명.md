### 목표:
```
3차 = 서비스 완성 (기능 중심)             기간: 4월 15일 ~ 5월 6일까지 (3시간 중간 발표)
4차 = AI + 운영 + 확장 (실무형 완성)      기간: 5월 8일 ~ 6월 16일까지 (17일 최종발표)
```

프로젝트 전체 구조
이 프로젝트는 단순 CRUD 프로젝트가 아니라  
단계적으로 완성되는 실무형 백엔드 서비스를 만드는 것을 목표로 합니다.

전체 흐름은 아래와 같습니다.
```
[3차] 서비스 완성  
→ 사용자 기능 + 데이터 구조 + 화면 출력 완성  
  
[4차] 실무형 확장  
→ AI 연결 + 비동기 처리 + 운영 + 확장 구조 추가
```

---
### 🔹 프로젝트 방향성 (창업 vs 취업)

🔹 개요  
	이 프로젝트는 단순 기능 구현이 아니라  
	각자의 목표(창업 / 취업)에 맞게 결과물을 만드는 것을 목표로 합니다.

같은 기술을 사용하더라도 무엇을 강조하느냐에 따라 프로젝트의 가치가 달라집니다.

취업 → 기술력 증명  
창업 → 서비스 가치 증명


따라서 기능은 필수 / 선택으로 나누어 제공되며 각자의 목표에 맞게 선택하여 프로젝트를 완성합니다.

### 🔸 1. 창업을 목표로 하는 경우

🔹 핵심 관점
	이 서비스가 실제로 사람들이 사용할 가치가 있는가?


기술보다 중요한 것은 문제 해결력 + 아이디어 + 사용자 경험입니다.

✔️ 반드시 고민해야 하는 요소
- 어떤 문제를 해결하는 서비스인가?
- 타겟 사용자는 누구인가?
- 기존 서비스와 무엇이 다른가?
- AI 기능이 실제 사용자 가치와 연결되는가?
- 이 서비스는 계속 사용할 이유가 있는가?


✔️ 반드시 챙겨야 하는 핵심 요소

- 사용자 흐름 (UX)
```
회원가입 → 사용 → 결과 확인 → 재사용
```
- 기능의 단순함과 명확성
- 핵심 기능 1~2개 집중 (과도한 기능 금지)
- AI 기능이 데모가 아닌 실제 기능으로 작동
- 데이터가 쌓이고 활용되는 구조
- 향후 확장 가능성 (기능 / 사용자 / 데이터)


✔️ 추가로 고려하면 좋은 요소
- 수익화 가능성 (구독 / 광고 / 프리미엄 기능)
- 실제 운영 가능 구조 (배포 / 서버 구조)
- 사용자 유지 전략 (리텐션)
- MVP → 확장 전략


✔️ 한 줄 핵심
	창업용 프로젝트 = 기술이 아니라 서비스 가치

---
### 🔸 2. 취업을 목표로 하는 경우  
  
🔹 핵심 관점
	이 개발자는 실무에 바로 투입 가능한가?

아이디어보다 중요한 것은 `기술 깊이 + 구조 설계 + 운영 이해`입니다.


✔️ 반드시 보여야 하는 요소
- Django + DRF 기반 API 설계 능력
- FastAPI 기반 AI 서버 분리 구조
- DB 설계 능력 (관계형 구조)
- 비동기 처리 구조 (Celery + Redis)
- Docker 기반 실행 환경 구성
- 배포 경험 (Compose 또는 Kubernetes)
- 모니터링 및 로그 이해 (Prometheus / Grafana)


✔️ 반드시 챙겨야 하는 핵심 요소
- 코드 구조 분리 (앱 단위, 책임 분리)
- API 설계 명확성 (RESTful)
- 에러 처리 / 예외 처리
- 인증 및 권한 처리
- 비동기 처리 흐름 이해
- 장애 발생 시 원인 추적 가능 구조


✔️ 추가로 강력한 포인트
- 커스텀 메트릭 설계
- 성능 측정 및 개선 경험
- CI/CD 경험
- Kubernetes 구조 이해
- 트러블슈팅 경험 정리


✔️ 한 줄 핵심
	취업용 프로젝트 = 기술 깊이 + 구조 + 운영 경험

---
### 🔸 3. 공통 핵심 (가장 중요)  
  
창업이든 취업이든  
👉 반드시 공통으로 만족해야 하는 기준이 있습니다.  
  
  
✔️ 반드시 포함되어야 하는 흐름
사용자 입력  
→ 서비스 서버 처리  
→ DB 저장  
→ AI 처리  
→ 비동기 처리  
→ 결과 저장  
→ 화면 출력  
→ 상태 확인 또는 알림

좋은 아이디어보다 완성된 구조가 더 강한 프로젝트입니다

따라서,  
본인의 목표에 맞게 선택 기능을 전략적으로 활용하여 프로젝트를 완성하시기 바랍니다.


---
### 3차 → 4차 연결 구조
	3차에서는 서비스의 기본 흐름을 완성합니다.

```
사용자 → 서비스 서버 → DB 저장 → 화면 출력
```

이 상태에서 이미  
✔ 서비스는 동작하고  
✔ 데이터 흐름이 완성되어 있어야 합니다.

---
### 4차에서는 여기에 AI와 운영 구조를 붙입니다

```
사용자 → 서비스 서버 → DB 저장 → AI 요청 → 비동기 처리 → 결과 저장 → 화면 출력 → 모니터링
```


즉, 최종적으로는 아래 흐름이 보여야 합니다.
```
사용자 요청 → 서비스 서버 처리 → DB 저장 → AI 분석 요청 → 비동기 처리 → 결과 저장 → 
화면 출력 → 운영 모니터링
```

---

### 핵심 차이

|구분|3차|4차|
|---|---|---|
|목적|기능 완성|실무형 구조|
|중심|CRUD + 사용자 흐름|AI + 운영 + 확장|
|처리|동기|비동기|
|구조|단일 서비스|서비스 + AI 서버|

### 포트폴리오의 최종 목표
	이 프로젝트는 결국 아래를 보여주는 것이 목적입니다.

> 기능 나열이 아니라 서비스 구조 + AI 연결 + 운영 가능성 + 확장성

##### (1) 취업용 포트폴리오

취업용이라면 아래가 보여야 합니다.
- Django + DRF 기반 API 설계 능력
- FastAPI 기반 AI 서버 분리 경험
- PostgreSQL, Redis, Celery 활용 경험
- Docker 기반 실행 및 환경 분리 경험
- Prometheus / Grafana 기반 모니터링 경험
- Kubernetes 배포 경험
- 장애 원인 추적, 성능 측정, 운영 관점 이해

즉, 실무에서 바로 적응 가능한 백엔드 개발자처럼 보여야 합니다.

---
##### (2) 창업용 포트폴리오

창업용이라면 아래가 보여야 합니다.
- 실제 사용자가 쓸 수 있는 서비스 흐름
- AI 기능이 단순 데모가 아니라 사용자 가치와 연결됨
- 기능 확장 가능한 구조
- 운영 가능한 인프라 구조
- 트래픽 증가에 대비할 수 있는 구조
- 향후 유료화/확장 가능성이 있는 구조

즉, 기술 데모가 아니라 서비스로 확장 가능한 제품처럼 보여야 합니다.
