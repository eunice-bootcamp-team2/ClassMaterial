작업 목적

센서 데이터 생성부(FastAPI)에서 만들어진 실시간 데이터를  
브라우저 화면까지 끊김 없이 전달하여,  
차트, 상태 카드, 지도, 알람 영역이 즉시 반응하도록  
**실시간 데이터 전달 경로를 구축하는 것**이 목적이다.

1단계에서는 실제 장비 연동보다  
**“데이터가 생성 → 전송 → 수신 → 화면 반영”** 흐름이 안정적으로 이어지는지 확인하는 것이 중요하다.  
따라서 FastAPI와 프론트엔드(Django Template + JavaScript) 사이를  
WebSocket 기반으로 연결하여, 페이지 새로고침 없이 데이터가 계속 흘러가는 구조를 먼저 완성한다.

---

작업 내용

1. 실시간 통신 구조 정의
- FastAPI를 실시간 데이터 송신 서버로 사용한다.
- 브라우저는 WebSocket 클라이언트로 접속하여 데이터를 지속적으로 수신한다.
- 1단계에서는 구조를 단순화하여 **FastAPI → 브라우저 직접 연결** 방식으로 먼저 구현한다.
- 이후 필요 시 Django 또는 Redis Pub/Sub를 중간 계층으로 확장할 수 있도록 설계한다.

2. WebSocket 엔드포인트 설계
- FastAPI에 WebSocket 전용 엔드포인트를 만든다.
- 예:
    - `/ws/sensors/`
    - `/ws/workers/`
    - `/ws/events/`
- 초기 단계에서는 하나의 통합 스트림으로 시작해도 되고, 데이터 규모가 커지면 센서/작업자/알람 채널로 분리할 수 있다.
- 메시지 포맷은 JSON으로 통일하여 프론트가 쉽게 파싱할 수 있도록 한다.

3. FastAPI 송신 로직 구현
- 가짜 데이터 생성기와 WebSocket 송신부를 연결한다.
- 일정 주기(예: 1초)마다 생성된 센서 데이터와 작업자 위치 데이터를 WebSocket을 통해 브라우저로 전달한다.
- 송신 데이터는 단순 텍스트가 아니라,  
    센서값 / 위치 / 상태 / 이벤트 정보를 포함한 구조화된 JSON으로 보낸다.
- 향후 실제 장비 연동 시에도 같은 포맷을 유지할 수 있도록 데이터 계약을 정리한다.

4. 프론트 WebSocket 연결 구현
- Django Template 내부 JavaScript에서 WebSocket 객체를 생성하여 FastAPI에 연결한다.
- 연결 성공 시, 실시간 데이터 수신이 시작되고 차트/지도/UI가 갱신되도록 구현한다.
- 연결 종료, 에러 발생, 재접속 상태를 사용자에게 알 수 있게 최소한의 상태 표시를 둔다.

5. 수신 데이터 파싱 및 화면 반영
- 브라우저가 수신한 JSON 데이터를 파싱하여 다음 영역에 반영한다.
    - 상단 상태 카드
    - Chart.js 그래프
    - Leaflet 지도 상 센서/작업자 위치
    - 알람 리스트
- 각 영역은 데이터 구조에 맞게 분리된 업데이트 함수를 사용하여 유지보수성을 확보한다.
- 전체 화면을 다시 렌더링하지 않고, 필요한 영역만 선택적으로 갱신한다.

6. 연결 유지 및 재접속 처리
- WebSocket은 네트워크 상태에 따라 끊길 수 있으므로, 재접속 로직을 반드시 넣는다.
- 연결 종료 시 일정 시간 후 자동 재연결을 시도하고, 연결 상태를 UI에 표시한다.
- 예:
    - 연결 중
    - 연결됨
    - 연결 끊김
    - 재연결 시도 중

7. 성능과 갱신 주기 제어
- 1초 주기로 데이터를 보내되, 화면이 너무 자주 갱신되어 깜빡이지 않도록 처리한다.
- 차트는 최근 N개 데이터만 유지하도록 제한하고, 불필요한 DOM 업데이트를 줄인다.
- 지도 마커와 알람 리스트 역시 중복 업데이트를 방지하도록 한다.

8. 통신 장애 테스트
- 서버 재시작, 브라우저 새로고침, 일시적 네트워크 끊김 상황을 가정해 테스트한다.
- 데이터 수신이 잠시 멈췄다가 재개되어도 UI가 깨지지 않도록 확인한다.
- FastAPI가 중지되었을 때도 브라우저가 완전히 멈추지 않고 상태 표시를 바꿀 수 있어야 한다.

### 세부 작업 순서

STEP 1. WebSocket 통신 경로 확정
- FastAPI를 송신 서버로 정하고, 브라우저가 직접 접속하는 구조로 정리한다.
- WebSocket URL 규칙을 정한다.

STEP 2. FastAPI WebSocket 엔드포인트 생성
- `/ws/sensors/` 같은 엔드포인트를 만들고, 브라우저 연결을 받을 수 있는지 확인한다.

STEP 3. 가짜 데이터와 송신부 연결
- 난수 기반 센서값/작업자 위치 생성기를 WebSocket 송신 루프와 연결한다.
- 1초마다 JSON 메시지를 전송한다.

STEP 4. 브라우저 연결 테스트
- JavaScript에서 WebSocket 객체를 생성하고 FastAPI에 접속한다.
- 콘솔에서 메시지가 정상 수신되는지 먼저 확인한다.

STEP 5. UI 갱신 함수 연결
- 수신한 데이터를 카드/차트/지도/알람에 반영하는 함수를 붙인다.
- 영역별로 분리하여 디버깅이 쉽도록 작성한다.

STEP 6. 재접속 로직 추가
- 연결 종료 시 재시도하는 로직을 작성한다.
- 사용자에게 연결 상태를 보여주는 문구를 넣는다.

STEP 7. 예외 처리 및 안정화
- 잘못된 JSON, 누락 필드, 중복 메시지, 네트워크 지연 상황에서 UI가 깨지지 않는지 점검한다.

STEP 8. 테스트 시나리오 검증
- 정상 송신
- 서버 중단
- 재시작 후 재연결
- 브라우저 새로고침
- 위험 이벤트 송신  
    이 흐름을 반복 검증한다.

---
FastAPI 송신 예시
```python
import asyncio  
import json  
from fastapi import FastAPI, WebSocket  
  
app = FastAPI()  
  
@app.websocket("/ws/sensors/")  
async def websocket_endpoint(websocket: WebSocket):  
    await websocket.accept()  
    while True:  
        data = {  
            "type": "sensor_update",  
            "device_id": "sensor_01",  
            "location": {"x": 150, "y": 200},  
            "gas": {"co": 18, "h2s": 4},  
            "status": "normal"  
        }  
        await websocket.send_text(json.dumps(data))  
        await asyncio.sleep(1)
```

프론트 연결 예시
```js
const socket = new WebSocket("ws://127.0.0.1:8001/ws/sensors/");  
  
socket.onopen = function () {  
  console.log("WebSocket connected");  
};  
  
socket.onmessage = function (event) {  
  const data = JSON.parse(event.data);  
  console.log("received:", data);  
  // 카드/차트/지도 갱신 함수 호출  
};  
  
socket.onclose = function () {  
  console.log("WebSocket disconnected");  
};  
  
socket.onerror = function (error) {  
  console.error("WebSocket error:", error);  
};
```

완료 기준

- 브라우저가 FastAPI WebSocket에 정상 연결된다.
- 센서 데이터와 작업자 위치 데이터가 설정된 주기마다 지속적으로 수신된다.
- 수신된 데이터가 카드, 차트, 지도, 알람 UI에 정상 반영된다.
- 브라우저 새로고침 후 자동으로 다시 연결된다.
- FastAPI 재시작 후에도 재접속 로직이 동작한다.
- 네트워크 오류나 데이터 누락 상황에서도 화면이 깨지지 않는다.
- 데이터 수신 지연 없이 관제 화면이 실시간처럼 동작한다.

작업 시 주의사항

- 1단계에서는 구조를 단순하게 유지하기 위해 FastAPI와 브라우저를 직접 연결하는 것이 유리하다.
- 처음부터 Django Channels, Redis, Kafka까지 모두 붙이면 디버깅 범위가 너무 커질 수 있으므로 단계적으로 확장한다.
- WebSocket 메시지 포맷은 프론트/백엔드가 반드시 동일하게 합의해야 한다.
- UI 업데이트 로직과 통신 로직을 한 함수에 몰아넣지 말고 분리하는 것이 좋다.
- 차트는 최근 N개 데이터만 유지하고, 누적 데이터를 무한정 쌓지 않도록 제한해야 한다.
- 연결 끊김 상황은 반드시 테스트해야 하며, 재접속 로직이 없으면 실시간 시스템처럼 보이지 않는다.
- 요구사항 문서상 플랫폼은 실시간 모니터링과 데이터 시각화를 지원해야 하므로, 1단계에서는 실제 장비가 없어도 WebSocket 기반의 체감형 실시간 흐름을 먼저 확보하는 것이 중요하다.
