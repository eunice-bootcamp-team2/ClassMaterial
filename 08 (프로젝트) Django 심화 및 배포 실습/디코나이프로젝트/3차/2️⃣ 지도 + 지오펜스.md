작업 목적

공장 내부 평면도 이미지를 기반으로 관제 화면에서 공간 정보를 시각화하고,  
운영자가 위험 구역(지오펜스)을 직접 설정할 수 있도록 지도 기능을 구현한다.  
또한 센서 위치와 작업자 위치를 동일한 좌표계 위에 표현하여,  
이후 서버에서 **“위치 + 임계치 + 지오펜스”** 조건으로 위험 판단이 가능하도록  
공간 데이터의 기준점을 만드는 것이 목적이다.

---
작업 내용

1. 공장 이미지 업로드 및 지도 베이스 구성
- 실제 지도(OpenStreetMap)가 아니라 **공장 평면도 이미지(jpg, png)** 를 업로드하여 지도처럼 사용한다.
- Leaflet를 활용해 일반 지도가 아닌 **이미지 오버레이 기반 커스텀 맵** 형태로 구성한다.
- 이미지가 업로드되면 화면에 맞게 표시되도록 하고, 이후 좌표 클릭, 마커 표시, 폴리곤 생성이 가능하도록 기본 캔버스 역할을 하게 한다.
- 1단계에서는 실제 공장 좌표계가 없어도 되므로, 이미지 내부의 상대 좌표 또는 단순 2차원 좌표계를 기준으로 작업한다.

2. 좌표계 정의
- Leaflet에서 사용하는 좌표를 공장 평면도에 맞는 내부 좌표계로 변환한다.
- 초기 단계에서는 위도/경도 기반이 아닌 **이미지 기준 x, y 좌표** 또는 Leaflet의 간이 좌표계를 사용한다.
- 이 좌표계는 이후
    - 센서 위치 저장
    - 작업자 위치 표시
    - 지오펜스 폴리곤 저장  
        에 모두 공통 기준으로 사용된다.
- 좌표 원점(예: 좌상단 0,0)과 스케일을 문서로 정리해 두어야 추후 확장 시 혼란이 없다.

3. 지오펜스 생성 UI 구현
- 지도 위에서 운영자가 클릭하여 위험 구역을 직접 지정할 수 있도록 한다.
- 최소 3개 이상의 점을 찍어 polygon 형태의 폐합 영역을 만들 수 있어야 한다.
- 생성한 영역은 즉시 화면에 색상(예: 반투명 빨강/노랑)으로 표시하여 시각적으로 구분한다.
- 지오펜스 이름, 구역 유형, 설명, 위험도 수준 등의 메타데이터를 함께 입력할 수 있도록 폼 UI를 고려한다.
- 생성 완료 후 해당 polygon 좌표는 DRF API를 통해 DB에 저장한다.

4. 지오펜스 조회 / 수정 / 삭제 기능
- 저장된 지오펜스는 페이지 재접속 시 다시 불러와 화면에 표시되어야 한다.
- 운영자가 기존 위험 구역을 선택하여 수정하거나 삭제할 수 있어야 한다.
- 초기 단계에서는 “신규 생성 / 목록 조회 / 삭제”만 먼저 구현하고, 수정 기능은 후속으로 붙여도 된다.
- 위험 구역이 많아질 경우 화면이 복잡해지므로, ON/OFF 토글 또는 레이어 표시 여부를 고려한다.

5. 센서 위치 표시
- 센서(Device)마다 고정 위치를 지도 위에 마커로 표시한다.
- 센서 종류별(가스 센서, 전력 센서 등)로 아이콘 또는 색상을 다르게 표현한다.
- 센서 마커 클릭 시
    - 센서명
    - device_id
    - 센서 종류
    - 현재 상태(정상/주의/위험)
    - 최근 측정값  
        등이 팝업 또는 사이드 패널에 나타나도록 구성한다.
- 초기 단계에서는 DB에 저장된 센서 위치를 불러와 고정 배치하고, 시뮬레이션 데이터와 연계해 상태값만 바뀌도록 구현한다.

6. 작업자 위치 표시 (시뮬레이션)
- 실제 웨어러블 장비가 없으므로, 1단계에서는 가짜 작업자 위치 데이터를 사용한다.
- 작업자 점(point)이 공장 이미지 위에서 일정 주기로 이동하는 것처럼 보이도록 한다.
- 이 위치는 단순 시각화용이 아니라, 이후 서버에서 지오펜스 내부 판별의 입력값으로 사용된다.
- 작업자 위치는 센서 위치와 구분되는 전용 아이콘 또는 색상으로 표시한다.

7. 공간 판단을 위한 데이터 구조 정리
- 지도에서 그린 지오펜스는 단순 화면 요소가 아니라 **백엔드 판단용 데이터**로 저장되어야 한다.
- 프론트는 polygon 좌표를 만들고,
- DRF는 이를 JSON 형태로 저장하며,
- 서버는 센서 데이터 또는 작업자 위치 데이터가 들어올 때마다 해당 polygon 내부 여부를 판단한다.
- 즉, 지도 기능은 화면 요소이면서 동시에 서버 판단 로직의 입력 데이터가 된다.

세부 작업 순서

STEP 1. 공장 이미지 준비
- 사용할 공장 평면도 이미지 파일을 준비한다.
- 이미지 비율, 해상도, 주요 구역 표시 여부를 확인한다.

STEP 2. Leaflet 이미지 맵 구성
- 일반 지도 대신 공장 이미지를 Leaflet에 올린다.
- 줌, 이동, 좌표 클릭이 가능한 상태로 만든다.

STEP 3. 좌표 기준 정리
- 클릭 시 좌표가 어떻게 출력되는지 확인한다.
- 공통으로 사용할 좌표 체계를 정한다.

STEP 4. 센서 위치 마커 표시
- 더미 데이터 또는 DB 데이터를 기반으로 센서를 고정 위치에 배치한다.
- 센서 상태에 따라 마커 색상이 변경되도록 준비한다.

STEP 5. 지오펜스 생성 UI 구현
- 클릭으로 다각형을 만드는 기능을 붙인다.
- 생성 완료 시 polygon 좌표를 콘솔 또는 임시 데이터로 확인한다.

STEP 6. DRF 저장 연동
- 생성한 polygon 좌표를 DRF API로 전송하여 DB에 저장한다.
- 저장 후 다시 조회해서 화면에 재표시되는지 확인한다.

STEP 7. 작업자 위치 시뮬레이션 반영
- 가짜 이동 좌표를 일정 주기로 업데이트한다.
- 작업자 위치가 지도에서 자연스럽게 움직이는지 확인한다.

STEP 8. 지오펜스 내부 판별 연계 준비
- 서버가 작업자 위치를 받아 polygon 내부 여부를 판단할 수 있도록 좌표 구조를 맞춘다.
- 이후 알람 로직과 연결될 수 있도록 데이터 포맷을 고정한다.

---
데이터 구조 예시

지오펜스 저장 예시
```json
{  
  "name": "위험구역 A",  
  "zone_type": "danger",  
  "polygon": [  
    [100, 120],  
    [180, 120],  
    [180, 220],  
    [100, 220]  
  ]  
}
```

센서 위치 예시
```json
{  
  "device_id": "sensor_01",  
  "device_name": "가스센서 A",  
  "sensor_type": "gas",  
  "x": 140,  
  "y": 160,  
  "status": "normal"  
}
```

작업자 위치 예시
```json
{  
  "worker_id": "worker_01",  
  "x": 150,  
  "y": 170,  
  "status": "moving"  
}
```

DRF 연동 흐름

1. 프론트에서 좌표 생성
Leaflet에서 클릭한 좌표를 polygon 배열로 만든다.
```js
map.on('click', function (e) {  
  console.log(e.latlng);  
});
```

2. 프론트에서 DRF로 저장 요청
```js
fetch('/api/geofence/', {  
  method: 'POST',  
  headers: { 'Content-Type': 'application/json' },  
  body: JSON.stringify({  
    name: '위험구역 A',  
    polygon: coords  
  })  
});
```

3. 백엔드에서 저장
```js
GeoFence.objects.create(  
    name=request.data['name'],  
    polygon=request.data['polygon']  
)
```

완료 기준
- 공장 평면도 이미지가 지도처럼 정상 표시된다.
- 지도 위 클릭 또는 지정 UI를 통해 지오펜스를 생성할 수 있다.
- 생성한 지오펜스가 화면에 즉시 표시되고 재접속 후에도 유지된다.
- DB에 저장된 센서 위치가 지도 위에 정상적으로 표시된다.
- 센서 종류와 상태에 따라 마커 구분이 가능하다.
- 시뮬레이션 작업자 위치가 지도 위에서 이동한다.
- 지오펜스 좌표, 센서 좌표, 작업자 좌표가 동일한 좌표계를 사용한다.
- 이후 서버에서 polygon 내부 판별 로직을 연결할 수 있는 형태로 데이터가 정리된다.

작업 시 주의사항
- 처음부터 실제 위경도 좌표를 맞추려고 하지 말고, 공장 이미지 기준 내부 좌표계로 단순하게 시작한다.
- 지오펜스는 프론트에서 “그리는 기능”이고, 실제 위험 판단은 백엔드에서 수행한다.
- 센서 좌표, 작업자 좌표, 지오펜스 polygon 좌표는 반드시 동일한 기준 좌표계를 사용해야 한다.
- 지오펜스가 너무 많아지면 화면이 복잡해지므로 색상 규칙과 레이어 표시 기준을 미리 정해두는 것이 좋다.
- 1단계에서는 “정확한 실측 좌표”보다 “동작 가능한 구조”가 더 중요하다.
- 위험 구역, 작업자 위치, 센서 상태가 한 화면에서 겹쳐 보이기 때문에 시각적 우선순위를 정해야 한다.
- 위험 구역의 목적은 단순 시각화가 아니라, 이후 서버에서 **“작업자 위치가 위험 구역 내부인지”** 판단하기 위한 기준 데이터라는 점을 유지해야 한다. 요구사항 문서에서는 메시맵 기반 실시간 모니터링, 작업자 위치 측위, 위험구역 관리, 통합 대시보드 제공이 명시되어 있다.
