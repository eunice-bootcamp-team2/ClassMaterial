
작업 목적
Figma로 설계된 관제 화면을 실제 웹 화면으로 구현하고,  
센서 데이터가 실시간으로 갱신되는 대시보드를 구성한다.  
1단계에서는 화면이 자연스럽게 동작하고, 운영자가 주요 상태를 한눈에 볼 수 있도록  
UI 구현과 데이터 연결 안정화에 집중한다.

---
작업 내용

1. 화면 레이아웃 구현
- Figma 시안을 기준으로 전체 대시보드 화면 구조를 HTML/CSS로 구현한다.
- 상단 요약 영역, 센서 상태 카드, 차트 영역, 알람 영역, 지도 영역 등 주요 구역을 먼저 나눈다.
- 초기 단계에서는 Django Template 기반으로 화면을 구현하고, 정적 레이아웃이 깨지지 않도록 반응형보다는 고정형 대시보드 레이아웃을 우선 적용한다.
- 웹 퍼블리셔가 전달한 디자인 산출물과 간격, 색상, 폰트, 카드 구조가 최대한 일치하도록 구성한다.

2. 공통 UI 컴포넌트 구성
- 반복적으로 사용하는 카드, 상태 배지, 테이블, 알람 박스, 버튼 영역을 공통 구조로 정리한다.
- 센서 상태에 따라 정상 / 주의 / 위험 색상이 다르게 보이도록 CSS 클래스를 분리한다.
- 추후 React 전환 가능성을 고려하여, 템플릿 안에서도 영역별로 ID/class를 명확히 분리한다.

3. Chart.js 기반 센서 그래프 구현
- 센서별 실시간 데이터를 선 그래프 또는 막대 그래프로 표시한다.
- 초기에는 CO, H2S, CO2 등 대표 센서 2~3개부터 연결하고, 이후 동일 패턴으로 확장 가능하게 작성한다.
- 그래프는 시간축 기준으로 최근 N개 데이터(예: 최근 20개)를 보여주도록 구성한다.
- 정상 / 주의 / 위험 상태가 시각적으로 구분될 수 있도록 기준선 또는 라벨 영역을 함께 고려한다.

4. 실시간 데이터 반영 구조 연결
- WebSocket 연결이 정상적으로 이루어지면 브라우저가 실시간 데이터를 수신하도록 구성한다.
- 수신된 JSON 데이터를 파싱하여
    - 카드 수치 갱신
    - 상태 색상 변경
    - 차트 데이터 추가
    - 최근 이벤트 리스트 반영  
        순서로 업데이트한다.
- 새 데이터가 들어올 때마다 전체 화면을 새로고침하지 않고, 필요한 영역만 갱신되도록 작성한다.

5. 초기 더미 데이터 바인딩
- WebSocket 연결 전에도 화면 개발이 가능하도록 초기 더미 JSON 데이터를 준비한다.
- 퍼블리싱 단계에서는 고정 더미 데이터로 먼저 UI를 완성하고,
- 이후 FastAPI에서 전달하는 가짜 실시간 데이터로 연결한다.
- 이 과정을 분리하면 화면 작업과 데이터 작업을 병렬로 진행할 수 있다.

6. 상태 및 예외 처리
- WebSocket 연결이 끊겼을 때 “연결 끊김” 또는 “재연결 시도 중” 같은 상태 문구를 표시한다.
- 데이터가 아직 없을 경우 빈 차트, 0값, placeholder 문구가 자연스럽게 보이도록 처리한다.
- 비정상 데이터(null, undefined, 필드 누락)가 들어와도 화면이 깨지지 않도록 방어 로직을 작성한다.

---
세부 작업 순서

STEP 1. Figma 화면 영역 분해
- 헤더
- 요약 카드
- 센서 차트 영역
- 지도/지오펜스 영역
- 이벤트/알람 영역  
    먼저 이렇게 구역을 나누고 각 구역의 우선순위를 정한다.

STEP 2. 정적 화면 먼저 구현
- 실제 데이터 없이 HTML/CSS만으로 화면을 먼저 완성한다.
- 이 단계에서는 디자인 정합성과 사용자 동선이 중요하다.

STEP 3. 더미 데이터 연결
- JSON 샘플 데이터를 기준으로 카드와 그래프가 정상적으로 보이는지 확인한다.

STEP 4. Chart.js 연결
- 차트 라이브러리를 붙이고, 더미 데이터 기준으로 그래프가 정상 출력되는지 검증한다.

STEP 5. WebSocket 연결
- FastAPI 또는 실시간 데이터 송신부와 연결하여 브라우저가 실시간으로 데이터를 수신하도록 한다.

STEP 6. 실시간 갱신 로직 연결
- 새 데이터가 들어올 때 카드/차트/이벤트 리스트가 자연스럽게 갱신되도록 구현한다.

STEP 7. 예외 처리 및 안정화
- 데이터 누락, 연결 끊김, 브라우저 새로고침, 느린 응답 상황에서 화면이 깨지지 않는지 점검한다.

---
입력 데이터 형식 예시

프론트 화면에서는 아래와 같은 형태의 JSON 데이터를 기준으로 연결한다.
```json
{  
  "timestamp": "2026-04-12T10:00:00",  
  "device_id": "sensor_01",  
  "worker_id": "worker_01",  
  "location": { "x": 120, "y": 240 },  
  "gas": {  
    "co": 18,  
    "h2s": 6,  
    "co2": 820,  
    "o2": 20.3  
  },  
  "power": {  
    "current": 12.4,  
    "voltage": 220.1,  
    "watt": 2710  
  },  
  "status": "normal"  
}
```

---
완료 기준
- 페이지 로딩 시 주요 카드, 차트, 알람 영역이 정상 출력된다.
- 더미 데이터와 실시간 데이터 모두 동일한 구조로 화면에 반영된다.
- WebSocket으로 수신한 데이터가 1초 단위 또는 설정 주기 단위로 갱신된다.
- 차트가 끊기지 않고 최근 데이터 흐름을 지속적으로 표시한다.
- 센서 상태값에 따라 정상 / 주의 / 위험 색상이 즉시 반영된다.
- 데이터가 비정상적으로 들어오더라도 UI가 깨지지 않는다.
- 새로고침 또는 재접속 시 화면이 정상적으로 다시 연결된다.

- 화면 동작 확인용 테스트 시나리오

작업 시 주의사항
- 처음부터 모든 센서를 한 번에 붙이지 말고, 대표 센서 2~3개 먼저 연결한 뒤 확장한다.
- 화면 구현과 데이터 연결을 동시에 시작하지 말고, 반드시 정적 화면 → 더미 데이터 → 실시간 데이터 순서로 진행한다.
- 차트는 데이터가 누적될수록 무거워질 수 있으므로 최근 N개 데이터만 유지하도록 제한한다.
- 색상, 상태 문구, 단위(ppm, %, W 등)는 문서에 정의된 기준과 일치시킨다.
- 운영자 관점에서 가장 먼저 봐야 하는 정보(현재 위험 상태, 최근 알람, 센서 수치)를 화면 상단에 우선 배치한다.
