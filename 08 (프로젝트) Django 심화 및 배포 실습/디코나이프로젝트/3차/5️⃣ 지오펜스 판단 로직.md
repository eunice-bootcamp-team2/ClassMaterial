작업 목적

실시간으로 수신되는 작업자 위치 데이터와 센서 데이터를 기반으로,  
현재 작업자가 위험 구역(지오펜스) 내부에 있는지 확인하고,  
동시에 해당 위치 주변 또는 연관 센서의 측정값이 임계치를 초과했는지를 판단하여  
**위험 상황을 서버에서 자동으로 감지하고 알람 이벤트를 생성하는 것**이 목적이다.

이 기능은 단순 화면 표시가 아니라,  
관제 플랫폼의 핵심 판단 로직이며  
이후 AI 이상 탐지, 이벤트 관리, 경보 시스템으로 확장되는 중심 기능이 된다.

---

작업 내용

1. 판단 대상 데이터 정의
지오펜스 판단 로직은 다음 3가지 데이터를 기준으로 동작한다.

- **지오펜스 데이터**: DB에 저장된 polygon 좌표
- **작업자 위치 데이터**: 실시간으로 들어오는 현재 작업자 좌표
- **센서 측정 데이터**: 가스 및 전력 센서 수치와 상태값

즉, 서버는 단순히 센서값만 보는 것이 아니라  
누가, 어디에 있고, 그 위치에서 어떤 위험값이 발생했는가를 함께 판단해야 한다.


 2. 작업자 위치의 지오펜스 내부 여부 판별
- 서버는 수신한 작업자 위치 좌표가 특정 polygon 내부에 포함되는지 검사한다.
- 이 기능은 point-in-polygon 알고리즘 또는 공간 판별 라이브러리를 통해 구현한다.
- 1단계에서는 공장 이미지 기반 내부 좌표계(x, y) 기준으로 단순 판별하면 충분하다.
- 하나의 작업자가 여러 지오펜스 중 어느 구역에 속하는지 확인하고,  
    속하지 않으면 일반 상태로 처리한다.

3. 센서 임계치 비교
- 작업자 위치가 지오펜스 내부로 판별되면,  
    해당 구역과 연관된 센서 또는 가장 가까운 센서 데이터를 기준으로 위험도를 계산한다.
- 센서값은 문서에 정의된 임계치 기준으로 정상 / 주의 / 위험 단계를 나눈다.
- 예:
    - CO 25 미만 → 정상
    - CO 25~200 → 주의
    - CO 200 이상 → 위험
- 전력 데이터는 절대 임계치보다 평균 사용량 대비 이상 증감, 과부하 패턴 등으로 확장 가능하지만,  
    1단계에서는 가짜 기준값 또는 상태 플래그 기준으로 단순 비교해도 된다.

4. 위치 + 임계치 결합 판단
- 지오펜스 판단은 단독으로는 알람을 만들지 않는다.
- 센서 임계치 초과도 단독으로는 전체 알람으로 연결하지 않는다.
- 반드시 **공간 조건 + 데이터 조건**을 함께 만족할 때 위험 이벤트로 처리한다.

즉, 기본 로직은 다음과 같다.
```
작업자 위치 ∈ 지오펜스  
AND  
연관 센서값 > 임계치  
→ 알람 발생

필요 시 향후에는 여기에 시간 조건도 추가할 수 있다.

작업자 위치 ∈ 지오펜스  
AND  
연관 센서값 > 임계치  
AND  
위험 상태가 N초 이상 지속  
→ 알람 발생
```

5. 알람 이벤트 생성
- 조건이 만족되면 서버는 알람 이벤트 객체를 생성한다.
- 이벤트에는 다음 정보가 포함되어야 한다.
    - 발생 시각
    - 작업자 ID
    - 지오펜스 이름
    - 센서 ID
    - 위험 항목 (예: CO, H2S)
    - 측정값
    - 위험 단계
    - 메시지
- 이 이벤트는 DB 저장 또는 실시간 알림 송신의 기준 데이터가 된다.

6. UI 표시를 위한 결과 전달
- 서버는 판단 결과를 프론트로 전달한다.
- 프론트는 이를 받아 다음과 같이 표시한다.
    - 경고 배너 표시
    - 지도 위 작업자/센서 강조
    - 이벤트 리스트 추가
    - 상태 카드 색상 변경
- 즉, 판단은 서버가 하고, 표시와 인터랙션은 프론트가 담당한다.

7. 중복 알람 방지
- 같은 작업자, 같은 구역, 같은 센서, 같은 위험 상태가 짧은 시간 동안 반복 발생할 수 있다.
- 이 경우 매초 동일한 경고를 계속 생성하면 UI가 과도하게 깜빡이거나 이벤트 로그가 불필요하게 증가한다.
- 따라서 중복 알람 방지 정책이 필요하다.
- 예:
    - 동일 위험 조건은 10초 내 1회만 알람 생성
    - 위험 단계가 변경될 때만 새 이벤트 생성
- 1단계에서는 간단한 메모리 캐시나 최근 이벤트 기록 비교 방식으로도 구현 가능하다.

8. 테스트 시나리오별 검증
- 다음 상황을 각각 확인해야 한다.
    1. 작업자가 지오펜스 밖에 있고 센서값 정상 → 알람 없음
    2. 작업자가 지오펜스 안에 있으나 센서값 정상 → 알람 없음
    3. 작업자가 지오펜스 밖에 있고 센서값 위험 → 일반 경고만 또는 알람 없음
    4. 작업자가 지오펜스 안에 있고 센서값 위험 → 알람 발생
- 이 테스트를 통해 단순 수치 경고와 실제 위험 경보를 구분할 수 있다.

세부 작업 순서

STEP 1. 지오펜스 좌표 데이터 구조 확정
- DB에 저장된 polygon 구조를 확인하고, 서버에서 읽을 수 있는 형태로 정리한다.

STEP 2. 작업자 위치 입력 포맷 확정
- 실시간으로 들어오는 작업자 위치 데이터를 `x`, `y` 기준으로 통일한다.

STEP 3. 센서 데이터 상태 판별 함수 작성
- 각 센서값을 임계치 기준으로 정상 / 주의 / 위험으로 분류하는 함수를 만든다.

STEP 4. polygon 내부 여부 판별 함수 작성
- 작업자 좌표가 polygon 내부에 있는지 검사하는 함수를 만든다.
- 초기에는 직접 구현하거나 간단한 라이브러리 사용이 가능하다.

STEP 5. 위치 + 센서값 결합 로직 작성
- 작업자가 특정 지오펜스 안에 있고, 해당 구역 센서값이 위험 조건인지 함께 검사한다.

STEP 6. 알람 이벤트 생성 로직 작성
- 조건을 만족하면 알람 메시지와 이벤트 데이터를 만든다.

STEP 7. 프론트 송신 연결
- 생성된 알람 이벤트를 WebSocket 또는 API 응답으로 프론트에 전달한다.

STEP 8. 중복 알람 방지 처리
- 동일 조건 반복 발생 시 불필요한 연속 경고를 막는 정책을 적용한다.

STEP 9. 시나리오 테스트
- 정상 / 주의 / 위험 / 지오펜스 내부 / 외부 조합별로 결과를 검증한다.

---
판단 흐름 예시
① 작업자 위치 수신  
② DB의 지오펜스 목록 조회  
③ 현재 위치가 어떤 지오펜스 내부인지 판별  
④ 해당 구역과 연결된 센서 데이터 확인  
⑤ 센서값이 임계치를 초과했는지 비교  
⑥ 조건 만족 시 알람 이벤트 생성  
⑦ 프론트에 알람 전달 및 UI 갱신

---
의사코드 예시
```js
worker_point = (x, y)  
geofences = load_geofences()  
sensor_data = get_latest_sensor_data()  
  
for geofence in geofences:  
    if point_in_polygon(worker_point, geofence.polygon):  
        status = check_sensor_threshold(sensor_data)  
        if status == "danger":  
            create_alert(  
                worker_id=worker_id,  
                geofence_name=geofence.name,  
                sensor_id=sensor_data["device_id"],  
                message="위험구역 내부에서 위험 수치 감지"  
            )
```

데이터 구조 예시

지오펜스 데이터
```json
{  
  "id": 1,  
  "name": "위험구역 A",  
  "polygon": [  
    [100, 120],  
    [180, 120],  
    [180, 220],  
    [100, 220]  
  ]  
}
```

작업자 위치 데이터
```json
{  
  "worker_id": "worker_01",  
  "location": {  
    "x": 150,  
    "y": 170  
  }  
}
```

센서 데이터
```json
{  
  "device_id": "sensor_01",  
  "gas": {  
    "co": 230,  
    "h2s": 12,  
    "o2": 19.2  
  },  
  "status": "danger"  
}
```

```json
{  
  "type": "alert",  
  "timestamp": "2026-04-12T10:01:10",  
  "worker_id": "worker_01",  
  "geofence_name": "위험구역 A",  
  "sensor_id": "sensor_01",  
  "level": "danger",  
  "message": "작업자 worker_01이 위험구역 A 내부에서 CO 위험 수치에 노출됨"  
}
```

---
완료 기준

- 서버가 작업자 위치가 지오펜스 내부인지 정상적으로 판별한다.
- 센서 데이터가 임계치 기준으로 정상 / 주의 / 위험 상태로 분류된다.
- 위치 조건과 데이터 조건이 모두 만족할 때만 알람 이벤트가 발생한다.
- 생성된 알람이 프론트 UI에 즉시 반영된다.
- 지오펜스 외부에서는 동일 센서 위험값이 있어도 전체 경고 로직이 다르게 동작한다.
- 동일 알람이 과도하게 반복 생성되지 않는다.
- 정상 / 주의 / 위험 시나리오 테스트 결과가 기대한 대로 나온다.

주요 산출물

- 지오펜스 내부 판별 함수
- 센서 임계치 비교 함수

- 프론트 연동용 알람 메시지 포맷

- 정상/위험 케이스 검증 로그

작업 시 주의사항

- 판단 로직은 프론트가 아니라 반드시 서버에서 수행해야 한다.
- 지오펜스는 단순히 화면에 그려진 영역이 아니라, 서버 판단용 기준 데이터라는 점을 유지해야 한다.
- 센서값과 위치 데이터의 시간 차이가 너무 크면 잘못된 판단이 나올 수 있으므로, 같은 시점의 최신 데이터를 기준으로 비교하는 원칙이 필요하다.
- 한 작업자가 여러 구역 경계에 걸치는 상황, 여러 센서가 동시에 위험한 상황 등 예외 케이스를 고려해야 한다.
- 1단계에서는 가장 가까운 센서 1개 또는 지오펜스에 연결된 대표 센서 기준으로 단순화해도 되지만, 이후 다중 센서 기반 판단으로 확장할 수 있도록 구조를 분리해 두는 것이 좋다.
- 요구사항 문서에서도 위험 구역, 실시간 모니터링, 경보 및 알림 관리, 위험도 판단 기준 관리가 명시되어 있으므로, 이 로직은 단순 데모 기능이 아니라 시스템의 핵심 업무 로직에 해당한다.
