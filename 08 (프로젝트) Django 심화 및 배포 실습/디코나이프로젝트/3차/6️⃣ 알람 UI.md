작업 목적

서버에서 판단된 위험 이벤트를 운영자가 즉시 인지할 수 있도록  
대시보드 화면에 **시각적으로 명확한 알람 UI**를 구성한다.  
1단계에서는 복잡한 알림 채널 연동보다  
**“위험 상황이 발생했을 때 화면에서 바로 보이고, 어떤 문제가 발생했는지 이해할 수 있는 상태”**를 만드는 것이 목적이다.

즉, 알람 UI는 단순히 메시지를 띄우는 기능이 아니라  
운영자가 현재 위험 상태를 한눈에 파악하고,  
발생 시각, 대상, 위험 수준, 위치 정보를 빠르게 확인할 수 있게 하는  
관제 화면의 핵심 인터페이스이다.

---

### 작업 내용

#### 1. 위험 상태 시각 규칙 정의
- 알람 UI는 정상 / 주의 / 위험 상태를 색상과 텍스트로 명확히 구분해야 한다.
- 예:
    - 정상: 녹색 또는 회색
    - 주의: 노란색 / 주황색
    - 위험: 빨간색
- 색상만으로 구분하지 말고, 상태 텍스트(정상, 주의, 위험)와 아이콘을 함께 사용한다.
- 화면 전체에서 동일한 위험도 체계를 유지하여 카드, 지도, 이벤트 리스트, 센서 상태가 서로 다르게 보이지 않도록 통일한다.

#### 2. 실시간 알람 배너 또는 상태 박스 구성
- 위험 이벤트가 발생하면 화면 상단 또는 우측 패널에 알람 배너를 띄운다.
- 운영자가 페이지를 보고 있을 때 바로 인지할 수 있도록  
    시각적으로 가장 먼저 보이는 위치에 배치한다.
- 알람 박스에는 최소한 아래 정보가 포함되어야 한다.
    - 위험 단계
    - 발생 시각
    - 작업자 또는 센서 이름
    - 지오펜스 이름
    - 경고 메시지
- 1단계에서는 팝업보다 **고정형 경고 영역**이 더 안정적이며 관리하기 쉽다.

#### 3. 이벤트 리스트 UI 구성
- 최근 발생한 알람 및 이벤트를 시간순으로 보여주는 리스트 영역을 만든다.
- 이벤트 리스트에는 다음 정보를 표시한다.
    - 발생 시각
    - 이벤트 유형
    - 센서명 / 작업자명
    - 위치 또는 구역명
    - 상태 레벨
    - 간단한 설명
- 최신 이벤트가 위로 오도록 정렬하고, 리스트가 길어질 경우 스크롤이 가능하도록 한다.
- 정상 정보까지 모두 넣기보다, 1단계에서는 **주의/위험 이벤트 위주로 표시**하는 것이 관제 화면 목적에 더 적합하다.

#### 4. 지도 및 상태 카드와 시각적 연동
- 알람이 발생했을 때 이벤트 리스트만 바뀌는 것이 아니라,  
    관련 지도 마커, 작업자 아이콘, 센서 카드도 함께 강조되어야 한다.
- 예:
    - 위험 센서는 빨간색 테두리
    - 위험 구역은 반투명 빨간색 강조
    - 작업자 아이콘 깜빡임 또는 강조 표시
- 이렇게 하면 운영자가 알람 메시지와 공간 위치를 동시에 이해할 수 있다.

#### 5. 실시간 수신 이벤트 반영
- WebSocket 또는 서버 응답으로 전달된 알람 이벤트를 받아  
    UI에서 즉시 반영한다.
- 실시간 반영 대상은 다음과 같다.
    - 경고 배너 갱신
    - 이벤트 리스트 상단 추가
    - 관련 카드 상태 변경
    - 지도 강조
- 새 이벤트 발생 시 전체 페이지를 새로고침하지 않고, 해당 UI 요소만 부분 갱신한다.

#### 6. 알람 확인 상태(읽음/미확인) 구분
- 동일한 이벤트가 계속 쌓일 경우 운영자가 현재 확인한 경고와 미확인 경고를 구분할 수 있어야 한다.
- 1단계에서는 간단하게
    - 신규 이벤트: 강조 표시
    - 일정 시간 경과 또는 클릭 후: 일반 상태  
        정도의 방식으로 구현할 수 있다.
- 향후 2단계에서는 확인 처리, 조치 상태, 담당자 배정 등으로 확장 가능하다.

#### 7. 중복 알람 표시 제어
- 동일 이벤트가 짧은 주기로 반복될 경우 UI가 과도하게 깜빡이거나 리스트가 도배되지 않도록 제어해야 한다.
- 예:
    - 같은 작업자/센서/구역/위험 수준 조합은 일정 시간 내 하나로 묶기
    - 이벤트 리스트에는 최초 시각과 최근 갱신 시각만 표시
- 이 로직은 서버에서 먼저 제어하는 것이 바람직하지만, 프론트에서도 기본 중복 표시 방지 처리가 필요하다.

#### 8. 빈 상태 및 예외 상황 처리
- 아직 이벤트가 없을 경우 “현재 발생한 경고 없음” 같은 기본 문구를 표시한다.
- 통신 끊김 상태에서는 “실시간 이벤트 수신 중단” 같은 안내를 별도로 보여준다.
- 알람 데이터 일부가 누락되어도 UI 전체가 깨지지 않도록 기본값과 예외 처리를 둔다.

### 세부 작업 순서

#### STEP 1. 알람 UI 영역 정의
- Figma 화면 기준으로 알람 영역 위치를 확정한다.
- 상단 경고 배너, 우측 이벤트 패널, 하단 로그 리스트 중 어떤 구조가 가장 적합한지 정한다.

#### STEP 2. 상태 색상 체계 정리
- 정상 / 주의 / 위험 상태의 색상, 텍스트, 아이콘 규칙을 정한다.
- 이 규칙을 카드, 지도, 이벤트 리스트 전체에 공통 적용한다.

#### STEP 3. 이벤트 리스트 정적 화면 구현
- 더미 데이터 기준으로 최근 이벤트 리스트 디자인을 먼저 완성한다.
- 시간, 레벨, 메시지, 대상 정보가 잘 보이는지 확인한다.

#### STEP 4. 경고 배너/요약 박스 구현
- 실시간 위험 상황을 가장 먼저 보여줄 수 있는 경고 박스를 만든다.
- 신규 위험 발생 시 해당 영역이 즉시 바뀌도록 준비한다.

#### STEP 5. WebSocket 알람 메시지 연결
- 서버가 보낸 알람 메시지를 브라우저가 수신하면 이벤트 리스트와 경고 박스가 즉시 갱신되도록 연결한다.

#### STEP 6. 지도/카드 연동 처리
- 특정 이벤트가 발생했을 때 관련 센서 카드, 작업자 마커, 위험구역이 동시에 강조되도록 반영한다.

#### STEP 7. 중복 표시 및 신규 강조 처리
- 같은 이벤트가 반복 발생할 때 UI가 과도하게 복제되지 않도록 처리한다.
- 신규 알람은 일정 시간 강조 표시되도록 한다.

#### STEP 8. 예외/빈 상태 테스트
- 이벤트 없음, 통신 오류, 누락 데이터, 연속 이벤트 발생 상황을 테스트한다.

알람 배너 표시 예시

- 발생 시각: 2026-04-12 10:01:10
- 메시지: 작업자 A가 위험구역 A 내부에서 CO 위험 수치에 노출됨

- 이벤트 유형 (가스 경보 / 전력 이상 / 위치 경고)
- 센서명
- 작업자명
- 지오펜스명
- 위험도 레벨
- 요약 메시지

완료 기준

- 위험 이벤트가 발생하면 화면에서 즉시 확인할 수 있다.
- 정상 / 주의 / 위험 상태가 색상과 텍스트로 명확히 구분된다.
- 최근 이벤트 리스트가 시간순으로 정상 표시된다.
- 신규 알람 발생 시 경고 배너 또는 핵심 알림 영역이 갱신된다.
- 관련 센서, 작업자, 지오펜스가 지도와 카드에서 함께 강조된다.
- 동일 이벤트가 과도하게 중복 표시되지 않는다.
- 이벤트가 없을 때도 화면이 자연스럽게 유지된다.
- 통신 오류나 데이터 누락 시에도 알람 영역이 깨지지 않는다.

작업 시 주의사항

- 알람 UI는 “많이 띄우는 것”보다 “운영자가 바로 이해하는 것”이 더 중요하다.
- 색상만으로 상태를 구분하면 가독성이 떨어질 수 있으므로 텍스트와 아이콘을 함께 사용한다.
- 신규 이벤트가 발생했을 때 화면 전체가 과도하게 깜빡이거나 정신없어지지 않도록 주의한다.
- 이벤트 리스트는 너무 많은 정보를 한 줄에 담지 말고, 핵심 정보 중심으로 정리해야 한다.
- 지도, 카드, 알람 리스트가 서로 다른 기준으로 표시되면 혼란이 생기므로 상태 체계를 반드시 통일한다.
- 1단계에서는 확인/조치 워크플로우까지 복잡하게 가지 말고, “발생을 즉시 보여주는 UI”에 집중하는 것이 적절하다.
- 요구사항 문서에도 현재 발생 중인 위험 및 경보 현황을 대시보드에서 확인하고, 위험 수준에 따라 우선적으로 표시해야 한다고 명시되어 있다. 또한 경보 이력 관리와 처리 상태 확인 기능이 이후 확장 항목으로 제시되어 있다.
