### 발표가이드

`[4가지를 중심으로 설명]`

(1) 이 프로젝트가 무엇을 해결하는 서비스인지
- 어떤 주제를 선택했는지
- 누가 사용하는 서비스인지
- 사용자가 어떤 흐름으로 이용하는지

(2) 핵심 데이터 구조가 어떻게 설계되었는지
- 핵심 도메인 모델이 무엇인지
- 어떤 관계로 연결되어 있는지
- 왜 이렇게 모델을 나눴는지

(3) 실제 기능이 끝까지 동작하는지
- 회원가입 / 로그인
- 핵심 도메인 CRUD
- 검색 / 분류 / 페이지네이션
- 댓글, 좋아요, 업로드 등 선택 기능

(4) 구조를 어떻게 설계했는지
- Django Template와 DRF API를 어떻게 분리했는지
- Serializer / View / Model 역할을 어떻게 나눴는지
- 앱을 책임 기준으로 어떻게 분리했는지

발표 범위 안내
```
이번 3차 발표는 서비스 완성(기능 중심) 발표입니다.  
  
따라서 평가의 중심은 아래 3가지입니다.  
- 사용자 흐름이 실제로 끝까지 동작하는가  
- 핵심 데이터 구조와 백엔드 구조를 설명할 수 있는가  
- 타인이 실행 가능한 수준으로 문서화되어 있는가  
  
※ 4차 범위인 AI 연결, 비동기 처리, 운영/모니터링, 배포 고도화는 
   이번 3차 발표의 필수 평가 대상이 아닙니다.  
※ 단, 팀이 자율적으로 구현한 경우에는 확장 계획 또는 추가 구현으로 짧게 언급할 수 
   있습니다.
```

`2.` 핵심 기능 소개
	필수 기능 중심으로 설명합니다.

```
필수/선택 판정 기준  
  
이번 발표 채점은 3차 프로젝트의 최종 수락 기준(DoD)을 우선 기준으로 적용합니다.  
  
따라서 아래 항목은 발표에서 실제 동작 여부를 확인합니다.  
- 핵심 도메인 CRUD  
- 검색 / 페이지네이션  
- 관리자 페이지  
- 사용자 상호작용 기능 1종 이상 (예: 댓글, 좋아요, 북마크 중 택1 이상)  
- 첨부 데이터 처리 1종 이상 (예: 이미지 업로드 또는 파일 업로드)  
  
선택 기능이 있다면 추가로 설명합니다.  
- JWT 인증  
- 태그 / 필터링  
- Soft Delete  
- 관리자 페이지 커스터마이징  
- 검색 고도화  
- 페이지네이션 고도화  
- 권한 처리 고도화  
  
※ 프로젝트 주제 특성상 상호작용 기능 또는 첨부 데이터 처리 중 한쪽이 어울리지 않는 경우,  
다른 한쪽으로 대체하여 필수 기준을 충족한 것으로 인정합니다.  
※ 즉, 두 항목을 모두 구현해야 하는 것은 아니며, 프로젝트에 맞는 방식으로 최소 1가지를 명확히 시연하면 됩니다.
```

`4.` 백엔드 구조 설명
이 발표는 기능만 보는 것이 아니라  
구조를 어떻게 나눴는지도 중요합니다.

반드시 설명할 내용:
- Model: DB 구조 정의
- Serializer: DB ↔ JSON 변환
- View: 요청 처리
- Template: 화면 출력

또한 아래도 함께 설명하면 좋습니다.
- Django Template와 DRF API 분리 여부
- static / js 분리 여부
- APIView 또는 ViewSet 사용 이유
- 앱 분리 기준이 모델 기준이 아니라 책임 기준이라는 점

채점 기본 원칙
- 필수 항목은 기본점수 100점 기준으로 채점합니다.
- 선택 기능은 가산점 항목으로 처리합니다.
- 따라서 기본점수 100점 + 가산점 최대 20점 구조로 운영합니다.
- 단, 필수 항목이 부족한 경우 선택 기능을 많이 넣어도 기본점수를 대체할 수 없습니다.

가산점 적용 규칙
- 가산점은 구현 + 발표 시연 + 설명이 모두 확인된 경우만 반영합니다.
- 단순히 코드만 존재하거나 발표에서 설명하지 못하면 가산점으로 인정하지 않습니다.
- 가산점 총합은 최대 20점까지만 인정합니다.
- 선택 기능이 많더라도 필수 기능이 미완성인 경우 높은 평가를 받을 수 없습니다.
