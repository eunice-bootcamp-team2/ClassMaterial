
체크 방법
- `[ ]` 미확인 / 미구현
- `[x]` 확인 완료 / 발표 가능

주의사항
- 체크리스트에 `[x]` 표시한 항목은 발표에서 실제로 시연 가능해야 합니다.
- 체크한 내용과 실제 발표 내용이 다를 경우 감점될 수 있습니다.
- 자가점검은 코드가 있다가 아니라 실제로 동작한다를 기준으로 체크합니다.

### 1. 프로젝트 소개 및 발표 구성

- [ ]  프로젝트명과 한 줄 소개를 말할 수 있다.
- [ ]  이 서비스가 해결하려는 문제가 무엇인지 설명할 수 있다.
- [ ]  주요 사용자가 누구인지 설명할 수 있다.
- [ ]  발표 시간이 10분 내외로 맞춰져 있다.

### 4. 필수 기능 자가점검

#### 4-1. 회원가입

- [ ]  회원가입이 실제로 된다.
- [ ]  필수값 누락 시 검증이 동작한다.
- [ ]  중복 가입이 차단된다.
- [ ]  비밀번호가 해시 저장된다.

#### 4-2. 로그인 / 로그아웃

- [ ]  로그인 기능이 실제로 된다.
- [ ]  로그인 후 보호된 기능에 접근 가능하다.
- [ ]  로그아웃 후 접근 제한이 정상 동작한다.

#### 4-3. 핵심 도메인 CRUD

- [ ]  핵심 데이터 생성(Create)이 된다.
- [ ]  핵심 데이터 조회(Read)가 된다.
- [ ]  핵심 데이터 수정(Update)이 된다.
- [ ]  핵심 데이터 삭제(Delete)가 된다.
- [ ]  권한 규칙이 있다.  
    (예: 작성자만 수정/삭제 가능)

#### 4-4. 분류 기능(카테고리 1단계)

- [ ]  핵심 데이터와 카테고리가 연결되어 있다.
- [ ]  목록 또는 상세 조회에서 분류 정보가 보인다.

#### 4-5. 검색

- [ ]  단일 필드 검색이 실제로 동작한다.
- [ ]  검색어에 따라 결과가 달라진다.

#### 4-6. 페이지네이션

- [ ]  목록에서 페이지 이동이 된다.
- [ ]  페이지네이션이 화면 또는 API에서 확인된다.

#### 4-7. 관리자 페이지

- [ ]  관리자 계정으로 로그인할 수 있다.
- [ ]  핵심 데이터 관리가 가능하다.
- [ ]  주요 데이터의 생성/조회/수정/삭제 확인이 가능하다.

#### 4-8. 확장 기능 1종 이상

- [ ]  우리 프로젝트에 맞는 확장 기능 1종 이상이 실제로 동작한다.
- [ ]  해당 기능을 발표에서 직접 시연할 수 있다.

### 5. 데이터 흐름 완성도

- [ ]  사용자 입력 → 서버 처리 → DB 저장 → 화면 출력 흐름이 끊기지 않는다.
- [ ]  생성한 데이터가 실제 DB에 반영된다.
- [ ]  저장된 데이터가 다시 화면 또는 API 응답에 표시된다.
- [ ]  핵심 시연 흐름을 처음부터 끝까지 1회 이상 점검했다.

## 선택 기능 가산점 자가확인

아래 항목은 구현 + 시연 + 설명이 모두 가능할 때만 체크합니다.

- [ ]  JWT 인증 구현 (Access Token 포함 전체 흐름)

- [ ]  파일 업로드 고도화 (용량/확장자 정책, 메타데이터, 다중 업로드 등)

- [ ]  인터렉션 고도화 (토글, 중복 방지, 집계, 랭킹 반영 등)
- [ ]  태그 기능
- [ ]  검색 고도화 (필터링, 다중 조건 검색)
- [ ]  페이지네이션 고도화
- [ ]  관리자 페이지 커스터마이징
- [ ]  Soft Delete 적용
- [ ]  권한 처리 고도화
- [ ]  PostgreSQL 전환 및 정상 동작 확인
- [ ]  예외 처리 / 에러 응답 표준화
