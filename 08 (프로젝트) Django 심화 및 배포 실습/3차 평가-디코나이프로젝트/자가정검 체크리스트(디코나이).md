### 자가점검 체크리스트

체크 방법
- `[ ]` 미확인 / 미구현
- `[x]` 확인 완료 / 발표 가능

주의사항
- 체크한 항목은 발표에서 실제로 시연 가능해야 합니다.
- 코드가 있다가 아니라 실제로 동작한다를 기준으로 체크합니다.

### 1. 프로젝트 소개 / 문제 정의

- [ ]  우리 프로젝트가 해결하려는 산업 현장 문제가 무엇인지 설명할 수 있다.
- [ ]  왜 관제 플랫폼이 필요한지 설명할 수 있다.
- [ ]  단순 모니터링이 아니라 사전 감지/예방이 왜 중요한지 설명할 수 있다.
- [ ]  3차 발표의 범위를 한 문장으로 설명할 수 있다.

예:

- [ ]  “3차는 AI 완성이 아니라, UI + 데이터 흐름 + 지오펜스 + 알람을 실제로 보이게 만드는 단계입니다.” 라고 설명 가능하다.

---

### 3. 핵심 기능 자가점검

#### 3-1. 대시보드 UI

- [ ]  Figma 기반 화면이 구현되어 있다.
- [ ]  차트가 정상적으로 출력된다.
- [ ]  데이터 변경 시 UI가 갱신된다.

#### 3-2. 지도 + 지오펜스

- [ ]  공장 이미지 또는 지도 기반 좌표계가 준비되어 있다.
- [ ]  센서 위치가 표시된다.
- [ ]  지오펜스가 생성되거나 최소한 시각적으로 표현된다.

#### 3-3. 가짜 데이터 생성

- [ ]  센서값이 주기적으로 바뀐다.
- [ ]  작업자 위치 또는 객체 위치가 이동하는 것처럼 보인다.
- [ ]  정적인 목업이 아니라 데이터가 실제로 변한다.

#### 3-4. 실시간 통신

- [ ]  FastAPI에서 WebSocket으로 데이터를 보낸다.
- [ ]  프론트에서 이를 정상적으로 수신한다.
- [ ]  데이터가 끊기지 않고 일정 시간 이상 반영된다.
- [ ]  연결 끊김 또는 서버 재시작 상황에서 재연결 또는 상태 표시가 확인된다.

#### 3-5. 지오펜스 판단 로직

- [ ]  위치가 지오펜스 내부인지 판단할 수 있다.
- [ ]  임계치 초과 여부를 비교할 수 있다.
- [ ]  조건 충족 시 위험 상태를 판단한다.
- [ ]  지오펜스 외부에서는 동일 위험값이어도 전체 알람이 다르게 동작함을 확인했다.
- [ ]  동일 알람이 과도하게 반복 생성되지 않음을 확인했다.
- [ ]  정상 / 주의 / 위험 시나리오를 각각 테스트했다.

#### 3-6. 알람 UI

- [ ]  조건 충족 시 색상 변화 또는 경고 표시가 된다.
- [ ]  이벤트 리스트 또는 알람 표시가 반영된다.
- [ ]  발표에서 위험 발생 장면을 직접 보여줄 수 있다.
- [ ]  경고 배너, 이벤트 리스트, 지도 또는 상태 카드 강조가 함께 반영된다.
- [ ]  이벤트가 없을 때 빈 상태 문구가 정상 표시된다.
- [ ]  통신 오류 또는 데이터 누락 시 UI가 깨지지 않는다.

---

### 4. 데이터 흐름 완성도

- [ ]  데이터 생성 → 전송 → 화면 반영 → 판단 → 알람 흐름이 실제로 이어진다.
- [ ]  핵심 시연 흐름을 처음부터 끝까지 한 번 이상 점검했다.
- [ ]  발표용 시연 순서를 팀원끼리 정리했다.

---

### 5. 팀 역할 설명

- [ ]  우리 팀은 데이터 흐름 기준 / 도메인 기준 중 어떤 방식으로 역할을 나눴는지 설명할 수 있다.
- [ ]  각 팀원이 자신의 담당 범위를 설명할 수 있다.
- [ ]  두 방식을 모두 설명하지 않고, 우리 팀 방식 1가지만 일관되게 설명할 수 있다.

---

### 6. 발표 자료 준비 상태

- [ ]  프로젝트 개요 1장이 준비되어 있다.
- [ ]  시스템 구조도 1장이 준비되어 있다.
- [ ]  대시보드 화면 자료가 준비되어 있다.
- [ ]  지도 + 지오펜스 화면 자료가 준비되어 있다.
- [ ]  데이터 흐름 설명 자료가 준비되어 있다.
- [ ]  알람 발생 흐름 설명 자료가 준비되어 있다.
- [ ]  발표용 JSON 예시 또는 데이터 계약 문서를 팀 내에서 공유했다.
- [ ]  위험 발생 장면을 재현할 수 있는 시나리오 모드 또는 테스트 절차를 준비했다.
- [ ]  팀원별 발표 순서가 아니라, 데이터 흐름 기준 시연 순서를 정리했다.

있으면 좋은 자료

- [ ]  역할 분담표
- [ ]  JSON 인터페이스 예시
- [ ]  향후 4차 확장 방향 1장

### 7. 실행 가능성 / 안정성

- [ ]  발표 직전에 핵심 흐름을 다시 실행해봤다.
- [ ]  발표 중 시연할 화면과 순서를 정리했다.
- [ ]  발표 중 보여줄 데이터 상태를 미리 준비했다.
- [ ]  핵심 시연 시 오류 없이 동작한다.
