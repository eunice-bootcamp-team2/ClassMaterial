무엇을 모니터링할지 설계하고, 필요한 서버마다 메트릭을 붙이는 단계
- 어디를 볼지 정한다
- 그 지점에 메트릭을 붙인다
- Prometheus가 수집하게 한다
- Grafana 대시보드로 본다
- 부하를 주고 해석한다
```
메트릭 붙이기 → Prometheus 수집 → Grafana 대시보드 → k6 부하 테스트 → 그래프 해석
```

지금까지: Django / FastAPI 연결 완료, Prometheus / Grafana 기본 연결 완료, `up` 확인 완료  
이제부터: 무엇을 볼지 정한 뒤, AI 라인에 필요한 메트릭을 붙이고, 그 메트릭이 실제 부하에서 어떻게 변하는지 보는 단계입니다.

### 어디를 볼지 정하기

파이프라인: 요청이 어디서 어디로 흐르는지 보는 큰 길
```
브라우저 → Django → Redis → Celery → FastAPI → DB
```
이부분은 어느 구간에서 병목이 생길 수 있지? 찾기 위한 지도입니다.

엔드포인트: 그 큰 길 안에서 실제로 관측할 API 지점
```
Django: /ai/chat/  
FastAPI: /recommend/similarity  
Django: /ai/tasks/{id}/status/
```
이건 정확히 어느 API가 느린지? 보는 관측 포인트입니다.

관찰 대상 : AI 추론
```
사용자 버튼 클릭
→ Django가 기준 리뷰 / 후보 리뷰 조회
→ Django가 FastAPI에 임베딩 또는 유사도 계산 요청
→ FastAPI는 벡터 결과를 반환
→ Django가 PostgreSQL(pgvector)에 저장
→ PostgreSQL이 유사도 계산 또는 유사 리뷰 조회
→ Django가 화면에 결과 반환
```

관찰 대상 파이프라인
```
[브라우저]
  ↓
[JS: 비슷한 후기 보기 버튼 클릭]
  ↓
[Django API: /ai/reviews/<review_id>/analyze/]
  ↓
[Django ORM: source_review / candidate_reviews 조회]
  ↓
[FastAPI 호출]
  ↓
[FastAPI: 임베딩/유사도 계산]
  ↓
[Django: ReviewSimilarityResult 저장]
  ↓
[PostgreSQL/pgvector]
  ↓
[Django 응답 반환]
  ↓
[브라우저에 유사 리뷰 출력]
```

여기서 핵심은 전체 파이프라인과 핵심 엔드포인트를 같이 정하는 것입니다.

### 먼저 볼 파이프라인 구간
현재 프로젝트의 AI 기능은 아래 5개 구간으로 쪼개서 보면 됩니다.

① 프론트 → Django
사용자가 버튼을 눌렀을 때 Django API가 얼마나 빨리 응답하는가?

② Django 내부 후보 리뷰 조회
기준 리뷰 1개와 후보 리뷰 최대 20개 조회가 얼마나 걸리는가?  
현재 `same product`, `exclude self`, `latest 20` 구조입니다.

`backend/apps/ai_gateway/views.py` 확인할 위치
```python
class ReviewAnalyzeAPIView(APIView):
    permission_classes = [AllowAny]

    def get(self, request, review_id):
        source_review = get_object_or_404(
            Review.objects.select_related("user", "product"),
            id=review_id,
            is_public=True,
        )

        candidate_reviews = (
            Review.objects
            .select_related("user")
            .filter(
                product=source_review.product,   # same product
                is_public=True
            )
            .exclude(id=source_review.id)        # exclude self
            .order_by("-created_at")[:20]        # latest 20
        )
```

③ Django → FastAPI 호출
후보 리뷰를 돌면서 FastAPI를 반복 호출하는 구간이 얼마나 느린가?  
이 부분은 현재 구조상 병목 후보 1순위입니다. 

④ Django → DB 저장
`ReviewSimilarityResult.objects.update_or_create(...)` 저장 구간이 얼마나 걸리는가?  

`backend/apps/ai_gateway/views.py`
```python
from apps.ai_gateway.models import ReviewSimilarityResult

# ...

for candidate in candidate_reviews:

    if not candidate.content.strip():
        continue

    similarity_result = FastAPIClient.get_similarity(
        source_review.content,
        candidate.content
    )

    score = round(similarity_result["similarity"], 4)

    if score >= self.SIMILARITY_THRESHOLD:

        # 여기 핵심 (DB 저장)
        ReviewSimilarityResult.objects.update_or_create(
            source_review=source_review,
            compared_review=candidate,
            defaults={
                "product": source_review.product,
                "similarity_score": score,
                "model_name": "e5-small-korean",
            }
        )
```
이 코드의 역할
```
이미 있으면 UPDATE, 없으면 CREATE → 유사도 결과를 DB에 저장
```
왜 update_or_create를 쓰는가?
```
source_review + compared_review 조합이  
이미 존재하면 → 업데이트  
없으면 → 새로 생성
즉, 같은 리뷰 쌍을 중복 저장하지 않기 위해
```
모니터링 관점에서 이 위치가 중요한 이유는
```
🔥 DB 병목 발생 가능 구간  
🔥 I/O 작업 (가장 느려질 수 있음)  
🔥 트랜잭션 발생
```
그래서 반드시 측정해야 합니다.

⑤ 전체 응답 시간
최종적으로 사용자가 버튼 누르고 비슷한 후기가 보일 때까지 얼마나 걸리는가?

위의 내용은 어디를 모니터링 할지 정하는 계획 설계 부분입니다. 조금 어렵게 느껴질수 있습니다. 

실제 프로젝트를 만들때 처음부터 모든 구간을 다 보려고 하면 어렵습니다. 그래서 내 기능 파이프라인에서 무엇을 모니터링할지 정하는 기준을 정하는 팁은 다음과 같습니다.

`1.` 사용자가 직접 기다리는 구간부터 본다
가장 먼저 봐야 하는 것은  
사용자가 버튼을 누르고 결과를 기다리는 구간입니다.

현재 기능에서는 
```
비슷한 후기 보기 버튼 클릭  
→ Django API 호출  
→ 결과 반환
```
이 구간이 가장 중요합니다.

왜냐하면  
사용자는 내부에서 Redis가 어떻게 되고, DB가 어떻게 되고를 먼저 느끼는 것이 아니라  
버튼 눌렀는데 왜 늦지?를 먼저 느끼기 때문입니다.
```
즉, 사용자가 기다리는 시간 = 가장 먼저 모니터링할 대상
```

`2.` 한 기능 안에서 시간이 오래 걸릴 만한 작업을 찾는다
모니터링 포인트를 고를 때는 그 코드가 어려워 보여서가 아니라  
시간이 오래 걸릴 가능성이 높은 작업인지를 보면 됩니다.

현재 프로젝트에서 오래 걸릴 수 있는 작업은 이런 것들입니다.
```
- DB에서 리뷰 여러 개 조회
- FastAPI에 요청 보내기
- 후보 리뷰 개수만큼 반복 호출하기
- DB에 저장하기
- pgvector 유사도 계산하기
```
즉, 이렇게 기억하면 됩니다.
```
반복문, 외부 서버 호출, DB 저장, DB 계산  
→ 느려질 가능성이 높다  
→ 모니터링 후보
```

`3.` 기다리는 작업
- DB 조회 → 기다릴 수 있음
- HTTP 요청 → 기다릴 수 있음
- 저장 → 기다릴 수 있음
즉 기준은 이것입니다.
```
CPU가 바로 처리하는 코드보다  
외부와 통신하거나 저장하는 코드가 더 중요하다
```

`4.` 반복되는 작업은 우선순위를 높인다
한 번만 실행되는 작업보다 여러 번 반복되는 작업이 더 위험합니다.
```
기준 리뷰 1개  
→ 후보 리뷰 여러 개  
→ 후보마다 FastAPI 호출
```
이 구조는 후보가 20개면 FastAPI 호출도 여러 번 일어날 수 있습니다.
pgvector로 바꿨어도 여전히 반복 작업 모니터링 대상입니다. 즉,
```
for문이 사라진 게 아니라  
DB 안으로 들어간 것입니다.
```
pgvector도 동일하게 반복 작업 구조입니다.
- FastAPI 호출
- DB 저장
- 유사도 계산

`5.` 없어도 되는 작업보다 결과를 만드는 작업을 먼저 본다
모니터링 대상을 고를 때  
이 기능에서 진짜 결과를 만드는 핵심 작업이 무엇인지 봐야 합니다.

현재 프로젝트에서 결과를 만드는 핵심은:
- 후보 리뷰 조회
- FastAPI 유사도 계산
- DB 저장
- 최종 응답 반환

반면에
- 버튼 색상
- 안내 문구
- 단순 텍스트 가공
이런 것은 모니터링 1순위가 아닙니다.
```
즉, 이 작업이 없으면 결과가 안 나오나?  
→ 그렇다면 먼저 모니터링
```

`6.` 에러가 났을 때 사용자가 체감하는 구간을 본다
모니터링은 느린 것만 보는 게 아니라 실패하는 지점도 보는 것입니다.

질문
- 이 구간이 실패하면 사용자 화면에서는 어떻게 보일까?

예를 들면:
- Django API 실패  
    → 버튼 눌렀는데 바로 에러
- FastAPI 실패  
    → AI 결과 없음
- DB 저장 실패  
    → 결과가 보이지 않거나 일부만 보일 수 있음
- 후보 리뷰 조회 문제  
    → 비교할 리뷰가 없다고 나올 수 있음

즉, 모니터링 대상은  
실패했을 때 사용자 경험에 영향을 주는 구간을 먼저 잡으면 됩니다.

`7.` 처음에는 전체 시간 + 중간 2~3개만 보면 된다
처음부터 너무 많이 측정하려고 하면 오히려 더 헷갈립니다.

처음에는 아래 정도만 잡아도 충분합니다.
1차로 볼 것
- 전체 응답 시간
- 후보 리뷰 조회 시간
- FastAPI 호출 시간
- DB 저장 시간

이 4개만 있어도  
어디서 시간이 많이 쓰이는지 감이 잡힙니다.

즉 처음기준은 이렇습니다.
맨 처음에는  
전체 1개 + 중간 핵심 3개  
이 정도만 측정하면 충분하다

`8.` 사용자 질문으로 바꾸면 더 쉽다
설계가 어렵게 느껴질 때는  
기술 용어 대신 사용자 질문으로 바꾸면 쉽습니다.

예를 들면:
- 왜 버튼 누르면 늦지?
- 왜 어떤 리뷰는 빠르고 어떤 리뷰는 느리지?
- 왜 AI 결과가 없지?
- 후보 리뷰가 많으면 더 느려지나?
- FastAPI가 느린 건가, DB가 느린 건가?

이 질문에 답하려면 무엇을 봐야 하는지가 곧 모니터링 대상입니다.
```
즉,
내가 나중에 알고 싶은 질문  
→ 지금 붙여야 할 메트릭
```
입니다.

### ✅ STEP 2. Django에 메트릭 붙이기

`backend/apps/ai_gateway/views.py`
```python

# ==============================

# ==============================
# [유지] Celery 작업 상태 조회용 import

from django.shortcuts import get_object_or_404
from requests.exceptions import RequestException
from rest_framework import status
from rest_framework.permissions import AllowAny
from rest_framework.response import Response
from rest_framework.views import APIView

# ==============================
# [유지] AIAnalysisTask import
# - Celery 작업 상태를 DB에 저장하는 모델
# ==============================
from .models import AIAnalysisTask

# ==============================

# ==============================
# [유지] FastAPI 직접 호출용 client
# ==============================
from .services import FastAPIClient

# ==============================
# [유지] Celery task import
# ==============================
from .tasks import analyze_review_similarity_task

# ==============================
# [추가] Prometheus 메트릭 import
# - views.py에서는 "작업 등록 API"만 측정
# ==============================
from prometheus_client import Counter, Histogram

# ==============================
# [추가] 시간 측정용
# ==============================
import time


# =========================================================
# [추가] 작업 등록 API 요청 수
# - 사용자가 AI 분석 버튼을 몇 번 눌렀는지
# =========================================================
AI_ANALYZE_REQUEST_COUNT = Counter(
    "ai_analyze_request_total",
    "Total AI analyze requests",
)

# =========================================================
# [추가] 작업 등록 API 전체 시간
# - /ai/reviews/<review_id>/analyze/ POST 처리 시간
# - 주의: 실제 AI 계산 시간 전체가 아니라
#   "작업 등록 요청" 처리 시간입니다.
# =========================================================
AI_ANALYZE_DURATION = Histogram(
    "ai_analyze_duration_seconds",
    "AI analyze request registration duration",
)


# =========================================================
# [유지] FastAPI 임베딩 테스트용 API
# POST /ai/embed/
# =========================================================
class EmbeddingAPIView(APIView):
    permission_classes = [AllowAny]

    def post(self, request):
        serializer = EmbeddingRequestSerializer(data=request.data)

        if not serializer.is_valid():
            return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)

        texts = serializer.validated_data["texts"]

        try:
            result = FastAPIClient.get_embeddings(texts)
            return Response(result, status=status.HTTP_200_OK)

        except RequestException as e:
            return Response(
                {"detail": f"FastAPI 호출 실패: {str(e)}"},
                status=status.HTTP_502_BAD_GATEWAY,
            )


# =========================================================
# [유지] FastAPI 유사도 테스트용 API
# POST /ai/similarity/
# =========================================================
class SimilarityAPIView(APIView):
    permission_classes = [AllowAny]

    def post(self, request):
        serializer = SimilarityRequestSerializer(data=request.data)

        if not serializer.is_valid():
            return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)

        text1 = serializer.validated_data["text1"]
        text2 = serializer.validated_data["text2"]

        try:
            result = FastAPIClient.get_similarity(text1, text2)
            return Response(result, status=status.HTTP_200_OK)

        except RequestException as e:
            return Response(
                {"detail": f"FastAPI 호출 실패: {str(e)}"},
                status=status.HTTP_502_BAD_GATEWAY,
            )


# =========================================================
# [수정] AI 분석 작업 등록 API
# 기존:
#   GET /ai/reviews/<review_id>/analyze/
#   -> View 안에서 FastAPI 직접 호출 + DB 저장 + 즉시 결과 반환
#
# 현재:
#   POST /ai/reviews/<review_id>/analyze/
#   -> Celery 작업만 등록하고 task_id 반환
# =========================================================
class ReviewAnalyzeAPIView(APIView):
    permission_classes = [AllowAny]

    def post(self, request, review_id):
        # ==============================
        # [추가] 요청 수 증가
        # ==============================
        AI_ANALYZE_REQUEST_COUNT.inc()

        # ==============================
        # [추가] 전체 처리 시간 측정 시작
        # ==============================
        start_total = time.time()

        # ==============================
        # [유지] 기준 리뷰 존재 여부 확인
        # ==============================
        source_review = get_object_or_404(
            Review.objects.select_related("user", "product"),
            id=review_id,
            is_public=True,
        )

        # ==============================
        # [유지] 리뷰 내용 비어 있으면 에러 반환
        # ==============================
        if not source_review.content.strip():
            return Response(
                {"detail": "분석할 리뷰 내용이 없습니다."},
                status=status.HTTP_400_BAD_REQUEST,
            )

        # ==============================
        # [유지] 로그인 사용자 ID 기록
        # ==============================
        requested_by_id = request.user.id if request.user.is_authenticated else None

        # ==============================
        # [유지] Celery 작업 등록
        # - 실제 AI 계산은 worker(tasks.py)에서 수행
        # ==============================
        async_result = analyze_review_similarity_task.delay(
            review_id=source_review.id,
            requested_by_id=requested_by_id,
        )

        # ==============================
        # [유지] 작업 상태 DB 저장
        # ==============================
        AIAnalysisTask.objects.create(
            source_review=source_review,
            requested_by_id=requested_by_id,
            task_id=async_result.id,
            status=AIAnalysisTask.STATUS_PENDING,
            model_name="upskyy/e5-small-korean",
            similarity_threshold=0.45,
        )

        # ==============================
        # [추가] 작업 등록 요청 처리 시간 기록
        # ==============================
        AI_ANALYZE_DURATION.observe(time.time() - start_total)

        # ==============================
        # [유지] task_id 반환
        # ==============================
        return Response(
            {
                "detail": "AI 분석 작업이 등록되었습니다.",
                "task_id": async_result.id,
                "status": "PENDING",
                "review_id": source_review.id,
            },
            status=status.HTTP_202_ACCEPTED,
        )
```

`backend/apps/ai_gateway/tasks.py`
```python
# backend/apps/ai_gateway/tasks.py

# ==============================
# [유지] 기본 라이브러리 import
# ==============================
import json
import logging
import time

# ==============================
# [유지] Redis publish 용
# ==============================
import redis

# ==============================
# [유지] Django / Celery / 외부 호출 관련 import
# ==============================
from apps.reviews.models import Review
from celery import shared_task
from django.utils import timezone
from pgvector.django import CosineDistance
from requests import RequestException

# ==============================
# [유지] 기존 모델 / 서비스 import
# ==============================
from .models import AIAnalysisTask, ReviewEmbedding, ReviewSimilarityResult
from .services import FastAPIClient

# ==============================
# [추가] Prometheus 메트릭 import
# ==============================
from prometheus_client import Counter, Histogram


# ==============================
# [유지] logger 객체
# ==============================
logger = logging.getLogger(__name__)


# =========================================================
# [유지] 유사도 점수 -> 사용자용 문구
# =========================================================
def get_similarity_label(score: float) -> str:
    if score > 0.7:
        return "매우 비슷"
    if score > 0.5:
        return "비슷"
    if score > 0.3:
        return "약간 비슷"
    return "관련 있음"


# =========================================================
# [추가] Prometheus 메트릭 정의
# =========================================================

# 후보 리뷰 조회 시간
AI_CANDIDATE_QUERY_DURATION = Histogram(
    "ai_candidate_query_duration_seconds",
    "Candidate review query duration inside celery task",
)

# FastAPI 임베딩/호출 시간
AI_FASTAPI_DURATION = Histogram(
    "ai_fastapi_duration_seconds",
    "FastAPI call duration inside celery task",
)

# DB 저장 시간
AI_DB_SAVE_DURATION = Histogram(
    "ai_db_save_duration_seconds",
    "DB save duration inside celery task",
)

# Celery task 전체 처리 시간
AI_TASK_TOTAL_DURATION = Histogram(
    "ai_task_total_duration_seconds",
    "Total AI processing duration inside celery task",
)

# FastAPI 에러 수
AI_FASTAPI_ERROR_COUNT = Counter(
    "ai_fastapi_error_total",
    "Total FastAPI call errors inside celery task",
)

# DB 저장 에러 수
AI_DB_SAVE_ERROR_COUNT = Counter(
    "ai_db_save_error_total",
    "Total DB save errors inside celery task",
)

# 실제 저장 성공 수
AI_SIMILARITY_SAVED_COUNT = Counter(
    "ai_similarity_saved_total",
    "Total similarity results saved inside celery task",
)


# =========================================================
# [유지 + 수정]
# 기준 리뷰 1개를 기준으로 같은 상품 내 다른 리뷰들과
# pgvector 기반 유사도 검색을 수행한 뒤 결과를 저장하고,
# Redis publish를 통해 WebSocket 클라이언트에 전달
# =========================================================
@shared_task(
    bind=True,
    autoretry_for=(RequestException,),
    retry_backoff=True,
    retry_kwargs={"max_retries": 3},
)
def analyze_review_similarity_task(
    self,
    review_id: int,
    requested_by_id: int | None = None,
):
    # ==============================
    # [유지] 모델 / threshold 상수
    # ==============================
    MODEL_NAME = "upskyy/e5-small-korean"
    SIMILARITY_THRESHOLD = 0.45

    # ==============================
    # [추가] 전체 task 시간 측정 시작
    # ==============================
    task_start = time.time()

    logger.info(f"[START] Task 시작 | task_id={self.request.id} review_id={review_id}")

    # ==============================
    # [유지] Redis 연결
    # ==============================
    redis_client = redis.Redis(
        host="redis",
        port=6379,
        db=0,
        decode_responses=True,
    )

    # ==============================
    # [유지] 작업 상태 DB 업데이트
    # ==============================
    task_status = AIAnalysisTask.objects.get(task_id=self.request.id)
    task_status.status = AIAnalysisTask.STATUS_STARTED
    task_status.started_at = timezone.now()
    task_status.error_message = ""
    task_status.save(update_fields=["status", "started_at", "error_message"])

    try:
        # ==============================
        # [유지] 기준 리뷰 조회
        # ==============================
        source_review = Review.objects.select_related("user", "product").get(
            id=review_id,
            is_public=True,
        )

        logger.info(f"[SOURCE] 기준 리뷰 조회 완료 | review_id={source_review.id}")

        # ==============================
        # [유지] 내용 비어 있으면 실패 처리
        # ==============================
        if not source_review.content or not source_review.content.strip():
            raise ValueError("분석할 리뷰 내용이 없습니다.")

        # =========================================================
        # [추가] FastAPI 호출 시간 측정 - 기준 리뷰 임베딩 생성
        # =========================================================
        fastapi_start = time.time()
        try:
            source_embedding = FastAPIClient.get_embedding(source_review.content)
            AI_FASTAPI_DURATION.observe(time.time() - fastapi_start)
        except Exception:
            AI_FASTAPI_ERROR_COUNT.inc()
            raise

        # =========================================================
        # [추가] DB 저장 시간 측정 - 기준 리뷰 임베딩 저장
        # =========================================================
        db_start = time.time()
        try:
            ReviewEmbedding.objects.update_or_create(
                review=source_review,
                defaults={"embedding": source_embedding},
            )
            AI_DB_SAVE_DURATION.observe(time.time() - db_start)
        except Exception:
            AI_DB_SAVE_ERROR_COUNT.inc()
            raise

        logger.info(
            f"[EMBED] 기준 리뷰 임베딩 저장 완료 | review_id={source_review.id}"
        )

        # =========================================================
        # [추가] 후보 리뷰 조회 시간 측정
        # =========================================================
        query_start = time.time()
        candidate_reviews = (
            Review.objects.select_related("user")
            .filter(
                product=source_review.product,
                is_public=True,
            )
            .exclude(id=source_review.id)
            .order_by("-created_at")[:20]
        )
        AI_CANDIDATE_QUERY_DURATION.observe(time.time() - query_start)

        candidate_count = candidate_reviews.count()

        logger.info(f"[CANDIDATES] 후보 리뷰 개수={candidate_count}")

        task_status.candidate_count = candidate_count
        task_status.save(update_fields=["candidate_count"])

        # =========================================================
        # [유지 + 수정]
        # 후보 리뷰 임베딩이 없으면 생성해서 저장
        # 이 구간도 FastAPI 호출 + DB 저장이므로 메트릭 측정
        # =========================================================
        for candidate in candidate_reviews:
            if not candidate.content or not candidate.content.strip():
                continue

            exists = ReviewEmbedding.objects.filter(review=candidate).exists()
            if exists:
                continue

            fastapi_start = time.time()
            try:
                candidate_embedding = FastAPIClient.get_embedding(candidate.content)
                AI_FASTAPI_DURATION.observe(time.time() - fastapi_start)
            except Exception:
                AI_FASTAPI_ERROR_COUNT.inc()
                raise

            db_start = time.time()
            try:
                ReviewEmbedding.objects.create(
                    review=candidate,
                    embedding=candidate_embedding,
                )
                AI_DB_SAVE_DURATION.observe(time.time() - db_start)
            except Exception:
                AI_DB_SAVE_ERROR_COUNT.inc()
                raise

            logger.info(f"[EMBED] 후보 리뷰 임베딩 생성 | candidate_id={candidate.id}")

        # =========================================================
        # [유지]
        # pgvector로 유사 리뷰 검색
        # 주의: 여기 자체는 DB 유사도 검색 구간이지만
        # 우선 1차 실습에서는 별도 쿼리 시간 메트릭 없이 유지
        # =========================================================
        similar_embedding_rows = (
            ReviewEmbedding.objects.select_related("review", "review__user")
            .exclude(review_id=source_review.id)
            .filter(review__product=source_review.product)
            .annotate(distance=CosineDistance("embedding", source_embedding))
            .order_by("distance")[:3]
        )

        results = []

        # =========================================================
        # [유지 + 수정]
        # 기존 결과가 중복 저장되지 않게 update_or_create 사용
        # 이 구간은 DB 저장 시간이므로 메트릭 측정
        # =========================================================
        for item in similar_embedding_rows:
            compared_review = item.review
            score = round(float(1 - item.distance), 4)

            if score < SIMILARITY_THRESHOLD:
                continue

            similarity_label = get_similarity_label(score)

            db_start = time.time()
            try:
                saved_result, _ = ReviewSimilarityResult.objects.update_or_create(
                    source_review=source_review,
                    compared_review=compared_review,
                    model_name=MODEL_NAME,
                    defaults={
                        "product": source_review.product,
                        "requested_by_id": requested_by_id,
                        "similarity_score": score,
                        "similarity_label": similarity_label,
                        "similarity_threshold": SIMILARITY_THRESHOLD,
                        "source_review_snapshot": source_review.content,
                        "compared_review_snapshot": compared_review.content,
                        "compared_username_snapshot": compared_review.user.username,
                    },
                )
                AI_DB_SAVE_DURATION.observe(time.time() - db_start)
                AI_SIMILARITY_SAVED_COUNT.inc()
            except Exception:
                AI_DB_SAVE_ERROR_COUNT.inc()
                raise

            logger.info(
                f"[SAVE] 유사도 저장 | compared_review_id={compared_review.id} score={score}"
            )

            results.append(
                {
                    "analysis_id": saved_result.id,
                    "review_id": compared_review.id,
                    "username": compared_review.user.username,
                    "content": compared_review.content,
                    "score": score,
                    "label": similarity_label,
                    "created_at": compared_review.created_at.strftime("%Y-%m-%d %H:%M"),
                }
            )

        # ==============================
        # [유지] 점수순 정렬 후 top3 반환
        # ==============================
        results.sort(key=lambda x: x["score"], reverse=True)
        top_results = results[:3]

        # ==============================
        # [유지] 작업 성공 상태 저장
        # ==============================
        task_status.status = AIAnalysisTask.STATUS_SUCCESS
        task_status.result_count = len(top_results)
        task_status.finished_at = timezone.now()
        task_status.save(update_fields=["status", "result_count", "finished_at"])

        logger.info(
            f"[SUCCESS] Task 완료 | 결과 수={len(top_results)} task_id={self.request.id}"
        )

        # ==============================
        # [유지] 최종 응답 데이터 구성
        # ==============================
        response_data = {
            "source_review": {
                "review_id": source_review.id,
                "username": source_review.user.username,
                "content": source_review.content,
            },
            "similar_reviews": top_results,
            "candidate_count": candidate_count,
            "similarity_threshold": SIMILARITY_THRESHOLD,
            "model_name": MODEL_NAME,
            "task_id": self.request.id,
            "status": "SUCCESS",
        }

        logger.info(f"[REDIS] 결과 publish | channel=task_result_{self.request.id}")

        # ==============================
        # [유지] Redis publish
        # ==============================
        redis_client.publish(
            f"task_result_{self.request.id}",
            json.dumps(response_data, ensure_ascii=False),
        )

        # ==============================
        # [추가] 전체 task 처리 시간 기록
        # ==============================
        AI_TASK_TOTAL_DURATION.observe(time.time() - task_start)

        return response_data

    except Exception as e:
        logger.exception(
            f"[ERROR] Task 실패 | task_id={self.request.id} error={str(e)}"
        )

        # ==============================
        # [유지] 작업 실패 상태 저장
        # ==============================
        task_status.status = AIAnalysisTask.STATUS_FAILURE
        task_status.error_message = str(e)
        task_status.finished_at = timezone.now()
        task_status.save(update_fields=["status", "error_message", "finished_at"])

        error_data = {
            "task_id": self.request.id,
            "status": "FAILURE",
            "error": str(e),
        }

        # ==============================
        # [유지] 실패 결과도 Redis publish
        # ==============================
        redis_client.publish(
            f"task_result_{self.request.id}",
            json.dumps(error_data, ensure_ascii=False),
        )

        raise
```

FastAPI에서 기본적으로 보고 싶은 것은:

- Prometheus가 FastAPI도 수집하는지 확인

왜 FastAPI도 꼭 봐야 하나? 예를 들어 나중에 이런 상황이 생길 수 있습니다.
상황1
- Django 전체 시간은 느린데  
- FastAPI 응답 시간은 정상
이 경우:
- 후보 리뷰 조회
- DB 저장
- Celery/Redis 쪽을 의심
상황2
- Django 전체 시간도 느리고  
- FastAPI p95도 튐
이 경우:
- AI 서버 자체가 느림
- 모델 추론 병목 가능성 큼
즉, FastAPI 메트릭이 있어야 원인 분리가 됩니다.

즉 쉽게 말하면 
- Django만 보면 전체 기능이 느리다는 건 알 수 있음
- FastAPI도 보면 AI 서버가 느린지까지 알 수 있음

FastAPI에서 확인할일
```
1. FastAPI /metrics 열리는지 확인  
2. Prometheus가 FastAPI를 수집하는지 확인  
3. Grafana에서 FastAPI 패널 만들기
```
