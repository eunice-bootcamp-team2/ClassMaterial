### 전체 배포 전략
배포는 한 번에 자동화까지 가는 것이 아니라, 아래 순서로 진행하는 것이 가장 안전합니다.
```
1. CI 구축 (코드 검증)
2. EC2 수동 배포 (환경 검증)
3. CD 자동화 (배포 자동화)
```
바로 완전 자동 CD부터 붙이기보다, 먼저 EC2에 1번 수동 배포를 성공시키고, 그다음 GitHub Actions로 자동 배포를 붙이는 순서가 가장 안전합니다.

즉, `CI 성공 → EC2 1회 수동 배포 성공 → 그 다음 CD 자동화` 순서로 가는 게 초보자에게 가장 덜 헷갈립니다.

현재 프로젝트는 다음과 같은 구조입니다.
```
Django (API 서버)
+ FastAPI (AI 서버)
+ Celery (비동기 처리)
+ Redis (큐)
+ PostgreSQL (DB)
```

그리고 이 모든 서비스는 `backend/docker-compose.yml` 에서 한 번에 실행되는 구조입니다.

따라서 배포도 
```
EC2 1대 + Docker Compose
```
구조로 가는 것이 가장 적절합니다.

### ✅ Amazon RDS란?
Amazon RDS는 AWS에서 제공하는 관리형 관계형 데이터베이스 서비스입니다.

👉 쉽게 말하면
```
DB 서버를 내가 직접 설치하지 않고, AWS가 대신 운영해주는 서비스
```

🔹 지원 DB 종류
```
- MySQL
- PostgreSQL
- MariaDB
- Oracle
- SQL Server
- Amazon Aurora
```

🔹 어떻게 사용하는가?
로컬 DB랑 거의 동일합니다
```
로컬: localhost:3306  
RDS: mydb.xxxxxx.rds.amazonaws.com:3306
```
✔️ 바뀌는 것
- DB 위치 (로컬 → AWS 서버)

✔️ 동일한 것
- 접속 방식 (host, port, user, password)

🔹 AWS가 해주는 것 (자동 관리)
```
- DB 설치 및 초기 설정
- OS 및 DB 패치
- 자동 백업 / 복구
- 장애 발생 시 자동 복구 (Multi-AZ)
- 모니터링
```

🔹 개발자가 해야 하는 것
```
- 테이블 설계
- 쿼리 작성
- 성능 튜닝 (인덱스 등)
```
핵심
```
- 인프라는 AWS가 관리  
- 데이터와 성능은 개발자가 관리
```

🟢 장점
- DB 운영 부담 거의 없음
- 자동 백업 및 복구
- 장애 대응 자동 처리
- 몇 분 안에 DB 생성 가능

🔴 단점
- OS 직접 제어 불가능
- 비용이 EC2보다 비쌀 수 있음
- 네트워크 지연 가능 (서버와 멀면 느림)


### ✅ Amazon EC2란?
Amazon EC2는 AWS에서 제공하는 가상 서버(컴퓨터)입니다.

쉽게 말하면:
- 클라우드에 있는 내 컴퓨터 한 대

🔹 특징
```
- 원하는 OS 설치 가능 (Linux, Windows)
- DB, 웹서버, Redis 등 모든 것 설치 가능
```

🔹 어떻게 사용하는가?
	직접 서버를 구성합니다
```
1. EC2 생성  
2. 접속 (SSH)  
3. MySQL/PostgreSQL 설치  
4. Django/FastAPI 실행
```

🔹 내가 해야 하는 것
```
- DB 설치
- 백업 설정
- 보안 설정
- 장애 복구
- 서버 관리
```
핵심
모든 운영을 내가 직접 해야 함

🟢 장점
- 자유로운 커스터마이징
- 원하는 프로그램 다 설치 가능
- 비용 조절 가능

🔴 단점
- 운영 부담 큼
- 보안 직접 관리해야 함
- 백업 안 하면 데이터 날아갈 수 있음
- 장애 발생 시 직접 복구해야 함
---
### ✅ 핵심 차이
| 구분     | RDS    | EC2 |
| ------ | ------ | --- |
| 역할     | DB 서비스 | 서버  |
| DB 설치  | 자동     | 직접  |
| 백업     | 자동     | 직접  |
| 장애 복구  | 자동     | 직접  |
| 운영 난이도 | 낮음     | 높음  |
| 자유도    | 낮음     | 높음  |

✅ 핵심 정리
RDS = DB를 대신 운영해주는 서비스  
EC2 = 내가 직접 운영하는 서버


✅ 추천 구조 (실무)

현재 프로젝트 기준
```
EC2 → Django / FastAPI / Redis / Celery  
RDS → PostgreSQL
```
✔️ 이유
- DB는 안정성이 중요 → RDS 사용
- 서버는 자유롭게 구성 → EC2 사용

최종 정리
이렇게 기억하면 끝입니다

EC2는 컴퓨터 
RDS는 DB 서비스  
→ 컴퓨터(EC2)에서 프로그램 실행  
→ 데이터는 RDS에 저장

```python
def make_embeddings(texts: list[str]) -> list[list[float]]:
    """
    여러 문장을 받아 임베딩 벡터 리스트로 반환
    """

    # ✅ AI 비활성화 상태
    if embedding_model is None:
        return [[0.0] * 384 for _ in texts]  # 더미 벡터

    # ✅ AI 활성화 상태
    vectors = embedding_model.encode(texts)
    return [vector.tolist() for vector in vectors]


def calculate_similarity(text1: str, text2: str) -> float:
    """
    두 문장의 cosine similarity 계산
    """

    # ✅ AI 비활성화 상태
    if embedding_model is None:
        return 0.0  # 더미 결과

    # ✅ AI 활성화 상태
    vectors = embedding_model.encode([text1, text2])
    score = cosine_similarity([vectors[0]], [vectors[1]])[0][0]
    return float(score)
```

```nginx
server {

    client_max_body_size 20M;

    location /static/ {
        alias /app/staticfiles/;
    }

    location /media/ {
        alias /app/media/;

        proxy_pass http://fastapi-server:8001/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

    location / {
        proxy_pass http://drf-web:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

}
```

- `/ai/` → FastAPI
- 나머지 `/` → Django
